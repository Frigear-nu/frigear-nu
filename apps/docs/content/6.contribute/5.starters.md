This page is for contributors who change a [starter](/guide/concepts/glossary): how to work on one, which files must
stay identical and what CI checks. Each starter is a pnpm workspace under `.starters/<starter>`, copied into a new
project with `pnpx giget@latest gh:Frigear-nu/frigear-nu/.starters/<starter> <dir>`.

| Starter | What it is | Guide |
| --- | --- | --- |
| `.starters/workspace` | `apps/web`: users, auth, account, admin | [Workspace starter](/examples/starters/workspace) |
| `.starters/mobile` | `apps/mobile`: a Capacitor app on `@frigear-nu/mobile` against any issuer | [Mobile starter](/examples/starters/mobile) |
| `.starters/mobile-standalone` | `workspace` + `apps/mobile`; `apps/web` adds `@frigear-nu/oauth-server` and the API | [Standalone mobile starter](/examples/starters/mobile-standalone) |
| `.starters/desktop` | `apps/desktop`: a Tauri app on `@frigear-nu/desktop`, remote (any issuer) or local (its own server) | [Desktop starter](/examples/starters/desktop) |
| `.starters/multi-platform` | `mobile-standalone` + `apps/desktop`; `apps/web` also registers the desktop clients | [Multi-platform starter](/examples/starters/multi-platform) |

## How starters differ from packages

- They are not part of the repository's pnpm workspace: `pnpm-workspace.yaml` lists only `apps/*` and `packages/*`.
- They depend on the **published** `@frigear-nu/*` versions, never `workspace:*` or `catalog:`.
- Each has its own `AGENTS.md`.

## Keep shared files identical

These are the same in every starter: `.github/`, `.nvmrc`, `.gitignore`, `pnpm-workspace.yaml`, `scripts/` and
`packages/`. `apps/mobile` is the same in `mobile`, `mobile-standalone` and `multi-platform`. `mobile-standalone/apps/web`
differs from `workspace/apps/web` only in `nuxt.config.ts`, `package.json`, `.env.example`, `AGENTS.md`, the migrations
and `server/api/`. `multi-platform/apps/web` differs from `mobile-standalone/apps/web` only in `nuxt.config.ts`,
`package.json`, `AGENTS.md` and the migrations, and `multi-platform/apps/desktop` from `desktop/apps/desktop` only in
`nuxt.config.ts`, `identity.ts`, `.env.example`, `AGENTS.md` and the migrations.

::warning
Change a shared file in every starter in the same commit. The `drift` job of `.github/workflows/starters.yml` fails
otherwise.
::

`pnpm prepare:env` runs the CLI's [`prepare env`](/cli/environment), which copies each `.env.example` and fills in
empty secrets, never overwriting a value. A secret every starter needs goes in `BUILTIN_SECRETS` of
`packages/cli/src/env/prepare.ts`, so the starters keep no script of their own.

## Work on a starter in a copy

Work in a copy outside the repository, then copy the changes back:

```bash
cp -R .starters/<starter> "$TMPDIR/<starter>"
cd "$TMPDIR/<starter>" && pnpm install
```

To try unreleased packages, point `@frigear-nu/*` at packed or linked builds with `overrides`, in the copy only.

::warning
Never commit the copy's `node_modules`, `.nuxt`, `.output`, `.data`, `.env`, `pnpm-lock.yaml`,
`capacitor.config.json`, the native `ios/` and `android/` folders or the `src-tauri/` of `apps/desktop`.
::

The `desktop` and `multi-platform` starters have no `src-tauri/`: `pnpm desktop:setup` (`frigear-desktop doctor --fix`, which runs `init`) creates it for the mode in
`DESKTOP_MODE`, so the guide documents that step instead. Try it in the copy; Tauri builds need Rust, and local mode
needs Bun.

## Regenerate the migrations

After releasing a module that changes a schema, or bumping a starter's versions, regenerate the migrations of every
starter with a database, in the copy:

```bash
pnpm db:generate
```

Then commit them back: `apps/web/server/db/migrations` of `workspace`, `mobile-standalone` and `multi-platform`, and
`apps/desktop/server/db/migrations` of `desktop` and `multi-platform` (its `db:generate` runs in local mode). CI fails
when they are out of date.

## What CI checks

`.github/workflows/starters.yml` runs on pull requests that touch `.starters/`, on `main`, weekly and by hand:

- **starter**, for each starter: install, lint, typecheck and build against the published versions, and the
  migrations. It smoke tests the OAuth server of `mobile-standalone` and `multi-platform` (with the desktop clients),
  and the desktop app's local mode as well: its typecheck, and the sidecar compiled with Bun, started on a fresh data
  folder. In `desktop` a user registers and signs in; in `multi-platform` the sidecar starts a browser handoff at the
  built `apps/web`, which accepts its authorize URL.
- **drift**: the shared files above are identical.
- **desktop-native**, on `main` and by hand only: `frigear-desktop init` and a debug build without installers of the
  desktop starter's Tauri shell (local mode) on macOS, Linux and Windows.

## Release packages before merging

A starter that needs an unreleased `@frigear-nu` version is skipped with a warning on pull requests. On `main` it fails.
Release the packages first, as [Publishing](/contribute/publishing) describes.

## Keep the guides in step

Each starter has a guide under Examples. When you change a starter's files or commands, update its guide in the same
change.
