This page is for changing the CLI itself. To use it, see the [CLI section](/cli/overview).

## Run it from the repository

The root `cli` script runs `packages/cli/bin/cli.mjs`, which loads the TypeScript source with jiti, so there is no
build step:

```bash
pnpm cli --help
pnpm cli platform add mobile --ref <branch>
```

`--ref` copies the starters and app templates from your branch instead of `main`; it has to be pushed. Try a command
on a scratch project in a temporary directory, not in the repository.

## Layout and tests

The source is in `packages/cli/src`. Each command is a file in `commands/` that parses arguments, prompts and prints;
the work is in plain functions next to it (`platform/`, `upgrade/`, `utils/`) and exported from `src/index.ts`, so
[other tools can call them](/cli/from-code). Put new logic in such a function, and test it directly.

The tests run against the repository's own `.starters/`, with giget mocked, so nothing is downloaded or installed:

```bash
pnpm --filter @frigear-nu/cli test
```

The built-in platforms' root scripts are checked against the multi-platform starter's `package.json`: when you add a
script to a starter, add it to the platform in `src/platform/define.ts` too.

## Add an upgrade migration

A release with a breaking change in a published package adds a migration to `packages/cli/src/upgrades/`, so
[`upgrade`](/cli/upgrade) carries the change to every app. The entry names the first version with the change
(`since`) and has rules (a regular expression with a message, and an optional `replace`), a `project` check for
`nuxt.config` options, and `steps` for a person. Add a test for it to `packages/cli/test/upgrade.test.ts`, and a row
to [Upgrading](/get-started/upgrading#breaking-changes-by-release).

## After `module:create` in the Frigear repository

The command only creates the package. [Scaffold a module](/contribute/writing-a-module/scaffold) starts the path through
the rest: the folder layout, `setup()`, tests, the release config and the module page.

## Release

The published package is built with unbuild into `dist/`, and `publishConfig` points `bin` at `dist/cli.mjs`. It is
released like every other package: see [Publishing](/contribute/publishing). `create-frigear-app` runs the latest CLI,
so it does not need a release of its own.
