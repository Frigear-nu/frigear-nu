This guide creates a new project that uses the published `@frigear-nu` modules: a pnpm workspace with one Nuxt app in
`apps/web`, where people can register, sign in, manage their account, and where admins manage users. It takes about
five minutes.

::note
**Nuxt 4 only.** Every `@frigear-nu` module is a Nuxt 4 module (Nuxt `^4.6`) and expects the Nuxt 4 directory
structure, with app code under `app/`. Nuxt 3 is not supported. Every example in these docs is a Nuxt 4 example.
::

## Requirements

| Tool | Version |
| --- | --- |
| Node.js | `24` (the starter pins `24.22.1` in `.nvmrc`) |
| pnpm | `12.10.0` (pinned in the starter's `package.json`, use `corepack enable`) |

## Create the project

The starter lives in this repository under [`.starters/workspace`](https://github.com/Frigear-nu/frigear-nu/tree/main/.starters/workspace).
Copy it with [giget](https://github.com/unjs/giget):

```bash
pnpx giget@latest gh:Frigear-nu/frigear-nu/.starters/workspace my-project
cd my-project
git init
corepack enable
pnpm install
```

Create `apps/web/.env` from the example file:

```bash
pnpm prepare:env
```

Then fill in the two variables in `apps/web/.env`:

| Variable | What it is |
| --- | --- |
| `NUXT_SESSION_PASSWORD` | Encrypts the session cookie. At least 32 characters, for example from `openssl rand -base64 32`. |
| `NUXT_ACL_ADMINS` | Comma separated emails that are always admins. Put your own email here to become the first admin. |

Start the app:

```bash
pnpm dev
```

On the first start, NuxtHub creates a local SQLite database in `apps/web/.data/` and applies the committed migrations.

## Sign in

1. Open `http://localhost:3000` and choose **Create account**. Register with the email you put in `NUXT_ACL_ADMINS`.
2. You land on `/account`, with Profile, Security and API tokens pages. An **Admin** badge shows that the allowlist
   matched.
3. Open `/admin` for the admin dashboard. **Users** (`/admin/users`) lists, creates and edits users.

Emails such as password resets are not sent yet: the `log` driver of [Notify](/modules/notify) prints them in the
terminal running `pnpm dev`. Configure a real driver before you deploy.

::note
The allowlist is applied when you sign in. If you add your email to `NUXT_ACL_ADMINS` after signing in, sign out and in
again.
::

::warning
With the currently published versions (`@frigear-nu/users@1.2.1`, `@frigear-nu/account@0.2.1`), the **Users** list
(`/admin/users`) and the **API tokens** page (`/account/api-tokens`) fail with `tableUi is not defined`. The pages use a
UI helper they do not import, which only works inside this monorepo. A fix is on its way; the rest of the app works.
::

## What is in the starter

```
my-project/
  package.json              root scripts: dev, build, lint, typecheck, test, db:generate, db:migrate
  pnpm-workspace.yaml       apps/* and packages/*
  AGENTS.md                 conventions for you and your coding agents
  packages/eslint-config/   shared lint config for packages you add
  apps/web/
    nuxt.config.ts          the modules and their options
    app/pages/index.vue     the landing page
    server/utils/acl.ts                 effectiveRole(): the stored role, or admin for NUXT_ACL_ADMINS
    server/utils/map-session-user.ts    puts the effective role in the session
    server/plugins/users-policy.ts      who may administer users (admins only)
    server/db/migrations/sqlite/        the database schema, committed
```

The app installs these modules. Each one installs the modules it depends on, such as [Auth](/modules/auth),
[Notify](/modules/notify) and [UI](/modules/ui):

| Module | Gives you |
| --- | --- |
| [Users](/modules/users) | The `users` table, self-service profile, email and password changes, and `/admin/users`. |
| [Authorization](/modules/authorization) | A `role` on users and route rules that guard `/account/**` and `/admin/**`. |
| [Account](/modules/account) | The `/account` pages. |
| [Admin](/modules/admin), [Widget](/modules/widget), [Menu](/modules/menu) | The admin shell and dashboard, its widgets, and the account menus. |

The relevant part of `apps/web/nuxt.config.ts`:

```ts [apps/web/nuxt.config.ts]
export default defineNuxtConfig({
  modules: [
    '@nuxthub/core',
    '@nuxt/ui',
    '@frigear-nu/menu',
    '@frigear-nu/widget',
    '@frigear-nu/users',
    '@frigear-nu/authorization',
    '@frigear-nu/account',
    '@frigear-nu/admin',
  ],
  runtimeConfig: { aclAdmins: '' },
  hub: { db: { dialect: 'sqlite', driver: 'libsql', connection: { url: 'file:./.data/db/sqlite.db' } } },
  account: { settings: { pages: { index: true, profile: true, security: true, apiTokens: true } } },
  admin: { settings: { roles: ['admin'] } },
  authentication: {
    settings: {
      afterLogin: '/account',
      pages: { login: true, register: true },
      session: { mapper: '~~/server/utils/map-session-user' },
    },
  },
  authorization: { redirectTo: '/login' },
  notify: { email: { driver: 'log' } },
  users: { settings: { admin: true, profilePath: '/account/profile' } },
})
```

The user admin is denied unless the host allows it. The starter's policy allows admins everything:

```ts [apps/web/server/plugins/users-policy.ts]
export default defineNitroPlugin((nitro) => {
  nitro.hooks.hook('users:admin:authorize', async (ctx) => {
    const actor = await db.query.users.findFirst({ where: (t, { eq }) => eq(t.id, ctx.userId) })
    ctx.allowed = !!actor && effectiveRole(actor) === 'admin'
  })
})
```

Change `server/utils/acl.ts` and this plugin when you need more roles. The [website](/applications/website) has a fuller
example with a role hierarchy.

## Add a module

Every module follows the same steps. For example, to add [Forms](/modules/forms) (forms stored in the database, with
an admin for editing them and reading submissions):

1. Install it in the app, from the project root:

   ```bash
   pnpm --filter ./apps/web add @frigear-nu/forms
   ```

2. Add it to `modules` in `apps/web/nuxt.config.ts` and set its options. The [module page](/modules/forms) lists them,
   plus what it needs from NuxtHub (Forms uses KV for rate limiting and blob storage for uploads):

   ```ts [apps/web/nuxt.config.ts]
   export default defineNuxtConfig({
     modules: [
       // ...
       '@frigear-nu/forms',
     ],
     hub: {
       kv: true,
       blob: true,
       db: { dialect: 'sqlite', driver: 'libsql', connection: { url: 'file:./.data/db/sqlite.db' } },
     },
     forms: {
       settings: {
         pages: { form: true, admin: true, adminForm: true, adminSubmissions: true, adminSubmission: true },
       },
     },
   })
   ```

3. Staff access is the host's decision, like the user admin. Allow admins in a Nitro plugin:

   ```ts [apps/web/server/plugins/forms-policy.ts]
   import { db } from '@nuxthub/db'
   // Loads the module's hook types: Nitro's server tsconfig does not include module types.
   import type {} from '@frigear-nu/forms'

   export default defineNitroPlugin((nitro) => {
     nitro.hooks.hook('forms:authorize', async (ctx) => {
       const actor = await db.query.users.findFirst({ where: (t, { eq }) => eq(t.id, ctx.userId) })
       ctx.allowed = !!actor && effectiveRole(actor) === 'admin'
     })
   })
   ```

4. The module adds tables, so generate a migration and commit it:

   ```bash
   pnpm db:generate
   ```

   Run it after every module you add or upgrade. It prints `No schema changes, nothing to migrate` when the database is
   already up to date.

5. Restart `pnpm dev`. The new migration is applied on start, and the forms admin appears under `/admin`.

Each module page lists what it needs under **Requires**, **Options** and **Hooks**: other modules, NuxtHub features,
host policies and environment variables such as Stripe keys. To find the right module, see
[Which module do I need?](/getting-started/introduction#which-module-do-i-need).

## Use an existing Nuxt 4 app

To add the modules to an app you already have instead of starting from the starter:

1. Install the modules and their peers:

   ```bash
   pnpm add @frigear-nu/users @frigear-nu/authorization @frigear-nu/account @frigear-nu/menu \
     @nuxthub/core @nuxt/ui @libsql/client drizzle-orm drizzle-kit tailwindcss
   ```

2. Add the modules and options from the config above to your `nuxt.config.ts`.
3. Load Nuxt UI's styles in your CSS (`@import "tailwindcss"; @import "@nuxt/ui";`) and wrap the app in `<UApp>`.
4. Set `NUXT_SESSION_PASSWORD`, and copy `server/utils/acl.ts`, `server/utils/map-session-user.ts` and
   `server/plugins/users-policy.ts` from the starter if you want the admin allowlist.
5. Run `nuxt db generate` and commit `server/db/migrations`.

Two pnpm settings from the starter's `pnpm-workspace.yaml` are needed with the current releases:

- `strictDepBuilds: false`: the published modules still declare a development `postinstall` that pnpm skips, and the
  skip would otherwise fail the install.
- `overrides` for `@frigear-nu/auth` and `@frigear-nu/users`: the modules pin each other's versions exactly. If
  `pnpm why @frigear-nu/auth` lists more than one version, the overrides make the app use one copy of each.

## Go to production

Every module ships its schema for SQLite and PostgreSQL, so you can deploy to Cloudflare D1, libSQL/Turso or Postgres.
Pick the database in `hub.db` (see the [NuxtHub database docs](https://hub.nuxt.com/docs/database)), generate the
migrations for that dialect, and set `NUXT_SESSION_PASSWORD` in the host's environment.
