## Requirements

| Tool | Version | Where it is pinned |
| --- | --- | --- |
| Node.js | `24.22.1` | `.nvmrc` at the repository root |
| pnpm | `12.10.0` | `packageManager` in the root `package.json` |

Enable Corepack so the pnpm version declared by the project is used, and use `nvm use` (or your own version manager) for
Node.

## Install dependencies

From the repository root:

```bash
corepack enable
pnpm install
```

The install ends with the root `postinstall`, which runs every package's `dev:stub` script in dependency order: it
stubs the module build and runs `nuxt prepare`. Packages have no `postinstall` of their own, because it would be
published to npm and run in every consumer's install.

Always run `pnpm` from the repository root, including commands scoped to one app or package. The packages depend on each
other with `workspace:^`, which pnpm resolves from there. Scope a command with `--filter`, which has no short alias
(`-f` means `--force`):

```bash
pnpm --filter @frigear-nu/website <command>
pnpm --filter ./apps/website <command>
```

## Configure the environment

The website needs a few environment variables. Copy the example file and edit it:

```bash
cp apps/website/.env.example apps/website/.env
```

Only `NUXT_SESSION_PASSWORD` (the password that encrypts the session cookie) is required to start the app. Everything
else is optional until you use the feature: Stripe keys, the OAuth server signing key, the email driver and "Log in with
frigear.nu". The [website page](/applications/website#environment) lists them with the module that reads each one. The
docs app needs no environment.

## Run an application

```bash
pnpm --filter @frigear-nu/website dev
pnpm --filter @frigear-nu/docs dev
```

Each application starts its own Nuxt dev server; the terminal shows the local URL. Workspace packages resolve to their
TypeScript source, so you do not need to build them to run an app.

## Database

In development the website uses a local SQLite (libsql) file at `apps/website/.data/db/sqlite.db`. NuxtHub applies the
committed migrations when the dev server starts. After changing a schema, or a module that extends one:

```bash
pnpm --filter @frigear-nu/website db:generate   # generate migration files from schema changes
pnpm --filter @frigear-nu/website db:migrate    # apply migrations to the development database
```

Commit the generated SQL, snapshot and journal together. See [Module Kit](/modules/module-kit#migrations-and-database-backed-module-tests)
for the migration workflow, including fixtures. To start over, delete `apps/website/.data`.

## Build and validate

```bash
pnpm build:packages          # builds every package under packages/ except the base layer
pnpm build:website           # builds the website (raises Node's memory limit to 6 GB)
pnpm --filter @frigear-nu/docs build
```

The root scripts run lint, type checks and tests across the workspace with Turborepo:

```bash
pnpm lint
pnpm lint:fix
pnpm typecheck
pnpm test
```

Scope any of them to one project with `--filter`, for example `pnpm --filter ./packages/forms test`.
