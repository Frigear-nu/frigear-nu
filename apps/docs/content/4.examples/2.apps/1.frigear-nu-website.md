Read this app to see how a complete [host app](/guide/concepts/glossary) configures the modules, answers their policy
hooks and deploys.

The Frigear website app is the code; [frigear.nu](/guide/concepts/glossary) is the live service it runs, which is also
the default [issuer](/guide/concepts/glossary). The app is a private Nuxt 4 app on the
[base layer](/modules/platform/base-layer) in `apps/website` (`@frigear-nu/website`), deployed to Cloudflare Workers.
It replaces the [previous Nuxt website](https://github.com/Frigear-nu/nuxt-frigear-nu).

To run it from the repository root:

```bash
pnpm install
cp apps/website/.env.example apps/website/.env   # NUXT_APP_SECRET can stay empty in development
pnpm --filter @frigear-nu/website dev
```

## Modules

`nuxt.config.ts` extends `@frigear-nu/base` and installs these modules in this order, after Nuxt modules such as
`@nuxt/ui`, `@nuxthub/core`, `@nuxt/content` and `@nuxtjs/i18n`.

| Module | What the Frigear website app configures |
| --- | --- |
| [UI](/modules/interface/ui) | Defaults. |
| [Menu](/modules/interface/menu) | Defaults. The base layer adds a content `main` menu. |
| [Auth](/modules/identity/auth) | Sign-in at `/sign-in`, sign-up at `/sign-up`, password, WebAuthn, magic link, email verification, Facebook and Sign in with frigear.nu. |
| [Users](/modules/identity/users) | Staff user management, MCP, email-change verification, profile at `/account/profile`. |
| [Authorization](/modules/identity/authorization) | Sends visitors on guarded pages to `/sign-in`. |
| [Widget](/modules/interface/widget) | Defaults. |
| [Admin](/modules/interface/admin) | Open to the `admin`, `manager` and `coordinator` roles. |
| [Account](/modules/identity/account) | Index, profile, security, documents and API token pages, plus a list of documents. |
| [Notify](/modules/platform/notify) | The `log` email driver unless `NUXT_NOTIFY_*` picks a real one. |
| [Email Templates](/modules/platform/email-templates) | Brand name and logo for module emails. |
| [Stripe](/modules/commerce/stripe) | Keys from the environment. |
| [Subscriptions](/modules/commerce/subscriptions) | `monthly`, `quarterly` and `yearly` membership plans, with price lookup keys from the environment. |
| [Payments](/modules/commerce/payments) | MCP. |
| [Events](/modules/features/events) | All pages, including the admin pages, and MCP. |
| [Forms](/modules/features/forms) | Form and admin pages, MCP and seeded forms (see [Forms](#forms)). |
| [Cookie Consent](/modules/features/cookie-consent) | Policy link `/legal/gdpr`. |
| [OAuth Server](/modules/identity/oauth-server) | Admin and applications pages, MCP. |
| [Preferences](/modules/identity/preferences) | Defaults. |

In production, sign-up goes to `https://frigear.nu/sign-up` instead of the local page. The app also depends on
[Module Kit](/modules/platform/module-kit) directly. [MCP](/modules/features/mcp) is not listed: other modules install
it as a dependency.

## Content

The base layer reads site content from `content/`. The app has two locales, so it keeps one tree per locale:

| Folder | Contents |
| --- | --- |
| `content/da`, `content/en` | `config.yaml` (name, logo, navigation, footer) and `pages/**` Markdown. `da` is the default locale, and `en` is prefixed. |
| `content/events` | Event definition YAML files, such as `2026/01.general-assembly.yml`. |
| `content/_templates/events` | An event template for local development. |

::note
Nothing reads `content/events` or `content/_templates` yet. They hold event definitions ported from the old app. The
Events module stores events in the database.
::

The app's own translations are in `i18n/locales`. The same files can override module strings, as
[Module Kit](/modules/platform/module-kit) explains.

## Environment

Copy `apps/website/.env.example` to `.env`. The last column names what reads each variable.

| Variable | Purpose | Read by |
| --- | --- | --- |
| `NUXT_APP_SECRET` | Seals the session cookie (Nuxt's `appSecret`). Empty in development (Nuxt generates one); required in production, at least 32 characters (`openssl rand -base64 32`). | nuxt-auth-utils (Auth) |
| `NUXT_SESSION_PASSWORD` | Fallback encryption key for form submissions and stored OAuth tokens, when `NUXT_FORMS_ENCRYPTION_KEY` / `NUXT_AUTH_TOKENS_KEY` are unset. | [Forms](/modules/features/forms), Auth |
| `NUXT_ACL_ADMINS` | Comma-separated emails that always get the `admin` role, once the address is verified. Sets up the first admin. | The app |
| `NUXT_STRIPE_SECRET_KEY`, `NUXT_STRIPE_WEBHOOK_SECRET`, `NUXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` | Stripe credentials. | [Stripe](/modules/commerce/stripe) |
| `SUBSCRIPTIONS_MONTHLY_LOOKUP_KEY`, `SUBSCRIPTIONS_QUARTERLY_LOOKUP_KEY`, `SUBSCRIPTIONS_YEARLY_LOOKUP_KEY` | Stripe price lookup keys for the plans. Defaults: `membership_month`, `membership_quarter`, `membership_annual`. | [Subscriptions](/modules/commerce/subscriptions) |
| `NUXT_OAUTH_SERVER_PRIVATE_KEY`, `NUXT_OAUTH_SERVER_PREVIOUS_PUBLIC_KEYS` | The token signing key, and the retired public keys while rotating. | [OAuth Server](/modules/identity/oauth-server) |
| `NUXT_NOTIFY_EMAIL_DRIVER`, `NUXT_NOTIFY_EMAIL_FROM` and the provider keys | Email delivery. | [Notify](/modules/platform/notify) |
| `FRIGEAR_SSO_URL`, `FRIGEAR_SSO_CLIENT_ID`, `FRIGEAR_SSO_CLIENT_SECRET` | Sign in with frigear.nu. On for pull request previews, or when these are set. | Auth |
| `NUXT_FRIGEAR_FORCE_ID` | Use the frigear.nu user id as the local user id. | Auth |
| `NUXT_OAUTH_FACEBOOK_CLIENT_ID`, `NUXT_OAUTH_FACEBOOK_CLIENT_SECRET` | Facebook sign-in, offered only when these are set. | Auth |
| `NUXT_FORMS_SEED_ENABLED`, `NUXT_FORMS_APPLICATIONS_TO`, `NUXT_MAIL_TO`, `NUXT_CONTACT_<SUBJECT>` | Forms seeding and recipients (see [Forms](#forms)). | The app |
| `DEPLOYMENT_HOST`, `CLOUDFLARE_WORKER_NAME`, `NUXT_HUB_CLOUDFLARE_DATABASE_ID`, `NUXT_HUB_CLOUDFLARE_KV_NAMESPACE_ID`, `NUXT_HUB_CLOUDFLARE_BUCKET_NAME` | Cloudflare deployment (see [Deployment](#deployment)). | The app |

## Forms

The app seeds and guards the [Forms](/modules/features/forms) module in its own code, not in the module.

- **Seeded forms.** `forms/index.ts` and `forms/contact.ts` define three forms. `contact` is published and has a
  subject select. `project-application` and `board-member-application` are drafts. They are inserted only when
  `NUXT_FORMS_SEED_ENABLED=true` turns on `forms.seed.enabled`, and never overwrite an existing slug.
- **Recipients.** `NUXT_FORMS_APPLICATIONS_TO` (comma-separated) receives both application forms. The contact form
  sends to `NUXT_MAIL_TO`, and `NUXT_CONTACT_<SUBJECT>`, such as `NUXT_CONTACT_SUPPORT`, routes one subject to its own
  address. Without a recipient, submissions are only stored.
- **Who manages forms.** The `coordinator` role and every role above it hold `forms:manage`, `forms:credentials` and
  `forms:pii` (`authorization.roles` in `nuxt.config.ts`). `forms:pii` gates submission answers in MCP tools only: the
  admin pages show submissions with `forms:manage`.

## Access control

`nuxt.config.ts` defines the roles in `authorization.roles`. They form a chain, each role inheriting the one below:
`admin` > `manager` > `coordinator` > `eventmanager` > `barmanager` > `crew` > `member` > `user`. `supplier` and
`partner` only inherit `user`. Every signed-in user holds `user` (`defaultRoles`).

| Role | Adds |
| --- | --- |
| `crew` | `documents:crew`: the crew documents on `/account/documents` (a permission the app registers in `authentication.permissions`). |
| `eventmanager` | `events:manage`, `events:refund`, `events:pii`. |
| `coordinator` | `admin:access` (the admin area), `users:read`, `users:list`, `forms:manage`, `forms:credentials`, `forms:pii`, `payments:manage`. |
| `manager` | `users:create`, `users:update`, `users:delete`, `users:manage`, `subscriptions:manage`, `roles:read`, `roles:assign`. |
| `admin` | `*`, plus the sensitive `events:pii` and `forms:pii` by name, so it holds every permission. |

- **The first admin.** `server/plugins/authorization-roles.ts` adds `admin` to verified emails in `NUXT_ACL_ADMINS`, in
  the `authorization:roles` hook (`shared/acl.ts`). Nothing is stored. Admins assign every other role on the user's
  page in the admin. A role can only be assigned by someone whose roles are strictly above it, so a manager assigns
  coordinator and below, and only admins assign manager or admin.

- **Admin addresses.** `server/policies.ts` lets only admins create a user with, or change an address to, an email in
  `NUXT_ACL_ADMINS`, since the account would become an admin once it is verified.
- **Single sign-on claims.** `server/plugins/oauth-policy.ts` adds `roles` (the effective roles) and `role` (the most
  senior one) to ID tokens and userinfo with the `profile` scope, so an admin here is an admin in the other Frigear
  apps.

## Database

Production uses Cloudflare D1. `nuxt.config.ts` adds a KV namespace, for Stripe webhook idempotency and the
subscription plans cache, and an R2 bucket for form file uploads. Development uses a local SQLite file. Migrations live
in `apps/website/server/db/migrations/sqlite`. [Local development](/contribute/local-development#database) has the
commands.

## Deployment

The app builds with the `cloudflare_module` Nitro preset and runs on Cloudflare Workers.

- **Production.** Pushing to `main` runs `.github/workflows/deploy-production.yml`. It deploys and applies the D1
  migrations.
- **Previews.** Pull requests from collaborators run `deploy-preview.yml`. Each gets its own D1 database and a Worker
  Preview (`pr-<n>`), both deleted when the pull request closes. Both workflows call the reusable `deploy-website.yml`.
- **Locally.** The root `cloudflare:*` scripts and `apps/website/scripts/deploy.sh` run the same steps against an
  existing `.output` build.
