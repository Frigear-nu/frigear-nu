**What you'll have afterwards:**

- A Nuxt 4 web app on `http://localhost:3000` where people sign up, sign in and manage their account.
- You, signed in with the `admin` role, so the admin area at `/admin` is open to you.
- User management at `/admin/users`, where you list, create and edit users.

Use this [starter](/guide/concepts/glossary) for a website. It is a pnpm workspace with one
[host app](/guide/concepts/glossary) in `apps/web`, built on the published `@frigear-nu` modules.

::tip
Building a mobile app? The [mobile starter](/examples/starters/mobile) is a Capacitor app that signs in at an
[issuer](/guide/concepts/glossary) you already have. The
[standalone mobile starter](/examples/starters/mobile-standalone) is this starter plus a mobile app that signs in at it.
::

## Prerequisites

The tools in [Requirements](/get-started/installation#requirements). Nothing else.

## 1. Create the project

Copy [`.starters/workspace`](https://github.com/Frigear-nu/frigear-nu/tree/main/.starters/workspace):

::code-group

```bash [pnpm create]
pnpm create frigear-app my-app --platform web
cd my-app
git init
```

```bash [giget]
pnpx giget@latest gh:Frigear-nu/frigear-nu/.starters/workspace my-app
cd my-app
git init && corepack enable && pnpm install
pnpm prepare:env
```

::

## 2. Run it

::warning
Set `NUXT_ACL_ADMINS` before you sign up, or the `admin` role only applies after you sign in again.
::

Put your own email in `NUXT_ACL_ADMINS` in `apps/web/.env`, then start the app:

```bash
pnpm dev
```

## 3. Sign in

Open `http://localhost:3000`, choose **Create account** and sign up with that email.

::callout{color="success" icon="i-lucide-check"}
**What you should see:** `/account` with the **Admin** badge.
::

Passkeys are on. On **Security** (`/account/security`), add one. From then on the passkey button on the sign-in page
signs you in without a password, on any device your passkey syncs to.

[Installation](/get-started/installation#_1-create-the-project) explains each of these steps, what you should see
afterwards and what to do when the admin role does not apply.

| `apps/web/server/utils/map-session-user.ts` | Puts that role in the session at sign-in. |

| `apps/web/server/db/migrations/sqlite/` | The database schema, committed. |
| `apps/web/modules/libsql-binding.ts` | Puts the SQLite driver's native binding in the server build. |

[Project structure](/get-started/project-structure) explains each file.

### The modules

The app installs these modules directly. Each one installs the modules it depends on, such as
[Auth](/modules/identity/auth), [Notify](/modules/platform/notify) and [UI](/modules/interface/ui).

| Module | Gives you |
| --- | --- |
| [Users](/modules/identity/users) | The `users` table, self-service profile, email and password changes, and `/admin/users`. |
| [Authorization](/modules/identity/authorization) | A `role` on users, and route rules that guard `/account/**` and `/admin/**`. |
| [Account](/modules/identity/account) | The `/account` pages. |
| [Admin](/modules/interface/admin), [Widget](/modules/interface/widget), [Menu](/modules/interface/menu) | The admin area and its dashboard, the dashboard widgets, and the account menus. |

[Configuration](/get-started/configuration#_1-set-module-options-in-nuxtconfigts) shows the full
`apps/web/nuxt.config.ts` and explains each option.

### Who may manage users

User management is denied unless the host app allows it. The app answers the
[policy hook](/guide/concepts/glossary) of Users in a server plugin. The starter's plugin allows the `admin` role
everything, and offers it every role in the role select:

```ts [apps/web/server/plugins/users-policy.ts]
import { db } from '@nuxthub/db'
// Loads the `users:admin:*` hook types (Nitro's server tsconfig does not include module types).
import type {} from '@frigear-nu/users'

export default defineNitroPlugin((nitro) => {
  nitro.hooks.hook('users:admin:authorize', async (ctx) => {
    const actor = await db.query.users.findFirst({ where: (t, { eq }) => eq(t.id, ctx.userId) })
    ctx.allowed = !!actor && effectiveRole(actor) === 'admin'
  })

  // The roles the role select offers.
  nitro.hooks.hook('users:admin:roles', async (ctx) => {
    const actor = await db.query.users.findFirst({ where: (t, { eq }) => eq(t.id, ctx.userId) })
    ctx.roles = actor && effectiveRole(actor) === 'admin' ? [...userRoles] : []
  })
})
```

Change `server/utils/acl.ts` and this plugin when you need more roles. The
[Frigear website app](/examples/apps/frigear-nu-website) has a fuller example with a role hierarchy.

### Other ways to grow it

- **Add a module.** [Add a module](/get-started/adding-modules#add-a-module) walks through adding Forms, with its
  policy hook and migration. To find the right module, see
  [Which module do I need?](/get-started/adding-modules#which-module-do-i-need).
- **Use an existing Nuxt 4 app instead.**
  [Use an existing Nuxt 4 app](/get-started/installation#use-an-existing-nuxt-4-app) lists the packages and files to
  copy.
- **Go to production.** [Deployment](/get-started/deployment) lists the database, secrets and email driver to set.
  Launch on your final `https` domain: a passkey belongs to the domain it was created on, so moving means users add
  theirs again. Set `authentication.settings.webAuthn: false` to offer email and password only.
