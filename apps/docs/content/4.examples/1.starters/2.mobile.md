This guide creates a **Capacitor** app from the published `@frigear-nu` modules: a pnpm workspace with one app in
`apps/mobile`, a static Nuxt 4 SPA on [Mobile](/modules/interface/mobile) that signs in with [OAuth Client](/modules/identity/oauth-client)
at an issuer you already have: frigear.nu, your own [Frigear OAuth server](/modules/identity/oauth-server), or any provider on the
[checklist](/guide/going-further/own-oauth-server). It has two tabs: **Home** shows the claims of your ID token and calls `/api/me` on
your API with the access token, **Account** shows your profile and signs you out.

::tip
No server yet? The [standalone mobile starter](/examples/starters/mobile-standalone) is this app plus a web app that is the
OAuth server and the API, wired together.
::

## Requirements

| Tool | Version |
| --- | --- |
| Node.js | `24` (the starter pins `24.22.1` in `.nvmrc`) |
| pnpm | `12.10.0` (pinned in the starter's `package.json`, use `corepack enable`) |
| Xcode | For iOS: a recent Xcode with an iOS simulator. The native project uses Swift Package Manager, no CocoaPods. |
| Android Studio | For Android: a JDK and the Android SDK. |

## Create the project

The starter lives in this repository under [`.starters/mobile`](https://github.com/Frigear-nu/frigear-nu/tree/main/.starters/mobile).
Copy it with the [CLI](/contribute/tooling/cli) or [giget](https://github.com/unjs/giget). `init` also runs `pnpm install`
and `pnpm prepare:env`:

::code-group

```bash [CLI]
pnpx @frigear-nu/cli init my-app --starter mobile
cd my-app
git init
```

```bash [giget]
pnpx giget@latest gh:Frigear-nu/frigear-nu/.starters/mobile my-app
cd my-app
git init
corepack enable
pnpm install
pnpm prepare:env
```

::

`pnpm prepare:env` copies `apps/mobile/.env.example` to `apps/mobile/.env` (it never overwrites a value).

## Choose the issuer

The app needs an issuer that knows it. Set the issuer and your API in `apps/mobile/.env`:

| Variable | What it is |
| --- | --- |
| `NUXT_PUBLIC_OAUTH_CLIENT_ISSUER` | The issuer URL, for example `https://frigear.nu`. Default in the example: `http://localhost:3000`. |
| `NUXT_PUBLIC_OAUTH_CLIENT_API_BASE` | The API that `useApi()` and `$api` call with the access token. Without it: the issuer. |
| `NUXT_PUBLIC_OAUTH_CLIENT_CLIENT_ID` | Optional: overrides `clientId` of `identity.ts` per environment. |
| `NUXT_PUBLIC_OAUTH_CLIENT_SCOPE` | Optional: overrides `scopes` of `identity.ts`, space separated. |

`NUXT_PUBLIC_*` values are baked into the build: run `pnpm mobile:sync` after you change them.

Then register a **public client** (PKCE, no secret) at the issuer, with the values from `apps/mobile/identity.ts`:

| What | Value in the starter |
| --- | --- |
| Client id | `mobile` (`clientId`) |
| Redirect URI of the app | `com.example.mobile:/auth/callback` (`appId` in lowercase, then `callbackPath`) |
| Redirect URI for `pnpm dev` | `http://localhost:3001/auth/callback` (development only) |
| CORS origins | `capacitor://localhost` (iOS), `https://localhost` (Android), `http://localhost:3001` (development) |
| Scopes | `openid profile email` (see below for `offline_access`) |

The app needs a refresh token to stay signed in. The Frigear OAuth server always issues one (it does not support the
`offline_access` scope and drops it); most other issuers only issue one for `offline_access`, so add it to `scopes` in
`identity.ts` (or `NUXT_PUBLIC_OAUTH_CLIENT_SCOPE`) when you use Keycloak, Auth0, Zitadel and the like.

How that looks for each kind of issuer:

- **Your own Frigear server** (`@frigear-nu/oauth-server`): one entry in `oauthServer.clients` with these redirect URIs
  and `cors.paths: ['/api/']` for your API. [Add apps/mobile to an existing workspace](#add-appsmobile-to-an-existing-workspace)
  shows the config; the [standalone starter](/examples/starters/mobile-standalone) has it wired up.
- **frigear.nu**: staff register the client; ask a staff member of frigear.nu. Its CORS allows the webview origins, so
  the app works on a device; a browser on `http://localhost:3001` is not an allowed origin there. frigear.nu has no
  `/api/me`: point `NUXT_PUBLIC_OAUTH_CLIENT_API_BASE` at your own API, or the Home tab shows the failed call.
- **Keycloak, Auth0, Zitadel and others**: see [Use your own OAuth server](/guide/going-further/own-oauth-server) for the checklist
  (discovery, PKCE S256, exact redirect URIs, CORS, refresh tokens) and a recipe per provider.

## First run

```bash
pnpm dev
```

Open `http://localhost:3001`. Every page needs a signed-in user, so you land on `/login`:

1. **Sign in** sends you to the issuer, where you sign in and approve the app.
2. The issuer redirects to `http://localhost:3001/auth/callback`, the app exchanges the code for tokens and opens
   **Home**: your ID token claims and the result of `GET /api/me` on your API.
3. **Account** shows your name and email. **Sign out** revokes the refresh token at the issuer.

Tokens live in `localStorage` in a browser and in the Keychain / Keystore on a device
([`@aparajita/capacitor-secure-storage`](https://github.com/aparajita/capacitor-secure-storage)). A reload keeps you
signed in; the access token is refreshed when it expires.

## Run it on the iOS simulator

```bash
pnpm mobile:ios
```

The script creates the native projects the first time (`frigear-mobile native --if-missing`: `cap add ios` and
`cap add android`, plus the URL scheme of the redirect URI in `Info.plist` and `AndroidManifest.xml`), builds the SPA
(`nuxt generate`), copies it into `ios/` (`cap sync ios`) and asks which simulator to run (`cap run ios`).

**Sign in** opens the in-app browser at the issuer. After you approve, the issuer redirects to
`com.example.mobile:/auth/callback`, iOS hands that URL to the app and you are signed in. The simulator shares your
Mac's network, so an issuer on `http://localhost:3000` works as is.

Run `pnpm mobile:sync` after every change to the web code or `.env`, and after every `pnpm install` (the Swift Package
Manager paths point into `node_modules`). `pnpm mobile:doctor` lists missing plugins and URL schemes.

## Run it on an iPhone

With an issuer on the internet, open the project in Xcode and run it on the phone:

```bash
pnpm mobile:ios:device
```

The script builds with `MOBILE_LAN=1`, which rewrites `localhost` in the issuer and API base to this Mac's LAN address
(`MOBILE_LAN=192.168.1.20` picks it), so a phone on the same Wi-Fi reaches an issuer running on your Mac. Start that
server on every interface (for a Nuxt server: `nuxt dev --host 0.0.0.0`). Then, in Xcode:

1. Select the **App** target, **Signing & Capabilities**, and pick your team (a free Apple ID works; the install then
   expires after 7 days). Do not commit the team id.
2. Connect the phone, turn on **Developer Mode** on it (Settings, Privacy & Security), choose it as the run destination
   and press **Run**.
3. The first time, trust the developer profile on the phone (Settings, General, VPN & Device Management), and allow
   local network access when asked.

`MOBILE_LAN` never applies to `nuxt dev`, and the build fails when `MOBILE_RELEASE=1` is also set, so a LAN address never
ships. For live reload on a device, see [Device development](/modules/interface/mobile).

## Android

```bash
pnpm mobile:android
```

The same steps for Android: native project, build, `cap sync android`, `cap run android`. Android shows the web tab bar
and header (the native chrome is iOS only by default), and the back button closes an overlay, goes back, then returns to
the first tab. The Android WebView runs at `https://localhost`, so a plain `http` development server is mixed content:
use an `https` issuer, or live reload, when you test on Android.

## Rename the app

Everything that names the app is in `apps/mobile/identity.ts`:

```ts [apps/mobile/identity.ts]
export const appId = 'com.example.mobile' // bundle id, application id, and (lowercase) the redirect URI scheme
export const appName = 'Example' // home screen name and fallback page title
export const clientId = 'mobile' // the OAuth client_id
export const callbackPath = '/auth/callback'
export const devPort = 3001 // keep the `dev` script of apps/mobile/package.json in step
export const scopes = ['openid', 'profile', 'email'] // add 'offline_access' for issuers that need it
```

After changing `appId`:

1. Register the new redirect URI (`<new app id>:/auth/callback`) at the issuer, or let a Frigear server in the same
   workspace pick it up from `@workspace/mobile/identity`.
2. Delete `apps/mobile/ios` and `apps/mobile/android`, then run `pnpm mobile:native` (or any `mobile:ios` /
   `mobile:android` script) to create them with the new id and URL scheme.

Use lowercase letters, digits, `.` and `-` in the app id: the redirect URI scheme is the app id in lowercase, with `_`
turned into `-`. The tabs are `mobile.tabs` in `apps/mobile/nuxt.config.ts`, and the login page's title and icon are in
`apps/mobile/app/app.config.ts`.

## What is in the starter

```
my-app/
  package.json              root scripts: dev, build, lint, typecheck, prepare:env, mobile:*
  pnpm-workspace.yaml       apps/* and packages/*
  AGENTS.md                 conventions for you and your coding agents
  scripts/prepare-env.mjs   creates the apps' .env files
  packages/eslint-config/   shared lint config for packages you add
  apps/mobile/
    identity.ts             app id, name, client id, callback path, dev port, scopes (@workspace/mobile/identity)
    nuxt.config.ts          @nuxt/ui and @frigear-nu/mobile, the tabs, oauthClient from identity.ts
    .env.example            NUXT_PUBLIC_OAUTH_CLIENT_ISSUER and _API_BASE
    app/app.vue             <UApp :toaster="useMobileToaster()">
    app/app.config.ts       login page branding
    app/pages/index.vue     Home: claims and useApi('/api/me')
    app/pages/account.vue   Account: profile and sign out
```

`ios/` and `android/` are not in the starter: `pnpm mobile:native` creates them. Commit them once you change native
settings such as the signing team, icons or entitlements.

The app's `package.json` lists the Capacitor plugins the shell uses (`@capacitor/app`, `browser`, `haptics`,
`action-sheet`, `dialog`, `share`, `status-bar`, `keyboard`, `preferences`, `@capgo/capacitor-native-navigation`) and
`@aparajita/capacitor-secure-storage` for the tokens. Capacitor only links the native code of the app's own
dependencies, so add plugins to `apps/mobile`, not to a package it uses.

## Add apps/mobile to an existing workspace

To add the app to a project made from the [workspace starter](/examples/starters/workspace) (or any pnpm workspace with
`apps/*`), copy just the app:

::code-group

```bash [CLI]
pnpx @frigear-nu/cli app:create mobile --template mobile
pnpm prepare:env
```

```bash [giget]
pnpx giget@latest gh:Frigear-nu/frigear-nu/.starters/mobile/apps/mobile apps/mobile
pnpm install
pnpm prepare:env
```

::

`pnpm prepare:env` creates `apps/mobile/.env` too: `scripts/prepare-env.mjs` handles every app with an `.env.example`
(copy it from a current starter if your project predates it). Add the root scripts you want from the
[standalone starter](/examples/starters/mobile-standalone#commands): `dev:mobile`, `mobile:native`, `mobile:ios`, ...

To make `apps/web` the issuer and API of the app, apply the difference between the two starters, which is all in
`apps/web`:

1. Install the OAuth server and the app's identity:

   ```bash
   pnpm --filter ./apps/web add @frigear-nu/oauth-server @workspace/mobile@workspace:*
   ```

2. Register the app as a configured client in `apps/web/nuxt.config.ts`:

   ```ts [apps/web/nuxt.config.ts]
   import { appName, clientId, devRedirectUri, nativeRedirectUri } from '@workspace/mobile/identity'

   export default defineNuxtConfig({
     modules: [
       // ...
       '@frigear-nu/oauth-server',
     ],
     oauthServer: {
       cors: {
         origins: ['capacitor://localhost', 'https://localhost'],
         paths: ['/api/'],
       },
       clients: [{
         id: clientId,
         name: appName,
         redirectUris: [nativeRedirectUri],
         devRedirectUris: [devRedirectUri],
       }],
       settings: { pages: { admin: true } },
     },
   })
   ```

3. Add the host policy of the OAuth server, `apps/web/server/plugins/oauth-policy.ts` (who administers applications,
   and the roles of a user), and an API route the app calls, `apps/web/server/api/me.get.ts` with `requireUser`. Copy
   both from [`.starters/mobile-standalone/apps/web`](https://github.com/Frigear-nu/frigear-nu/tree/main/.starters/mobile-standalone/apps/web/server).
4. Add `NUXT_OAUTH_SERVER_PRIVATE_KEY=` to `apps/web/.env.example` and generate a key (see
   [Signing keys](/guide/going-further/signing-keys)). `nuxt dev` works without one: it keeps a dev key in
   `.data/oauth-server/dev-key.pem`.
5. The OAuth server adds tables: run `pnpm db:generate` and commit the migration.

The [standalone starter guide](/examples/starters/mobile-standalone#how-the-two-apps-fit-together) explains each piece.

## Production checklist

- [ ] Set your own `appId`, `appName` and `clientId` in `identity.ts`, and recreate `ios/` and `android/`.
- [ ] Register the production redirect URI `<app id>:/auth/callback` at the issuer. Do not register the `localhost` one
  in production.
- [ ] Point `NUXT_PUBLIC_OAUTH_CLIENT_ISSUER` and `NUXT_PUBLIC_OAUTH_CLIENT_API_BASE` at `https` production URLs in the
  environment of the release build. Never ship a `localhost` or LAN address.
- [ ] Allow `capacitor://localhost` and `https://localhost` for CORS at the issuer and on your API.
- [ ] Build releases with `MOBILE_RELEASE=1` (for example `MOBILE_RELEASE=1 pnpm mobile:sync`), so `MOBILE_LAN` cannot
  slip in.
- [ ] Keep `@aparajita/capacitor-secure-storage` installed: without it a production build fails, because tokens would be
  stored unencrypted.
- [ ] Run `pnpm mobile:doctor` and fix what it reports; `frigear-mobile doctor --strict` exits with `1` on errors, for CI.
- [ ] Replace the app icon and splash screen in the native projects, set the version and build number, and set up
  signing for the App Store and Google Play.

The [Mobile release checklist](/modules/interface/mobile) has the details.
