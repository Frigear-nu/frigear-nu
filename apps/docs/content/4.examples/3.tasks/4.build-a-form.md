**What you'll build:** a published contact form at `/forms/contact`, defined in code and seeded into the database, that
stores each submission and emails it to your team.

## Prerequisites

- [Forms](/modules/features/forms), which needs [Notify](/modules/platform/notify) (installed with it) and NuxtHub **KV**
  (rate limiting) and **blob** (uploads).
- A host app with users and the [admin area](/modules/interface/admin), such as the
  [workspace starter](/examples/starters/workspace). [Add a module](/get-started/adding-modules#add-a-module) shows
  the install, the staff policy and the migration for Forms.

## 1. Enable the pages and seeding

```ts [apps/web/nuxt.config.ts]
import { contactForm } from './forms/contact'

export default defineNuxtConfig({
  modules: ['@nuxthub/core', '@frigear-nu/forms'],
  hub: { kv: true, blob: true, db: { dialect: 'sqlite', driver: 'libsql', connection: { url: 'file:./.data/db/sqlite.db' } } },
  forms: {
    settings: {
      pages: { form: true, admin: true, adminForm: true, adminSubmissions: true, adminSubmission: true },
    },
    seed: {
      enabled: true, // or NUXT_FORMS_SEED_ENABLED=true
      forms: [{ slug: 'contact', name: 'Contact', status: 'published', definition: contactForm }],
    },
  },
})
```

`status` defaults to `draft`. Seeding inserts a slug only when it does not exist yet and never overwrites a form, so
edit forms later in the admin (`/admin/forms`).

## 2. Write the definition

`defineForm()` from `@frigear-nu/forms/utils` types a `FormDefinition`: a mode, steps, fields, and where answers go.

```ts [apps/web/forms/contact.ts]
import { defineForm } from '@frigear-nu/forms/utils'

export const contactForm = defineForm({
  mode: 'single',
  storage: 'db',
  steps: [
    {
      id: 'message',
      fields: [
        { key: 'name', type: 'text', label: 'Name', required: true },
        { key: 'email', type: 'email', label: 'Email', required: true },
        {
          key: 'subject',
          type: 'select',
          label: 'Subject',
          options: [{ value: 'support', label: 'Support' }, { value: 'other', label: 'Other' }],
        },
        { key: 'message', type: 'textarea', label: 'Message', required: true },
      ],
    },
  ],
  submit: { successMessage: 'Thanks, we will be in touch.' },
  delivery: {
    email: {
      to: ['office@example.com'],
      subject: 'New message from {{ answer.name }}',
      replyToField: 'email',
    },
  },
})
```

- `to` takes literal addresses. Without `body`, the notification lists every visible answer.
- Field keys start with a letter and contain letters, digits and underscores.
- `replyToField` must name an `email` field.
- `access` defaults to `{ availability: 'web', auth: 'none' }`: a public page with no sign-in.
- The email goes through [Notify](/modules/platform/notify), which prints it with the `log` driver until you configure
  a real one. The row is stored first, so a delivery error never loses a submission.

## 3. Allow staff, migrate and open the form

Forms staff access is denied by default; allow it with a `forms:authorize` Nitro plugin (see
[Add a module](/get-started/adding-modules#add-a-module)), then generate the migration:

```bash
pnpm db:generate
```

Restart `pnpm dev`. The form is at `/forms/contact`. Submissions are in the admin under `/admin/forms`. To place the
form in any page instead, render `<FormRenderer slug="contact" />`.
