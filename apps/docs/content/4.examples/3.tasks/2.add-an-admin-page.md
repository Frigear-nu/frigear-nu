**What you'll build:** a Units list page at `/admin/units` in your app, and the staff-only API route it reads. The
page has a sidebar entry under **Manage**, a heading with an action, a table in a card and an empty state.

## Prerequisites

- The [workspace starter](/examples/starters/workspace), or another [host app](/guide/concepts/glossary) with
  [Admin](/modules/interface/admin).
- A signed-in user with the `admin` role:
  [Roles and the first admin](/get-started/authentication#_4-roles-and-the-first-admin).
- [Pages](/guide/ux-patterns/pages), for the patterns this page follows.

The paths below are for the starter's `apps/web`. In another host app, leave out the `apps/web/` prefix.

::note
Admin brings [UI](/modules/interface/ui), [Menu](/modules/interface/menu) and [Widget](/modules/interface/widget). Only
users whose role is in `admin.settings.roles` get into the [admin area](/guide/concepts/glossary). It defaults to
`['admin']`.
::

## 1. Add the API route

The page reads its rows from `/api/admin/units`, so that route comes first. It must let only staff in.

::caution
Sign-in alone is not authorization. The role rule on `/admin/**` guards the page, not the API routes behind it. A
route that only calls `requireAuth` answers every signed-in user.
::

Check the caller's role the way the starter's `server/plugins/users-policy.ts` does: load the user by id and compare
`effectiveRole` (from `server/utils/acl.ts`) with `admin`. The error keeps the shape every module API uses, with
`data.code` set to `forbidden`.

```ts [apps/web/server/api/admin/units.get.ts]
import { db } from '@nuxthub/db'

export default defineEventHandler(async (event) => {
  // Signed in (401 otherwise), then staff (403 otherwise).
  const user = await requireUser(event)
  const actor = await db.query.users.findFirst({ where: (t, { eq }) => eq(t.id, user.id) })
  if (!actor || effectiveRole(actor) !== 'admin') {
    throw createError({ statusCode: 403, statusMessage: 'You are not allowed to manage units.', data: { code: 'forbidden' } })
  }

  const items: { id: number, name: string, code: string }[] = [] // load your units here
  return { items, total: items.length }
})
```

- `requireUser` comes from [Users](/modules/identity/users), which the starter installs. It answers `401` without a
  valid credential.
- `db` and `effectiveRole` are the starter's. In another host app, use your own database access and role check.
- The response is `{ items, total }`, the shape the page in step 2 reads.
- Staff routes live under `/api/admin/...`. More checks for server routes are on
  [Protect a route](/examples/tasks/protect-a-route).

::note
A module does not write this check by hand. It defines one staff guard with `defineStaffGuard` and calls
`guard.require(event)`. See [Staff guards](/modules/identity/auth/server#staff-guards).
::

## 2. Add the page

Pages under `/admin` get the `admin` layout automatically, so your page renders only its own body. Create
`apps/web/app/pages/admin/units.vue`. Its root is a plain `<div class="flex flex-col gap-4">`. It renders its own
heading (`PageHeading`), which is the page's only `<h1>`.

```vue [apps/web/app/pages/admin/units.vue]
<script setup lang="ts">
import type { TableColumn } from '@nuxt/ui'

const t = useModuleT('units')
const { data, status } = await useFetch('/api/admin/units', { default: () => ({ items: [], total: 0 }) })
const pending = computed(() => status.value === 'pending')

const TableIdentity = resolveComponent('TableIdentity')
const columns: TableColumn<{ id: number, name: string, code: string }>[] = [
  {
    accessorKey: 'name',
    header: t('admin.name', 'Name'),
    cell: ({ row }) => h(TableIdentity, { title: row.original.name, description: row.original.code }),
  },
]
</script>

<template>
  <div class="flex flex-col gap-4">
    <PageHeading :title="t('admin.title', 'Units')">
      <template #actions>
        <UButton icon="i-lucide-plus" :label="t('admin.create', 'Add unit')" />
      </template>
    </PageHeading>

    <TableCard :loading="pending && !data.items.length">
      <UTable :data="data.items" :columns="columns" :ui="tableUi()">
        <template #empty>
          <UEmpty variant="naked" icon="i-lucide-building" :title="t('admin.empty', 'No units yet')">
            <template #actions>
              <UButton :label="t('admin.create', 'Add unit')" />
            </template>
          </UEmpty>
        </template>
      </UTable>
    </TableCard>
  </div>
</template>
```

The page follows the [list pattern](/guide/ux-patterns/pages#lists):

- **Heading and action.** A list is a `PageHeading` with the primary action, and a `UTable` styled with `tableUi()`
  inside a `TableCard`. Past about eight rows, add a `PageToolbar` for search.
- **Empty state.** An empty list is a `UEmpty` with exactly one action. It is never an empty table, and it never shows
  while `status` is `'pending'`.
- **Strings.** Every string goes through `useModuleT` with an English default. Buttons name the object: "Add unit",
  not "Add".
- **Row menu.** A list with actions adds a row menu (`RowMenu`) in the last column. It comes from a
  `use<Entity>Actions()` composable that owns create, edit and remove. See
  [Forms and actions](/guide/ux-patterns/forms-and-actions#one-actions-composable-per-entity).

## 3. Add the sidebar entry

The page needs an entry in the admin sidebar, or nobody finds it. The sidebar has three groups:

| Group | Menu path | Argument |
| --- | --- | --- |
| Overview | `admin.nav.overview` | `'overview'` |
| Manage | `admin.nav` | `'manage'`, the default |
| Settings | `admin.nav.settings` | `'settings'` |

Put a new feature in an existing group. Add the entry at build time with `extendAdminNav` from
`@frigear-nu/admin/utils`. It runs in a Nuxt module's `setup()`:

::tabs
:::tabs-item{label="Host app"}
Your app has no module of its own, so add a local one. Nuxt registers every file in `apps/web/modules/` as a module,
as the starter's `libsql-binding.ts` shows.

```ts [apps/web/modules/units-nav.ts]
import { defineNuxtModule } from 'nuxt/kit'
import { adminRoute, extendAdminNav } from '@frigear-nu/admin/utils'

export default defineNuxtModule({
  meta: { name: 'units-nav' },
  setup(_options, nuxt) {
    extendAdminNav(nuxt, { label: 'Units', to: adminRoute(nuxt, 'units'), icon: 'i-lucide-building', order: 20 })
  },
})
```
:::

:::tabs-item{label="Module"}
A module adds the entry in its own `setup()`:

```ts [src/module.ts]
import { adminRoute, extendAdminNav } from '@frigear-nu/admin/utils'

extendAdminNav(nuxt, { label: 'Units', to: adminRoute(nuxt, 'units'), icon: 'i-lucide-building', order: 20 })
// A configuration page goes into the Settings group:
// extendAdminNav(nuxt, { label: 'Integrations', to: adminRoute(nuxt, 'integrations') }, 'settings')
```
:::
::

- `adminRoute(nuxt, 'units')` is `/admin/units`, below the configured `base`.
- A configuration page goes into the Settings group: pass `'settings'` as the third argument.
- A module can instead register a runtime menu source with `extendMenuItem('admin.nav', ...)`. That works whether or
  not Admin is installed.

::callout{color="success" icon="i-lucide-check"}
**What you should see:** after a restart of `pnpm dev`, **Units** in the **Manage** group of the admin sidebar. It
opens `/admin/units`, with the **Units** heading and the **Add unit** button. Signed in without the `admin` role,
`GET /api/admin/units` answers `403`.
::
