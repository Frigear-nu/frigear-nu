**What you'll build:** a `/admin/events`-style list page in your app, with a sidebar entry under **Manage**, a heading,
a table card, a row menu and an empty state.

## Prerequisites

- [Admin](/modules/interface/admin) installed, which brings [UI](/modules/interface/ui), [Menu](/modules/interface/menu)
  and [Widget](/modules/interface/widget). The [workspace starter](/examples/starters/workspace) has all of them.
- A signed-in user whose role is allowed into the area: `admin.settings.roles` defaults to `['admin']`.

Pages under `/admin` get the `admin` layout automatically, so the page only renders its own body.

## 1. Add the page

Create `app/pages/admin/units.vue`. The page root is a plain `<div class="flex flex-col gap-4">`, and the page renders
its own `PageHeading`, which is the page's only `<h1>`:

```vue [app/pages/admin/units.vue]
<script setup lang="ts">
import type { TableColumn } from '@nuxt/ui'

const t = useModuleT('units')
const { data, status } = await useFetch('/api/admin/units', { default: () => ({ items: [], total: 0 }) })
const pending = computed(() => status.value === 'pending')

const TableIdentity = resolveComponent('TableIdentity')
const columns: TableColumn<{ id: number, name: string, code: string }>[] = [
  {
    accessorKey: 'name',
    header: t('admin.name', 'Name'),
    cell: ({ row }) => h(TableIdentity, { title: row.original.name, description: row.original.code }),
  },
]
</script>

<template>
  <div class="flex flex-col gap-4">
    <PageHeading :title="t('admin.title', 'Units')">
      <template #actions>
        <UButton icon="i-lucide-plus" :label="t('admin.create', 'Add unit')" />
      </template>
    </PageHeading>

    <TableCard :loading="pending && !data.items.length">
      <UTable :data="data.items" :columns="columns" :ui="tableUi()">
        <template #empty>
          <UEmpty variant="naked" icon="i-lucide-building" :title="t('admin.empty', 'No units yet')">
            <template #actions>
              <UButton :label="t('admin.create', 'Add unit')" />
            </template>
          </UEmpty>
        </template>
      </UTable>
    </TableCard>
  </div>
</template>
```

What the conventions mean:

- A list is `PageHeading` with the primary action, `PageToolbar` for search past about eight rows, and `UTable` with
  `tableUi()` inside `TableCard`.
- An empty list is a `UEmpty` with exactly one action, never an empty table, and never shown while `status` is
  `'pending'`.
- Every string goes through `useModuleT` with an English default. Buttons name the object ("Add unit", not "Add").
- A row menu in the last column (`RowMenu`) comes from a `use<Entity>Actions()` composable that owns create, edit and
  remove.

## 2. Add the sidebar entry

The sidebar is three groups: `overview` (`admin.nav.overview`), `manage` (`admin.nav`, the default) and `settings`
(`admin.nav.settings`). A new feature goes into an existing group. In a module's `setup()`, add an entry at build time
with `extendAdminNav` from `@frigear-nu/admin/utils`:

```ts [src/module.ts]
import { adminRoute, extendAdminNav } from '@frigear-nu/admin/utils'

extendAdminNav(nuxt, { label: 'Units', to: adminRoute(nuxt, 'units'), icon: 'i-lucide-building', order: 20 })
// A configuration page goes into the Settings group:
// extendAdminNav(nuxt, { label: 'Integrations', to: adminRoute(nuxt, 'integrations') }, 'settings')
```

`adminRoute(nuxt, 'units')` is `/admin/units` below the configured `base`. A module can instead register a runtime menu
source with `extendMenuItem('admin.nav', ...)`, which works whether or not Admin is installed.

## 3. Guard the API

The page is guarded by the role rule on `/admin/**`; the API routes are not. Guard `/api/admin/units` yourself with
`requireAuth`: see [Protect a route](/examples/tasks/protect-a-route). Staff routes live under `/api/admin/<module>`.
