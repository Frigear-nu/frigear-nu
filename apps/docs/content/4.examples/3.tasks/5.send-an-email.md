**What you'll build:** a `welcome` email written as a Vue component and sent from a server route, delivered by a real
provider outside development.

## Prerequisites

- [Notify](/modules/platform/notify) for dispatch and drivers. Auth, Users, Forms and Subscriptions install it for you.
- [Email Templates](/modules/platform/email-templates) for Vue templates. List it in `modules`; being a dependency of
  another module is not enough for those modules' templates to render.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@frigear-nu/notify', '@frigear-nu/email-templates'],
  notify: { email: { driver: 'log' } },
})
```

## 1. Write the template

Every top-level `.vue` file in `app/emails` is a template, named by its file name:

```vue [app/emails/welcome.vue]
<script setup lang="ts">
import { EmailButton, EmailDivider, EmailHeading, EmailLayout, EmailLinkFallback, EmailText } from '@frigear-nu/email-templates/components'

defineProps<{ name: string, url: string }>()
</script>

<template>
  <EmailLayout :preview="`Welcome, ${name}!`">
    <ESubject>Welcome, {{ name }}</ESubject>
    <EmailHeading>Welcome, {{ name }}!</EmailHeading>
    <EmailDivider />
    <EmailText>Thanks for signing up. Click the button below to get started.</EmailText>
    <EmailButton :href="url">Get started</EmailButton>
    <EmailLinkFallback :href="url" />
  </EmailLayout>
</template>
```

`<ESubject>` sets the subject. Import the `Email*` components: only the renderer's own `E*` components are global.

## 2. Send it

`sendEmailTemplate` is auto-imported in server code. The template name and its props are typed, so a misspelled name or
a missing prop does not compile:

```ts [server/api/welcome.post.ts]
export default defineEventHandler(async (event) => {
  const { user } = await requireAuth(event, { sessionOnly: true })
  await sendEmailTemplate('welcome', { name: user.name, url: 'https://example.com/account' }, {
    to: user.email,
    replyTo: 'support@frigear.nu',
  })
  return { sent: true }
})
```

The message is an `EmailNotification` without `body`, plus `subject` (overrides `<ESubject>`, required when the template
has none), `text` (your own plain text, or `false` for HTML only) and `locale`.

To send without a template, call `dispatchEmailNotification({ to, subject, body, text })` from Notify.

## 3. Choose a driver

The `log` driver prints emails to the terminal, which is the safe default for development. Switch per environment with
variables; they win over `nuxt.config.ts`:

| Variable | Purpose |
| --- | --- |
| `NUXT_NOTIFY_EMAIL_DRIVER` | `log` (default), `resend`, `ses` or `cloudflare`. |
| `NUXT_NOTIFY_EMAIL_FROM` | Sender address, for example `Frigear <no-reply@frigear.nu>`. |
| `NUXT_NOTIFY_EMAIL_RESEND_API_TOKEN` | The API token, with the `resend` driver. |

`ses` and `cloudflare` have their own credentials. A missing one fails the send with an error naming the variable.
