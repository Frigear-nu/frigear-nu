**What you'll build:** a public event list and detail page where signed-in users buy tickets through Stripe Checkout,
a "my tickets" page, and a staff admin where you create events.

## Prerequisites

- A Stripe account with a secret key and a webhook endpoint: see [Stripe setup](/guide/going-further/stripe-setup).
- A host app with users and the [admin area](/modules/interface/admin), such as the
  [workspace starter](/examples/starters/workspace).
- [Events](/modules/features/events), which needs [Stripe](/modules/commerce/stripe) and
  [Payments](/modules/commerce/payments). Installing Events installs them.

## 1. Install and configure

```bash
pnpm --filter ./apps/web add @frigear-nu/events @frigear-nu/payments @frigear-nu/stripe
```

Events needs NuxtHub KV (Stripe and Payments use it too):

```ts [apps/web/nuxt.config.ts]
export default defineNuxtConfig({
  modules: [
    // ...
    '@frigear-nu/events',
  ],
  hub: { kv: true, db: { dialect: 'sqlite', driver: 'libsql', connection: { url: 'file:./.data/db/sqlite.db' } } },
  events: {
    settings: {
      pages: { events: true, event: true, tickets: true, admin: true, adminEvent: true },
      reservationMinutes: 30,
    },
  },
})
```

The pages are `/events`, `/events/:slug` and `/account/tickets`, plus `/admin/events` for staff.

## 2. Set the Stripe keys

```bash [apps/web/.env]
NUXT_STRIPE_SECRET_KEY=sk_...
NUXT_STRIPE_WEBHOOK_SECRET=whsec_...
NUXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=pk_...
```

Point the Stripe webhook at `/api/stripe/webhook` (the default `stripe.settings.webhookPath`). Payments listens for
`checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`,
`checkout.session.expired` and `charge.refunded`. A ticket becomes `paid` only from those verified events, never from
the success redirect.

## 3. Let staff manage events

Staff access is the host's decision and is denied by default:

```ts [apps/web/server/plugins/events-policy.ts]
export default defineNitroPlugin((nitro) => {
  nitro.hooks.hook('events:authorize', async (ctx) => {
    ctx.allowed = await isEventStaff(ctx.userId) // your own check, from ctx.userId
  })
})
```

Identify the caller from `ctx.userId`, never from the session on `ctx.event`. The admin plugins in the
[workspace starter](/examples/starters/workspace) load the user and compare `effectiveRole(actor)` the same way.

## 4. Generate the migration

Events, Payments and Stripe add tables. Generate and commit the migration, then restart `pnpm dev`:

```bash
pnpm db:generate
```

## 5. Create an event and sell a ticket

1. Open `/admin/events`, choose **New event**, then add a ticket type in the Tickets tab. Prices are stored in minor
   units; a price of `0` is a free ticket, issued immediately without Stripe.
2. Publish the event. It now appears at `/events`.
3. Signed in, buy a ticket from `/events/<slug>`. A paid ticket redirects to Stripe Checkout and stays `pending`, holding
   its seat for `reservationMinutes`, until the payment arrives.

From code, `useEvent(slug)` gives `purchase(ticketTypeId, addonIds?)`, and the server route is
`POST /api/events/:slug/purchase` (scope `tickets:write`).

## 6. React to a paid ticket

`events:ticket:paid` fires when a ticket became paid, and immediately for free tickets. Send confirmations here:

```ts [apps/web/server/plugins/ticket-paid.ts]
export default defineNitroPlugin((nitro) => {
  nitro.hooks.hook('events:ticket:paid', async ({ ticket }) => {
    console.log(`Ticket ${ticket.id} for ${ticket.eventSlug} is paid`)
  })
})
```

Replace the log with [an email](/examples/tasks/send-an-email). The ticket carries `ticketTypeName`, `amount`,
`currency` and the buyer's `locale`.
