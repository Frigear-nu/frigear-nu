**What you'll build:** three server routes in your app: one that any signed-in credential can call, one that needs a
scope, and one that only a browser session may call.

## Prerequisites

- [Auth](/modules/identity/auth) in `modules` (the [workspace starter](/examples/starters/workspace) has it through
  Users).
- [Users](/modules/identity/users) if you want `requireUser`, which returns just the user.

`requireAuth` is auto-imported in server code. Use it, not nuxt-auth-utils' `requireUserSession`.

## 1. Require a signed-in user

`requireAuth(event)` accepts a cookie session, a user API token or an OAuth access token. It answers `401` without a
valid credential, and returns the principal:

```ts [server/api/me/summary.get.ts]
export default defineEventHandler(async (event) => {
  const { user, kind } = await requireAuth(event) // kind: 'session' | 'user-token' | 'oauth'
  return { id: user.id, via: kind }
})
```

## 2. Require a scope

Pass `scopes` to also require every listed scope. The call answers `403 insufficient_scope` when a token lacks one;
cookie sessions pass.

```ts [server/api/tickets.get.ts]
export default defineEventHandler(async (event) => {
  const { user } = await requireAuth(event, { scopes: ['tickets:read'] })
  return getTickets(user.id)
})
```

To let users pick a custom scope when they create an API token, register it in your module's `setup()` with
`addAuthScope` from `@frigear-nu/auth/utils`:

```ts [src/module.ts]
import { addAuthScope } from '@frigear-nu/auth/utils'

addAuthScope(nuxt, { name: 'reports:admin', description: 'Run reports', roles: ['admin'] })
```

## 3. Allow cookie sessions only

Anything that changes who the user is or how they sign in (password, email, passkeys, API tokens, billing) must pass
`sessionOnly: true`. A bearer token then gets `403 session_required`.

```ts [server/api/account/email.put.ts]
export default defineEventHandler(async (event) => {
  const { user } = await requireAuth(event, { sessionOnly: true })
  // ... change the email of `user`
})
```

## 4. Get just the user

With [Users](/modules/identity/users) installed, `requireUser(event, options)` takes the same options and returns the
user instead of the principal:

```ts
const user = await requireUser(event, { scopes: ['profile:read'], sessionOnly: false })
```

Use `requireAuth` when the route needs to know how the caller authenticated.

## Order inside a handler

Authenticate and authorize first, then parse params and body, then load the target. Never answer 404 before 401 or 403.
