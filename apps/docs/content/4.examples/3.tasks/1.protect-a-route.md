**What you'll build:** three server routes in your app. Any signed-in user can call the first, the second needs a
[scope](/guide/concepts/glossary), and only a browser session may call the third.

## Prerequisites

- The [workspace starter](/examples/starters/workspace), or another [host app](/guide/concepts/glossary) with
  [Auth](/modules/identity/auth).
- [Users](/modules/identity/users), for step 4.
- [Auth and scopes](/guide/concepts/auth-and-scopes), for the background.

The paths below are for the starter's `apps/web`. In another host app, leave out the `apps/web/` prefix.

## 1. Require a signed-in user

A route that returns a user's data must first know who is calling. `requireAuth(event)` answers that. It is
auto-imported in server code. Use it, not nuxt-auth-utils' `requireUserSession`.

- It accepts all three kinds of credential: a cookie [session](/guide/concepts/glossary), an
  [API token](/guide/concepts/glossary) and an [access token](/guide/concepts/glossary). See
  [The principal](/guide/concepts/auth-and-scopes#the-principal).
- It answers `401` when there is no valid credential.
- It returns the [principal](/guide/concepts/glossary): the user, and how they proved who they are.

```ts [apps/web/server/api/me/summary.get.ts]
export default defineEventHandler(async (event) => {
  const { user, kind } = await requireAuth(event) // kind: 'session' | 'user-token' | 'oauth'
  return { id: user.id, via: kind }
})
```

::tip
Call `requireAuth` first in every handler, before you parse input or load a record. The full order is on
[HTTP routes](/guide/best-practices/http-routes#handler-order).
::

## 2. Require a scope

A scope lets a token do one thing and nothing else. Pass `scopes` to require every listed scope:

```ts [apps/web/server/api/tickets.get.ts]
export default defineEventHandler(async (event) => {
  const { user } = await requireAuth(event, { scopes: ['tickets:read'] })
  return getTickets(user.id)
})
```

`getTickets` stands for your own function that loads the user's tickets.

- A token that lacks a scope gets `403 insufficient_scope`.
- A cookie session passes, except for PII (personal data) scopes.

To let users pick a scope of your own when they create an API token, register it. Where that happens depends on
whether the route lives in your app or in a module you write:

::tabs
:::tabs-item{label="Host app"}
Your app lists its scopes under `authentication.scopes` in `nuxt.config.ts`:

```ts [apps/web/nuxt.config.ts]
export default defineNuxtConfig({
  authentication: {
    scopes: [{ name: 'reports:admin', description: 'Run reports', roles: ['admin'] }],
  },
})
```
:::

:::tabs-item{label="Module"}
A module registers its scopes in its `setup()`, with `addAuthScope` from `@frigear-nu/auth/utils`:

```ts [src/module.ts]
import { addAuthScope } from '@frigear-nu/auth/utils'

addAuthScope(nuxt, { name: 'reports:admin', description: 'Run reports', roles: ['admin'] })
```
:::
::

`roles` limits who may pick the scope. Leave it out to offer the scope to every user.

## 3. Allow cookie sessions only

::caution
Pass `sessionOnly: true` on anything that changes who the user is or how they sign in: password, email, passkeys, API
tokens and billing. Otherwise a leaked token could take over the account. See
[sessionOnly](/guide/concepts/auth-and-scopes#sessiononly).
::

With `sessionOnly: true`, a request that brings a token gets `403 session_required`.

```ts [apps/web/server/api/account/email.put.ts]
export default defineEventHandler(async (event) => {
  const { user } = await requireAuth(event, { sessionOnly: true })
  // ... change the email of `user`
})
```

## 4. Get just the user

Most routes need only the user, not how they signed in. With [Users](/modules/identity/users) installed,
`requireUser(event, options)` takes the same options as `requireAuth` and returns the user instead of the principal:

```ts [apps/web/server/api/me/profile.get.ts]
export default defineEventHandler(async (event) => {
  const user = await requireUser(event, { scopes: ['profile:read'], sessionOnly: false })
  return { id: user.id }
})
```

Use `requireAuth` when the route needs to know how the caller signed in.

For a route that is open to everyone but personalised for a signed-in user, `getUser(event)` returns the user or
`null`, and never throws.

::callout{color="success" icon="i-lucide-check"}
**What you should see:** signed in, `GET /api/me/summary` answers `{ "id": …, "via": "session" }`. Signed out, it
answers `401`. With an API token, `PUT /api/account/email` answers `403 session_required`.
::

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| `401` with an API token | The token is not in the `Authorization` header. | Send `Authorization: Bearer <token>`. |
| `403 insufficient_scope` | The token was created without the scope. | Create a token with the scope. |
| `403 session_required` | The route has `sessionOnly: true`, and the request used a token. | Call it from the browser, signed in. |
| Your scope is missing from the API token form | The scope is not registered, or the user's role is not in its `roles`. | Register it, as in step 2. |
