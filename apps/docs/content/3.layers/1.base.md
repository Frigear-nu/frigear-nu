`@frigear-nu/base` is a [Nuxt layer](https://nuxt.com/docs/4.x/guide/going-further/layers#publishing-layers-npm-package) published to npm,(https://nuxt.com/docs/4.x/getting-started/layers) that centralizes the
module wiring, styling, UI defaults and content-driven page conventions of Frigear websites, so applications do not
repeat the same setup. [`apps/website`](/applications/website) extends it.

::note
**Requires** the Nuxt 4 app layout (`app/`). It bundles every module listed under [Bundled modules](#bundled-modules),
including [`@frigear-nu/menu`](/modules/menu). `@nuxtjs/i18n` is installed, but localization stays opt-in until the app
sets `i18n.locales`.
::

## Quick setup

Install the layer and `nuxt` (a peer dependency), then extend it:

```bash
pnpm add @frigear-nu/base nuxt
```

Inside this monorepo use the workspace protocol instead (`"@frigear-nu/base": "workspace:*"`).

```ts
export default defineNuxtConfig({
  extends: ['@frigear-nu/base'],
})
```

Put the site content under `content/` in the app (see [Content collections](#content-collections)).

## Options

The layer has no options of its own. It sets the defaults below, which an app overrides in its own
`nuxt.config.ts` or `app.config.ts`.

| Setting | Default | Purpose |
| --- | --- | --- |
| `i18n.strategy` | `'prefix_except_default'` | The default locale is unprefixed, the others get a prefix. |
| `i18n.detectBrowserLanguage` | `false` | No automatic locale redirect. |
| `menus.content.main` | `true` | Builds the `main` menu from content (see [Menu](/modules/menu)); the header reads it with `useMenu('main')`. |
| `robots.disallow` | `['/admin', '/api', '/auth', '/account']` | Keeps app, API and auth routes out of search results. Whether the site is indexable at all comes from `site.indexable`, set by the host. |
| `content.build.markdown.highlight` | `false` | Code highlighting is off. |
| `content.experimental.sqliteConnector` | `'native'` | Native SQLite connector for Nuxt Content. |
| `sourcemap.server` | `false` | Skips server source maps to halve production build time; client source maps are kept. |
| `features.inlineStyles` | `true` | Inlines critical styles. |
| `experimental.defaults.nuxtLink.prefetchOn` | `{ interaction: true, visibility: false }` | Links prefetch on interaction only. |
| `app.config` `ui.colors` | `{ primary: 'green', neutral: 'slate' }` | Nuxt UI colours. |
| `app.config` `header.icon` | `{ desktop: false, mobile: true }` | Whether navigation icons show in the desktop and mobile header. |
| `eslint.config.stylistic` | `commaDangle: 'always-multiline'`, `braceStyle: '1tbs'` | Lint style. |

`app.config` also accepts `socials` (`Record<string, string>`) and `github.url`, typed in `app/app.d.ts`.

## Bundled modules

`nuxt.config.ts` registers these modules, so apps do not list them again:

| Group | Modules |
| --- | --- |
| Layer-internal | `modules/config` (a no-op placeholder), `modules/routing` (see [Routing](#routing)) |
| Nuxt | `@nuxt/eslint`, `@nuxt/icon`, `@nuxt/image`, `@nuxt/fonts`, `@nuxt/hints`, `@nuxt/ui`, `@nuxt/content`, `@nuxtjs/device`, `@nuxtjs/i18n` |
| SEO | `@nuxtjs/sitemap`, `@nuxtjs/robots`, `nuxt-og-image`, `nuxt-seo-utils` |
| Content | `@comark/nuxt` |
| Frigear | `@frigear-nu/menu` |

It also adds `app/assets/css/main.css` (Tailwind, Nuxt UI, the green and brand colour scales and the `Public Sans`
font) to `css` unless the app already has a `main.css`.

`app/app.vue` renders `<CookieConsentBanner />`, which comes from
[Cookie Consent](/modules/cookie-consent). That module is not bundled, so an app that extends the layer without it
needs to provide the component.

## Content collections

Collections are defined in the layer's `content.config.ts`, relative to the consuming app's `content/` directory:

| Collection | Type | Source | Schema |
| --- | --- | --- | --- |
| `config` | `data` | `content/config.yaml` | `WebsiteConfigSchema` |
| `pages` | `page` | `content/pages/**` (Markdown) | `WebsitePageSchema` |

### Localized collections

Whether the flat or the locale-suffixed collections exist depends on the app's `i18n.locales`, read once at build time.
Flat and suffixed collections cannot be mixed.

- **No `i18n.locales` (default):** one `config` and one `pages` collection, from `content/config.yaml` and
  `content/pages/**`.
- **`i18n.locales` set:** one pair per locale (`config_da`, `pages_da`, `config_en`, `pages_en`, ...), from
  `content/<locale>/config.yaml` and `content/<locale>/pages/**`. The flat collections are not defined. A locale code
  with a hyphen becomes an underscore in the name (`en-GB` gives `pages_en_GB`).

```ts
export default defineNuxtConfig({
  extends: ['@frigear-nu/base'],
  i18n: {
    locales: [
      { code: 'da', name: 'Danish' },
      { code: 'en', name: 'English' },
    ],
    defaultLocale: 'en',
  },
})
```

`useConfig()` and `useCurrentPage()` pick the right collection through `useContentLocale()`, so app code does not branch
on whether locales are configured.

### `config` schema

`WebsiteConfigSchema`. Every field is optional, so an app can start with an empty `config.yaml`.

| Field | Type | Description |
| --- | --- | --- |
| `name` | `string \| { long: string, short?: string }` | Site name. |
| `logo` | `string \| { light: string, dark: string, class?: string, alt?: string }` | One image path, or separate light and dark images. |
| `navigation` | `Array<{ label: string, description?: string, to: string, icon?: string, tags?: string[] }>` | Navigation entries. `useNavigation(tags?)` filters by `tags`. |
| `footer` | `{ sections?, copyright?, right? }` | Footer content (tables below). |
| `seo` | `{ titleTemplate?, description?, image? }` | Site-wide SEO defaults (see [SEO](#seo)). The layer ships none. |

`footer.sections` entries:

| Field | Type | Description |
| --- | --- | --- |
| `label` | `string` | Section heading. |
| `icon` | `string` (optional) | Section icon. |
| `links` | `Array<{ label: string, to: string, icon?: string }>` | Links under the section. |

`footer.right` entries, rendered as buttons on the right of the footer:

| Field | Type | Description |
| --- | --- | --- |
| `label` | `string` | Link text. |
| `to` | `string` | Link target. |
| `icon` | `string` (optional) | Link icon. |
| `variant` | `'link' \| 'solid' \| 'outline' \| 'soft' \| 'subtle' \| 'ghost'` (optional) | Button variant. |
| `size` | `'xs' \| 'sm' \| 'md' \| 'lg' \| 'xl'` (optional) | Button size. |

`footer.copyright` is a string. In it, `{fullYear}` becomes the current year and `{url}` the request URL. When it is
omitted the footer has no left part.

### `pages` schema

`WebsitePageSchema`. Every field is optional.

| Field | Type | Description |
| --- | --- | --- |
| `title` | `string` | Page title, used for the document title and `og:title`. |
| `description` | `string` | Page description, used for meta tags. |
| `seo` | `{ title?, description?, image?, noindex? }` | Overrides for the document title, meta description, social image and indexing (see [SEO](#seo)). |
| `container` | `boolean` | Wraps the rendered body in a `UContainer`. Use it for plain prose pages such as legal; pages built from `u-page-*` sections manage their own containers. |
| `pageHeader` | `{ title?: string, description?: string }` | Props for the page header component. |

### SEO

`app.vue` calls `usePageSeo()`, which sets the title, description, Open Graph and Twitter tags for the current page.
The layer sets no values of its own: with nothing configured the title is the page `title`, with no suffix.

Each value resolves in this order:

| Value | Order |
| --- | --- |
| Title | page `seo.title`, page `title`, site `name` (long, then short) |
| Description | page `seo.description`, page `description`, `config.yaml` `seo.description` |
| Image | page `seo.image`, `config.yaml` `seo.image` |

Set a title template in `config.yaml`. `%s` is the page title and `%siteName` is `site.name` from `nuxt.config.ts`:

```yaml
seo:
  titleTemplate: '%s | %siteName'
  description: Default description for pages that have none.
```

A title that equals the site name is not wrapped, so the home page does not read "Frigear.nu | Frigear.nu". Set
`seo.noindex: true` on a page to add `noindex, nofollow`. Canonical URLs and default Open Graph tags come from
`nuxt-seo-utils`; the site `url` and `name` come from the `site` key.

## Layouts, components and routing

### Layouts

| Layout | Renders |
| --- | --- |
| `default` | `AppHeader`, the page in a `UMain`, then `AppFooter`. |
| `page` | The same, with the page wrapped in a `UContainer`. |

Both hide the header or footer when the route sets `meta.header = false` or `meta.footer = false`.

### Components

Override any component by creating a file at the same path in the consuming app.

| Component | Purpose |
| --- | --- |
| `AppHeader` | The site header: logo, `main` menu, language select (only with more than one locale), colour mode button. |
| `AppHeaderLogo`, `AppHeaderCenter`, `AppHeaderBody`, `AppHeaderRight`, `AppHeaderCTA` | Header slots. `AppHeaderRight` and `AppHeaderCTA` are empty placeholders meant to be overridden. |
| `AppFooter`, `AppFooterLeft`, `AppFooterRight` | The footer, built from `config.footer`. |
| `AppLogo` | The logo from `config.logo`, falling back to the site name. |
| `LanguageSelect` | Locale dropdown that navigates with `localizePath`. |
| `IconMenuToggle` | The mobile menu toggle. |
| `ContactForm` | A content component with a contact form (its text is Norwegian). It posts to `/api/_submit`, which the layer does not provide. |
| `HeroBackground` | A decorative hero background for content pages. |

### Routing

The layer ships a catch-all content page, `app/pages/[[lang]]/[...path].vue`, which renders the `pages` document for the
current route (and throws a 404 when there is none), and a landing page template, `app/templates/LandingPage.vue`.
The `routing` module registers the landing page at `/`, and, with locales configured, one route per locale (the default
locale unprefixed, the others at `/<code>`). With locales configured it also replaces the catch-all with one explicit
route per locale, so each route name carries its locale.

If the app has its own `app/pages/index.vue`, the layer skips the landing page and logs a warning; the app then has to
handle locale-root routes itself.

## Composables

Auto-imported in apps that extend the layer.

| Composable | Signature | Returns |
| --- | --- | --- |
| `useConfig` | `() => AsyncData` | The `config` document (or its locale-suffixed equivalent), re-fetched when the content locale changes. |
| `useCurrentPage` | `() => AsyncData` | The `pages` document matching the current route, with the locale prefix stripped. |
| `useNavigation` | `(tags?: string[]) => AsyncData` | `config.navigation`, filtered to entries sharing at least one tag when `tags` is given. |
| `useContentLocale` | `() => { locale, defaultLocale, stripLocalePrefix, localizePath }` | Locale helpers (below). |

```ts
const { data: config } = await useConfig()
const { data: page } = useCurrentPage()
const { data: footerNavigation } = useNavigation(['footer'])
const { locale, defaultLocale, stripLocalePrefix, localizePath } = useContentLocale()
```

| `useContentLocale` property | Type | Description |
| --- | --- | --- |
| `locale` | `ComputedRef<string \| undefined>` | The current locale, only when it is one of the app's configured codes; otherwise `undefined`. |
| `defaultLocale` | `ComputedRef<string \| undefined>` | The default locale reported by `$i18n`. |
| `stripLocalePrefix` | `(path: string) => string` | Removes the current locale prefix (`/en/services` gives `/services`). |
| `localizePath` | `(path: string, targetLocale: string) => string` | The equivalent of `path` for `targetLocale`. Used instead of `switchLocalePath`, which cannot resolve the layer's landing and catch-all routes. |

## Utils

Auto-imported, from `shared/utils/content.ts` (re-exported by `app/utils.ts`).

```ts
// 'pages' + 'no' => 'pages_no'; name unchanged when locale is omitted.
function localizedCollectionName<Name extends string>(name: Name, locale?: string): Name

// A string returns itself; an object returns prop[key].
function stringOrPropValue<Prop extends Record<string, unknown>>(
  prop: string | undefined | Prop,
  key: Prop extends string ? string : keyof Prop,
): unknown

// Locale codes from an `i18n.locales` config (strings or `{ code }` objects).
function getAvailableLocales(config: { i18n?: { locales?: Array<string | { code: string }> } }): string[]

// The `pages` collection(s) to query: the locale's own when it is available, every locale's otherwise,
// or ['pages'] when no locales are configured.
function getCollectionsToQuery(locale: string | undefined, availableLocales: string[]): string[]

// The `pages` collection for a route path, from its first segment.
function getCollectionFromPath(path: string, availableLocales: string[]): string
```

`landingPageExists(rootDir)` in `utils/pages.ts` is a build-time helper for the routing module, not for apps.
