## `@frigear-nu/base`

A base layer that will configure pages based on what is in your `content/*` folder, based on [
`@nuxt/content`](https://content.nuxt.com) It also provides some common configuration and utilities for Frigear
applications.

## Installation

```bash
pnpm add @frigear-nu/base
```

Then in your app's `nuxt.config.ts`:

```ts
export default defineNuxtConfig({
  extends: [
    '@frigear-nu/base',
  ],
})
```

## Configuration

### Collections

This layer creates at least 2 collections based on the content in your `content` folder:

- `config` - a single YAML file at `content/config.yaml` that defines site-wide configuration (title, description,
  navigation, etc.)
- `pages` - a collection of Markdown files under `content/pages/**` that define the content pages for the site.
- `config_<locale>` - optional locale-suffixed collections if i18n is configured and content is nested under locale
  folders.
- `pages_<locale>` - optional locale-suffixed collections if i18n is configured and content is nested under locale
  folders.

### Helpers / Utils / Composables
- You can query these collections manually by using the `useConfig()`, `useCurrentPage()` and `useContentLocale()`
composables to get the current page content based on the route..

- There are also some other helpers available in [
`@frigear-nu/base/shared/utils/**`](../../../packages/base-layer/shared/utils) for working with content and queries in
localized collections.
- [`composables`](../../../packages/base-layer/app/composables) contains some other useful composables for working with content and
pages, including `useCurrentPage()` and `useConfig()`.

### Optional i18n for content

Content collections (`config`, `pages`) support opt-in localization, fully driven by the consuming app:

- By default (no i18n configured), content stays flat: `content/config.yaml`, `content/pages/**`.
- To localize, register `@nuxtjs/i18n` in the consuming app and configure its `locales` (e.g. `['en', 'no']`), then nest
  content under a locale folder: `content/en/config.yaml`, `content/en/pages/**`, `content/no/config.yaml`,
  `content/no/pages/**`.
- When locales are configured, `content.config.ts` defines locale-suffixed collections (`config_en`, `pages_en`, ...)
  instead of the flat ones. `useConfig`/`useCurrentPage` pick the right collection automatically based on the current
  `$i18n` locale.
- No locale folder/config means no behavior change — this feature is entirely opt-in.

This relies on [`@nuxt/i18n`](https://i18n.nuxtjs.org) to provide internationalization support. You can configure the
locales and default locale in your `nuxt.config.ts`:

```ts
export default defineNuxtConfig({
  extends: [
    '@frigear-nu/base',
  ],
  i18n: {
    locales: ['en', 'dk'],
    defaultLocale: 'en',
  },
})
```

You will now also need to prefix the content in your `content` folder with the locale, for example `content/en/` and
`content/dk/`.

To add custom translations/override other layers, add files to your `i18n` folder, for example `i18n/locales/en.json`
and `i18n/locales/dk.json`.
