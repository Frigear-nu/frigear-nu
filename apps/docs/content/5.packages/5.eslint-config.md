---
title: ESLint config
description: The shared ESLint flat config for frigear packages and simple Node or Nuxt projects.
---

`@frigear-nu/eslint-config` is the ESLint flat config every package in this workspace lints with. It wraps
[`@nuxt/eslint-config`](https://eslint.nuxt.com/packages/config) in standalone mode with the `tooling`, `stylistic`
and `typescript` features on, and ignores `dist`, `.nuxt`, `.output`, `.data` and `playground`.

For Nuxt modules it turns on `no-undef` in `src/runtime/**` outside `src/runtime/server/**`. A module installed in a
host's `node_modules` gets no auto-imports in its app code, so components, composables and plugins import what they
use from `#imports` (`import { computed, useModuleT } from '#imports'`); the rule fails the lint when one is missing.

## Quick setup

```bash
pnpm add -D @frigear-nu/eslint-config eslint
```

Inside this monorepo use the workspace protocol instead (`"@frigear-nu/eslint-config": "workspace:*"`).

```js [eslint.config.mjs]
export { default } from '@frigear-nu/eslint-config'
```

```json [package.json]
{
  "scripts": {
    "lint": "eslint .",
    "lint:fix": "eslint . --fix"
  }
}
```

The config is published as plain ESM (`src/index.mjs` with `src/index.d.mts`), so there is no build step.

::note
A Nuxt app with [`@nuxt/eslint`](https://eslint.nuxt.com) should keep the config that module generates
(`withNuxt` from `./.nuxt/eslint.config.mjs`), as `apps/website` does.
::
