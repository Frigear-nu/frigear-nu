The starters are templates for a **new project outside this repository**. Each is a pnpm workspace under
`.starters/<starter>`, copied with `pnpx giget@latest gh:Frigear-nu/frigear-nu/.starters/<starter> <dir>`.

| Starter | What it is | Walkthrough |
| --- | --- | --- |
| `.starters/workspace` | `apps/web`: users, auth, account, admin | [Workspace starter](/examples/starters/workspace) |
| `.starters/mobile` | `apps/mobile`: a Capacitor app on `@frigear-nu/mobile` against any issuer | [Mobile starter](/examples/starters/mobile) |
| `.starters/mobile-standalone` | `workspace` + `apps/mobile`; `apps/web` adds `@frigear-nu/oauth-server` and the API | [Standalone mobile starter](/examples/starters/mobile-standalone) |

New users begin at [Installation](/get-started/installation), which compares them.

## What they are not

- They are not part of this pnpm workspace: `pnpm-workspace.yaml` only lists `apps/*` and `packages/*`.
- They depend on the **published** `@frigear-nu/*` versions, never `workspace:*` or `catalog:`.
- Each has its own `AGENTS.md`.

## Keep shared files identical

`.github/`, `.nvmrc`, `.gitignore`, `pnpm-workspace.yaml`, `scripts/` and `packages/` are the same in every starter.
`apps/mobile` is the same in `mobile` and `mobile-standalone`, and `mobile-standalone/apps/web` differs from
`workspace/apps/web` only in `nuxt.config.ts`, `package.json`, `.env.example`, `AGENTS.md`, the migrations,
`server/api/` and `server/plugins/oauth-policy.ts`.

Change a shared file in every starter in the same commit. The `drift` job of `.github/workflows/starters.yml` fails
otherwise.

`scripts/prepare-env.mjs` (`pnpm prepare:env`) is zero-dependency: it copies each `.env.example` and fills in empty
secrets, never overwriting a value.

## Work on a starter in a copy

Work in a copy outside the repository, then copy the changes back:

```bash
cp -R .starters/<starter> "$TMPDIR/<starter>"
cd "$TMPDIR/<starter>" && pnpm install
```

To try unreleased packages, point `@frigear-nu/*` at packed or linked builds with `overrides` in the copy only. Never
commit the copy's `node_modules`, `.nuxt`, `.output`, `.data`, `.env`, `pnpm-lock.yaml`, `capacitor.config.json` or the
native `ios/` and `android/` folders.

## Regenerate the migrations

After releasing a module that changes a schema, or bumping a starter's versions, regenerate the migrations of every
starter that has `apps/web`, in the copy:

```bash
pnpm db:generate
```

Then commit `apps/web/server/db/migrations` back. CI fails when they are out of date.

## Unreleased versions

A starter that needs an unreleased `@frigear-nu` version is skipped with a warning on pull requests and fails on
`main`. Release the packages before merging: see [Publishing](/contribute/publishing).

## Keep the walkthroughs in step

Each starter has a walkthrough under [Examples](/examples/starters/workspace). When you change a starter's files or
commands, update its page in the same change.
