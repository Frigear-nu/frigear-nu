`@frigear-nu/cli` is a [citty](https://github.com/unjs/citty) CLI published to npm. It works in any pnpm workspace, not
only in this repository.

## Quick setup

Run it without installing it:

```bash
pnpx @frigear-nu/cli --help
pnpx @frigear-nu/cli <command> --help
```

To create a project, `pnpm create frigear-app` (or `npm create frigear-app@latest`) is the same as `init` below.

Inside this repository, use the root `cli` script instead. It runs `packages/cli/bin/cli.mjs`, which loads the
TypeScript source with `jiti`, so there is no build step:

```bash
pnpm cli --help
```

The starters and app templates are downloaded from the `Frigear-nu/frigear-nu` GitHub repository with
[giget](https://github.com/unjs/giget). While that repository is not public, set `GIGET_AUTH` to a GitHub token that can
read it (for example `GIGET_AUTH=$(gh auth token)`).

## Commands

| Command | Purpose |
| --- | --- |
| `init` | Creates a new project from a starter. |
| `app:create` | Adds an app from a starter to `apps/<name>` of a workspace. |
| `module:create` | Scaffolds a new Nuxt module under `packages/`. |
| `add` | Installs Frigear modules in a Nuxt app and adds them to its `nuxt.config`. |

Every command takes `--cwd <dir>` (default: `INIT_CWD`, else the current directory).

### `init`

```bash
pnpx @frigear-nu/cli init [dir] [--platform <platform>] [-t <template>] [--ref <ref>] [--force] [--no-install]
```

| Argument | Default | Purpose |
| --- | --- | --- |
| `dir` | `frigear-app` | Directory to create. Its name becomes the root `package.json` `name`. |
| `--platform`, `--starter` | asked, `web` when not interactive | What to build: `web`, `mobile` or `web,mobile`, or the starter's name. See the table below. |
| `-t`, `--template` | | Any [giget](https://github.com/unjs/giget) source to copy instead of a starter, for example `gh:org/repo/path#ref`. Not together with `--platform`. |
| `--ref` | `main` | Branch or tag of the repository to copy the starter from. |
| `--force` | `false` | Write into a directory that is not empty. |
| `--no-install` | | Skip `pnpm install` and `pnpm prepare:env`. |

| `--platform` | Starter (also accepted as the value) | What you get |
| --- | --- | --- |
| `web` | `workspace` | `apps/web` with sign-in, account pages and a user admin |
| `mobile` | `mobile` | `apps/mobile`, a Capacitor app that signs in at an existing issuer |
| `web,mobile` | `mobile-standalone` | both, with `apps/web` as the app's OAuth server and API |

With `-t`, the root `package.json` is still renamed (when there is one), and `pnpm prepare:env` only runs when the
template has that script.

### `app:create`

```bash
pnpx @frigear-nu/cli app:create <name> [--template <template>] [--ref <ref>] [--no-install]
```

| Argument | Default | Purpose |
| --- | --- | --- |
| `name` | required | Folder under `apps/`, kebab-cased. |
| `--template` | `web` | `web` (the `workspace` starter's app), `web-standalone` (the `mobile-standalone` starter's OAuth server app) or `mobile`. |

It needs a `pnpm-workspace.yaml` above `--cwd`. The package is named `<scope>/<name>`, with the scope of the existing
apps (`@workspace` in the starters), else of the root package. It fails when `apps/<name>` already has a
`package.json`, and runs `pnpm install` at the root unless `--no-install` is passed.

### `module:create`

```bash
pnpx @frigear-nu/cli module:create <name> [--template <template>] [--scope <scope>] [--dir <dir>]
```

| Argument | Default | Purpose |
| --- | --- | --- |
| `name` | required | Name of the module, for example `my-module`. It is kebab-cased. |
| `--template` | `gh:nuxt/starter#module` | A giget template source, for example `gh:github.com/my/package`. |
| `--scope` | the root package's scope | npm scope, for example `@acme`. `--scope ""` leaves the name unscoped. In this repository the root is `@frigear-nu/root`, so modules are `@frigear-nu/<name>`. |
| `--dir` | `packages` | Workspace folder to create the module in. |

It downloads the template into `<workspace root>/<dir>/<name>` and sets the `name` in its `package.json`. It exits
with an error, without changing anything, when that folder already contains a `package.json`.

### `add`

```bash
pnpx @frigear-nu/cli add <module...> [--app <app>] [--no-install]
```

| Argument | Default | Purpose |
| --- | --- | --- |
| `module` | required | One or more modules: `forms` means `@frigear-nu/forms`; a scoped name is used as is. |
| `--app` | see below | The app: a path, or a folder under `apps/`. |
| `--no-install` | | Only edit `nuxt.config`. |

Without `--app`, the app is the current directory when it has a `nuxt.config`, else the only app under `apps/` with
one. The command runs `pnpm add` in the app and appends the modules to `modules` (once). Module options and the
migration are still yours: it prints each module's documentation link, and a module that adds tables needs
`pnpm db:generate`. See [Adding modules](/get-started/adding-modules).

### `create-frigear-app`

```bash
pnpm create frigear-app [dir] [--platform <platform>] [-t <template>] [--ref <ref>] [--force] [--no-install]
npm create frigear-app@latest [dir] [--platform <platform>]
```

`packages/create-frigear-app` publishes `init` under its own name, so `pnpm create` and `npm create` find it. It
takes the same arguments as `init` and depends on `@frigear-nu/cli` with `workspace:^`, so release the CLI first when
`init` changed.

## After `module:create` in this repository

The command only creates the package. To make it a working workspace module:

1. Run `pnpm install` from the repository root.
2. Match the structure of a sibling module (tsconfig, build and test setup) instead of keeping the starter's.
3. To publish it, add a `.release-it.json` (copy a sibling's and change the package name and tag), and add the package to
   the `package` choices and the `all` list in `.github/workflows/release.yml`. See
   [Publishing packages](/contribute/publishing).
4. Document it with a page in the right category folder under `apps/docs/content/3.modules/`, following
   [Documentation](/contribute/documentation), and add it to the root `README.md` package list.

The rest of the path is in [Scaffold a module](/contribute/writing-a-module/scaffold).

## Developing the CLI

The source is in `packages/cli/src` (`commands/` for the commands). `pnpm --filter @frigear-nu/cli test` runs the
command tests against the repository's own `.starters/` (giget is mocked, nothing is downloaded or installed). The
published package is built with unbuild into `dist/` (`publishConfig` points `bin` at `dist/cli.mjs`) and released like
every other package, see [Publishing](/contribute/publishing).
