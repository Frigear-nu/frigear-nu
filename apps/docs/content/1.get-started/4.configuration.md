You configure a Frigear app in two places: `apps/web/nuxt.config.ts` for modules and their options, and
`apps/web/.env` for secrets and values that differ per environment.

## nuxt.config.ts

Each module has its own config key, such as `account`, `admin`, `users`, `notify` or `authentication` (the key of
[Auth](/modules/identity/auth)). Every module's options are listed on its page under [Modules](/modules). The starter's
config:

```ts [apps/web/nuxt.config.ts]
export default defineNuxtConfig({
  modules: [
    '@nuxt/eslint',
    '@nuxthub/core',
    '@nuxt/ui',
    '@frigear-nu/menu',
    '@frigear-nu/widget',
    '@frigear-nu/users',
    '@frigear-nu/authorization',
    '@frigear-nu/account',
    '@frigear-nu/admin',
  ],

  runtimeConfig: {
    aclAdmins: '',
  },

  hub: {
    db: {
      dialect: 'sqlite',
      driver: 'libsql',
      connection: { url: 'file:./.data/db/sqlite.db' },
    },
  },

  account: {
    settings: {
      pages: { index: true, profile: true, security: true, apiTokens: true },
    },
  },

  admin: {
    settings: {
      roles: ['admin'],
    },
  },

  authentication: {
    settings: {
      afterLogin: '/account',
      pages: { login: true, register: true },
      session: { mapper: '~~/server/utils/map-session-user' },
    },
  },

  authorization: {
    redirectTo: '/login',
  },

  notify: {
    email: { driver: 'log' },
  },

  users: {
    settings: {
      admin: true,
      profilePath: '/account/profile',
    },
  },
})
```

What the options do:

| Key | Purpose |
| --- | --- |
| `modules` | Order matters only for readability: each module installs the ones it depends on (auth, notify, ui, ...). |
| `hub.db` | The database. Local sqlite in `.data/`; NuxtHub applies `server/db/migrations` on `nuxt dev` and `nuxt build`. See [Database](/get-started/database). |
| `account.settings.pages` | Which `/account` pages exist. |
| `admin.settings.roles` | The roles that may open the `/admin` area. |
| `authentication.settings` | Sign-in: the pages, where users land after login and the session mapper. See [Authentication](/get-started/authentication). |
| `authorization.redirectTo` | Where guests on a guarded page (`/account/**`, `/admin/**`) are sent. |
| `notify.email` | Email delivery. The `log` driver prints emails in the terminal until you configure a real driver. |
| `users.settings` | `admin: true` turns on `/admin/users`; `profilePath` is where the profile page lives. |

Restart `pnpm dev` after you change module options so Nuxt regenerates its types.

## Environment variables

Nuxt maps `NUXT_`-prefixed environment variables onto `runtimeConfig`: `runtimeConfig.aclAdmins` is set by
`NUXT_ACL_ADMINS`. Read values with `useRuntimeConfig()`, not `process.env`.

`apps/web/.env.example` documents the two variables of the starter:

```bash
# Encrypts the session cookie; at least 32 characters. `pnpm prepare:env` fills in a random one when it is empty.
NUXT_SESSION_PASSWORD=

# Comma separated emails that are always admins. Register with one of them, then sign in again.
NUXT_ACL_ADMINS=
```

Run `pnpm prepare:env` to copy every `apps/*/.env.example` to `.env` and generate empty secrets. It never overwrites a
value, so it is safe to run again. Never commit `.env`.

Each module documents its own variables on its page: Stripe keys on [Stripe](/modules/commerce/stripe), email drivers
on [Notify](/modules/platform/notify#environment-variables), OAuth provider credentials on
[Auth](/modules/identity/auth#oauth-providers). The [website](/examples/apps/frigear-nu-website) lists the full set it
uses.
