**What you'll have afterwards:**

- Your app running in production on the [hosting platform](/guide/concepts/glossary) you chose, such as Cloudflare,
  Vercel or a Node server.
- A production database with the same tables as your local one.
- Real emails instead of logged ones.

A local app keeps secrets in `.env`, prints emails in the terminal and stores data in a SQLite file. Production needs
each of these replaced. This page lists what to change before you deploy.

## Prerequisites

An app that runs locally, from [Installation](/get-started/installation) to [Database](/get-started/database).

## 1. Pick the production database

Every module ships its schema for SQLite and PostgreSQL. So you can deploy to Cloudflare D1, libSQL/Turso or
PostgreSQL.

- Set the database in `hub.db`. The [NuxtHub database docs](https://hub.nuxt.com/docs/database) list the options.
- Generate and commit the migrations for that dialect ([Database](/get-started/database#sqlite-and-postgresql)).

## 2. Set the production environment

::caution
Set `NUXT_SESSION_PASSWORD` in your hosting platform's environment to a new random value. Never reuse the one in your
local `.env`.
::

- [ ] Set `NUXT_SESSION_PASSWORD` as above.
- [ ] Set `NUXT_ACL_ADMINS`. Or give the first admin the `admin` role, and empty the list.
- [ ] Configure a real [Notify](/modules/platform/notify) driver, so password resets are sent instead of logged.
- [ ] Set the environment variables of each module you added, such as the Stripe keys.

## 3. Build locally first

Run the production build on your machine before you deploy:

```bash
pnpm build
pnpm preview
```

::callout{color="success" icon="i-lucide-check"}
**What you should see:** `pnpm build` finishes without errors, and `pnpm preview` serves the built app.
::

## 4. Deploy

Nuxt builds for the hosting platform you choose with a Nitro preset. The
[Nuxt deployment docs](https://nuxt.com/docs/4.x/getting-started/deployment) list the preset for each platform.

::note
**An example.** The [Frigear website app](/examples/apps/frigear-nu-website#deployment) builds with the
`cloudflare_module` Nitro preset and ships to Cloudflare Workers. Pushing to `main` deploys to production and applies
the D1 migrations. Every pull request gets its own preview with its own D1 database.
::

You now have an app with sign-in, an admin area and a database, in production.
