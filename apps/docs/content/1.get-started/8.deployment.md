Every module ships its schema for SQLite and PostgreSQL, so you can deploy to Cloudflare D1, libSQL/Turso or Postgres.
Nuxt builds for the target you choose with a Nitro preset; see the
[Nuxt deployment docs](https://nuxt.com/docs/4.x/getting-started/deployment) for your host.

## Production checklist

- [ ] Pick the database in `hub.db` (see the [NuxtHub database docs](https://hub.nuxt.com/docs/database)) and generate
  and commit the migrations for that dialect ([Database](/get-started/database)).
- [ ] Set `NUXT_SESSION_PASSWORD` in the host's environment: a new random value, not the one in your local `.env`.
- [ ] Set `NUXT_ACL_ADMINS`, or give the first admin the `admin` role and empty the list.
- [ ] Configure a real [Notify](/modules/platform/notify) driver, so password resets are sent instead of logged.
- [ ] Set the environment variables of each module you added, such as the Stripe keys.

Run the production build locally first:

```bash
pnpm build
pnpm preview
```

## An example

The [Frigear website](/examples/apps/frigear-nu-website#deployment) builds with the `cloudflare_module` Nitro preset
and ships to Cloudflare Workers. Pushing to `main` deploys to production and applies D1 migrations, and every pull
request gets its own preview with a per-PR D1 database.
