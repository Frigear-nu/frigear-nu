[Auth](/modules/identity/auth) owns sign-in and tells every server route who is calling. [Users](/modules/identity/users)
installs it for you and stores the users. The config key is `authentication`, not `auth` (that belongs to
nuxt-auth-utils).

## Sign-in methods

You turn methods on under `authentication.settings` in `nuxt.config.ts`:

| Method | Option | Default |
| --- | --- | --- |
| Email and password | `password` | `true` (`passwordReset` follows it) |
| Magic link (emailed, single use) | `magicLink` | off |
| Passkeys | `webAuthn` | `false` |
| OAuth providers (GitHub, Google, any OpenID Connect provider, ...) | credentials in env vars | off until configured |

```ts [apps/web/nuxt.config.ts]
export default defineNuxtConfig({
  authentication: {
    settings: {
      afterLogin: '/account',
      pages: { login: true, register: true },
      magicLink: true,
    },
  },
})
```

- `pages.login` and `pages.register` add the `/login` and `/register` pages.
- `afterLogin` is where users land after signing in, unless a `?redirect=` was requested.
- An OAuth provider turns on once its nuxt-auth-utils credentials exist, for example `NUXT_OAUTH_OIDC_CLIENT_ID`. Register
  `<origin>/api/auth/<provider>` as the callback URL at the provider. Without credentials the route answers `404`.
- Magic links and password resets are emailed, so configure a [Notify](/modules/platform/notify) driver. Until then
  the `log` driver prints them in the terminal.

The full list of options is on the [Auth](/modules/identity/auth) page.

## Who is calling

A caller is a cookie session, a user API token (`Authorization: Bearer fnu_...`) or an OAuth access token issued to
an application. All three resolve to the same principal in server code. Sessions may do everything; tokens carry the
scopes they were given. [Auth and scopes](/guide/concepts/auth-and-scopes) explains the model.

## Protect a server route

`requireAuth` is auto-imported in server code. Use it instead of nuxt-auth-utils' `requireUserSession`.

```ts [server/api/tickets.get.ts]
export default defineEventHandler(async (event) => {
  const { user } = await requireAuth(event, { scopes: ['tickets:read'] })
  return getTickets(user.id)
})
```

| Call | Behaviour |
| --- | --- |
| `requireAuth(event)` | The principal from any credential. `401` without a valid one. |
| `requireAuth(event, { scopes })` | Also needs every scope. `403 insufficient_scope` otherwise. Sessions pass. |
| `requireAuth(event, { sessionOnly: true })` | Cookie sessions only. `403 session_required` for tokens. |
| `getAuth(event)` | The principal or `null`. Never throws. |

When you only need the user, `requireUser(event, options)` from [Users](/modules/identity/users) returns just the user.

Use `sessionOnly: true` for anything that changes who the user is or how they sign in: password, email, passkeys, API
tokens, billing. Use `scopes` for reads and actions an integration plausibly needs.

## Protect a page

Page access is the job of [Authorization](/modules/identity/authorization), which the starter installs. Add a rule to
`routeRules` in `nuxt.config.ts`:

```ts [apps/web/nuxt.config.ts]
export default defineNuxtConfig({
  routeRules: {
    '/members/**': { authenticated: true },
    '/admin/**': { roles: ['admin'], ssr: false },
  },
})
```

Guests are sent to `authorization.redirectTo` (`/login` in the starter) with the requested page in `?redirect=`, and
come back after signing in. A wrong role gets `403`. For one page, use `definePageMeta`, which replaces the matching
route rules:

```vue
<script setup lang="ts">
definePageMeta({ authorize: isAdmin }) // an ability, an ability name, or { roles, ability, args, guest }
</script>
```

Rules for `/api/**` are enforced too, so `'/api/admin/**': { roles: ['admin'] }` guards the staff API of every module.

## Roles and the first admin

The starter keeps a `role` on each user and treats the emails in `NUXT_ACL_ADMINS` as admins. `effectiveRole()` in
`server/utils/acl.ts` applies this, and the session mapper puts the result in the session at sign-in. Change that file
and `server/plugins/users-policy.ts` when you need more roles.
