The workspace starter is a pnpm workspace with one Nuxt 4 app in `apps/web`. Run every command from the project
root, not from inside `apps/web`: pnpm resolves workspace dependencies relative to the root.

```
my-project/
  package.json              root scripts: dev, build, lint, typecheck, test, prepare:env, db:generate, db:migrate
  pnpm-workspace.yaml       apps/* and packages/*
  AGENTS.md                 conventions for you and your coding agents
  scripts/prepare-env.mjs   creates the apps' .env files and fills in empty secrets
  packages/eslint-config/   shared lint config for packages you add
  apps/web/
    nuxt.config.ts          the modules and their options
    app/pages/index.vue     the landing page
    server/utils/acl.ts                 effectiveRole(): the stored role, or admin for NUXT_ACL_ADMINS
    server/utils/map-session-user.ts    puts the effective role in the session
    server/plugins/users-policy.ts      who may administer users (admins only)
    server/db/migrations/sqlite/        the database schema, committed
    modules/libsql-binding.ts           puts the sqlite driver's native binding in the server build
```

## The workspace root

The root `package.json` scripts run the app through `--filter ./apps/web`:

| Script | What it does |
| --- | --- |
| `pnpm dev` | Starts the `apps/web` dev server. |
| `pnpm build`, `pnpm preview` | Builds every workspace, or previews `apps/web`. |
| `pnpm lint`, `pnpm lint:fix` | Runs ESLint in every workspace. |
| `pnpm typecheck`, `pnpm test` | Runs them in every workspace. |
| `pnpm prepare:env` | Creates each app's `.env` ([Configuration](/get-started/configuration)). |
| `pnpm db:generate`, `pnpm db:migrate` | Generates and applies migrations ([Database](/get-started/database)). |

To run something in one app, stay at the root and use `--filter`:

```bash
pnpm --filter ./apps/web <command>
```

`pnpm-workspace.yaml` lists `apps/*` and `packages/*`. Put your own shared code in `packages/`. The starter's
`packages/eslint-config` is the lint config that its apps use.

`AGENTS.md` holds the conventions of the project for you and for coding agents. Keep it up to date as the project
changes.

## apps/web

The Nuxt 4 app uses the Nuxt 4 layout: app code is under `app/` and server code under `server/`.

| Path | Purpose |
| --- | --- |
| `nuxt.config.ts` | The modules the app installs and their options. See [Configuration](/get-started/configuration). |
| `app/pages/index.vue` | The landing page. Replace it with your own. |
| `server/utils/acl.ts` | `effectiveRole()`: the stored role, except that emails in `NUXT_ACL_ADMINS` are always `admin`. |
| `server/utils/map-session-user.ts` | The session mapper of [Auth](/modules/identity/auth). It puts the effective role in the session at sign-in. |
| `server/plugins/users-policy.ts` | A Nitro plugin that decides who may use the user admin. The starter allows admins. |
| `server/db/migrations/sqlite/` | The committed SQL, snapshot and journal for the database. |
| `modules/libsql-binding.ts` | A local module that puts the sqlite driver's native binding in the server build. |

Add your own pages under `app/pages`, components under `app/components` and API routes under `server/api`. Nuxt
auto-imports components, composables and utils from `app/`, and server utils from `server/utils`.

## What the modules give you

The app installs these modules. Each one installs the modules it depends on, such as [Auth](/modules/identity/auth),
[Notify](/modules/platform/notify) and [UI](/modules/interface/ui):

| Module | Gives you |
| --- | --- |
| [Users](/modules/identity/users) | The `users` table, self-service profile, email and password changes, and `/admin/users`. |
| [Authorization](/modules/identity/authorization) | A `role` on users and route rules that guard `/account/**` and `/admin/**`. |
| [Account](/modules/identity/account) | The `/account` pages. |
| [Admin](/modules/interface/admin), [Widget](/modules/interface/widget), [Menu](/modules/interface/menu) | The admin shell and dashboard, its widgets, and the account menus. |
