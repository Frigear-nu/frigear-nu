Every new app starts from a **starter**: a pnpm workspace in
[`.starters/`](https://github.com/Frigear-nu/frigear-nu/tree/main/.starters) that you copy with the
[CLI](/contribute/tooling/cli) or [giget](https://github.com/unjs/giget). It uses the published `@frigear-nu` modules,
so it builds on its own, outside this repository. This page creates the `workspace` starter, a web app with sign-in,
account pages and a user admin, and runs it. For a mobile app, see [Other starters](#other-starters).

## Requirements

| Tool | Version |
| --- | --- |
| Node.js | `24` (the starter pins `24.22.1` in `.nvmrc`) |
| pnpm | `12.10.0` (pinned in the starter's `package.json`, use `corepack enable`) |

## Create the project

::code-group

```bash [pnpm create]
corepack enable
pnpm create frigear-app my-app --starter workspace
cd my-app
git init
```

```bash [giget]
pnpx giget@latest gh:Frigear-nu/frigear-nu/.starters/workspace my-app
cd my-app
git init
corepack enable
pnpm install
```

::

`pnpm create frigear-app` (the [CLI](/contribute/tooling/cli)'s `init` command) also names the root package after the
folder and runs `pnpm install` and `pnpm prepare:env` for you. While the repository is not public, set `GIGET_AUTH` to
a GitHub token that can read it (`GIGET_AUTH=$(gh auth token)`) for either command.

For the `mobile` or `mobile-standalone` starter, replace `workspace` with its name and see
[Other starters](#other-starters).

## Run it for the first time

Create `apps/web/.env` from the example file:

```bash
pnpm prepare:env
```

`scripts/prepare-env.mjs` copies every `apps/*/.env.example` to `.env` and fills in empty secrets: here
`NUXT_SESSION_PASSWORD`, which encrypts the session cookie. It never overwrites a value, so it is safe to run again.
Then set the one variable that is yours in `apps/web/.env`:

| Variable | What it is |
| --- | --- |
| `NUXT_ACL_ADMINS` | Comma separated emails that are always admins. Put your own email here to become the first admin. |

Start the app:

```bash
pnpm dev
```

On the first start, NuxtHub creates a local SQLite database in `apps/web/.data/` and applies the committed migrations.

## Sign in

1. Open `http://localhost:3000` and choose **Create account**. Register with the email you put in `NUXT_ACL_ADMINS`.
2. You land on `/account`, with Profile, Security and API tokens pages. An **Admin** badge shows that the allowlist
   matched.
3. Open `/admin` for the admin dashboard. **Users** (`/admin/users`) lists, creates and edits users.

Emails such as password resets are not sent yet: the `log` driver of [Notify](/modules/platform/notify) prints them in the
terminal running `pnpm dev`. Configure a real driver before you deploy.

::note
The allowlist is applied when you sign in. If you add your email to `NUXT_ACL_ADMINS` after signing in, sign out and in
again.
::

## Other starters

| You want | Starter | Guide |
| --- | --- | --- |
| A web app with sign-in, account pages and a user admin | `workspace` | [Workspace starter](/examples/starters/workspace) |
| An iOS and Android app that signs in at an existing issuer (frigear.nu, your own Frigear server, Keycloak, ...) | `mobile` | [Mobile starter](/examples/starters/mobile) |
| A mobile app with its own users and API, and nothing else to run | `mobile-standalone` | [Standalone mobile starter](/examples/starters/mobile-standalone) |
| A mobile app next to a web app you already made from `workspace` | `mobile`'s `apps/mobile` only | [Add apps/mobile to an existing workspace](/examples/starters/mobile#add-appsmobile-to-an-existing-workspace) |

Not sure? Start with `workspace` for a website, or `mobile-standalone` for an app: both run without any outside
service, and you can split them up later.

### Compare the starters

| | `workspace` | `mobile` | `mobile-standalone` |
| --- | --- | --- | --- |
| Apps | `apps/web` | `apps/mobile` | `apps/web` + `apps/mobile` |
| Users and sign-in | In `apps/web` ([auth](/modules/identity/auth), [users](/modules/identity/users)), cookie sessions | At a remote issuer, as an OAuth public client ([auth in client mode](/modules/identity/auth/client-mode)), with guards from [authorization](/modules/identity/authorization) | In `apps/web`; the app signs in there through the [OAuth server](/modules/identity/oauth-server) |
| Database | SQLite through NuxtHub, with committed migrations | None | Same as `workspace`, plus the `oauth_*` tables |
| API | `apps/web/server` | The issuer's or your own, called with bearer tokens | `apps/web/server`, open to the app through `cors.paths` |
| Needs before the first run | Nothing; set `NUXT_ACL_ADMINS` to your email to get admin | An issuer with a registered client, set in `apps/mobile/.env` ([own OAuth server](/guide/going-further/own-oauth-server)) | Nothing; set `NUXT_ACL_ADMINS` to your email to get admin |
| Native builds | No | iOS and Android through Capacitor ([mobile](/modules/interface/mobile)) | iOS and Android through Capacitor |

Each guide has its own create and first-run steps. `mobile` does not run after them alone: its `.env` points at
`http://localhost:3000`, so set `NUXT_PUBLIC_AUTHENTICATION_CLIENT_ISSUER` and `NUXT_PUBLIC_AUTHENTICATION_CLIENT_API_BASE` to your issuer
first (or run `mobile-standalone`, which provides that server at `localhost:3000`). The rest of Get Started follows the
`workspace` starter.

## Use an existing Nuxt 4 app

To add the modules to an app you already have instead of starting from the starter:

1. Install the modules and their peers:

   ```bash
   pnpm add @frigear-nu/users @frigear-nu/authorization @frigear-nu/account @frigear-nu/menu \
     @nuxthub/core @nuxt/ui @libsql/client drizzle-orm drizzle-kit tailwindcss
   ```

2. Add the modules and options from the [configuration](/get-started/configuration) page to your `nuxt.config.ts`.
3. Load Nuxt UI's styles in your CSS (`@import "tailwindcss"; @import "@nuxt/ui";`) and wrap the app in `<UApp>`.
4. Set `NUXT_SESSION_PASSWORD`, and copy `server/utils/acl.ts`, `server/utils/map-session-user.ts` and
   `server/plugins/users-policy.ts` from the starter if you want the admin allowlist.
5. Run `nuxt db generate` and commit `server/db/migrations`.
