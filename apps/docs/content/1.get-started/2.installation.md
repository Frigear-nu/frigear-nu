title: Quick start

Every new app starts from a **starter**: a pnpm workspace in
[`.starters/`](https://github.com/Frigear-nu/frigear-nu/tree/main/.starters) that you copy with
[giget](https://github.com/unjs/giget). It uses the published `@frigear-nu` modules, so it builds on its own, outside
this repository. Each starter has a guide that walks through it from the first run to production.

## Pick a starter

| You want | Starter | Guide |
| --- | --- | --- |
| A web app with sign-in, account pages and a user admin | `workspace` | [Workspace starter](/examples/starters/workspace) |
| An iOS and Android app that signs in at an existing issuer (frigear.nu, your own Frigear server, Keycloak, ...) | `mobile` | [Mobile starter](/examples/starters/mobile) |
| A mobile app with its own users and API, and nothing else to run | `mobile-standalone` | [Standalone mobile starter](/examples/starters/mobile-standalone) |
| A mobile app next to a web app you already made from `workspace` | `mobile`'s `apps/mobile` only | [Add apps/mobile to an existing workspace](/examples/starters/mobile#add-appsmobile-to-an-existing-workspace) |

Not sure? Start with `workspace` for a website, or `mobile-standalone` for an app: both run without any outside
service, and you can split them up later.

## How they differ

| | `workspace` | `mobile` | `mobile-standalone` |
| --- | --- | --- | --- |
| Apps | `apps/web` | `apps/mobile` | `apps/web` + `apps/mobile` |
| Users and sign-in | In `apps/web` ([auth](/modules/identity/auth), [users](/modules/identity/users)), cookie sessions | At a remote issuer, as an OAuth public client ([oauth-client](/modules/identity/oauth-client)) | In `apps/web`; the app signs in there through the [OAuth server](/modules/identity/oauth-server) |
| Database | SQLite through NuxtHub, with committed migrations | None | Same as `workspace`, plus the `oauth_*` tables |
| API | `apps/web/server` | The issuer's or your own, called with bearer tokens | `apps/web/server`, open to the app through `cors.paths` |
| Needs before the first run | Nothing; set `NUXT_ACL_ADMINS` to your email to get admin | An issuer with a registered client, set in `apps/mobile/.env` ([own OAuth server](/guide/going-further/own-oauth-server)) | Nothing; set `NUXT_ACL_ADMINS` to your email to get admin |
| Native builds | No | iOS and Android through Capacitor ([mobile](/modules/interface/mobile)) | iOS and Android through Capacitor |

All three share the same tooling: one `pnpm-workspace.yaml`, the shared ESLint config in `packages/eslint-config`, an
`AGENTS.md` for coding agents and `pnpm prepare:env`, which creates every app's `.env` from its `.env.example` and fills
in generated secrets without overwriting values you set.

## Create it

```bash
pnpx giget@latest gh:Frigear-nu/frigear-nu/.starters/<starter> my-app
```

```bash
cd my-app && pnpm install && pnpm prepare:env && pnpm dev
```

Replace `<starter>` with `workspace`, `mobile` or `mobile-standalone`, then follow its guide. `mobile` is the one that does not work after those four steps alone: its `.env` points at
`http://localhost:3000`, so set `NUXT_PUBLIC_OAUTH_CLIENT_ISSUER` and `NUXT_PUBLIC_OAUTH_CLIENT_API_BASE` to your issuer
first (or run `mobile-standalone`, which provides that server at `localhost:3000`). The guides cover the `.env`
values to set, signing in for the first time, running on a simulator or device, renaming the app and the production
checklist.
