Modules install their own dependencies automatically, so you usually add only the one you want. The [module
reference](/modules) lists every module with its options and hooks.

## Add a module

Every module follows the same steps. For example, to add [Forms](/modules/features/forms) (forms stored in the
database, with an admin for editing them and reading submissions):

1. Install it in the app, from the project root:

   ```bash
   pnpm --filter ./apps/web add @frigear-nu/forms
   ```

2. Add it to `modules` in `apps/web/nuxt.config.ts` and set its options. The module page lists them, plus what it
   needs from NuxtHub (Forms uses KV for rate limiting and blob storage for uploads):

   ```ts [apps/web/nuxt.config.ts]
   export default defineNuxtConfig({
     modules: [
       // ...
       '@frigear-nu/forms',
     ],
     hub: {
       kv: true,
       blob: true,
       db: { dialect: 'sqlite', driver: 'libsql', connection: { url: 'file:./.data/db/sqlite.db' } },
     },
     forms: {
       settings: {
         pages: { form: true, admin: true, adminForm: true, adminSubmissions: true, adminSubmission: true },
       },
     },
   })
   ```

3. Staff access is the host's decision, like the user admin. Allow admins in a Nitro plugin:

   ```ts [apps/web/server/plugins/forms-policy.ts]
   import { db } from '@nuxthub/db'
   // Loads the module's hook types: Nitro's server tsconfig does not include module types.
   import type {} from '@frigear-nu/forms'

   export default defineNitroPlugin((nitro) => {
     nitro.hooks.hook('forms:authorize', async (ctx) => {
       const actor = await db.query.users.findFirst({ where: (t, { eq }) => eq(t.id, ctx.userId) })
       ctx.allowed = !!actor && effectiveRole(actor) === 'admin'
     })
   })
   ```

4. The module adds tables, so generate a migration and commit it:

   ```bash
   pnpm db:generate
   ```

   Run it after every module you add or upgrade. It prints `No schema changes, nothing to migrate` when the database
   is already up to date.

5. Restart `pnpm dev`. The new migration is applied on start, and the forms admin appears under `/admin`.

## What a module page tells you

Each module page lists what it needs under **Requires**, **Options** and **Hooks**: other modules, NuxtHub features,
host policies and environment variables such as Stripe keys. A module declares the modules it depends on and Nuxt
installs them with it, so you list only the ones you want. To write a module of your own, see
[Writing a module](/contribute/writing-a-module/scaffold).
