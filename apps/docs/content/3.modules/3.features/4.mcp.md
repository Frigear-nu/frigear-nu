title: MCP
description: Let AI agents use your app on a user's behalf, seeing only the tools and data that user's token allows.

This module lets an AI agent work in your app for a [signed-in user](/guide/concepts/glossary): list their tickets,
submit a form or, for [staff](/guide/concepts/glossary), manage events. Your app serves one Model Context Protocol (MCP)
endpoint at `/mcp`. Each agent sees only the tools its token allows, and other people's personal data stays hidden. Use
it when users should reach your app through an agent. For scripts that call your HTTP routes directly, an
[API token](/modules/identity/auth/server#user-api-tokens) is enough.

The package is `@frigear-nu/mcp`, built on [`@nuxtjs/mcp-toolkit`](https://mcp-toolkit.nuxt.dev).

## What you get

- **Server routes** (on by default): the MCP endpoint at `/mcp`. Agents connect with an API token, an
  [access token](/guide/concepts/glossary) or a session, as
  [the principal](/guide/concepts/auth-and-scopes#the-principal) explains.
- **Tools from other modules** (opt-in per module): each adds its tools when its `settings.mcp` is on.
- **Composables and helpers** (on by default): definers for your own tools, each limited to the scopes it declares.
- **Agent instructions and an audit log** (on by default): the agent is told its limits, and every call is logged
  without its arguments or result.

:module-runtime{server}

::note
**Installed for you:** [Auth](/modules/identity/auth), `@nuxtjs/mcp-toolkit` (`>=0.24.0`) and Module Kit.
**You add:** nothing.
**Optional:** the modules whose tools you want, listed in Quick setup.
::

## Quick setup

::steps

### Install MCP

Events, Forms, OAuth Server, Payments and Subscriptions install MCP for you. Users installs it when
`users.settings.mcp` is on. To use it on its own:

```bash
pnpm add @frigear-nu/mcp
```

### Turn on the tools you want

Each module adds its tools only when its `settings.mcp` is `true`. The default is `false`.

:::warning
MCP's own options go under `mcpModules`, not `mcp`. The `mcp` key belongs to `@nuxtjs/mcp-toolkit`.
:::

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  users: { settings: { mcp: true } },
  events: { settings: { mcp: true } },
  forms: { settings: { mcp: true } },
  payments: { settings: { mcp: true } },
  subscriptions: { settings: { mcp: true } },
  oauthServer: { settings: { mcp: true } },
})
```

| Module | Tools |
| --- | --- |
| `events` | Events, tickets and staff catalogue tools. See [MCP tools](/modules/features/events/server#mcp-tools). |
| `forms` | Forms, submitting and staff tools. See [MCP tools](/modules/features/forms/server#mcp-tools). |
| `oauthServer` | `my-oauth-applications`, with the scope `oauth:read`. |
| `users` | `get-my-profile`, with the scope `profile:read`. |
| `payments` | `my-payments`, with the scope `payments:read`. |
| `subscriptions` | `my-subscriptions`, with the scope `subscriptions:read`. |

### Connect an agent

Create an API token with the scopes the agent needs. Point the agent's MCP client at `https://<your app>/mcp`, with the
header `Authorization: Bearer fnu_…`.

::

::callout{color="success" icon="i-lucide-check"}
**What you should see:** with a token that carries only `tickets:read`, the agent lists `list-events`, `get-event` and
`my-tickets`, and no staff tools.
::

## Options

Options go under the `mcpModules` key.

| Option | Type | Default | Purpose |
| --- | --- | --- | --- |
| `route` | `string` | `/mcp` | The route of the MCP endpoint. It sets the toolkit's `mcp.route`. |

The module sets the toolkit's `mcp.instructions`, unless your app sets its own. They tell the agent that it acts as the
user, that personal data needs a `*:pii` scope, that some settings change only in the admin area, and how money is
written. The module also turns on Nitro's `asyncContext`, which the definers use to reach the request.

## Server

Add tools, resources and prompts to MCP from a module. This section is for module authors.

### Rules every tool follows

| Rule | What it means |
| --- | --- |
| Scopes | Every definition declares the scopes it needs. A token without them never sees the tool, and a direct call is refused. |
| Staff tools | They also pass the module's policy hook, such as `events:authorize`, on every listing and call. |
| "My" tools | They take no user id. They act on the signed-in user (`ctx.user`). |
| Personal data | Staff tools return ids, statuses and counts. Names, emails and answers need a personally identifiable information (PII) scope, `*:pii`. |
| Money | Amounts are whole currency units next to a currency code: `52.2` with `"USD"` is 52.20 dollars. |
| No exfiltration | Where form submissions are delivered can be neither read nor changed through MCP. |
| Session-only areas | User administration and OAuth application administration are not exposed. |
| Unscoped definitions | A definition not made with the scoped definers is dropped. |
| Unserializable input | A tool whose input cannot become JSON Schema is dropped and logged. |
| Failing hooks | A policy hook that throws hides the tool. |

Convert at the edge with `fromCents` and `toCents` from
`@frigear-nu/mcp/utils`, which know that JPY has no decimals, and describe money fields with `MONEY_NOTICE`.

### Add tools from a module

Register the tools from the module's `setup()`, only when your app turned them on, as the built-in modules do:

```ts
import { addAuthScope } from '@frigear-nu/auth/utils'
import { addMcpDefinitions } from '@frigear-nu/mcp/utils'

// moduleDependencies: { '@frigear-nu/mcp': { version: '>=0.0.1' } }
addAuthScope(nuxt, { name: 'notes:read', description: 'Read your notes' })
if (options.settings?.mcp === true) addMcpDefinitions(nuxt, resolver.resolve('./runtime/server/mcp'))
```

`addMcpDefinitions(nuxt, dir)` takes a folder laid out like a project's `server/mcp`, with optional `tools/`,
`resources/` and `prompts/`. A subfolder of `tools/` becomes a group: `tools/admin/…` is the group `admin`.

### Define a tool

Three auto-imported definers take the toolkit's options plus `ScopedAccess`, and pass a `ScopedMcpContext` to the
handler.

| Definer | Handler signature |
| --- | --- |
| `defineScopedMcpTool` | `(args, ctx: ScopedMcpContext, extra) => result` |
| `defineScopedMcpResource` | `(ctx: ScopedMcpContext, ...toolkitResourceArgs) => result` |
| `defineScopedMcpPrompt` | `(args, ctx: ScopedMcpContext) => result` |

```ts
interface ScopedAccess {
  /** Required: a definition without scopes is never exposed. */
  scopes: string[]
  /** Never exposed to API tokens or OAuth tokens. */
  sessionOnly?: boolean
  /** Extra check on every listing and call, typically the module's `*:authorize` hook. Identify the caller from `principal.user.id`. */
  gate?: (event: H3Event, principal: AuthPrincipal) => boolean | Promise<boolean>
}

interface ScopedMcpContext {
  event: H3Event
  principal: AuthPrincipal
  /** The authenticated user. Use this; never take a user id as an argument. */
  user: AuthUser
  /** Whether the credential carries `scope` (e.g. an opt-in `*:pii` scope). */
  hasScope: (scope: string) => boolean
}
```

```ts [runtime/server/mcp/tools/my-notes.ts]
export default defineScopedMcpTool({
  description: 'List my notes',
  scopes: ['notes:read'],
  handler: (_args, { user }) => listNotes(user.id),
})
```

A staff tool adds a `gate`, and withholds personal data unless the token carries the PII scope:

```ts [runtime/server/mcp/tools/admin/list-all-notes.ts]
export default defineScopedMcpTool({
  description: 'List every note (staff)',
  scopes: ['notes:manage'],
  gate: canManageNotes, // e.g. your `notes:authorize` hook
  handler: (_args, ctx) => {
    const allow = ctx.hasScope('notes:pii')
    const notes = listAllNotes().map(note => redactPii(pick(note, ['id', 'text', 'ownerEmail']), { allow, fields: ['ownerEmail'] }))
    return { notice: piiNotice(allow, 'notes:pii', 'Owner emails'), notes }
  },
})
```

These helpers are auto-imported too:

```ts
pick(row, ['id', 'text']) // an explicit allow-list, so a new column is never exposed by accident
redactPii(row, { allow, fields }) // drops `fields` unless `allow`
piiNotice(allowed, scope, fieldsLabel) // message for the agent when data was withheld; undefined when allowed
```

::warning
Return allow-listed fields, never a raw database row. Write input schemas with plain types: zod transforms and
`z.coerce.date()` cannot become JSON Schema, and such a tool is dropped. Parse with your REST schema inside the handler.
::

`@frigear-nu/mcp/utils` also exports `isPrincipalAllowed`, `scopeTags`, `SCOPED_META_KEY` and the `ScopedAccess`,
`RedactOptions` and `McpDefinitionKind` types.

## Hooks

MCP adds one build-time hook and listens to two Nitro hooks of the toolkit.

| Hook | When | Payload |
| --- | --- | --- |
| `mcp:definitions:paths` (Nuxt) | Build time, while definition folders are collected. `addMcpDefinitions` pushes to it. | `{ tools, resources, prompts, handlers: string[] }` |
| `mcp:config:resolved` (Nitro, toolkit) | Per request. The module drops unscoped or non-serializable definitions here. | `{ config, event }` |
| `mcp:tool:called` (Nitro, toolkit) | After every tool call. The module logs the call. | `{ name, result, durationMs, event }` |
