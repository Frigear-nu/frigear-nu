## Hooks

Register with `nitro.hooks.hook(...)` in a Nitro plugin.

| Hook                         | When                                                                    | Payload                      |
| ---------------------------- | ----------------------------------------------------------------------- | ---------------------------- |
| `events:authorize`           | Staff gate for management routes, check-in and staff scopes.            | `AuthorizeContext`           |
| `events:purchase:before`     | During purchase, after the capacity checks; throw to deny.              | `PurchaseBeforeContext`      |
| `events:ticket:paid`         | A ticket became paid (free tickets immediately). Send confirmations here. | `TicketHookContext`        |
| `events:ticket:refunded`     | A ticket was fully refunded.                                            | `TicketHookContext`          |
| `events:membership:check`    | A membership requirement is evaluated.                                  | `MembershipCheckContext`     |
| `events:membership:options`  | The admin UI asks which memberships can be picked.                      | `MembershipOptionsContext`   |

```ts
type AuthorizeContext = { event: H3Event, userId: number, allowed: boolean }          // set allowed = true
type PurchaseBeforeContext = { event: H3Event, userId: number, eventId: string, ticketTypeId: string, addonIds: string[] }
type TicketHookContext = { ticket: TicketDto }
type MembershipCheckContext = { userId: number, requirement: 'any' | string[], satisfied: boolean }
type MembershipOptionsContext = { available: boolean, options: Array<{ value: string, label: string }> }
```

`requiresMembership` and `excludesMembership` are `null` (nobody / everyone), `'any'` (any active membership) or a list
of membership keys.

## Routes

Public and self-service routes are under `/api/events`, staff routes under `/api/admin/events`. App code and tests build
the paths with `eventsApi` from `@frigear-nu/events/utils` (`eventsApi.admin.event(id)`, `eventsApi.me.tickets`, ...).
User routes also accept bearer and OAuth tokens that carry the scope. Errors carry a snake_case `data.code`
(`not_found`, `conflict`, `forbidden`, `session_required`, ...); validation failures are h3's 400.

| Method | Path | Auth | Status | Purpose |
| ------ | ---- | ---- | ------ | ------- |
| GET    | `/api/events` | public | 200 | Published events. |
| GET    | `/api/events/:slug` | public (optional `tickets:read`) | 200 | Event detail; includes per-user `blocked` flags when signed in. |
| POST   | `/api/events/:slug/purchase` | `tickets:write` | 200 | Buy a ticket: `{ ticket, url? }`. |
| GET    | `/api/events/me/tickets` | `tickets:read` | 200 | The caller's tickets (also the account bootstrap's `events:tickets:mine`). |
| GET    | `/api/events/me/tickets/:id` | `tickets:read` | 200 | One of the caller's tickets (poll after returning from Stripe). |
| POST   | `/api/events/me/tickets/:id/pay` | `tickets:write` | 200 | Resume payment of a pending ticket: `{ url }`. |
| GET    | `/api/admin/events` | staff | 200 | Paginated `{ items, total, page, pageSize }`: `page`, `pageSize` (max 100), `q` (name in any language, slug), `status`, `sort` (`startsAt`, `createdAt`, `slug`, `status`), `order`. |
| POST   | `/api/admin/events` | staff | 201 | Create an event (accepts the whole nested catalogue). |
| GET    | `/api/admin/events/:id` | staff | 200 | One event with all ticket types, addon groups and addons, whatever its status. |
| PATCH  | `/api/admin/events/:id` | staff | 200 | Update an event (409 `conflict` on a taken slug). |
| DELETE | `/api/admin/events/:id` | staff | 204 | Delete an event; 409 when it has paid tickets (archive it instead). |
| POST   | `/api/admin/events/:id/clone` | staff | 201 | Copy into a new draft (`<slug>-copy`, `-copy-2`, ...). Tickets are not copied; dates stay. |
| GET    | `/api/admin/events/:id/tickets` | staff | 200 | Attendees, paginated: `q` (holder name or email), `status`, `sort` (`createdAt`, `status`, `checkedInAt`, `name`, `email`). Includes the QR `code`. |
| POST   | `/api/admin/events/:id/ticket-types` | staff | 201 | Add a ticket type (404 for an unknown event, 409 for a taken key). |
| PATCH  | `/api/admin/events/ticket-types/:id` | staff | 200 | Update a ticket type. |
| DELETE | `/api/admin/events/ticket-types/:id` | staff | 204 | Delete a ticket type; 409 while it has active tickets. |
| POST   | `/api/admin/events/ticket-types/:id/addon-groups` | staff | 201 | Add an addon group (404 for an unknown ticket type). |
| PATCH  | `/api/admin/events/addon-groups/:id` | staff | 200 | Update an addon group. |
| DELETE | `/api/admin/events/addon-groups/:id` | staff | 204 | Delete an addon group and its addons. |
| POST   | `/api/admin/events/addon-groups/:id/addons` | staff | 201 | Add an addon (404 for an unknown group). |
| PATCH  | `/api/admin/events/addons/:id` | staff | 200 | Update an addon. |
| DELETE | `/api/admin/events/addons/:id` | staff | 204 | Delete an addon. |
| POST   | `/api/admin/events/tickets/:id/cancel` | staff | 200 | Cancel an unpaid or free ticket; answers the attendee. |
| POST   | `/api/admin/events/tickets/:id/refund` | staff, **session only** | 200 | Start a full refund (only paid tickets with a payment); a bearer token gets 403 `session_required`. |
| GET    | `/api/admin/events/membership-options` | staff | 200 | `{ available, options }`: selectable memberships from the provider. |
| GET    | `/api/admin/events/upcoming` | staff | 200 | `{ total, items }`: the next published events, for the admin dashboard. |
| POST   | `/api/admin/events/check-in` | staff | 200 | Body `{ code }`. Check a ticket in. |

"staff" means the `events:manage` scope plus an allowing [`events:authorize`](/modules/features/events/server#staff-authorization) hook (the module's
`eventsStaff` guard). Deletes answer 404 `not_found` when the row does not exist. Static segments (`me`, `upcoming`,
`check-in`, `ticket-types`, ...) win over `:slug` / `:id` in the router.

## Database

| Table                | Purpose                                                                                                   |
| -------------------- | --------------------------------------------------------------------------------------------------------- |
| `events`             | `slug`, translated `name` / `description` / `body`, `image`, `location`, `locationUrl`, `startsAt` / `endsAt`, `status` (`draft`, `published`, `archived`), event-level `requiresMembership`. |
| `event_ticket_types` | Per event: `key` (unique per event), `name`, `description`, `price` (`0` = free), `currency` (default `DKK`), `hidePrice`, `capacity`, `saleStartsAt` / `saleEndsAt`, `saleSchedule`, `maxPerUser` (default 1), `requiresMembership`, `excludesMembership`, `isDefault`, `sortOrder`. |
| `event_addon_groups` | Per ticket type, e.g. "Food": `required` (pick at least one), `multiple` (pick several), `sortOrder`.      |
| `event_addons`       | Choices in a group: `label`, `price`, optional `capacity`, `sortOrder`.                                    |
| `event_tickets`      | Purchased or reserved tickets: `status` (`pending`, `paid`, `cancelled`, `refunded`, `expired`), `addons`, `amount` and `currency` snapshot, `paymentId`, unique QR `code`, `locale`, `checkedInAt`, `checkedInBy`. |

Translated texts are a string or a `{ da, en }` map (`Translated`).

::warning
The module changes the generated schema, not the database: generate and commit a migration in every host app and
fixture that uses it (including the Payments, Users and Subscriptions tables it relies on). See
[Module Kit](/modules/platform/module-kit).
::

## Translations

`da` and `en` locale files are registered with [Module Kit](/modules/platform/module-kit/i18n) under `events.*`.
Key groups: `upcoming.*`, `ongoing.*`, `past.*`, `detail.*` (including the purchase flow), `tickets.*`
(including `tickets.status.*`), `cart.*`, `menu.*`, `admin.*` (including `admin.tabs.*` and `admin.statuses.*`), plus top-level messages such as
`title`, `empty`, `loading`, `ticketReady`, `paymentReceived` and `purchaseFailed`. Override any string in your app's
`i18n/locales/<code>.json` (see
[overriding module strings](/modules/platform/module-kit/i18n#overriding-module-strings-in-your-app)):

```json
{ "events": { "upcoming": { "title": "What's on" } } }
```
