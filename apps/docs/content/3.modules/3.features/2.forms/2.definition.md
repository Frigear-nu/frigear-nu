Author definitions with `defineForm()` from `@frigear-nu/forms/utils`. These are the real types (abridged):

```ts
type FormDefinition = {
  mode: 'single' | 'stepped' // 'single' has exactly one step and no stepper
  storage: 'db' | 'none' // default 'db'
  steps: FormStep[]
  submit?: {
    label?: Translated
    successMessage?: Translated
    redirect?: string // same-origin path
    allowResubmit?: { keep: string[] } // offers "send another"; these field keys stay filled in
  }
  delivery?: {
    email?: {
      to: string[] // literal addresses; ${...} placeholders are rejected
      subject?: Translated // may use {{variables}}
      body?: Translated // plain text with {{variables}}, up to 10,000 characters per language
      routes?: { field: string, to: Record<string, string[]> } // recipients by one field's answer, falling back to `to`
      replyToField?: string // key of an email field
    }
  }
  access?: FormAccess // default { availability: 'web', auth: 'none' }
}

type FormStep = { id: string, title?: Translated, description?: Translated, showIf?: Condition, fields: FormField[] }

type FormField = {
  key: string // unique across the form; the key of the answer
  type: 'text' | 'email' | 'tel' | 'number' | 'textarea' | 'select' | 'radio' | 'checkbox' | 'date' | 'file' | 'markdown' | 'captcha'
  label?: Translated
  description?: Translated
  placeholder?: Translated
  content?: Translated // markdown fields
  required?: boolean
  options?: { value: string, label: Translated }[] // select / radio
  multiple?: boolean // file fields
  autocomplete?: string // defaults: 'email' for email, 'tel' for tel ('tel-national' next to a country selector)
  validation?: { min?, max?, minLength?, maxLength?, pattern?, maxFiles?, maxSize?, accept?: string[], message?: Translated }
  phone?: PhoneConfig // tel fields
  captcha?: CaptchaConfig // captcha fields
  showIf?: Condition
}

type Condition = { field: string, op: 'eq' | 'neq' | 'in' | 'empty' | 'notEmpty' | 'truthy', value?: unknown }

type FormAccess = {
  availability: 'web' | 'api' // 'api' = no public page
  auth: 'none' | 'user' | 'token' | 'password'
  schedule?: Schedule // default always open; see Open period
}
```

`Translated` is a string or a `{ da, en }` map (falls back to `en`, then the first value).

Rules enforced when a definition is saved or seeded:

- **Conditions.** `showIf` only sees answers of fields **earlier** in the form and must reference an input field.
  `value` is the compared value for `eq`/`neq`, a list for `in`, and unused for `empty`, `notEmpty` and `truthy` (an
  alias of `notEmpty`). A hidden field's stale answer never keeps another field shown; hidden fields are not required
  and their answers are dropped.
- **Keys.** Field keys start with a letter and contain letters, digits and underscores; keys and step ids are unique.
- **Fields.** `select` and `radio` need options; `markdown` needs `content` and collects no answer; `file` needs
  `storage: 'db'`; `captcha` is always required while visible.
- **Files.** `maxSize` defaults to 10 MB, `maxFiles` to 10 (1 unless `multiple`).
- **Access.** `auth: 'token'` requires `availability: 'api'`, because a bearer token cannot be typed into a page.
- **Email.** `routes.field` must be an earlier input field and `replyToField` an email field.

## Phone fields

A `tel` field is one free-form input by default. `phone.mode: 'country'` adds a searchable country selector.

```ts
type PhoneConfig = {
  mode?: 'simple' | 'country' // default 'simple'
  countries?: string[] // ISO 3166-1 alpha-2, in display order; default all. Enforced on the server.
  defaultCountry?: string // default 'DK' when offered, else the first offered country
}

{ key: 'phone', type: 'tel', phone: { mode: 'country', countries: ['DK', 'SE', 'NO'], defaultCountry: 'DK' } }
```

- The answer is **one string**. With a selector it is `+<dial code><number>` (`+4512345678`; a leading trunk `0` is
  dropped, Italian numbers keep it), so submissions, emails and the API never see two values.
- Country mode requires an international number of at most 15 digits (E.164) with at least 4 digits after the code.
- Helpers `composePhone`, `parsePhone`, `phoneCountries` and `allPhoneCountries` are exported from `@frigear-nu/forms/utils`.

## Open period (seasonal forms)

`access.schedule` limits when a form accepts answers. A yearly season whose end is before its start wraps over new
year. `from` is inclusive, `to` exclusive.

```ts
// Every year from 1 Jan 23:00 to 1 Feb 23:00 (Oslo wall-clock time).
access: {
  availability: 'web',
  auth: 'none',
  schedule: {
    type: 'yearly',
    timezone: 'Europe/Oslo',
    from: { month: 1, day: 1, time: '23:00' },
    to: { month: 2, day: 1, time: '23:00' },
  },
}

// One fixed period (either end may be left out for an open-ended window).
schedule: { type: 'range', from: '2026-03-01T10:00:00Z', to: '2026-03-15T10:00:00Z' }
```

Outside the period the public page shows a "closed" notice (with the next opening when there is one) and the
definition and submit endpoints answer `403` with `data: { closed: true, opensAt }`. `isFormOpen` and
`nextFormOpening` are exported from the utils for custom UI.

## Email body and variables

Without `delivery.email.body` the notification lists every visible answer. The body is chosen by the submission's
locale (falling back to `en`); `subject` accepts the same variables.

```ts
delivery: {
  email: {
    to: ['office@example.com'],
    subject: 'New message from {{ answer.name }}',
    body: { en: 'Hi team,\n\n{{answer.name}} wrote via {{form.name}}:\n{{answer.message}}\n\nAll answers:\n{{answers}}' },
  },
}
```

| Variable | Replaced with |
| --- | --- |
| `{{form.name}}`, `{{form.slug}}`, `{{form.version}}` | The form's name, slug and version |
| `{{submission.id}}` | The stored submission id (empty when `storage: 'none'`) |
| `{{submission.createdAt}}`, `{{submission.locale}}` | ISO timestamp and locale of the submission |
| `{{answers}}` | All visible answers as `label: value` lines (a table in the HTML version), without captcha |
| `{{answer.<fieldKey>}}` | One answer, formatted like the default email: option labels, joined lists, file names, yes/no per locale |
| `{{files}}` | Names of the files stored with the submission |
| `{{replyTo}}` | The reply-to address taken from `replyToField` |

- Whitespace inside the braces is ignored. Unknown variables, hidden fields and unanswered fields render empty; the
  admin definition check warns about unknown variables (`unknownBodyVariables(definition)`) but never fails the save.
- Values are inserted once and never re-scanned, so an answer containing `{{form.name}}` stays literal.
- The body is plain text. The HTML version escapes every value and turns newlines into `<br>`. In the subject, line
  breaks are collapsed so an answer cannot inject headers.
- Rendering lives in `@frigear-nu/forms/utils` (`composeEmail`, `renderTemplateText`, `renderTemplateHtml`), so the
  builder previews the exact result with sample answers.

## Captcha

A `captcha` field renders Cloudflare Turnstile, Google reCAPTCHA v2 (checkbox) or hCaptcha.

```ts
type CaptchaConfig = {
  provider?: 'turnstile' | 'recaptcha' | 'hcaptcha' // default: captcha.defaultProvider
  siteKey?: string // public; overrides the configured site key for this field
  theme?: 'auto' | 'light' | 'dark'
  size?: 'normal' | 'compact'
}

{ key: 'human', type: 'captcha', captcha: { provider: 'turnstile' } }
```

- **Keys.** Site key: the field's `siteKey`, else the configured one. Secret key: the form's own encrypted secret
  (see [Per-form secrets](/modules/features/forms/server#per-form-secrets)), else the configured one, else the check fails closed. The admin builder
  warns when a provider has neither a field `siteKey` nor a configured site key.
- **Client.** The provider script loads lazily in the browser only. The token lives in the form state under the field
  key, the widget resets after every failed submit, and the token is **never** stored, delivered or shown in the
  preview JSON. In the admin preview and "Try it" modal the field is a stub that supplies a dummy token.
- **Server.** The token is verified (with the visitor's IP) against the provider's siteverify endpoint before anything
  is stored or delivered.
- **Token access.** Submissions with a valid form API token (`access.auth: 'token'`) skip the captcha.

| Outcome | Status |
| --- | --- |
| Token missing or invalid | `400` with an issue on the captcha field key in `data.issues` |
| Provider has no secret key (fails closed) | `500` |
| Provider unreachable | `502` |

Hosts and tests can replace the network call with the [`forms:captcha:verify`](/modules/features/forms/reference#hooks) hook.

## Visual builder

The admin editor (`/admin/forms/:id`) has **Builder**, **Delivery & storage**, **Access** and **JSON** tabs, all editing
the same unsaved definition (so they are state tabs, not routes); **Save form** is only enabled while it passes
validation. The heading carries the breadcrumb back to the list, the form's status badge and a `⋯` menu with
Submissions, Copy link, Duplicate form and Archive form.

- Pick *Single page* or *Stepped* (switching to single merges all steps), drag field types from the palette (or click
  to append), and drag fields or step headers to re-order. Every row has up/down buttons for pointer-free use; drag and
  drop uses the browser's native API.
- Selecting a field or step opens its settings: label, help text, placeholder, required, options, limits, its step and
  a `showIf` condition on an earlier field.
- Every text has a language button: plain text is the same in every language, and translating turns it into a map with
  one row per locale (the host's `@nuxtjs/i18n` locales, plus any code you add). Empty languages are dropped.
