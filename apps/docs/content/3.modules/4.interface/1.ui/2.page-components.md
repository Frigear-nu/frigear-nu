The components behind every admin and account page. They are auto-imported by name, with no prefix, and none is a
global component: a global component is bundled into the app entry and transformed before the first render of every
page, so use `resolveComponent('PageHeading')` with a literal name (Nuxt resolves it at build time) rather than
`global: true` when you need a component dynamically. `ConfirmDialog` is normally opened through `useConfirmDialog`. They carry structure
and spacing only; colours and radius come from Nuxt UI. Every built-in string can be replaced by a prop, and the
defaults are translated (see [the `patterns` strings](/modules/interface/ui/reference#the-patterns-strings)).

| Component | Props | Slots | Use | Replaces |
| --- | --- | --- | --- | --- |
| `AppShell` | `id`, `title`, `home`, `icon?`, `navigation: NavigationMenuItem[][]`, `navLabel`, `searchGroups?`, `searchLabel?`, `backTo?: { to, label, icon? }`, `wide?` | `brand({ collapsed })`, `sidebar-top({ collapsed })`, `sidebar-footer({ collapsed })`, `navbar-left`, `navbar-right`, default | The dashboard shell of the admin area; see [App shell](/modules/interface/ui/app-shell). | Per-area dashboard markup |
| `PageHeading` | `title?`, `description?`, `breadcrumb?: string \| BreadcrumbItem[]` | `title`, `badge`, `description`, default (meta row), `actions` | Title block of an app page. A string `breadcrumb` is a plain label above the title; an array renders breadcrumbs (`[{ label: 'Users', to: '/admin/users' }, { label: 'Ada' }]`). Title size is `text-xl sm:text-2xl font-semibold`. | Per-page heading markup |
| `PageTabs` | `items: (NavigationMenuItem & { value? })[]`, `v-model?` | none | Tabs under a heading. **Link mode** when items have `to` (each tab is a route); **state mode** with `v-model` (matches `value`). A bordered strip with an underline highlight; scrolls sideways on narrow screens and hides icons below `sm`. | `UTabs` used for page sections |
| `PageSectionSwitcher` | `items: NavigationMenuItem[]` (links, `active` marks the current one), `label?` | none | A full-width button with the current section (icon, label, chevron) that opens a menu of every section, the active one checked. The narrow-screen counterpart of a vertical section navigation on public `UPageAside` layouts (the account area uses it); `label` names it for screen readers and the current section is appended. Use `PageTabs` for tabs a page owns. | A horizontally scrolling tab strip for section navigation |
| `SectionCard` | `title?`, `description?`, `icon?`, `loading?`, `flush?` | `header`, `actions`, default, `footer` | A framed block of a page. `flush` removes the body padding for edge-to-edge content such as a list. A form's Save button goes in `footer`. | `UPageCard` as a form frame |
| `TableCard` | `title?`, `description?`, `loading?`, `refreshing?` | default (the `UTable`), `header`, `actions`, `footer` | The framed surface a table sits in. `title`/`description` and `actions` render the same header row as `SectionCard` (for tables in a tab or on a detail page); `header` replaces the title block; `footer` holds `TablePagination`. A table always sits in a `TableCard`, never in a `flush` `SectionCard`. `loading` shows skeleton rows (first load); `refreshing` keeps the rows on screen and dims them while new ones load. There is deliberately no generic table wrapper: write `<TableCard><UTable :ui="tableUi()" /></TableCard>` so `UTable`'s own slot typing stays intact. | Per-page table frames |
| `TablePagination` | `total`, `v-model:page`, `v-model:page-size`, `pageSizes?` (default `[20, 50, 100]`) | default (`{ range }`, replaces the range text) | The footer of a paginated list: "21–40 of 132", a rows-per-page select and the pages. Paging hides while everything fits on one page; a new page size goes back to page 1. | Hand-rolled totals and `UPagination` |
| `TableIdentity` | `title`, `description?`, `avatar?: AvatarProps` | `badges` | The first cell of a list row: the name, a muted second line (email, slug, URL) and an optional avatar or icon. | Per-module two-line name cells |
| `RowMenu` | `items: DropdownMenuItem[] \| DropdownMenuItem[][]`, `subject?`, `variant?: 'ghost' \| 'outline'`, `size?`, `label?` | none | The `⋯` menu of a table row or heading. Stops click propagation so it does not trigger the row's click; its accessible name is "Actions for {subject}", or `label` when given. Use `variant="outline"` in a heading. | Loose row icon buttons, per-module dropdowns |
| `StatusBadge` | `status`, `label?`, `colors?: Record<string, StatusColor>`, `size?`, `icon?` | none | A status as a subtle `UBadge`. The colour comes from `statusColor` (green for published, active, trialing, paid, succeeded; amber for pending, past_due, incomplete, scheduled; red for failed; neutral otherwise); `colors` overrides single statuses (`{ archived: 'warning' }`). `label` defaults to the status; pass a translated label. Renders nothing without a status or label. | Hand-built `UBadge` with `statusColor` |
| `StatCard` | `label`, `value?`, `hint?`, `icon?`, `to?`, `loading?`, `empty?` | default (overrides `value`) | A number with a label and optional icon. `to` makes the card a link to the list it summarises. Shows `empty` when there is no value. | Per-module stat tiles |
| `ListCard` | `title`, `description?`, `loading?`, `isEmpty?`, `empty?`, `to?`, `toLabel?` | default (`<li>` rows), `actions` | A card with a short divided list and a "view all" link; `toLabel` defaults to the translated "View all". | Per-module list cards |
| `DescriptionList` | `items: { key?, label, value? }[]`, `empty?`, `loading?`, `align?` | one slot per `key` | Label and value rows for key facts. A missing value shows "Not set" (or `empty`). | Hand-written key/value grids |
| `PageToolbar` | none | default (search and filters), `right` | The row of search and filter controls above a table. | Per-page filter rows |
| `FormRow` | every `UFormField` prop (`name`, `label`, `description`, `required`, ...; a `ui` is merged) | every `UFormField` slot | One row of an inline settings form in a `SectionCard`: `UFormField orientation="horizontal"` with the label and `description` in a left column (a third of the row, at most `16rem`) and the control on the right; rows stack below `sm`. Put rows in a `divide-y divide-default` parent (the `UForm`); short controls take `class="w-full sm:max-w-sm"`, long text `class="w-full"` (in the narrow account area every control takes `class="w-full"`, so it ends where the footer actions do). One control per row (it gets the row's `id`); a row of several controls nests a vertical `UFormField` per control. Slideover forms keep plain vertical `UFormField`s. | Stacked fields in a wide card, per-form `:ui` overrides |
| `FormSlideover` | `title`, `description?`, `formId`, `submitLabel`, `cancelLabel?`, `loading?`, `disabled?` | default (the form), `footer({ cancel })` | A `USlideover` for create and edit forms. Footer: Cancel (`color="neutral" variant="outline"`, label `cancelLabel`) and a submit button wired to `form="<formId>"`; `footer` replaces both and receives `cancel` to close with `false`. Emits `close`. | Create and edit modals |
| `ConfirmDialog` | `title?`, `description?`, `confirmText?`, `cancelText?`, `destructive?`, `dismissible?` | none | The modal behind `useConfirmDialog`; emits `close(boolean)`. Cancel is neutral and outlined, and defaults are translated. | Per-module delete modals |

There is no empty-state component and no page wrapper:

- Empty states are Nuxt UI's `UEmpty`: `variant="naked"` inside a card, naming the thing and offering exactly one action.
- A page root is `<div class="flex flex-col gap-4">`.

```vue
<script setup lang="ts">
const t = useModuleT('users')
const { data: user } = await useFetch(`/api/admin/users/${useRoute().params.id}`)
const actions = useUserActions()
</script>

<template>
  <div class="flex flex-col gap-4">
    <PageHeading
      :title="user.name"
      :breadcrumb="[{ label: t('admin.users', 'Users'), to: '/admin/users' }, { label: user.name }]"
    >
      <template #badge>
        <UBadge :color="statusColor(user.status)" :label="user.status" />
      </template>
      <template #actions>
        <RowMenu :items="actions.menu(user)" :subject="user.name" variant="outline" />
      </template>
    </PageHeading>

    <SectionCard :title="t('admin.details', 'Details')">
      <DescriptionList
        :items="[
          { label: t('admin.email', 'Email'), value: user.email },
          { label: t('admin.phone', 'Phone'), value: user.phone },
        ]"
      />
    </SectionCard>
  </div>
</template>
```

## Per-entity actions

`@frigear-nu/ui` provides the pieces; the actions for an entity live in the module that owns it, as a
`use<Entity>Actions()` composable: `create` and `edit` open a `FormSlideover` through `useOverlay()` and resolve with
the saved record (or `false`), `remove` confirms, toasts and refreshes, and `menu(record, { extra, onRemoved })` returns
the `RowMenu` items ordered Open, then edits, then the destructive action in its own red group. See
[UX patterns](/guide/ux-patterns/forms-and-actions#one-actions-composable-per-entity) for a full example.
