---
title: Campaigns
description: Newsletters people sign up to, also without an account, with double opt-in, stored consent and one-click unsubscribe.
---

Campaigns gives your app newsletters. A newsletter is a list that people sign up to with an email address, a phone
number or both. They do not need an account. A new subscriber confirms from a link in an email or SMS (double opt-in),
and the subscription stores the proof of their consent. Every message carries a signed link to unsubscribe again.
Signed-in users manage their newsletters on their account page, and staff manage the lists in the admin area.

The package is `@frigear-nu/campaigns`. Every message goes through [Notify](/modules/communication/notify), on the
email and SMS drivers your app sets. Campaigns ships no SMS provider of its own.

## What you get

- **Signup:** the global `<NewsletterSignup list="…">` component, also usable as `::newsletter-signup{list="…"}` in
  Nuxt Content, and a plain HTML form for other sites, shown on each list's staff page.
- **Public pages:**
  - `/newsletter/confirm`, where the link in the confirmation message leads. It confirms on a button, never when the
    page opens, so link scanners and mail previews confirm nothing. After a plain HTML form signup it says "check your
    inbox".
  - `/newsletter/unsubscribe`, where the unsubscribe link leads. It also acts on a button only.
- **Account page:** `/account/newsletters`, the signed-in user's newsletters, with an item in the account menu when
  [Menu](/modules/interface/menu) is installed.
- **Admin area** (needs [Admin](/modules/interface/admin)):
  - `/admin/campaigns/lists`, the newsletters with their subscriber counts.
  - `/admin/campaigns/lists/:id`, one newsletter: its settings, its subscribers and the signup code to copy.
  - A "Newsletters" item in the Manage group of the admin sidebar, when Menu is installed.
- **Email template** `campaigns-confirm`, when [Email Templates](/modules/communication/email-templates) is installed.

:module-runtime{server client}

::note
**Installed for you:** Auth, Users, Notify, UI and Module Kit.
**You add:** [NuxtHub](/guide/concepts/glossary) with a database and KV (the signup's rate limit).
**Optional:**
- Admin and Menu: the staff pages and the menu items.
- Email Templates: the confirmation email from its template.
- Forms: the captcha of the signup.
::

## Quick setup

::steps

### Install Campaigns

```bash
pnpm add @frigear-nu/campaigns
```

### Add it to `nuxt.config.ts`

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxthub/core', '@frigear-nu/users', '@frigear-nu/admin', '@frigear-nu/campaigns'],
  hub: { db: 'sqlite', kv: true },
})
```

Unsubscribe links are signed with a key derived from Nuxt's `appSecret`. Set it in production, as your sessions need
it too:

```bash [.env]
NUXT_APP_SECRET=a-long-random-string-of-at-least-32-characters
```

### Generate and commit a migration

Campaigns adds three tables. Generate a [migration](/modules/platform/module-kit/database) and commit it.

```bash
npx nuxt db generate
```

### Create a newsletter and put its signup on a page

Open `/admin/campaigns/lists` as an admin and create a newsletter. Then add its signup to a page:

```vue [app/pages/news.vue]
<template>
  <NewsletterSignup list="news" />
</template>
```

::

::callout{color="success" icon="i-lucide-check"}
**What you should see:** a signup sends a confirmation email. Its link opens `/newsletter/confirm`, and after the
click the subscriber shows up as subscribed on the newsletter's staff page.
::

## Options

Options go under the `campaigns` key.

| Option | Type | Default | Purpose |
| --- | --- | --- | --- |
| `rateLimit` | `number` | `10` | Signups per IP address and newsletter in the window. `0` turns the limit off. |
| `rateLimitWindowSeconds` | `number` | `600` | The window of the rate limit. |
| `confirmTtlHours` | `number` | `72` | How long a confirmation link works. |
| `resendAfterSeconds` | `number` | `300` | A new signup for an address that is still waiting to confirm sends the confirmation again only after this pause. |
| `corsOrigins` | `string[]` | `[]` | Other sites allowed to post to the subscribe route from the browser. A plain HTML form needs none. Env `NUXT_CAMPAIGNS_CORS_ORIGINS` (a JSON array). |
| `captcha` | `false \| 'turnstile' \| 'recaptcha' \| 'hcaptcha'` | `false` | A captcha the subscribe route checks. It needs [Forms](/modules/features/forms), whose site and secret keys it uses. |
| `signingKey` | `string` | from `appSecret` | The key unsubscribe links and IP hashes are signed with. Env `NUXT_CAMPAIGNS_SIGNING_KEY`. Without it and without `appSecret`, signups answer 501 `not_configured`. |
| `settings.pages.confirm` | `string \| boolean` | `/newsletter/confirm` | The confirm page. If you turn it off, serve your own page at the same path: confirmation links point there. |
| `settings.pages.unsubscribe` | `string \| boolean` | `/newsletter/unsubscribe` | The unsubscribe page. |
| `settings.pages.account` | `string \| boolean` | `/account/newsletters` | The signed-in user's newsletters. |
| `settings.pages.adminLists` | `string \| boolean` | `/admin/campaigns/lists` | The staff list of newsletters (with Admin). |
| `settings.pages.adminList` | `string \| boolean` | `/admin/campaigns/lists/:id` | One newsletter's staff page. It must contain `:id`. |

## Permissions

Campaigns registers these permissions with [Authorization](/modules/identity/authorization).

| Name | Who holds it | What it covers |
| --- | --- | --- |
| `campaigns:manage` | `admin` | Creating, editing and deleting newsletters, and their subscribers without addresses. |
| `campaigns:pii` | `admin` (sensitive) | Subscribers' email addresses and phone numbers, and searching by them. Never covered by `campaigns:*`. |
| `campaigns:subscriptions` | Every signed-in user (implicit) | The user's own newsletters. Also a token scope, through the `newsletters` scope. |
| `campaigns:send`, `campaigns:send-important` | `admin` | Declared for sending campaigns; no route uses them yet. |

The signup, confirm and unsubscribe routes are anonymous. The rate limit, the optional captcha and the tokens in the
messages guard them.

## How signing up works

- **One answer for every address.** The subscribe route answers `{ confirm }` whether the address was known or not,
  subscribed or not, so it never tells anyone who is on a list. A subscriber who signs up again gets no email.
- **Contacts.** A contact is one email address and/or one phone number, unique each. An anonymous signup never changes
  an existing contact. When a signed-in user's email address is verified, the contact with that address is linked to
  them.
- **Double opt-in.** With the newsletter's "Ask new subscribers to confirm" on (the default), a new subscription is
  `pending` until the link in the confirmation email or SMS is followed and confirmed. Without it, it is `active` at
  once. A signed-in user who turns on a newsletter from the account page with a verified address is active at once.
- **Consent proof.** Each subscription stores where the consent came from (`form`, `api`, `admin`, `forms` or
  `account`), the version of the consent text the person agreed to, when they asked, when they confirmed and a keyed
  hash of their IP address. Changing a newsletter's consent text starts a new version.
- **Unsubscribe links** are `<subscription id>.<signature>`, an HMAC-SHA-256 under the signing key. Nothing is stored
  per link, so every message to a subscriber can carry one. Unsubscribing clears a confirmation that is still waiting.
- **The account page** turns the email channel on or off. An SMS subscription can be turned off there; signing up for
  SMS goes through the signup, which confirms the phone number.
- **A honeypot.** The signup sends a hidden `website` field. When it is filled in, the route answers as usual and
  stores nothing.

## The signup component

```vue
<NewsletterSignup list="news" />
<NewsletterSignup list="news" title="Get our news" description="Once a month, no more." />
<NewsletterSignup list="news" :title="false" />
```

| Prop | Type | Purpose |
| --- | --- | --- |
| `list` | `string` | The newsletter's URL name. Required. |
| `title` | `string \| false` | Replaces the newsletter's name as the heading; `false` shows none. |
| `description` | `string` | Replaces the newsletter's description. |

It asks for a name, an email address and a phone number (the channels the newsletter has), shows the consent text next
to the checkbox and posts in the visitor's locale, which the confirmation message uses. With the `captcha` option it
shows the captcha widget of Forms.

In a Nuxt Content page:

```md
::newsletter-signup{list="news"}
::
```

**Another site.** Each newsletter's staff page has a plain HTML `<form>` to paste into a site that cannot run the
component. It posts to the subscribe route, which redirects the visitor to `/newsletter/confirm` to check their inbox.
A site that posts with JavaScript instead needs its origin in `corsOrigins`.

## Routes

Path builders come from `@frigear-nu/campaigns/api` (`campaignsApi`).

| Route | Who | What |
| --- | --- | --- |
| `GET /api/campaigns/lists/:slug` | Anyone | A public newsletter as the signup shows it. A newsletter that is not public is a 404. |
| `POST /api/campaigns/lists/:slug/subscribe` | Anyone (rate limited) | `{ email?, phone?, name?, locale?, channels?, consent, captcha? }`, as JSON or a plain form. Answers `{ confirm }`; a plain form post gets a 303 to the confirm page. 429 `rate_limited`, 400 `captcha_required` / `captcha_failed`. |
| `POST /api/campaigns/confirm/:token` | The token | Confirms the subscription. 400 `invalid_token` (unknown or used), 410 `token_expired`. |
| `POST /api/campaigns/unsubscribe/:token` | The token | Unsubscribes. The RFC 8058 one-click target: the body is not read. 400 `invalid_token`. |
| `GET`, `PATCH /api/campaigns/me/subscriptions` | `campaigns:subscriptions` | The user's newsletters; `PATCH { lists: { [listId]: { email?, sms? } } }` turns channels on (email only) or off. |
| `GET`, `POST /api/admin/campaigns/lists` | `campaigns:manage` | Every newsletter with its counts; creates one. 409 `conflict` for a URL name in use. |
| `GET`, `PATCH`, `DELETE /api/admin/campaigns/lists/:id` | `campaigns:manage` | One newsletter. Deleting it deletes its subscriptions. |
| `GET /api/admin/campaigns/lists/:id/subscribers` | `campaigns:manage` | Paginated subscriptions, `?status&channel&q&sort&order`. Addresses with `campaigns:pii`. |

## Database

Tables the module adds. Generate and commit a [migration](/modules/platform/module-kit/database) after installing.

| Table | What it holds |
| --- | --- |
| `campaign_lists` | `id` (`cml_`), `slug` (unique), `name`, `description`, `channels`, `doubleOptIn`, `public`, `consentText`, `consentVersion`, `formId` and `formFields` (a forms form that signs people up). |
| `campaign_contacts` | `id` (`cmc_`), `email` (lower-cased, unique), `phone` (E.164, unique), `userId`, `name`, `locale`. |
| `campaign_subscriptions` | `id` (`cms_`), `listId`, `contactId`, `channel` (unique together), `status` (`pending`, `active`, `unsubscribed`), `confirmTokenHash` (SHA-256 of the confirmation token), `confirmExpiresAt`, `source`, `consentVersion`, `requestedAt`, `confirmedAt`, `ipHash`, `unsubscribedAt`. |

## Translations

Override any string in your app's `i18n/locales/<code>.json`, under the `campaigns` key. Campaigns ships Danish and
English, and so do the confirmation email and SMS.
