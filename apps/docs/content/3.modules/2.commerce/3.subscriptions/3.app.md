This page covers the app side: the composables for your own pricing page, a middleware that guards pages by plan, the
components and the ready-made pages. It is for app developers, in server mode. Set up the module first:
[Overview](/modules/commerce/subscriptions).

## Composables

Both composables are auto-imported, and exported from `@frigear-nu/subscriptions/composables`.

```ts
usePlans(): { plans, status, loading, error, refresh }   // plans sorted by rank
useSubscription(): {
  subscription, plan, status, loading, loadError, isActive, cancelsAt,
  has(planKey: string): boolean,
  pending, error, refresh,
  subscribe(planKeyOrPriceId: string, options?: { successUrl?: string, cancelUrl?: string }): Promise<CheckoutResponse>,
  openPortal(returnUrl?: string): Promise<void>,
}
```

Both load through [`useCachedFetch`](/modules/interface/ui/composables#loading-data-that-survives-navigation), so their
data survives navigation. Plans are cached for five minutes, and the subscription for one minute.

- `loading` is `true` only while nothing is loaded yet. Render a placeholder for it, not the "no subscription" state.
- `loadError` is the error of loading the subscription. `error` and `pending` belong to `subscribe` and `openPortal`.
- `subscribe` sends a string that starts with `price_` as `priceId`, and anything else as `planKey`. It redirects to
  Stripe Checkout, or refreshes when an existing subscription was changed.
- `openPortal` redirects to the billing portal. `returnUrl` defaults to the current page.

## Middleware

The `subscription` route middleware sends people without the right plan away from a page:

```ts
definePageMeta({
  middleware: 'subscription',
  subscription: { plans: ['member'], redirectTo: '/join' }, // both optional
})
```

- It redirects to `redirectTo`, else to the membership page, with the original route in `?redirect=`. Without either
  target it does nothing.
- [Visitors](/guide/concepts/glossary) and users without an active plan are redirected.
- A subscription on a price outside every configured plan has no `activePlan`, so it is redirected too.

::warning
The middleware guards navigation only. Check the plan in every API route with
[`hasActiveSubscription`](/modules/commerce/subscriptions/server#check-a-users-plan).
::

## Components

`SubscriptionPlans` and `SubscriptionStatus` are built on `@nuxt/ui` and expose scoped slots.

| `SubscriptionPlans` prop | Type | Default | Purpose |
| --- | --- | --- | --- |
| `locale` | `string` | – | The formatting locale. |
| `currency` | `string` | the price's | Overrides the currency for formatting. |
| `interval` | `'day' \| 'week' \| 'month' \| 'year'` | the first price | Which price to show per plan. |
| `plans` | `string[]` | all | Shows only these plan keys. |
| `confirmChange` | `boolean` | `false` | Asks before changing an existing subscription. |
| `mode` | `'auto' \| 'list' \| 'tabs'` | `'auto'` | `auto` shows tabs on small screens and cards side by side from `sm` up. |
| `highlight` | `string` | the current plan | The plan key to emphasise. |

`SubscriptionPlans` emits `select(plan, price)`. Each plan has a `state`: `'current'`, `'upgrade'`, `'downgrade'` or
`'subscribe'`. A visitor who picks a plan is sent to the Users register page, with
`?redirect=<membership page>?plan=<key>`.

| Component | Slot | Slot props |
| --- | --- | --- |
| `SubscriptionPlans` | `loading`, `empty` | – |
| | `header`, `badge` | `{ plan, state }` |
| | `price` | `{ plan, price, formatPrice, intervalLabel }` |
| | `features` | `{ plan }` |
| | `action` | `{ plan, state, pending, select }` |
| | `confirm` | `{ plan, price }` |
| | `confirm-actions` | `{ plan, price, confirm }` |
| `SubscriptionStatus` | `header`, `loading`, `empty` | – (prop `locale`) |
| | `plan` | `{ plan, label, subscription }` |
| | `badge` | `{ subscription, badge }`, where `badge` is `{ status, label, color, icon }` |
| | `dates` | `{ subscription, cancelsAt, dateText }` |
| | `actions` | `{ manage, resubscribe, cancelling, pending }` |

`UsersAdminMembership` (prop `user`, emits `refresh`) is the panel in the admin user tab where
[staff](/guide/concepts/glossary) grant and revoke a free membership.

## Pages and menu

Each page you turn on in `settings.pages` is added at its path, unless a page already exists there.

| Page | Default path | What it shows |
| --- | --- | --- |
| Membership | `/account/membership` | The current subscription, or a "No membership yet" state, then the plans. |
| Success | `/account/membership/success` | Checks again every 3 seconds, for about 2 minutes, until the webhook has arrived. |
| Cancel | `/account/membership/cancel` | A way back to the membership page. |

The pages sit under `/account/**`, so they use the `account` layout. They follow the
[UX patterns](/guide/ux-patterns/layouts-and-navigation) for account pages.

Other modules add more when they are installed:

- **[Menu](/modules/interface/menu)**, with the membership page on: a Membership item (id `membership`, order 15) in
  the `account` menu.
- **[Widget](/modules/interface/widget)**: a membership summary in the `account.overview` widget area.
- **Widget and [Admin](/modules/interface/admin)**: a Membership tab (`?tab=membership`, order 10) and a Current
  membership card on the admin user page. They sit in the `admin.users` tab area and the `admin.users.overview` widget
  area. Revoking a free membership asks for confirmation first.
