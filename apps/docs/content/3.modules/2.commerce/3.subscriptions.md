---
title: Subscriptions
description: Recurring Stripe subscriptions - host-defined plans, checkout, upgrade/downgrade, billing portal, entitlements and account UI.
---

Recurring subscriptions on top of [Stripe](/modules/commerce/stripe). It handles **only** recurring subscriptions; one-off
payments belong to [Payments](/modules/commerce/payments). "Membership" is just a label a host chooses for its plans.

- **Stripe owns the catalog; the module mirrors per-user state.** No products or prices tables. Plans are declared in
  config and prices are resolved live from Stripe, cached in NuxtHub KV for about five minutes.
- **Host policy through hooks.** Seasonal windows, member discounts and similar rules are injected with
  [hooks](#hooks), not built in.
- **No copy in Stripe.** Labels come from config and optional i18n keys. The UI is headless-first (composables) with
  replaceable components and slots; pages are opt-in.
- **Entitlements, not roles.** Other code asks "does this user hold plan X?".

::note
**Requires** `@nuxthub/core` (KV on; the build throws without it), `@frigear-nu/module-kit`,
[`@frigear-nu/auth`](/modules/identity/auth), [`@frigear-nu/mcp`](/modules/features/mcp), [`@frigear-nu/users`](/modules/identity/users) and
[`@frigear-nu/stripe`](/modules/commerce/stripe) (configure it as described there: keys, webhook and KV) and
[`@frigear-nu/ui`](/modules/interface/ui) (the shared components the pages are built from).
**Optional** [`@frigear-nu/menu`](/modules/interface/menu), [`@frigear-nu/widget`](/modules/interface/widget) and
[`@frigear-nu/admin`](/modules/interface/admin) (the admin user tab and card need both), `@nuxt/ui` (components and pages) and
`@nuxtjs/i18n` (translated labels; English otherwise).
::

## Quick setup

```bash
pnpm add @frigear-nu/subscriptions @nuxthub/core
```

List the module after the ones it builds on:

```ts
export default defineNuxtConfig({
  modules: [
    '@nuxthub/core',
    '@nuxt/ui',
    '@frigear-nu/users',
    '@frigear-nu/menu', // optional
    '@frigear-nu/stripe',
    '@frigear-nu/subscriptions',
  ],
  hub: { db: { dialect: 'sqlite', driver: 'libsql' }, kv: true },
  subscriptions: {
    plans: {
      member: { label: 'Member', rank: 1, prices: [{ lookupKey: 'member_yearly' }] },
      patron: { label: 'Patron', rank: 2, prices: [{ lookupKey: 'patron_yearly' }] },
    },
    settings: { pages: { membership: true, success: true, cancel: true } },
  },
})
```

1. Set the Stripe [environment variables](/modules/commerce/stripe#environment-variables) (test keys in development).
2. Complete the [Stripe dashboard setup](#stripe-dashboard-setup).
3. Generate and commit your app's migration (see [Database](#database)); skipping it is the most common cause of failing
   webhooks and checkouts.
4. Verify: sign in, open `/account/membership` and subscribe with Stripe's test card `4242 4242 4242 4242`. After the
   redirect, `GET /api/subscriptions/me` returns the subscription once the webhook has landed.

## Options

| Option                                    | Type                           | Default | Purpose                                                                                           |
| ----------------------------------------- | ------------------------------ | ------- | ------------------------------------------------------------------------------------------------- |
| `plans`                                   | `Record<string, PlanConfig>`   | `{}`    | Plans keyed by plan key. Empty means "any active subscription" (see below).                       |
| `plans.<key>.prices`                      | `Array<string \| { lookupKey }>` | -     | Required. Stripe price ids and/or lookup refs; several per plan (monthly, yearly).                |
| `plans.<key>.rank`                        | `number`                       | -       | Required. Higher is a higher tier; decides upgrade vs downgrade. Amounts are never compared.      |
| `plans.<key>.label`                       | `string`                       | the key | Display label; i18n `subscriptions.catalog.<key>.label` wins when defined.                        |
| `plans.<key>.description`                 | `string`                       | -       | Optional; i18n `catalog.<key>.description` wins.                                                  |
| `plans.<key>.features`                    | `string[]`                     | -       | Bullet points on the plan card; i18n `catalog.<key>.features` (array) wins.                       |
| `plans.<key>.availability.disabledRanges` | `{ from, to }[]`               | -       | Date windows (inclusive; `{fullYear}` becomes the current year, e.g. `{fullYear}-06-01`) in which the plan is hidden from visitors without an active subscription. Subscribers still see it; checkout rejects a hidden plan. |
| `settings.pages.membership`               | `string \| boolean`            | off     | `true` = `/account/membership`, a string = custom path.                                           |
| `settings.pages.success`                  | `string \| boolean`            | off     | `true` = `/account/membership/success`.                                                           |
| `settings.pages.cancel`                   | `string \| boolean`            | off     | `true` = `/account/membership/cancel`.                                                            |
| `settings.allowChangeInPortal`            | `boolean`                      | `false` | Hint exposed as `public.subscriptions.allowChangeInPortal`. Not enforced; mirror your billing portal. |
| `settings.mcp`                            | `boolean`                      | `false` | Expose the `my-subscriptions` tool on the [MCP](/modules/features/mcp) endpoint.                           |

Without plans, checkout requires a `priceId` and accepts any active recurring Stripe price; stored rows get
`planKey = null`. Runtime config exposes `public.subscriptions` (`pages`, plans sorted by `rank` without prices, and
`allowChangeInPortal`) and a private `subscriptions.plans`. Pages need `@nuxt/ui` in the app; leave them out to build
your own UI with the [composables](#app).

## Server

### Entitlements

Auto-imported in Nitro, or import from `@frigear-nu/subscriptions/utils`:

```ts
getUserSubscription(userId: number, options?: { statuses?: string[] }): Promise<SubscriptionRow | null>
hasActiveSubscription(userId: number, options?: {
  plans?: string[]      // only these plan keys; omit for any plan
  statuses?: string[]   // default DEFAULT_ENTITLED_STATUSES = ['active', 'trialing']
}): Promise<boolean>
```

`getUserSubscription` returns the entitled row with the latest `currentPeriodEnd`. Rows with `endedAt`, and manual
grants past their end date, never count. These are meant for other modules (for example [Events](/modules/features/events)),
server middleware and gating.

Also exported from `@frigear-nu/subscriptions/utils`:

| Export                                       | Description                                                                                       |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `decideChangeKind(currentRank, targetRank)`  | `'upgrade'` or `'downgrade'` from plan ranks; an unconfigured current plan counts as lowest.      |
| `resolvePlanKey(plans, { id, lookupKey? })`  | Maps a Stripe price to the configured plan key, or `null`.                                         |
| `isWithinDisabledRanges(ranges, now?)`       | Whether a date falls in any `disabledRanges` window.                                               |
| `DEFAULT_ENTITLED_STATUSES`                  | `['active', 'trialing']`.                                                                          |

Further server helpers are auto-imported in Nitro: `listUserSubscriptions(userId)` (the `MeResponse`),
`getResolvedPlans()` (unfiltered, cached) and `getAvailablePlans(event?)` (after availability windows and the
`subscriptions:plans:filter` hook).

### Webhook handling

The module registers with [`registerStripeEventHandler`](/modules/commerce/stripe#in-a-module) for
`customer.subscription.created`, `updated`, `deleted`, `paused` and `resumed`. Each event is an idempotent upsert keyed
by the Stripe subscription id:

- The user is resolved from the Stripe customer id. For an unknown customer the event is logged and ignored (the webhook
  still succeeds); users are never created from webhooks.
- `planKey` comes from the first subscription item's price (price id or lookup key), else `null`.
- Period start and end are derived from the items; `deleted` stores status `canceled` and sets `endedAt`.

Retries and idempotency follow [Stripe](/modules/commerce/stripe#delivery-and-retries). When `@frigear-nu/payments` is
installed, `invoice.paid`, `invoice.payment_failed`, `invoice.voided` and `invoice.marked_uncollectible` for
subscription invoices are also handled: they are announced through the `subscriptions:invoice` hook and stored by
payments as [membership payments](/modules/commerce/payments#membership-payments). Without payments no invoice event is handled.

### Checkout

`POST /api/subscriptions/me/checkout` (session only, billing: a bearer token gets 403 `session_required`) takes `CheckoutBody`:

```ts
type CheckoutBody = {
  planKey?: string      // planKey or priceId is required (400 otherwise)
  priceId?: string      // required when the plan has several prices, and when no plans are configured
  successUrl?: string   // relative path or same-origin URL, else 400; defaults to the success page, membership page or '/'
  cancelUrl?: string
}

type CheckoutResponse =
  | { url: string }                                           // new Stripe Checkout Session: redirect to it
  | { updated: true, kind: 'upgrade' | 'downgrade' | 'resume' } // an existing subscription was changed in place
```

The plan must be in the filtered plan list (a hidden plan is 400). A user "has a subscription" here when a Stripe-synced
row is `active`, `trialing` or `past_due` and not ended; manual grants are ignored.

| Situation                                                        | Result                                                                                       |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| No existing subscription                                         | `kind: 'checkout'`: returns `{ url }`.                                                       |
| Same price, set to cancel at period end                          | `resume`: releases a pending schedule and clears the cancellation. Skips the hook.           |
| Same price, not cancelling                                       | `409` ("already subscribed to this price").                                                  |
| Higher plan rank                                                 | `upgrade`: immediate, `always_invoice` proration; a pending schedule is released.            |
| Lower or equal rank (including a monthly to yearly change)       | `downgrade`: deferred to the period end through a subscription schedule.                     |
| Existing subscription set to cancel at period end, any change    | Switched immediately, which also keeps it from ending.                                       |
| Subscription has no items, or its billing phase cannot be read   | `409`.                                                                                       |

A target price outside the configured plans (only possible with no plans configured) counts as an upgrade. The local
row is updated by the webhook afterwards; cancellation is done in the billing portal.

### Staff membership

Staff manage a user's membership through the admin routes below, authorized by the `users:admin:authorize` hook of
[Users](/modules/identity/users) (`view` for reads, `update` for changes). A free grant is a **manual** row (`source: 'manual'`,
id `manual_<uuid>`, no Stripe subscription) that counts as active until revoked or its optional `endsAt` passes.

```ts
// GET /api/admin/users/:id/membership
type AdminMembershipResponse = {
  plans: Array<{ key: string, label: string, rank: number }>
  current: {
    id: string
    planKey: string | null
    status: string
    source: 'stripe' | 'manual'
    currentPeriodEnd: string | null
    cancelAtPeriodEnd: boolean
  } | null
}

// POST /api/admin/users/:id/membership          body { planKey, endsAt? }   201 + SubscriptionDto; 400 unknown plan or past date, 409 paid subscription exists
// DELETE /api/admin/users/:id/membership        204; 404 when there is no free membership
// GET /api/admin/users/:id/membership/history   MeResponse
// POST .../membership/payment-link              body { planKey?, priceId?, email? }
type AdminPaymentLinkResponse = { url: string, emailed: boolean }
```

A payment link is a Stripe Checkout session valid for 24 hours; `email: true` also mails it through
[Notify](/modules/platform/notify) (rendered from the `subscriptions-payment-link` template when
[Email Templates](/modules/platform/email-templates) is installed). The plan filter hook is not applied for staff. Granting replaces an existing manual grant.

## App

Auto-imported, and also available from `@frigear-nu/subscriptions/composables`.

```ts
usePlans(): { plans, status, loading, error, refresh }   // plans sorted by rank
useSubscription(): {
  subscription, plan, status, loading, loadError, isActive, cancelsAt,
  has(planKey: string): boolean,
  pending, error, refresh,
  subscribe(planKeyOrPriceId: string, options?: { successUrl?: string, cancelUrl?: string }): Promise<CheckoutResponse>,
  openPortal(returnUrl?: string): Promise<void>,
}
```

Both load through [`useCachedFetch`](/modules/interface/ui#loading-data-that-survives-navigation), so their data survives
navigation (plans for five minutes, the subscription for a minute). `loading` is `true` only while nothing is loaded
yet; render a placeholder for it rather than the "no subscription" state. `loadError` is the error of loading the
subscription, while `error` and `pending` belong to `subscribe` / `openPortal`.

`subscribe` sends strings starting with `price_` as `priceId`, anything else as `planKey`; it redirects to Stripe
Checkout, or refreshes when an existing subscription was changed. `openPortal` redirects to the billing portal and
defaults `returnUrl` to the current page.

### Middleware

```ts
definePageMeta({
  middleware: 'subscription',
  subscription: { plans: ['member'], redirectTo: '/join' }, // both optional
})
```

Redirects to `redirectTo`, else to the membership page, with the original route in `?redirect=`; without either target
it does nothing. Anonymous users and users without an active plan are redirected, and a subscription on a price outside
every configured plan has no `activePlan` and is not let through. This guards navigation only; enforce access in API
routes with `hasActiveSubscription`.

### Components

`SubscriptionPlans` and `SubscriptionStatus` are built on `@nuxt/ui` and expose scoped slots.

| `interval`               | `'day' \| 'week' \| 'month' \| 'year'`   | first price | Which price to show per plan.                                                            |

Emits `select(plan, price)`. Each plan has a `state`: `'current' | 'upgrade' | 'downgrade' | 'subscribe'`. Visitors who

`UsersAdminMembership` (prop `user`, emits `refresh`) is the staff grant and revoke panel used by the admin user tab.

### Pages and menu

Each enabled page in `settings.pages` is added at its path (skipped if the path already exists): the membership page
(a `PageHeading`, then a `SectionCard` with the status when subscribed or a "No membership yet" empty state, then the
plans with confirmation), a success page (polls `me` up to five
times, two seconds apart, while the webhook lands) and a cancel page. The pages sit under `/account/**`, so the `account`
layout provides the shell and the container, but not the heading: each page renders its own `PageHeading` (the
keys of the menu item; success and cancel add a breadcrumb back to **Membership**). Success and cancel are empty states
with one action, **Back to membership**. With [Menu](/modules/interface/menu) and the membership page enabled, a "Membership"
item (id `membership`, order 15) is added to the `account` menu (the account tile and left navigation). With Widget installed, a
membership summary is added to the `account.overview` widget area. With Widget and Admin installed, the admin user page
gains a *Membership* tab (id `membership`, so `?tab=membership`; order 10, built from `SectionCard`, `DescriptionList` and a history table in a `TableCard`) and a *Current
membership* card (`admin.users` tab area, `admin.users.overview` widget area). Revoking a free membership asks for
confirmation first.

## Hooks

Register with `nitro.hooks.hook(...)` in a Nitro plugin. The module contains no seasonal or pricing rules.

| Hook                            | When                                                                              | Payload                |
| ------------------------------- | --------------------------------------------------------------------------------- | ---------------------- |
| `subscriptions:checkout:before` | After validation and the kind decision, for new checkouts and plan changes. Throw to deny. Not run for `resume`. | `CheckoutBeforeContext` |
| `subscriptions:plans:filter`    | Whenever plans are listed or checked (also gates checkout). Mutate or reassign `ctx.plans`. | `PlansFilterContext`   |

```ts
type CheckoutBeforeContext = {
  event: H3Event
  userId: number
  planKey: string | null
  priceId: string
  kind: 'checkout' | 'upgrade' | 'downgrade'
  params: Stripe.Checkout.SessionCreateParams   // only used when kind === 'checkout'
}

type PlansFilterContext = {
  event: H3Event | undefined   // undefined outside a request
  plans: ResolvedPlan[]        // a copy of the cached plans
}

type ResolvedPlan = { key: string, label: string, description?: string, rank: number, features?: string[], prices: PlanPrice[] }
type PlanPrice = {
  id: string
  amount: number | null           // minor units
  currency: string
  interval: 'day' | 'week' | 'month' | 'year'
  intervalCount: number
  trialPeriodDays: number | null
  lookupKey: string | null
}
```

The default `params` are `mode: 'subscription'`, the line item, `success_url`, `cancel_url`, `client_reference_id` (the
user id) and `subscription_data.metadata` (`userId`, `planKey`); the Stripe `customer` is added afterwards.

```ts
export default defineNitroPlugin((nitro) => {
  nitro.hooks.hook('subscriptions:checkout:before', (ctx) => {
    if (!isSignupSeason(new Date())) throw createError({ statusCode: 403, statusMessage: 'Sign-up is closed' })
    if (ctx.kind === 'checkout') ctx.params.metadata = { ...ctx.params.metadata, source: 'website' }
  })
})
```

## Routes

| Method | Path                                           | Auth                                            | Status | Purpose                                                                    |
| ------ | ---------------------------------------------- | ----------------------------------------------- | ------ | -------------------------------------------------------------------------- |
| GET    | `/api/subscriptions/plans`                     | public                                          | 200    | `{ plans: ResolvedPlan[] }`, after the `plans:filter` hook.                |
| GET    | `/api/subscriptions/me`                        | `requireUser`, scope `subscriptions:read`       | 200    | `MeResponse`: all subscriptions plus `activePlan`.                         |
| POST   | `/api/subscriptions/me/checkout`               | session only                                    | 200    | New checkout (`{ url }`) or plan change (`{ updated, kind }`), see [Checkout](#checkout). |
| POST   | `/api/subscriptions/me/portal`                 | session only                                    | 200    | Body `{ returnUrl? }` (same origin, else 400 `bad_request`). Returns `{ url }` of a billing portal session. |
| GET    | `/api/admin/users/:id/membership`              | `users:admin:authorize` (`view`)                | 200    | Current membership and the grantable plans.                                |
| GET    | `/api/admin/users/:id/membership/history`      | `users:admin:authorize` (`view`)                | 200    | Full history including ended rows, as `MeResponse`.                        |
| POST   | `/api/admin/users/:id/membership`              | `users:admin:authorize` (`update`)              | 201    | Grant a free membership; body `{ planKey, endsAt? }` (`endsAt` a future date). Answers the new `SubscriptionDto`. |
| DELETE | `/api/admin/users/:id/membership`              | `users:admin:authorize` (`update`)              | 204    | Revoke a free membership; 404 `not_found` when there is none.              |
| POST   | `/api/admin/users/:id/membership/payment-link` | `users:admin:authorize` (`update`)              | 200    | Create (and optionally email) a checkout link: `{ url, emailed }`.         |

`me` and `plans` are static segments. `checkout` and `portal` are billing actions, so they need a session: a bearer or OAuth token gets 403 `session_required`, whatever its scopes. `subscriptions:read` lets a token read `me`. Path builders: `subscriptionsApi` from `@frigear-nu/subscriptions/utils`. The scope is registered with
[Auth](/modules/identity/auth) as `subscriptions:read` ("Read your subscription and plans").

```ts
type SubscriptionDto = {
  id: string
  planKey: string | null
  priceId: string
  status: string                      // raw Stripe status
  cancelAtPeriodEnd: boolean
  currentPeriodStart: string | null   // ISO
  currentPeriodEnd: string | null
  endedAt: string | null
  source?: 'stripe' | 'manual'        // 'manual' for free grants made by staff
}

type MeResponse = {
  subscriptions: SubscriptionDto[]
  activePlan: string | null           // plan of the entitled subscription with the latest period end
}
```

## Stripe dashboard setup

The general walkthrough is in [Stripe setup](/guide/going-further/stripe-setup). For this module:

1. **Webhook events**: subscribe the endpoint to `customer.subscription.created`, `.updated`, `.deleted`, `.paused` and
   `.resumed`.
2. **Products and prices**: create recurring prices. Use lookup keys to keep config environment-independent (test and
   live have different price ids). No metadata or copy is needed in Stripe.
3. **Billing portal** (Settings > Billing > Customer portal): enable cancellation and payment method updates. Enable
   subscription updates only with `allowChangeInPortal: true`, and list the prices the portal may switch between.

## Database

One `subscriptions` table.

| Column                                 | Type                | Notes                                                                           |
| -------------------------------------- | ------------------- | ------------------------------------------------------------------------------- |
| `id`                                   | text, primary key   | Stripe subscription id (`sub_...`), or `manual_<uuid>` for free grants.          |
| `userId`                               | integer             | Indexed; no foreign key. The webhook resolves it through `users.stripeCustomerId`. |
| `planKey`                              | text, nullable      | `null` when the price is in no configured plan, so config changes never lose data. |
| `priceId`                              | text                | Empty for manual grants.                                                        |
| `status`                               | text                | Raw Stripe status.                                                              |
| `cancelAtPeriodEnd`                    | boolean             |                                                                                 |
| `currentPeriodStart`, `currentPeriodEnd`, `endedAt` | timestamps, nullable | `currentPeriodEnd` on a manual grant is its optional end date.        |
| `source`                               | text                | `stripe` (default) or `manual`.                                                 |
| `rawItems`                             | JSON, nullable      | Item id, price id, lookup key, quantity.                                        |
| `createdAt`, `updatedAt`               | timestamps          |                                                                                 |

Rows are never deleted; ended subscriptions get `endedAt`.

::warning
The module ships no migration: generate and commit one in every host app and fixture, covering this table **and** the
`users.stripe_customer_id` column from [Stripe](/modules/commerce/stripe#database). See [Database extensions](/guide/concepts/database-extensions).
::

## Translations

`da` and `en` locale files are registered with [Module Kit](/modules/platform/module-kit/i18n); components read them
through `useModuleT('subscriptions.<group>')`. Override any key in your app's `i18n/locales/<code>.json` (see
[overriding module strings](/modules/platform/module-kit/i18n#overriding-module-strings-in-your-app)). Parameters use `{name}`.

| Group        | Keys                                                                                                                           |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| `plans.*`    | `loading`, `empty`, `current`, `subscribe`, `upgrade`, `downgrade`, `trial` (`{days}`), `confirmTitle`, `confirmBody` (`{plan}`), `confirm`, `cancel`, `select`, `resubscribe` and the checkout, upgrade and downgrade confirmation texts. |
| `interval.*` | `day`, `week`, `month`, `year`, their plurals, and `quarter`.                                                                  |
| `status.*`   | `loading`, `title`, `none`, `renews` (`{date}`), `cancels` (`{date}`), `manage`, `resubscribe`, `active`, `trialing`, `pastDue`, `canceled`, `other`, `emptyTitle` and `emptyDescription` (the "No membership yet" empty state; they replace `heroTitle` and `heroDescription`), plus the status card texts. |
| `success.*`, `cancel.*` | Page texts: `title`, `body`, `back` ("Back to membership").                                                                   |
| `errors.*`   | `checkout`, `portal`.                                                                                                          |
| `menu.*`, `admin.*`, `overview.*` | Account menu item, the admin tab, card and membership panel, and the account overview summary.                 |
| `catalog.<planKey>.*` | `label`, `description` and `features` (array) per plan; host-defined and falling back to the plan config.            |
