One-time payments on top of [Stripe](/modules/commerce/stripe). The module is event-agnostic: other modules (for example
[Events](/modules/features/events)) ask it to charge something and are told through hooks when the money arrives.

:module-runtime{server client}

- **Stripe events are the only inbound signal.** The module has no webhook route of its own. It registers a handler with
  [`registerStripeEventHandler`](/modules/commerce/stripe#in-a-module) for `checkout.session.completed`,
  `checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`, `checkout.session.expired` and
  `charge.refunded`. The success redirect never marks anything as paid.
- **Prices are inline.** Checkout sessions use `price_data`, so no Stripe products or prices need syncing between
  environments.
- **Hooks, not coupling.** State transitions are announced through Nitro hooks; consumers filter on
  `payment.referenceType`.

::note
**Requires** `@nuxthub/core` (KV on), `@frigear-nu/module-kit`, [`@frigear-nu/auth`](/modules/identity/auth),
[`@frigear-nu/users`](/modules/identity/users) and [`@frigear-nu/stripe`](/modules/commerce/stripe) (configure it as described there).
**Optional** [`@frigear-nu/widget`](/modules/interface/widget) and [`@frigear-nu/admin`](/modules/interface/admin): the admin user tab and
card are only added when both are present.
::

## Quick setup

```bash
pnpm add @frigear-nu/payments @nuxthub/core
```

```ts
export default defineNuxtConfig({
  modules: ['@nuxthub/core', '@frigear-nu/users', '@frigear-nu/stripe', '@frigear-nu/payments'],
  payments: {
    settings: { checkoutExpiresInMinutes: 30 },
  },
})
```

## Options

| Option                              | Type     | Default | Purpose                                                                                       |
| ----------------------------------- | -------- | ------- | --------------------------------------------------------------------------------------------- |
| `settings.checkoutExpiresInMinutes` | `number` | `30`    | Minutes a Checkout session stays open. Clamped to Stripe's range of 30 - 1440. Also in `runtimeConfig.payments`. |
| `settings.mcp`                      | `boolean` | `false` | Expose the `my-payments` MCP tool. |

## Server

Auto-imported in Nitro:

| Util                                                              | Description                                                                                                    |
| ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `createPayment(input, event?)`                                    | Creates the Checkout session (`mode: 'payment'`) and a `pending` row. Returns `CreatePaymentResult`.           |
| `resumePayment(paymentId, userId, event?)`                        | Returns the open session's URL, or creates a fresh session once it expired. Returns `{ url }`.                 |
| `refundPayment(paymentId, { amount? })`                           | Asks Stripe for a (partial) refund. The status changes when `charge.refunded` arrives.                         |
| `getPayment(id)`, `getPaymentByReference(type, id)`               | Read one payment (the latest for a reference), or `null`.                                                      |
| `listUserPayments(userId, { limit? })`                            | A user's payments, newest first.                                                                               |

`@frigear-nu/payments/utils` exports the types below and `sumItems(items)`, which totals items in minor units.

```ts
type PaymentStatus = 'pending' | 'paid' | 'failed' | 'expired' | 'refunded' | 'partially_refunded'

type PaymentItem = {
  name: string
  description?: string
  amount: number      // unit amount in minor units (cents / øre)
  currency: string    // ISO 4217
  quantity?: number   // default 1
}

type CreatePaymentInput = {
  userId: number
  items: PaymentItem[]                           // one currency, total above zero
  reference?: { type: string, id: string }       // e.g. { type: 'event_ticket', id }
  successUrl: string                             // absolute URL or path on the current origin
  cancelUrl: string
  description?: string
  expiresInMinutes?: number                      // overrides settings.checkoutExpiresInMinutes
  metadata?: Record<string, string>
}

type CreatePaymentResult = { payment: PaymentDto, url: string }

type PaymentDto = {
  id: string                      // pay_...
  userId: number
  status: PaymentStatus
  amount: number
  currency: string
  description: string | null
  referenceType: string | null
  referenceId: string | null
  refundedAmount: number
  paidAt: string | null           // ISO
  createdAt: string               // ISO
}
```

Behaviour worth knowing:

- `successUrl` and `cancelUrl` are validated (relative path or same origin) when `event` is passed; without `event` they
  must be absolute `http(s)` URLs. Invalid URLs throw 400.
- `resumePayment` throws 404 for an unknown payment, and 409 when it is already paid or refunded. For an expired session
  it creates a new one from the stored `items` (same names, descriptions, unit amounts and quantities), runs
  `payments:checkout:before` and the same return URL validation as `createPayment`, and reuses the expired session's
  success and cancel URLs. `expiresInMinutes` is not stored; the configured `checkoutExpiresInMinutes` applies. Payments
  created before `items` was stored fall back to a single line item for the total, named after the description or
  `Payment`; the hook still runs.
- `refundPayment` throws 409 unless the payment is `paid` or `partially_refunded`, and 400 for an amount that is not
  positive or exceeds what is left to refund.

## App

| Export          | Returns                                                        | Description                                         |
| --------------- | -------------------------------------------------------------- | --------------------------------------------------- |
| `usePayments()` | `{ payments, refresh, status, loading, error, resume(paymentId) }` | The signed-in user's payments; `resume` redirects to Stripe. Awaitable (`await usePayments()` in pages). |

With [Widget](/modules/interface/widget) and [Admin](/modules/interface/admin) installed, the module adds a *Payments* tab (order 20) and a
*Last payment* card to the admin user page of [Users](/modules/identity/users) (`admin.users` tab area,
`admin.users.overview` widget area).

The *Payments* tab is a `TableCard` with a read-only `UTable` (amounts through `useFormat().money`, status badges
coloured with `statusColor`); there is no refund action yet, so rows have no menu. *Last payment* is a `SectionCard` with
a `DescriptionList`. On the admin dashboard, *Revenue, 30 days* is a `StatCard` and *Recent transactions* a `ListCard`
that links to the users list. All of them are built from the [UX patterns](/guide/ux-patterns/layouts-and-navigation) of
`@frigear-nu/ui`.

## Hooks

Register with `nitro.hooks.hook(...)` in a Nitro plugin.

| Hook                       | When                                                                                  | Payload                  |
| -------------------------- | ------------------------------------------------------------------------------------- | ------------------------ |
| `payments:checkout:before` | Before the session is created by `createPayment` or rebuilt by `resumePayment`; adjust `ctx.params` or throw to deny. | `CheckoutBeforeContext`  |
| `payments:paid`            | Once, when the payment became paid.                                                   | `PaymentHookContext`     |
| `payments:failed`          | An asynchronous payment method failed.                                                | `PaymentHookContext`     |
| `payments:expired`         | The Checkout session expired unpaid.                                                  | `PaymentHookContext`     |
| `payments:refunded`        | A refund changed the payment (`partially_refunded` or `refunded`).                    | `PaymentHookContext`     |
| `payments:authorize`       | Staff gate of `GET /api/admin/payments/recent`: set `ctx.allowed = true`. Denied by default. | `AuthorizeContext`  |

```ts
type PaymentHookContext = { payment: PaymentDto }

type CheckoutBeforeContext = {
  event?: H3Event
  userId: number
  reference?: { type: string, id: string }
  params: Stripe.Checkout.SessionCreateParams   // mutable
}
```

Transitions are conditional updates: a redelivered Stripe event emits nothing twice, and a `paid` payment is never
downgraded by a late `expired` event.

## Routes

| Method | Path                                    | Auth                                      | Status | Purpose                                                                                       |
| ------ | --------------------------------------- | ----------------------------------------- | ------ | --------------------------------------------------------------------------------------------- |
| GET    | `/api/payments/me`                      | `requireUser`, scope `payments:read`      | 200    | The signed-in user's payments (`PaymentDto[]`).                                               |
| POST   | `/api/payments/me/:id/resume`           | `requireUser`, scope `payments:write`     | 200    | Returns `{ url }` for one of the caller's unpaid payments; 404 `not_found` for someone else's, 409 `conflict` when already paid. |
| GET    | `/api/admin/payments/recent`            | staff (`payments:manage` + `payments:authorize`) | 200 | Dashboard object `{ days, revenue, items }`: the last 30 days' revenue per currency and the latest settled payments with the user's name. |
| GET    | `/api/admin/users/:id/payments`         | `users:admin:authorize` (action `view`)   | 200    | Staff view of a user's payments, newest first. `?limit=` is validated (1 to 500, default 100). |

The two `/me` routes also accept bearer tokens and OAuth access tokens that carry the scope. The scopes are registered
with [Auth](/modules/identity/auth) as `payments:read` ("Read your payments"), `payments:write` ("Resume your payments") and
`payments:manage` ("See recent payments and revenue", staff). Path builders: `paymentsApi` from
`@frigear-nu/payments/utils`.

### Staff authorization

`/api/admin/payments/recent` is guarded by the module's `paymentsStaff` guard: the `payments:manage` scope **and** an
allowing `payments:authorize` hook (denied by default; `payments:manage` is only offered to users the hook lets in). The
host decides, for example by following the users admin policy:

```ts
export default defineNitroPlugin((nitro) => {
  nitro.hooks.hook('payments:authorize', async (ctx) => {
    ctx.allowed = await canViewPayments(ctx.userId) // ctx.userId, never the session on ctx.event
  })
})
```

## Database

One `payments` table.

| Column                            | Type                    | Notes                                                       |
| --------------------------------- | ----------------------- | ----------------------------------------------------------- |
| `id`                              | text, primary key       | `pay_` + random id.                                         |
| `userId`                          | integer                 | Indexed. No foreign key to `users`.                         |
| `status`                          | text                    | `PaymentStatus`, default `pending`.                         |
| `amount`, `currency`              | integer, text           | Minor units.                                                |
| `description`                     | text, nullable          |                                                             |
| `referenceType`, `referenceId`    | text, nullable          | Indexed together.                                           |
| `checkoutSessionId`               | text, unique, nullable  | Follows the new session after a resume. Null for invoice payments. |
| `invoiceId`                       | text, unique, nullable  | Stripe invoice id for membership charges (see below).       |
| `paymentIntentId`                 | text, nullable          | Indexed.                                                    |
| `refundedAmount`                  | integer                 | Default 0.                                                  |
| `metadata`                        | JSON, nullable          | `Record<string, string>`.                                   |
| `items`                           | JSON, nullable          | `PaymentItem[]` the session was created from; null for older rows. |
| `paidAt`, `createdAt`, `updatedAt` | timestamps             |                                                             |

::warning
Generate and commit a migration in every host app and fixture that uses the module; see
[Database extensions](/guide/concepts/database-extensions).
::

## Membership payments

When `@frigear-nu/subscriptions` is installed next to this module, every membership invoice (`invoice.paid`,
`invoice.payment_failed`, `invoice.voided`, `invoice.marked_uncollectible`) is stored as a payment with
`referenceType: 'subscription'` and `referenceId` set to the Stripe subscription id. They appear in the admin user
Payments tab and Last payment card, fire the `payments:*` hooks (filter on `referenceType`) and are returned by the
`my-payments` MCP tool. Refunds are applied like any other payment through `charge.refunded`. Without this module,
`@frigear-nu/subscriptions` behaves as before and records nothing. Zero-amount invoices (trials, full discounts) are skipped, and only invoices
received after upgrading are stored.

`recordInvoicePayment(input: InvoicePaymentInput)` is the auto-imported server util behind this; it is idempotent per
invoice id.

## MCP

Set `settings.mcp: true` to expose `my-payments` (scope `payments:read`): the signed-in user's own payments, newest
first, with an optional `limit`. `amount` and `refundedAmount` are in whole currency units (`52.2` = 52.20), not minor units, and `currency` is upper-case.

## Translations

`da` and `en` locale files are registered with [Module Kit](/modules/platform/module-kit/i18n) under `payments.*`:
`payments.status.<status>` (one key per `PaymentStatus`), `payments.defaultDescription` and `payments.admin.*` for the
admin tab. API error messages stay English. Override keys in your app's `i18n/locales/<code>.json` (see
[overriding module strings](/modules/platform/module-kit/i18n#overriding-module-strings-in-your-app)):

```json
{ "payments": { "status": { "partially_refunded": "Partly refunded" } } }
```
