## App

All composables are auto-imported and can be overridden by re-declaring one of the same name in the app. This section
is server mode; client mode has its own [App](/modules/identity/auth/client-mode#app) section.

### Session, actions and the API

The same client API as [client mode](/modules/identity/auth/client-mode), so code that only reads `loggedIn` and `user`
runs in either app:

```ts
const { ready, loggedIn, user, fetch, clear } = useUserSession() // nuxt-auth-utils' own
const { status, authenticated, login, logout } = useAuth()
await login({ returnTo: '/orders' }) // the login page, with ?redirect=/orders
await logout() // POST /api/auth/logout, clears the session, then `/` (`redirect: false` stays, a string goes there)

const { data: orders } = await useApi<Order[]>('/api/shop/me/orders')
const me = await useNuxtApp().$api<Me>('/api/me')
```

| Name | Server mode |
| --- | --- |
| `useAuth()` | `status`, `authenticated`, `signingIn` (always `false`), `login({ returnTo? })`, `logout({ redirect? })`. `getAccessToken()` returns `null` (the cookie is the credential), `completeLogin()` throws and `isCallbackUrl()` returns `false`. `claims` and `getClient()` are client mode only. |
| `$api` | `$fetch` for the app's own API. During a server render it sends the incoming `Cookie` and `Authorization` headers along. |
| `useApi(url, options)` | `useFetch` through `$api`. |

`$api` sends the caller's credentials **only to this app**: a path (`/x`, not `//x`) or a URL on the request's own
origin, and a `baseURL` is checked the same way. Any other URL goes out without them.

- During a server render an own-origin URL is rewritten to its path, so the forwarded credentials stay in-process (the
  request's origin comes from the `Host` header, which a client can choose).
- Only `Cookie` and `Authorization` are forwarded, and never over a header the caller set (a service token in `headers`
  wins). They are attached after the caller's own `onRequest` hooks.
- A `401` from this app while signed in clears the session and goes to the login page with `?redirect=`.

An app must not provide its own `$api` plugin: Nuxt cannot define `$api` twice. Remove it and use Auth's.

### Redirects

Every redirect after signing in (`?redirect=`, `afterLogin`, magic-link redirects, `login({ returnTo })`,
`logout({ redirect })`) is followed only when it is a path on this site. The one check, `isSafeRedirect(value)` from
`@frigear-nu/auth/mode`, rejects anything not starting with `/`, `//host`, any backslash and ASCII control characters.
Authorization uses the same function for the `?redirect=` it passes along; its configured `redirectTo` may be an
absolute URL and is used as configured (`client.redirect.login` must be a path).

### Composables of the sign-in flows

```ts
const { login, pending, error, isEnabled, passwordLoginEnabled, passkeyLoginEnabled, oauthProviders } = useLogin()
await login({ email: 'ada@example.com', password: 'secret' })

const { register, pending, error, isEnabled } = useRegistration()
await register({ name: 'Ada', email: 'ada@example.com', password: 'secret' })

const { requestReset, resetPassword, pending, error, isEnabled } = usePasswordReset()
await requestReset({ email: 'ada@example.com' })
await resetPassword({ code, password, confirmPassword }) // signs the user in

const { sendMagicLink, pending, error, isEnabled } = useMagicLink()
await sendMagicLink({ email: 'ada@example.com', name: 'Ada', redirect: '/dashboard' }) // redirect: same-origin path

const { isEnabled, registerPasskey, authenticateWithPasskey, listPasskeys, removePasskey } = usePasskeys()
await registerPasskey(user.email, 'MacBook') // the name is optional
const passkeys = await listPasskeys() // [{ id, name, backedUp, transports, createdAt }], never the public key
await removePasskey(passkeys[0].id) // only the signed-in user's own (404 otherwise)

const { login: loginPath, register: registerPath } = useAuthPages() // '/login' by default
```

The module also registers the `AuthCard` component when a login or local register page is enabled.

## Anonymous paths

`runtimeConfig.public.authentication.publicPaths` lists the anonymous entry points Auth owns, as route patterns. In
server mode they are the login and register pages that are on, `/forgot-password` and `/reset-password` (with
`passwordReset`), `/auth/**` (the magic-link page, `/auth/frigear`, Users' email-change pages), `/api/auth/**` and
`/api/_auth/**` (nuxt-auth-utils' session endpoint). In client mode they are the login page and the callback.
[Authorization](/modules/identity/authorization#sign-in-paths) keeps them reachable under any less specific guard,
such as `'/**': { authenticated: true }`. Every handler under `/api/auth` that needs a user checks it itself.

## Hooks

| Hook | When | Payload |
| --- | --- | --- |
| `auth:scope-available` (Nitro) | A user's available token scopes are computed | `{ event, user: { id, role? }, scope, available }`: set `available = false` to hide |
| `auth:email` (Nitro) | A magic-link or verification email is about to be sent | `{ type, notification, data: { name, url } }` |
| `auth:resolvers`, `auth:scopes`, `auth:user-store` (Nuxt) | Build time, when the virtual modules are generated | See [Extending](/modules/identity/auth/server#extending-build-time) |
| `auth:signed-in`, `auth:signed-out`, `auth:refresh-failed`, `auth:user-failed` (app) | Client mode only | See [Client mode hooks](/modules/identity/auth/client-mode#hooks) |

## Routes

Registered with `addModuleRoutes` under `/api/auth`; `authApi` (`@frigear-nu/auth/utils`) builds every path, e.g.
`authApi.me.token(id)`. Errors carry `statusMessage` and a snake_case `data.code`; validation failures are h3's 400.
The OAuth callbacks (`/api/auth/<provider>`, `/auth/frigear`) are registered redirect URIs and never move.

| Method | Path | Auth | Status | Purpose |
| --- | --- | --- | --- | --- |
| `POST` | `/api/auth/logout` | none | 204 | Clears the session. The account menu's sign-out item posts here, then reloads `/`. |
| `POST` | `/api/auth/login` | none | 200 | Email/password login (`password`). `401 invalid_credentials`; `403 email_not_verified` with `verifyEmail`. |
| `POST` | `/api/auth/register` | none | 201 | `{ name (max 120), email, password }`. Returns `{ id, verificationRequired }`; `409 conflict` when the email is taken (`password`). |
| `POST` | `/api/auth/forgot-password` | none | 200 | Email a reset link for `email`. Always answers `{ ok: true }` (`passwordReset`). |
| `POST` | `/api/auth/reset-password` | none | 200 | Reset with `code`, `password`, `confirmPassword`, then sign in; `400 invalid_link` (`passwordReset`). |
| `POST` | `/api/auth/magic-link` | none | 200 | Email a single-use link. Always answers `{ ok: true }` (`magicLink`). |
| `POST` | `/api/auth/magic-link/confirm` | none (the code) | 200 | `{ code }`. Consume the link, verify the email, sign in. Returns `{ redirect }` (the link's internal redirect or `afterLogin`); `400 invalid_link` when invalid, used or expired (`magicLink` or `verifyEmail`). The emailed link `/auth/magic-link?code=` is a page that calls it. |
| `POST` | `/api/auth/webauthn/register` | session for existing users | 200 | Register a passkey. An unknown email creates the account; an existing one needs that user's session (`webAuthn`). |
| `POST` | `/api/auth/webauthn/authenticate` | none | 200 | Sign in with a passkey. Every failure (unknown email, no passkeys, unknown or unverified credential) is the same `401 invalid_credentials`. Only the error is unified: a known address with passkeys still gets its credential ids, so this does not prevent account enumeration; that needs discoverable (usernameless) passkeys (`webAuthn`). |
| `GET` | `/api/auth/me/passkeys` | session only | 200 | Your passkeys: `[{ id, name, backedUp, transports, createdAt }]`, never the public key (`webAuthn`). |
| `DELETE` | `/api/auth/me/passkeys/:id` | session only | 204 | Remove one of your passkeys; `404 not_found` for anyone else's (`webAuthn`). |
| `GET` | `/api/auth/me/tokens` | session only | 200 | Your tokens: `[{ id, name, prefix, last4, scopes, expiresAt, lastUsedAt, createdAt, status }]` (ISO dates). |
| `POST` | `/api/auth/me/tokens` | session only | 201 | Create `{ name, scopes, expiresInDays? }`. The plaintext `token` is in this response only; `400 unknown_scope`. |
| `DELETE` | `/api/auth/me/tokens/:id` | session only | 204 | Revoke; the row is kept for the audit trail. `404 not_found` for anyone else's. |
| `GET` | `/api/auth/scopes` | session only | 200 | The scopes that can be granted to you. |
| `GET` | `/api/auth/bootstrap?scope=<scope>` | session or token | 200 | An area's user-scoped data in one request (see [Module Kit](/modules/platform/module-kit)); `400 bad_request` without a `scope`, `404 not_found` for an unknown one. |
| `GET` | `/api/auth/providers` | none | 200 | The OAuth buttons for this request: `[{ key, to, label?, icon?, external? }]`. |
| `GET` | `/api/auth/<provider>` | none | 302 | OAuth login and callback through any nuxt-auth-utils provider; `404` until its credentials are set or with `oauth.<provider>: false`. |
| `GET` | `/auth/frigear` | none | 302 | Log in with frigear.nu, and its callback; `404` unless enabled (`oauth.frigear`). |
| `GET` | `/api/auth/frigear-status` | none | 200 | `{ enabled }`: whether "Log in with frigear.nu" is active (`oauth.frigear`). |

Magic and verification links expire after 2 hours and are consumed atomically.

## Database

None of the tables has a foreign key to `users` (this module sits below it); whoever deletes a user calls
`deleteUserAuthData(userId)`, as the users admin does.

| Table | Present when | Holds |
| --- | --- | --- |
| `auth_user_tokens` | always | Hashed user tokens: name, prefix, last 4, scopes, expiry, revoke and last-use timestamps. |
| `user_credentials` | `webAuthn` | One row per passkey. |
| `password_resets` | `passwordReset` | Unique reset `code` with `expiresAt` / `usedAt`. |
| `magic_links` | `magicLink` or `verifyEmail` | Unique single-use `code`, optional internal `redirectUrl`, `expiresAt` / `usedAt`. |
| `auth_oauth_tokens` | `keepTokens` on a provider | Encrypted access/refresh token, `tokenType`, `scopes`, `expiresAt`; unique per (`userId`, `provider`). |

It also adds `password`, `email_verified_at` and `last_login_at` to the `users` table owned by
[Users](/modules/identity/users) (ignored without it).

## Translations

The module registers `da` and `en` locale files under the `auth.*` namespace, read through `@nuxtjs/i18n`; without it
the English defaults are used. Override strings in your app's `i18n/locales/<code>.json`, see
[overriding module strings](/modules/platform/module-kit/i18n#overriding-module-strings-in-your-app):

```json
{ "auth": { "signIn": "Log in", "email": { "label": "Your email" } } }
```

Key groups: `signIn`, `signUp`, `signOut`, `signedInAs`, `signInToContinue`, `name.*`, `email.*`, `password.*`, `forgotPassword.*`,
`resetPassword.*`, `magicLink.*`, `verifyEmail.*`, `confirm.*`, `passkey.*`, `emailPassword.*`, `passkeys.*`,
`oauth.<provider>.label`, `menu.*`, `errors.*`, and `client.*` (client mode's login and callback pages).
