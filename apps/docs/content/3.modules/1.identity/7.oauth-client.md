---
title: OAuth Client
description: Sign users in from a browser SPA or a Capacitor app with OAuth 2.1 / OpenID Connect and PKCE, with rotating refresh tokens, secure token storage and an authorized $api.
---

This [Nuxt module](https://nuxt.com/docs/4.x/guide/modules) makes a Nuxt app an OAuth **public client**: it signs the
user in at an issuer with the authorization code flow and PKCE, keeps the tokens in the browser or the device's
Keychain / Keystore, refreshes them, and calls your API with the access token. It runs in a browser SPA and inside a
[Capacitor](https://capacitorjs.com) webview. The framework-agnostic core (`@frigear-nu/oauth-client/core`) works
anywhere with `fetch` and WebCrypto.

:module-runtime{client mobile}

::note
**Requires** [`@frigear-nu/module-kit`](/modules/platform/module-kit), which is installed automatically. `@nuxt/ui` is optional
and provides the `/login` and callback pages and `OAuthSignInButton`. In a Capacitor app also install `@capacitor/app`,
`@capacitor/browser` and `@aparajita/capacitor-secure-storage`.
::

The four OAuth-related modules split the work as follows; [Identity](/guide/concepts/identity) explains the whole picture.

| Module | Role | Where it runs |
| --- | --- | --- |
| [OAuth Server](/modules/identity/oauth-server) | The **issuer**: users sign in, apps are registered, tokens are issued. | The server of frigear.nu or your own. |
| `oauth-client` (this page) | The **app**: starts the sign-in, stores and refreshes the tokens, sends them to the API. | The browser or the phone. |
| [Frigear Resource](/modules/identity/frigear-resource) | The **resource server**: verifies the access token a service receives. | Each service the app calls. |
| [Mobile](/modules/interface/mobile) | The Capacitor shell. Installs this module when `oauthClient` is configured. | The phone. |

Any OpenID Connect provider works as issuer: see [Use your own OAuth server](/guide/going-further/own-oauth-server). For a
server-rendered web app with its own users use [Auth](/modules/identity/auth) (single sign-on) instead: this client keeps
tokens in the browser, so the server cannot know who is signed in.

## Quick setup

```bash
pnpm add @frigear-nu/oauth-client
# inside a Capacitor app also:
pnpm add @capacitor/app @capacitor/browser @capacitor/preferences @aparajita/capacitor-secure-storage
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxt/ui', '@frigear-nu/oauth-client'],
  ssr: false,
  oauthClient: {
    issuer: 'https://frigear.nu',
    clientId: 'my-app',
    scopes: ['openid', 'profile', 'email', 'offline_access'],
    apiBase: 'https://api.example.com', // default: the issuer
    native: { scheme: 'com.example.app' }, // redirect URI com.example.app:/auth/callback
    protect: 'all',
  },
})
```

Register a **public** client at the issuer with these exact redirect URIs:

- browser: `<origin>/auth/callback`, for example `http://localhost:3000/auth/callback`;
- native: `<scheme in lowercase>:/auth/callback`, for example `com.example.app:/auth/callback`.

The issuer must also allow the app's origins (`capacitor://localhost`, `https://localhost`, your dev origin) for CORS on
the token, revoke and userinfo endpoints. The full list is in [Use your own OAuth server](/guide/going-further/own-oauth-server).

```vue [app/pages/bills.vue]
<script setup lang="ts">
const { claims, logout } = useOAuth()
const { data: bills } = await useApi<Bill[]>('/api/bills')
</script>
```

## Options

| Option | Type | Default | Purpose |
| --- | --- | --- | --- |
| `issuer` | `string` | | Required (option or env). The issuer URL. |
| `clientId` | `string` | | Required (option or env). The public client's id. |
| `scopes` | `string[]` | `['openid']` | Requested scopes. Add `offline_access` for refresh tokens where the provider needs it. |
| `apiBase` | `string` | the issuer | Base URL of `$api` and `useApi`. |
| `redirectUri` | `string` | `<origin><callbackPath>` | The browser redirect URI. |
| `callbackPath` | `string` | `/auth/callback` | Path of the callback page and of the redirect URIs derived from it. |
| `native.scheme` | `string` | | Custom URL scheme, usually the app id. The redirect URI is `<scheme lowercase>:<callbackPath>`. An invalid scheme (for example with `_`) fails the build. |
| `native.redirectUri` | `string` | | A full native redirect URI instead, for example a claimed `https` universal link. |
| `endpoints` | `Partial<OAuthEndpoints>` | discovered | `authorization`, `token`, `revocation`, `userinfo` and more; absolute or relative to the issuer. Win over discovery. |
| `discovery` | `boolean` | `true` | OpenID Connect discovery (`openid-configuration`, falling back to RFC 8414). `false` uses the [OAuth Server](/modules/identity/oauth-server) paths (`/oauth/authorize`, ...). |
| `authorizationParams` | `Record<string, string>` | `{}` | Extra authorization request parameters (`prompt`, `audience`, ...). |
| `storage` | `StorageOption` | `auto` | Where tokens live: `auto`, `secure`, `preferences`, `local`, `session`, `memory`, or a file path. See [Token storage](#token-storage). |
| `pages.login` | `boolean \| string` | `true` | The `/login` page (needs `@nuxt/ui`). A string sets another path, `false` none. |
| `pages.callback` | `boolean` | `true` | The callback page (needs `@nuxt/ui`). |
| `protect` | `'none' \| 'all'` | `none` | `all`: every page needs a signed-in user except `publicPaths`, the login and callback pages. |
| `publicPaths` | `string[]` | `[]` | Reachable signed out with `protect: 'all'`. `'/docs/**'` matches `/docs` and everything below. |
| `redirect.login` | `string` | the login page | Where signed-out visitors of a protected page go. |
| `redirect.afterLogin` | `string` | `/` | After a sign-in that started without a `returnTo`. |
| `redirect.afterLogout` | `string` | the login page with `protect: 'all'`, else `/` | After `logout()`. |
| `api.attachTo` | `string[]` | the `apiBase` and issuer origins | Origins that get the bearer token. Any other origin gets none. |
| `api.onUnauthorized` | `'signOut' \| 'none'` | `signOut` | What a `401` that a forced refresh did not fix does: sign out and go to the login page, or only throw. |
| `dev.rewriteLoopback` | `boolean \| string` | `true` | In development on a device, `localhost` in the issuer and `apiBase` becomes the host the app was loaded from. A string sets the host. |
| `allowClientSecretInBundle` | `boolean` | `false` | Allow a build that embeds a client secret. See [Security](#security). |

Branding of the login page goes in `app.config.ts`:

```ts [app/app.config.ts]
export default defineAppConfig({
  oauthClient: {
    login: { title: 'Household bills', description: 'Sign in to continue.', logo: '/logo.svg', icon: 'i-lucide-wallet' },
  },
})
```

`logo` is an image path or `{ light, dark }`; `icon` shows when there is no logo.

### Environment variables

Runtime config is `runtimeConfig.public.oauthClient`; the host's own values win over the module options.

| Variable | Option |
| --- | --- |
| `NUXT_PUBLIC_OAUTH_CLIENT_ISSUER` | `issuer` |
| `NUXT_PUBLIC_OAUTH_CLIENT_CLIENT_ID` | `clientId` |
| `NUXT_PUBLIC_OAUTH_CLIENT_SCOPE` | `scopes`, as a space separated string |
| `NUXT_PUBLIC_OAUTH_CLIENT_API_BASE` | `apiBase` |
| `NUXT_PUBLIC_OAUTH_CLIENT_REDIRECT_URI` | `redirectUri` (browser) |
| `NUXT_PUBLIC_OAUTH_CLIENT_NATIVE_REDIRECT_URI` | `nativeRedirectUri` |
| `NUXT_PUBLIC_OAUTH_CLIENT_SECRET` | Development only, against a confidential client. See [Security](#security). |

Lists set in `runtimeConfig.public.oauthClient` (`publicPaths`, `api.attachTo`) replace the module's.

### Token storage

The `storage` option decides where tokens live; `auto` uses the Keychain / Keystore
(`@aparajita/capacitor-secure-storage`) on a device.

| Value | Where |
| --- | --- |
| `auto` | Secure storage on a device, `localStorage` in a browser. |
| `secure` | Keychain / Keystore; required on a device. |
| `preferences` | `@capacitor/preferences` (UserDefaults / SharedPreferences, not encrypted). |
| `local` / `session` | `localStorage` / `sessionStorage`. |
| `memory` | Signed out on every reload. |
| a file path | A file whose default export is a `TokenStorage` or a function returning one. |

An app with `@capacitor/core` but without the secure storage plugin **fails a production build** with `auto`: the tokens
would sit unencrypted. Install the plugin, or set `storage: 'preferences'` to accept that. On a device an install marker
wipes tokens that survived a reinstall.

## App

```ts
const { status, authenticated, claims, signingIn, login, completeLogin, logout, getAccessToken, isCallbackUrl, getClient } = useOAuth()
const { data } = await useApi<Bill[]>('/api/bills') // client only (`server: false`) by default
const me = await useNuxtApp().$api<User>('/api/me')
```

| Name | What it is |
| --- | --- |
| `useOAuth()` | `status` (`unknown`, `signed-in`, `signed-out`), `authenticated`, `claims` (the id_token claims), `signingIn`, and `login({ returnTo?, params? })`, `completeLogin(url?)`, `logout({ redirect? })`, `getAccessToken()` (refreshed when needed, `null` signed out or on the server), `isCallbackUrl(url)` and `getClient()` (the core client). |
| `useApi(url, options)` | `useFetch` through `$api`, client only by default. |
| `$api` | `$fetch` with the bearer token for `api.attachTo` origins, and one forced refresh and retry on `401`. |
| `<OAuthSignInButton return-to="/bills" />` | A sign-in button (needs `@nuxt/ui`). |
| `/login`, `/auth/callback` | Pages (need `@nuxt/ui`). A page of the app at the same path wins. |
| `oauth` route middleware | Global. Redirects signed-out visitors of protected pages to `redirect.login`. |

Page meta decides what is protected:

```ts
definePageMeta({ oauth: false }) // public with `protect: 'all'`
definePageMeta({ oauth: true }) // protected with `protect: 'none'`
```

With SSR on the server renders signed out (`status: 'unknown'`): render signed-in content in `<ClientOnly>`, or use
`ssr: false`.

Inside a native app the plugin completes sign-ins from the cold-start URL (`App.getLaunchUrl()`) and from `appUrlOpen`
(callback URLs only: other deep links are left alone), and refreshes the tokens on `resume`.

## Hooks

Runtime hooks, called on the client with `useNuxtApp().hook(...)`:

| Hook | Payload | When |
| --- | --- | --- |
| `oauth:signed-in` | `{ claims }` | After a sign-in completed. |
| `oauth:signed-out` | `{ reason }` | After the session ended: `logout`, a rejected refresh token, or the API refusing the tokens. |
| `oauth:refresh-failed` | `{ error }` | A refresh failed but the session was kept (offline, server error, misconfigured client). |

## Security

- **PKCE (S256), `state`, `nonce` and the `iss` check.** There is no client secret. Pending sign-ins are keyed by `state`,
  so a forged callback is ignored and never cancels a real sign-in, and two tabs can sign in at once. An authorization
  response with a wrong `iss` is rejected (RFC 9207).
- **id_token checks.** `iss`, `aud` / `azp`, `sub` and `nonce`, not the device clock. A refreshed id_token that fails them
  keeps the previous claims; the rotated tokens are always stored. Signatures are not verified: the token comes straight
  from the token endpoint over TLS (OpenID Connect Core 3.1.3.7). Resource servers must verify access tokens themselves,
  as [Frigear Resource](/modules/identity/frigear-resource) does.
- **Refresh rotation.** One refresh runs at a time (single-flight in the page, Web Locks across tabs), and the stored
  tokens are re-read under the lock so a tab never reuses a rotated token. A refresh token that was not rotated is kept.
- **Errors by kind.** `session` (an explicit `invalid_grant` or similar: signed out), `config` (`invalid_client`,
  issuer mismatch), `transient` (network, timeouts, `429`, `5xx`, a `4xx` without an OAuth error body: the session is
  kept) and `authorization` (a failed sign-in). Every request to the issuer times out after 15 seconds.
- **Bearer tokens go to allowed origins only** (`api.attachTo`).
- **Secret guard.** `NUXT_PUBLIC_OAUTH_CLIENT_SECRET` is for `nuxt dev` against a confidential client. A production build
  that would embed a secret fails (`allowClientSecretInBundle: true` overrides this for throwaway builds). Outside
  development `clientSecret` is not declared at all, so a runtime env var cannot reach server-rendered pages.

## Without Nuxt

```ts
import { createOAuthClient, webStorage } from '@frigear-nu/oauth-client/core'

const client = createOAuthClient({
  issuer: 'https://frigear.nu',
  clientId: 'my-app',
  redirectUri: `${location.origin}/callback`,
  scope: 'openid offline_access',
  storage: webStorage(),
  attachTo: ['https://api.example.com'],
})
await client.authorize() // redirects
// on /callback:
const { returnTo } = await client.handleCallback(location.href)
const response = await client.fetch('https://api.example.com/me')
```

A Capacitor app without Nuxt uses `createCapacitorOAuthClient` and `onCapacitorCallback` from
`@frigear-nu/oauth-client/capacitor`. `TokenStorage` and `AuthorizationUserAgent` are the extension points for another
secure storage or an `ASWebAuthenticationSession` user agent.
