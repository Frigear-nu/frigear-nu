title: Grants
description: Who may see a record, as a list of grants where any one admits, with a registry of grant kinds that modules extend.

Grants decides who may see a record. A record stores a list of grants in one JSON column, `grants`, and any one grant
in the list lets a person in:

```json
[
  { "kind": "role", "role": "admin" },
  { "kind": "team", "teamId": "tem_123", "minRole": "lead" }
]
```

Each grant has a `kind`. Grants ships two kinds, `public` and `role`, and other modules register their own, such as
`team` (Teams) and `operation` (Operations). The package owns only the registry, the list and the rules below; it knows
nothing about teams or operations. For the permissions code checks, use [Authorization](/modules/identity/authorization).

## The rules

- **Any one grant admits.** A person who matches one grant of the list sees the record.
- **An empty list means nobody.** `[]` is never "every signed-in user". Staff routes still show the record to staff.
- **An unknown kind fails closed.** A grant of a kind no installed module registers, or a grant its kind's schema
  rejects, admits nobody. The rest of the list still counts.
- **Anonymous callers only through `public`.** A `public` grant admits everyone, signed in or not. Every other kind
  needs a signed-in user.

## What you get

- **Composables and helpers** (auto-imported on the server):
  - `grantsCanRead(event, permission, record)` serves a record to the caller (see [Reading a record](#reading-a-record)).
  - `grantsMatch(event, user, grants)` decides one list for one user, for a policy or for another user than the caller.
  - `grantsMembers(event, grants)` lists the user ids a list stands for.
  - `grantsValidate(event, grants, { stored })` checks a submitted list: every kind known, every grant valid, and what
    the grants point at exists (a team, an operation). It returns the list to store. `grantsListSchema()` is the same
    check without the references, as a zod schema.
  - `grantsRead(value)` reads a stored column: anything but an array is the empty list.
- **Components**: `<GrantsEditor v-model="grants" />` edits a list. Each kind brings its own fields.
- **Build-time helper**: `extendGrants(nuxt, kind)` from `@frigear-nu/grants/utils` registers a kind.
- **Framework-free helpers** in `@frigear-nu/grants/core`: `defineGrantKind`, `grantListShape` (the shape of a list,
  for request schemas), `chunkGrantParams`, `readGrants` and `hasPublicGrant`.

## Quick setup

::steps

### Install Grants

```bash
pnpm add @frigear-nu/grants
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxthub/core', '@frigear-nu/grants'],
})
```

### Store a list

Add a `grants` JSON column to your table, in both dialects.

```ts [schema.sqlite.ts]
grants: text({ mode: 'json' }).$type<Array<{ kind: string } & Record<string, unknown>>>().notNull().default([]),
```

```ts [schema.postgresql.ts]
grants: jsonb().$type<Array<{ kind: string } & Record<string, unknown>>>().notNull().default([]),
```

### Guard reads with a permission and a policy

Declare a read permission, and a policy on it that evaluates the record's grants. Access then goes through
`authorize()` like every other check: roles, token scopes, `authorization:before` and the policy.

```ts [src/runtime/access.ts]
export const notesAccess = defineAccess('notes', {
  permissions: {
    read: { label: 'Read notes', description: 'Read the notes you are granted.', implicit: true },
  },
})
```

```ts [src/runtime/server/policies.ts]
export default [
  definePolicy<{ grants: unknown }>('notes:read', ({ event, user, record }) =>
    record ? grantsMatch(event, user, record.grants) : undefined),
]
```

## Reading a record

Serve a record with `grantsCanRead`:

```ts [server/api/notes/[id].get.ts]
export default defineEventHandler(async (event) => {
  const { id } = await getValidatedRouterParams(event, idParams().parse)
  const note = await findNote(id)
  if (!note || !(await grantsCanRead(event, 'notes:read', note))) throw notFound('Note not found.')
  return toNoteDto(note)
})
```

`grantsCanRead` is the only place anonymous access lives:

- A record whose list holds a `public` grant is served to everyone, without sign-in.
- Every other record goes through `allows(event, permission, record)`. An anonymous caller is never allowed, and a
  token needs the read permission in its scopes.

Call it; never re-implement the `public` shortcut in a module. A list route filters with it, and a single-record route
answers the same 404 for a record that does not exist and one the caller may not read.

A record inside a parent (an FAQ item in its group) checks both: the parent, and the child unless the child has no list
of its own (`null`) and inherits the parent.

## Editing a list

```vue
<GrantsEditor v-model="state.grants" />
<GrantsEditor v-model="state.grants" :kinds="['role', 'team']" />
```

The editor shows each grant with its kind's fields, a remove button, and an "Add" menu with every registered kind.
`kinds` limits the menu (a mailbox leaves out `public`). It says "Nobody sees it yet" while the list is empty.

Give the request schema the shape of a list, and check the list in the handler before storing it:

```ts
import { grantListShape } from '@frigear-nu/grants/core'

const body = await readValidatedBody(event, z.object({ grants: grantListShape }).parse)
const grants = await grantsValidate(event, body.grants, { stored: existing?.grants })
```

`grantsValidate` answers `400 validation_failed` with one issue per bad grant (`grants.<index>`). It skips the
reference check for grants that are already stored, so a record whose team was deleted can still be edited.

## Built-in kinds

| Kind | Keys | Admits | `members` |
| --- | --- | --- | --- |
| `public` | none | Everyone, anonymous callers included. | Nobody: a public audience cannot be listed. |
| `role` | `role` | Signed-in users holding the global role (auth's effective roles, inheritance included). | Users with the role (or a role inheriting it) assigned in [Authorization](/modules/identity/authorization), checked against their effective roles. |

A role given only through `defaultRoles`, an `auto` role or the `authorization:roles` hook cannot be listed, so `members`
leaves its holders out. `matches` still admits them.

## Adding a kind

A kind is a server file and, optionally, a field component. Register it from your module's `setup()`:

```ts [src/module.ts]
import { extendGrants } from '@frigear-nu/grants/utils'

extendGrants(nuxt, {
  kind: 'shift',
  label: 'Shift',
  labelKey: 'shifts.grants.shift',
  icon: 'i-lucide-calendar-clock',
  server: resolver.resolve('./runtime/server/grants/shift'),
  field: resolver.resolve('./runtime/app/grants/ShiftGrantField.vue'),
  defaults: { shiftId: '' },
})
```

The server file exports `defineGrantKind`:

```ts [src/runtime/server/grants/shift.ts]
import { z } from 'zod'
import { chunkGrantParams, defineGrantKind } from '@frigear-nu/grants/core'

export default defineGrantKind<{ kind: 'shift', shiftId: string }>('shift', {
  schema: z.strictObject({ kind: z.literal('shift'), shiftId: z.string().min(1) }),
  matches: ({ event, user, grant }) => !!user && isOnShift(event, user.id, grant.shiftId),
  async members({ grants }) {
    const ids: number[] = []
    for (const chunk of chunkGrantParams(grants.map(grant => grant.shiftId))) ids.push(...await shiftUserIds(chunk))
    return ids
  },
  validate: async ({ grant }) => (await findShift(grant.shiftId)) ? undefined : 'This shift does not exist.',
})
```

| Part | Contract |
| --- | --- |
| `schema` | A strict zod object with `kind` as a literal. A grant it rejects admits nobody. |
| `matches({ event, user, grant })` | Does this user match this grant? `user` is never `null` except for `public`. Cache per request what you look up. |
| `members({ event, grants })` | Who matches any of `grants` (every grant of this kind in the list, in one call)? Return user ids. Keep each query under D1's 100 bound parameters: cut lists with `chunkGrantParams` (90 per query). |
| `validate({ event, grant })` | Optional. Return a message to refuse a grant before it is stored. |

A kind that throws in `matches` or `members` admits or lists nobody, and the error is logged. The field component
receives the grant as `v-model` and a `disabled` prop, and emits a whole new grant object.
