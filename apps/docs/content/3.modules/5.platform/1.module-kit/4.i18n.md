---
title: Module Kit translations
description: Register module locale files and let host apps override module strings.
---

Modules ship their own translations as one JSON file per locale and contribute them to `@nuxtjs/i18n`, which merges
every registered file per locale into one message tree. Namespace keys by module (`users.*`, `events.*`, ...) so slices
never collide; `@:path` links can reference keys from any slice.

| Helper | Signature | Purpose |
| --- | --- | --- |
| `registerLocales` | `(nuxt: Nuxt, langDir: string, codes?: string[]) => void` | Registers `<langDir>/<code>.json` for each code (default `da`, `en`). Missing files are skipped; does nothing without `@nuxtjs/i18n`. |
| `useModuleT` | `(namespace: string) => (key: string, fallback: string, params?: Record<string, string \| number>) => string` | Auto-imported composable for module UI that must work without i18n. Resolves `<namespace>.<key>` when the key exists, otherwise returns the English `fallback`. `{param}` placeholders are replaced either way. |

```ts
// in setup(options, nuxt)
registerLocales(nuxt, resolver.resolve('./runtime/i18n/lang')) // reads da.json / en.json
```

```ts
const t = useModuleT('events')
t('ongoing.title', 'Happening now')
t('detail.tickets.atLeastOneProductRequired', '{addonTitle} is required.', { addonTitle })
```

## Overriding module strings in your app

Every module that ships translations can be overridden the same way, with no module option. Redefine the key in your
app's own `i18n/locales/<code>.json`:

```json
{
  "payments": {
    "status": { "paid": "Payment received" }
  },
  "forms": {
    "actions": { "submit": "Send inquiry" }
  }
}
```

- Keys are namespaced by module. A module's full key list is its `src/runtime/i18n/lang/en.json`.
- Only list what you change: messages are deep-merged, so the rest keep the module's text.
- Your app wins. `@nuxtjs/i18n` merges module slices first, then extended layers, then your project's files last.
  Overrides therefore work for every locale, including ones a module does not ship.
- Keep parameters such as `{date}` or `{plan}` in your text; the component supplies them.
- Without `@nuxtjs/i18n`, nothing is registered and components use their English fallbacks.
