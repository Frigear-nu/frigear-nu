`@frigear-nu/module-kit/server` holds what every module route needs, so routes answer the same way everywhere (see
[HTTP route conventions](/guide/best-practices/http-routes)). Import it explicitly: it is not
auto-imported, so nothing clashes with h3's own helpers.

## Registering routes

`addModuleRoutes` (from `/utils`) registers a module's routes from one table in `setup()`. `file` is relative to
`./runtime/server/routes/`; `path` is joined onto `base` (required), and a path starting with `/` ignores `base` (as with
`moduleApiUrl`); `''` is `base` itself.

```ts
import { addModuleRoutes } from '@frigear-nu/module-kit/utils'

addModuleRoutes(resolver, [
  { method: 'get', path: '', file: 'admin/events.get' },
  { method: 'post', path: '', file: 'admin/events.post' },
  { method: 'get', path: ':id', file: 'admin/event.get' },
  { method: 'patch', path: ':id', file: 'admin/event.patch' },
  { method: 'post', path: ':id/clone', file: 'admin/event-clone.post' },
  { method: 'get', path: '/api/events/me/tickets', file: 'me/tickets.get' },
], { base: '/api/admin/events' })
```

## Errors

| Helper | Status | `data.code` |
| --- | --- | --- |
| `apiError(status, code, message, data?)` | any | `code` |
| `badRequest(message?, data?)` | 400 | `bad_request` |
| `validationError(issues, message?)` | 400 | `validation_failed`, issues in `data.issues` |
| `forbidden(message?, data?)` | 403 | `forbidden` |
| `notFound(message?, data?)` | 404 | `not_found` |
| `conflict(message?, data?)` | 409 | `conflict` |
| `notConfigured(message?, data?)` | 501 | `not_configured` |

Each returns an h3 error to `throw`: `statusMessage` is the human message (what `errorMessage()` in `@frigear-nu/ui`
shows in a toast), `data` is `{ ...data, code }` (`ApiErrorData`). `requireAuth` answers the same way, with the codes
`unauthorized`, `session_required` and `insufficient_scope`.

```ts
import { conflict, notFound } from '@frigear-nu/module-kit/server'

if (!form) throw notFound('Form not found.')
if (await slugTaken(body.slug)) throw conflict('That slug is taken.', { field: 'slug' })
```

## Params

`idParams(name = 'id')` (a non-empty string) and `intIdParams(name = 'id')` (a positive integer, coerced) are zod
schemas for `getValidatedRouterParams`, so ids are validated the same way in every module.

```ts
const { id } = await getValidatedRouterParams(event, idParams().parse)
const { tokenId } = await getValidatedRouterParams(event, idParams('tokenId').parse)
const { id: userId } = await getValidatedRouterParams(event, intIdParams().parse)
```

## Pagination

`pageQuery({ sort, defaultSort?, defaultOrder?, defaultPageSize?, maxPageSize?, filters? })` returns the zod schema of
a list query in the vocabulary of `useTableQuery`: `page` (from 1), `pageSize` (default 20, at most 100), `q`, `sort`
(one of `sort`, default `defaultSort` or the first), `order` (`asc`/`desc`, default `desc`) and the `filters` keys.
`paginate({ items, total, query })` returns `Page<T>`, `{ items, total, page, pageSize }`, and `pageRange(query)` the
`{ limit, offset }`. `orderByQuery(columns, query, { tiebreaker })` turns `query.sort`/`query.order` into an
`orderBy` (a sort key mapped to `undefined` falls back to the tiebreaker), with the tiebreaker (usually the id)
descending so pages stay stable. `escapeLike`, `likeEscaped(column, pattern)` and `likeContains(column, value)` search
case-insensitively with `lower(...) LIKE lower(...)` on both dialects, without letting `%` and `_` in the search act as
wildcards.

```ts
import { likeContains, orderByQuery, pageQuery, pageRange, paginate } from '@frigear-nu/module-kit/server'

const listQuery = pageQuery({ sort: ['startsAt', 'slug'], filters: { status: z.enum(['draft', 'published']).optional() } })

export default defineEventHandler(async (event) => {
  await eventsStaff.require(event)
  const query = await getValidatedQuery(event, listQuery.parse)
  const where = and(
    query.q ? likeContains(schema.events.slug, query.q) : undefined,
    query.status ? eq(schema.events.status, query.status) : undefined,
  )
  const orderBy = orderByQuery({ startsAt: schema.events.startsAt, slug: schema.events.slug }, query, { tiebreaker: schema.events.id })
  const { limit, offset } = pageRange(query)
  const [rows, [totals]] = await Promise.all([
    db.select().from(schema.events).where(where).orderBy(...orderBy).limit(limit).offset(offset),
    db.select({ total: count() }).from(schema.events).where(where),
  ])
  return paginate({ items: rows.map(toEventDto), total: totals?.total ?? 0, query })
})
```

## Responses and helpers

| Helper | Purpose |
| --- | --- |
| `created(event, dto)` | Sets 201 and returns `dto`. |
| `noContent(event)` | Sets 204 and returns `null`, for deletes and revokes. |
| `isoDate(value)` | A `Date`, epoch milliseconds or date string as an ISO string; `null`/`undefined` as `null`. |
| `uniqueCopySlug(base, exists)` | The first free `<base>-copy`, `<base>-copy-2`, ... `exists(slug)` may return any truthy value for taken. |
| `resolveSameOriginUrl(event, url, { fallback?, name? })` | A client-supplied return URL as an absolute URL on the request's origin; `fallback` (a path) when `url` is empty; 400 `bad_request` when it points elsewhere. |
| `sameOriginUrl(input, origin)` | The check behind it, without an event: the normalised absolute URL (`URL.href`), or `null`. |
| `applyBearerCors(event, options)` | CORS for bearer callers on other origins, see [Bearer CORS](#bearer-cors). |
| `matchesPathPrefix(pathname, prefixes)` | Whether a path is under one of the prefixes: `/api/` matches `/api` and `/api/x`, not `/apis`. |

## Bearer CORS

A browser app on another origin (the `capacitor://localhost` webview of a mobile app, a single-page app) that calls the
API with an access token needs CORS headers, but must never get cookies cross-origin. `applyBearerCors` adds exactly
that, from a middleware, for the paths you choose:

```ts
// server/middleware/api-cors.ts
import { applyBearerCors, matchesPathPrefix } from '@frigear-nu/module-kit/server'

export default defineEventHandler((event) => {
  if (!matchesPathPrefix(getRequestURL(event).pathname, ['/api/'])) return
  const preflight = applyBearerCors(event, {
    origins: ['capacitor://localhost', 'https://localhost'],
    methods: ['GET', 'POST', 'PATCH', 'DELETE', 'OPTIONS'],
    allowHeaders: ['authorization', 'content-type', 'accept'],
    exposeHeaders: ['www-authenticate'],
  })
  if (preflight) return ''
})
```

| Option | Default | Header |
| --- | --- | --- |
| `origins` | (required) | `Access-Control-Allow-Origin`: the request's `Origin` when it is listed exactly. `*` never matches. |
| `methods` | (required) | `Access-Control-Allow-Methods` (an array or a ready string). |
| `allowHeaders` | `authorization, content-type` | `Access-Control-Allow-Headers`. |
| `exposeHeaders` | none | `Access-Control-Expose-Headers`, e.g. `www-authenticate`. |
| `maxAge` | `600` | `Access-Control-Max-Age` in seconds. |

It always appends `Vary: Origin` (responses differ per origin, so caches must key on it), sets the CORS headers only for a
listed origin, never sends `Access-Control-Allow-Credentials`, and answers an `OPTIONS` request from a listed origin with
`204`, returning `true` so the middleware ends it. Everything else returns `false` and the request continues. The OAuth
server (`cors.paths`) and [Frigear resource](/modules/identity/frigear-resource#cors) use it.

## Field issues

h3's `readValidatedBody(event, schema.parse)` answers a failed parse with a 400 whose `data` carries the zod error only
as text. When the client needs per-field issues (a form that marks each input), parse yourself with `schema.safeParse`
and throw `validationError(issues)`; the issues arrive in `data.issues`. Forms `submit` is the example:

```ts
const result = definition.schema.safeParse(await readBody(event))
if (!result.success) throw validationError(result.error.issues)
```

## Naming server utils

Every module's `server/utils` is auto-imported into one Nitro namespace, so an exported name must be unique across all
modules: prefix it with the module (`toFormTokenDto`, `toAuthTokenDto`, never a generic `toTokenDto`). Two modules
exporting the same name clash and one silently wins.

## Path builders

Each module keeps typed path builders in `src/runtime/utils/api.ts` (`authApi`, `eventsApi`, `formsApi`, ...) and
exports them as `@frigear-nu/<pkg>/api`. Import them from there in app code and tests, not from `./utils`: the `./utils`
entry also holds build-time helpers that pull in `@nuxt/kit`. Relative imports inside the package stay relative.

```ts
import { authApi } from '@frigear-nu/auth/api'
```

## Testing routes

`@frigear-nu/module-kit/testing` has two helpers for e2e tests against a fixture started with `setup()` from
`@nuxt/test-utils/e2e`:

- `apiClient({ cookie?, bearer? })` acts as one caller. `json<T>(method, path, body?)` resolves with the parsed body
  of a 2xx response (`null` for 204) and rejects otherwise; `fetch(method, path, body?)` resolves with the raw
  `Response` whatever its status.
- `expectApiError(promise, status, code?)` asserts that the request of either failed with `status` (and `data.code`),
  and resolves with the error body.

```ts
import { apiClient, expectApiError } from '@frigear-nu/module-kit/testing'

const staff = apiClient({ cookie: staffCookie })
const created = await staff.json<{ id: string }>('POST', '/api/admin/events', { slug: 'party' })
await expectApiError(apiClient({ cookie: memberCookie }).json('DELETE', `/api/admin/events/${created.id}`), 403, 'forbidden')
expect((await staff.fetch('DELETE', `/api/admin/events/${created.id}`)).status).toBe(204)
```
