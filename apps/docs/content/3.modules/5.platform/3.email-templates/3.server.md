`sendEmailTemplate` and `renderEmailTemplate` are auto-imported in server code.

```ts
await sendEmailTemplate('welcome', { name: user.name, url }, {
  to: user.email,
  replyTo: 'support@frigear.nu',
})
```

| Function | Signature |
| --- | --- |
| `sendEmailTemplate` | `(name, props, message) => Promise<void>`. Renders, then sends with `dispatchEmailNotification`. |
| `renderEmailTemplate` | `(name, props, { locale?, text? }) => Promise<{ subject?, body, text? }>`. Renders without sending. |

`message` is an `EmailNotification` without `body` (`to`, `replyTo`, `meta`), plus:

| Field | Purpose |
| --- | --- |
| `subject` | Overrides the template's `<ESubject>`. Required when the template has none. |
| `text` | Your own plain-text body, or `false` to send HTML only. By default it is rendered from the template. |
| `locale` | Locale to render with, when `@nuxtjs/i18n` is installed. |

The template names are typed, and so are each template's props. Both are generated into
`.nuxt/types/email-templates.d.ts` from every template the renderer will see, so a misspelled name or a missing prop
does not compile. Adding or removing a template in dev regenerates them.

## Bundle and runtime notes

- Rendering bundles Vue SSR and the template components into the Nitro server. Templates that a published module
  ships are inlined, so the Vue plugin compiles them.
- nuxt-email-renderer has no option for template directories outside the layers. This module therefore rebuilds its
  `#email-templates` virtual module with the module templates added underneath. It does not work with
  `experimental.nitroViteEnvironment` yet: in that mode the renderer only compiles `.vue` files from the layer
  directories.
