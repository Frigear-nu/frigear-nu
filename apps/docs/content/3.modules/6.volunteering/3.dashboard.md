---
title: Dashboard
description: Lets modules put cards on a named dashboard, such as the volunteer home screen, and lets each user reorder, hide and collapse them.
---

Dashboard gives your app pages of cards that other modules fill. A shifts module adds "Your next shift" to the
volunteer home screen, an FAQ module adds "Latest answers", and neither knows the page. Each user can reorder, hide and
collapse the cards, and the layout follows them across devices. For a single area that only your own code fills, use
[Widget](/modules/interface/widget) directly instead.

The package is `@frigear-nu/dashboard`. A dashboard has a dotted name, such as `crew.home`. It is a
[registry](/guide/concepts/glossary) on top of Widget: each dashboard is the [widget area](/guide/concepts/glossary)
`dashboard.<name>`, plus a title and the platforms of each item.

## What you get

- **Components** (on by default): `<Dashboard>` draws a dashboard in a responsive grid, with an edit mode to move, hide
  and show items. `DashboardGrid`, `DashboardItem`, `ChartCard`, `ActionCard` and `EmptyCard` are the building blocks.
- **Composables and helpers** (on by default): `useDashboard` reads a dashboard for a page that lays it out itself,
  `useDashboardItem` gives an item its loading, error, collapsed and settings state, and `extendDashboard` adds items
  from a module.
- **Per-user layout** (on with Preferences): the order, hidden and collapsed items and item settings are saved as the
  `dashboardLayouts` preference.
- **Mobile Home tab** (on with Mobile): a Home tab at `/crew` that draws `crew.home`.

An item's component loads only when its dashboard is drawn.

:module-runtime{client mobile}

::note
**Installed for you:** [`@frigear-nu/widget`](/modules/interface/widget), [`@frigear-nu/ui`](/modules/interface/ui) and
[`@frigear-nu/module-kit`](/modules/platform/module-kit).

**You add:** nothing else.

**Optional:** [`@frigear-nu/preferences`](/modules/identity/preferences) to save each user's layout,
[`@frigear-nu/mobile`](/modules/interface/mobile) for the Home tab, and `@nuxtjs/i18n` to translate titles.
::

## Quick setup

::steps

### Install Dashboard

```bash
pnpm add @frigear-nu/dashboard
```

### Add it to nuxt.config.ts

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@frigear-nu/dashboard'],
})
```

### Draw a dashboard

On the web, put the dashboard on a page yourself. Dashboard adds no web page.

```vue [app/pages/crew/index.vue]
<template>
  <div class="flex flex-col gap-4">
    <PageHeading title="Home" />
    <Dashboard name="crew.home" />
  </div>
</template>
```

::

::callout{color="success" icon="i-lucide-check"}
**What you should see:** "Nothing here yet" until a module calls `extendDashboard(nuxt, 'crew.home', …)`. Then its
items appear in the grid, with a **Customise dashboard** button above them.
::

## Options

Options go under the `dashboard` key.

| Option | Type | Default | Purpose |
| --- | --- | --- | --- |
| `homeTab` | `object \| false` | `{ dashboard: 'crew.home', path: '/crew' }` | The Home tab, with Mobile installed. `false` turns it off. |
| `homeTab.dashboard` | `string` | `'crew.home'` | The dashboard the tab draws. |
| `homeTab.path` | `string` | `'/crew'` | The path of the tab's page. |
| `homeTab.label` | `string` | `'Home'` | The tab label. Without it the label is translated (`dashboard.home.label`). |
| `homeTab.icon` | `string` | `'i-lucide-house'` | The icon of the web tab bar. The native iOS tab uses the SF Symbol `house`. |

**`homeTab`.** With [Mobile](/modules/interface/mobile) installed, Dashboard registers a page at `path` that draws the
dashboard, and adds the tab `home` with `order: 0` and `requiresAuth: true`. A page of your own at the same path wins.
Without Mobile, nothing is registered.

## App

Your app draws dashboards with the components, or lays one out itself with `useDashboard`. Module authors add items
with `extendDashboard`.

### Add items from a module

Call `extendDashboard` in your module's `setup()`, only when Dashboard is installed. The order between modules does not
matter.

```ts [module.ts]
import { createResolver, defineNuxtModule, hasNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: { name: '@frigear-nu/shifts' },
  async setup(_options, nuxt) {
    const resolver = createResolver(import.meta.url)

    if (hasNuxtModule('@frigear-nu/dashboard')) {
      const { extendDashboard } = await import('@frigear-nu/dashboard/utils')
      extendDashboard(nuxt, 'crew.home', {
        id: 'shifts.next',
        component: resolver.resolve('./runtime/app/dashboard/NextShift.vue'),
        titleKey: 'shifts.dashboard.next',
        title: 'Your next shift',
        order: 10,
        span: 2,
        permission: 'shifts:read',
      })
    }
  },
})
```

As for every soft dependency, also list `@frigear-nu/dashboard` as an optional module dependency:

```ts
moduleDependencies: { '@frigear-nu/dashboard': { version: '>=0.0.0', optional: true } }
```

An item is a Widget [`WidgetDefinition`](/modules/interface/widget#add-widgets-and-tabs-from-a-module) with four
more fields:

```ts
type DashboardItem = WidgetDefinition & {
  title?: string // plain fallback title
  titleKey?: string // i18n key, translated at render time
  platforms?: ('web' | 'mobile')[] // default: both
  when?: { module?: string, platform?: 'web' | 'mobile' } // every key that is set must hold
}
```

- **`id`** is unique within a dashboard. An item registered again under the same `id` replaces the earlier one, so
  your app can replace a module's item. The `id` defaults to the component's file name. Keep it at most 100
  characters.
- **`permission`** hides the item from viewers who lack it. [Authorization](/modules/identity/authorization) does this
  through the `widgets:filter` [hook](/guide/concepts/glossary). The data behind the item is still checked on the server.
- **`platforms`** and **`when.platform`** pick where the item shows. The platform is `mobile` inside the native app of
  Mobile, and `web` everywhere else. The server always renders `web`: a server-rendered page (Mobile with
  `spa: false`) switches to `mobile` once hydration is done.
- **`when.module`** ships the item only when that module is installed. It is decided at build time, so the item's
  component is not even bundled otherwise.
- **`span`** is the number of columns the item takes in the default grid: one on phones, up to two from `md` and up to
  four from `xl`.

::warning
Add items with `extendDashboard`, never with `extendWidgets(nuxt, 'dashboard.<name>', …)`. A widget without the
dashboard part is not shown, and the build warns about it.
::

::caution
Hiding an item only hides the interface. Always call `authorize` on the server for the data an item loads.
::

### Write an item

An item is an ordinary Vue component. It receives its `props`, then every entry of the dashboard's `context`. Reuse
`StatCard` and `ListCard` from [UI](/modules/interface/ui), or the building blocks below.

```vue [runtime/app/dashboard/NextShift.vue]
<script setup lang="ts">
import { useDashboardItem, useFetch, watchEffect } from '#imports'

const { loading, error, onRefresh } = useDashboardItem()
const { data, status, error: fetchError, refresh } = useFetch('/api/shifts/me/next', { lazy: true })

watchEffect(() => {
  loading.value = status.value === 'pending'
  error.value = fetchError.value
})
onRefresh(refresh)
</script>

<template>
  <StatCard
    label="Your next shift"
    :value="data?.startsAt"
    icon="i-lucide-calendar-clock"
    empty="No shift booked"
  />
</template>
```

`useDashboardItem()` returns the item's context. Outside a dashboard it returns local state, so the component still
works on a page of its own.

```ts
useDashboardItem(): {
  dashboard: string
  id: string
  loading: Ref<boolean> // set it: the frame shows a skeleton instead of the item
  error: Ref<unknown> // set it: the frame shows the error and a "Try again" button
  collapsed: ComputedRef<boolean>
  settings: ComputedRef<Record<string, unknown>> // the user's settings of this item
  setSettings(value: Record<string, unknown>): Promise<void> // replaces them, `{}` clears them
  refresh(): Promise<void> // clears `error` and calls the `onRefresh` handler
  onRefresh(handler: () => unknown): void
}
```

An item that throws while rendering shows the same error state, without breaking the rest of the dashboard.

### Components

| Component | Props | Purpose |
| --- | --- | --- |
| `<Dashboard>` | `name: string`, `context?: Record<string, unknown>`, `editable?: boolean` (default `true`) | Draws the dashboard in `DashboardGrid`, with the edit mode. Slot `empty`. |
| `<DashboardGrid>` | none | One column on phones, two from `md`, four from `xl`. |
| `<DashboardItem>` | `item: DashboardEntry`, `context?`, `editing?`, `first?`, `last?` | One item with its title, collapse toggle, skeleton and error state. |
| `<ChartCard>` | `title`, `description?`, `loading?`, `isEmpty?`, `empty?` | A frame for a chart in the default slot, with `#actions`. No chart library is bundled. |
| `<ActionCard>` | `title`, `description?`, `icon?`, `actionLabel`, `to?`, `loading?` | A call to action with one primary button. Emits `action`. |
| `<EmptyCard>` | `title`, `description?`, `icon?`, `actionLabel?`, `to?` | An empty state (`UEmpty`) with exactly one action. Emits `action`. |

- **Edit mode.** **Customise dashboard** shows buttons to move each item up or down and to hide it, and lists the
  hidden items with a button to show each again. **Reset layout** asks for confirmation, then restores the default.
  The buttons are disabled while a change is being saved. When changes are not saved for the user, edit mode says
  they last until a reload.
- **Moving.** An item moves within the full order of the dashboard, so items the viewer does not see (on the other
  platform, or hidden by `widgets:filter`) keep their place.
- **Loading.** While the items load, `<Dashboard>` shows a skeleton grid, never an empty dashboard. If they fail to
  load, it shows an error with a **Try again** button.
- **`span`.** In a grid of your own, `dashboardSpanClass(span)` returns the classes of an item spanning `span` columns.

### Lay out a dashboard yourself

A page can draw the same items in its own layout. `useDashboard(name, context?)` returns them filtered by `permission`
and platform, in the user's order and without the hidden ones. Await it so they render on the server.

```vue [app/pages/crew/index.vue]
<script setup lang="ts">
const { items, hidden, move, hide, show, reset } = await useDashboard('crew.home')
const featured = computed(() => items.value[0])
const others = computed(() => items.value.slice(1))
</script>

<template>
  <div class="flex flex-col gap-4">
    <PageHeading title="Home" />
    <DashboardItem
      v-if="featured"
      :item="featured"
    />
    <DashboardGrid>
      <DashboardItem
        v-for="item in others"
        :key="item.id"
        :item="item"
      />
    </DashboardGrid>
  </div>
</template>
```

```ts
useDashboard(name: string, context?: MaybeRefOrGetter<Record<string, unknown> | undefined>): {
  items: ComputedRef<DashboardEntry[]> // shown items, in the user's order
  hidden: ComputedRef<DashboardEntry[]>
  collapsed: ComputedRef<string[]>
  layout: ComputedRef<DashboardLayout>
  persisted: ComputedRef<boolean> // whether changes are saved for the user
  saving: Ref<boolean> // a change is being saved
  platform: Ref<'web' | 'mobile'>
  move(id: string, toIndex: number): Promise<void> // index among `items`
  hide(id: string): Promise<void>
  show(id: string): Promise<void>
  toggleCollapsed(id: string): Promise<void>
  reset(): Promise<void>
  status, error, refresh // of the underlying `useWidgets`
}

// The item's widget data and dashboard data, with `title` translated.
type DashboardEntry = WidgetMeta & { title?: string, titleKey?: string, platforms?, when?, dashboard: string, collapsed: boolean }
```

`DashboardItem` provides `useDashboardItem()` to the item, so items behave the same in your layout.

### Per-user layout

Each user's layout is one [Preferences](/modules/identity/preferences) key, `dashboardLayouts`. Dashboard registers it
with `addUserPreferences` when Preferences is installed.

```ts
type DashboardLayouts = Record<string, { // by dashboard name
  order: string[] // item ids; new items keep their registered place
  hidden: string[]
  collapsed: string[]
  settings?: Record<string, Record<string, unknown>> // by item id
}>
```

- **Signed in with a cookie session, with Preferences:** every change is saved. The layout follows the user to every
  device. Preferences saves only from a cookie session, so this needs Auth in server mode.
- **Without Preferences, signed out, or Auth in client mode** (a Capacitor app, a bearer token): changes last for the
  session. After a reload the registered order applies. Session changes belong to one user: they are dropped when
  someone else signs in.
- **Saving.** One save runs at a time, and changes made meanwhile go out together in the next one. A failed save shows
  an error toast and rolls the dashboard back to the last saved layout.
- **Ids that no longer exist** are ignored, and dropped at the next save. An item a module adds later appears directly
  after the item registered before it.

The layout is bounded, because preferences are carried in the session cookie, which holds about 4 KB in all:

| Limit | Value |
| --- | --- |
| Dashboards with a saved layout | 20 |
| Ids in `order`, `hidden` or `collapsed` | 50 each |
| Length of an id | 100 characters |
| Item settings per dashboard, as JSON | 1 KB |

A save past a limit is rejected with `400` and rolled back. Keep item settings to a few small values.

### Utils

`@frigear-nu/dashboard/utils` is safe to import in another module's `setup()`. It does not import `@nuxt/kit`.

| Export | Purpose |
| --- | --- |
| `extendDashboard(nuxt, name, items)` | Adds one or more items to a dashboard, from a module's `setup()`. |
| `dashboardArea(name)` | The widget area of a dashboard: `dashboard.<name>`. |
| `applyLayout`, `orderItems`, `moveItem`, `hideItem`, `showItem`, `toggleCollapsed`, `setItemSettings`, `pruneLayout`, `resetLayout` | The layout logic `useDashboard` uses, as plain functions. |
| `filterByPlatform(items, platform)`, `isOnPlatform(item, platform)` | The platform filter. |

## Hooks

Dashboard adds no hooks of its own yet. Items are filtered by Widget's `widgets:filter` app hook, with the area
`dashboard.<name>`.

| Hook | Where | When | Payload |
| --- | --- | --- | --- |
| `widgets:filter` (Widget) | Nuxt app | Before a dashboard's items are drawn | `{ area: 'dashboard.<name>', widgets, context? }` |

## Routes

Dashboard registers no routes. Layouts are saved through the Preferences route `PATCH /api/preferences`.

## Translations

Override any string in your app's `i18n/locales/<code>.json`. The namespace is `dashboard`, in English and Danish.

| Key | Used for |
| --- | --- |
| `dashboard.home.label` | The Home tab label |
| `dashboard.edit.start`, `.done`, `.sessionOnly` | The edit mode buttons and the session-only hint |
| `dashboard.save.error` | The toast when a layout change could not be saved |
| `dashboard.reset.button`, `.title`, `.description`, `.confirm` | Reset layout and its confirmation |
| `dashboard.item.*` | Collapse, move and hide labels, and the error state of an item |
| `dashboard.hidden.title`, `.show` | The list of hidden items in edit mode |
| `dashboard.empty.*`, `dashboard.allHidden.*`, `dashboard.error`, `dashboard.retry` | The empty and error states |

## Planned

These parts of the design are not built yet.

- **Summary endpoint.** `GET /api/dashboard/me/:name/summary` will return serialisable card data for native cards. It
  will collect them from the [Nitro](/guide/concepts/glossary) hook `dashboard:summary:resolve`
  (`{ event, user, name, cards }`), guarded by `dashboard:read` (implicit for every user, and a token scope).
- **Admin overview.** The admin dashboard draws three widget areas today: `admin.dashboard.top`, `admin.dashboard` and
  `admin.dashboard.side`. Moving it to `<Dashboard>` would let admins rearrange it. That is a change to
  [Admin](/modules/interface/admin), proposed as a separate issue.
