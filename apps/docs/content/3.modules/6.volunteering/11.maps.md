---
title: Maps
description: Geographic and floor-plan maps owned by an operation, a team or the platform, that other modules add map kinds, layers and pages to.
---

Maps gives your app maps that people can look at on the web and in the app, and that staff draw on in the browser: a
festival site map on real map tiles, or a bar layout drawn on a floor plan. Any [owner](/guide/concepts/glossary) can
have maps, and other modules add their own kinds of maps, layers and map pages without changing this one. For who may
see a map, Maps uses the shared rules of [Audience](/modules/volunteering/audience).

The package is `@frigear-nu/maps`. A map has a base: `geo` maps sit on OpenStreetMap-style tiles, `plane` maps are a
flat drawing in their own units, optionally on a floor plan image.

## What you get

- **Pages:**
  - `/maps/:map`, a read-only map for volunteers, by key or id, with `?feature=` deep links (on by default).
- **Admin area** (opt-in, needs [Admin](/modules/interface/admin)):
  - `/admin/maps`, the maps list, filtered by owner.
  - `/admin/maps/:id`, a map with the editor, its layers and its floor plan.
  - A "Maps" tab on the staff operation page, when [Widget](/modules/interface/widget) is installed.
- **Components** (auto-imported): `<MapView>` and `<MapEditor>`.
- **Composables and helpers:**
  - `useMap(keyOrId)` for custom map pages.
  - `extendMaps`, `defineMapKind`, `defineMapFeatureKind` and `defineMapLayer` from `@frigear-nu/maps/utils`, for
    modules that ship their own maps.
  - `ensureMap(event, definition)`, a server util that creates a map from code once.
- **Server routes:** read, draw and admin routes under `/api/maps` and `/api/admin/maps`.

:module-runtime{server client mobile}

::note
**Installed for you:** Auth, UI, Module Kit, Leaflet and leaflet-geoman.
**You add:** [NuxtHub](/guide/concepts/glossary) with a database and Blob storage, and Audience.
**Optional:** Admin and Widget (staff pages and the operation tab), Menu (the admin sidebar item).
::

## Quick setup

::steps

### Install Maps

```bash
pnpm add @frigear-nu/maps @frigear-nu/audience
```

### Add it to `nuxt.config.ts`

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxthub/core', '@frigear-nu/users', '@frigear-nu/maps'],
  hub: { db: 'sqlite', blob: true },
  maps: {
    tiles: {
      url: 'https://tiles.example.com/{z}/{x}/{y}.png',
      attribution: '&copy; OpenStreetMap contributors',
    },
    settings: { pages: { admin: true, adminMap: true } },
  },
})
```

::warning
Without a migration, every map request fails: the tables do not exist yet.
::

### Generate and commit a migration

Maps adds three tables. Generate a [migration](/modules/platform/module-kit/database) and commit it.

```bash
npx nuxt db generate
```

::warning
Without a role holding `maps:manage`, nobody can open the admin pages or create maps.
::

### Grant `maps:manage`

`maps:manage` is granted to the `admin` and `coordinator` roles when your app has them. Grant it to other staff roles
in your [Authorization](/modules/identity/authorization) config.

::

::callout{color="success" icon="i-lucide-check"}
**What you should see:** `/admin/maps` lists the maps. "Add map" creates a map, and its page shows the drawing tools.
`/maps/<key>` shows the map read-only.
::

## Options

Options go under the `maps` key.

| Option | Type | Default | Purpose |
| --- | --- | --- | --- |
| `tiles.url` | `string` | OpenStreetMap's tiles | The tile URL template of geo maps. |
| `tiles.attribution` | `string` | OpenStreetMap's attribution | The attribution shown on geo maps. |
| `tiles.maxZoom` | `number` | `19` | The deepest zoom of the tiles. |
| `kinds`, `featureKinds`, `layers` | lists | `[]` | The host's own registrations, the same as `extendMaps`. |
| `settings.pages.view` | `string \| boolean` | `/maps/:map` | The read-only map page; `false` turns it off. |
| `settings.pages.admin` | `string \| boolean` | off | The staff map list. `true` is `/admin/maps`. |
| `settings.pages.adminMap` | `string \| boolean` | off | The staff map page; must contain `:id`. |
| `settings.operationsTab` | `boolean` | `true` | The "Maps" tab on the staff operation page. |
| `settings.maxUnderlayBytes` | `number` | 10 MB | The largest floor plan image. |

**`tiles`.** The default is OpenStreetMap's public tile server. Its
[tile usage policy](https://operations.osmfoundation.org/policies/tiles/) forbids heavy use, such as a festival where
thousands of phones open the site map at once. Use a hosted tile provider, or tiles you serve yourself, in production.
Keep the provider's attribution.

## Map kinds, feature kinds and layers

Modules describe their maps with three kinds of registration. They call `extendMaps` from their `setup()`.

| Registration | What it is | Example |
| --- | --- | --- |
| Map kind | A template: base, owner type, default view, the feature kinds and editor tools allowed, default layers. | `first-aid`, a geo map per operation with first aid posts. |
| Feature kind | What can be drawn: its geometry, a zod schema for its properties, an icon and a colour. | `first-aid.post`, a point with a capacity. |
| Layer | A provider layer: features computed on the server per request, for the callers its `permission` lets in. | `shifts.on-duty`, who is on shift now. |

Maps registers `maps.generic-geo` and `maps.generic-plane` kinds, and the feature kinds `maps.marker` (point),
`maps.line` (line), `maps.area` (polygon) and `maps.label` (text). Staff use them for maps no module owns.

- **Ids** are prefixed with the module (`first-aid.post`). A later registration with the same id replaces an earlier
  one, so a host can override a module's kind from its `maps` option.
- **An invalid registration fails the build** with the list of problems, such as an unknown feature kind or a geo map
  with `snapGrid`.
- **Editor tools** are `marker`, `polyline`, `polygon`, `rectangle`, `text` (a label) and `snapGrid` (plane maps
  only). A kind without `editorTools` gets the tools its feature kinds can draw.

### A module ships its own map

A `@frigear-nu/first-aid` module adds a "First aid posts" map per operation, its own feature kind and a page. List Maps
before it in `modules`, so `hasNuxtModule` sees it.

```ts [packages/first-aid/src/module.ts]
import { hasNuxtModule } from '@nuxt/kit'
import { defineMapFeatureKind, defineMapKind, extendMaps } from '@frigear-nu/maps/utils'

if (hasNuxtModule('@frigear-nu/maps')) {
  extendMaps(nuxt, {
    featureKinds: [defineMapFeatureKind({
      id: 'first-aid.post',
      label: { da: 'Førstehjælp', en: 'First aid' },
      icon: 'i-lucide-cross',
      geometry: 'Point',
      properties: resolver.resolve('./runtime/map/post-properties'),
    })],
    kinds: [defineMapKind({
      id: 'first-aid',
      label: { da: 'Førstehjælpsposter', en: 'First aid posts' },
      base: 'geo',
      ownerType: 'operation',
      defaultView: { center: [55.617, 12.079], zoom: 15 },
      featureKinds: ['first-aid.post', 'maps.marker'],
      editorTools: ['marker'],
      editPermission: 'first-aid:manage',
    })],
  })
}
```

The properties file default-exports a zod object. It is bundled into the browser (the editor builds its form from it)
and into the server (which validates with it), so it imports only `zod` and `@frigear-nu/maps/properties`.

```ts [packages/first-aid/src/runtime/map/post-properties.ts]
import { z } from 'zod'
import { translatedProperty } from '@frigear-nu/maps/properties'

export default z.object({
  capacity: z.number().int().min(0).meta({ label: { da: 'Kapacitet', en: 'Capacity' } }),
  staffed: z.boolean().optional(),
  note: translatedProperty({ label: 'Note' }).optional(),
})
```

The editor's form supports strings, numbers, booleans, enums, `.optional()`, `.default()` and translated texts
(`translatedProperty`). Labels and help texts come from `.meta({ label, help })`.

One map per operation, created when the operation is:

```ts [packages/first-aid/src/runtime/server/plugins/maps.ts]
export default defineNitroPlugin(nitro => nitro.hooks.hook('operations:created', ({ event, operation }) =>
  ensureMap(event, {
    key: `first-aid-${operation.id}`,
    kind: 'first-aid',
    owner: { type: 'operation', id: operation.id },
    name: { da: 'Førstehjælp', en: 'First aid' },
  })))
```

And the page:

```vue [packages/first-aid/src/runtime/app/pages/first-aid/[operationId].vue]
<script setup lang="ts">
import { useRoute } from '#imports'

const route = useRoute()
</script>

<template>
  <MapView :map="`first-aid-${route.params.operationId}`" />
</template>
```

Staff edit it with `<MapEditor>` on the same key. The editor offers only the marker tool, and the `first-aid.post`
form.

### Modules that integrate

Each of these registers with Maps only when Maps is installed, and none is imported by Maps.

| Module | Registers |
| --- | --- |
| [Operations](/modules/volunteering/operations#maps) | The `operations.site` (geo) and `operations.venue-layout` (plane) kinds, two maps per new operation (`operation-<id>-site` and `operation-<id>-venue`), and `maps:edit:resolve` for holders of `operations:manage`. |
| [Teams](/modules/volunteering/teams#maps) | `maps:edit:resolve` for a team's leads, on maps owned by a `team`. |
| [Shifts](/modules/volunteering/shifts#maps-layer) | The `shifts.on-duty` layer on `operations.venue-layout` maps. |

### Provider layers

A provider layer's features come from a server function, run on every request. Register it for a map kind or one map
key. Its `permission` is checked on every request; without one, whoever may read the map sees the layer.

```ts [module.ts]
extendMaps(nuxt, {
  layers: [defineMapLayer({
    key: 'shifts.on-duty',
    label: { da: 'På vagt', en: 'On duty' },
    appliesTo: { kind: 'operations.venue-layout' },
    provider: resolver.resolve('./runtime/server/maps/on-duty'),
    permission: 'shifts:read',
    refreshInterval: 60,
  })],
})
```

```ts [runtime/server/maps/on-duty.ts]
import type { H3Event } from 'h3'
import type { MapDto, MapFeatureCollection } from '@frigear-nu/maps/utils'

export default async function onDuty(event: H3Event, map: MapDto): Promise<MapFeatureCollection> {
  return { type: 'FeatureCollection', features: [/* GeoJSON features, properties.label shown in popups */] }
}
```

Maps drops features whose geometry is invalid for the map's base. A `component` on the layer draws it instead of the
default markers: it gets `layer` (with the GeoJSON `url`), `map` and `leaflet`.

## Visibility and access

A map's `visibility` is an [Audience](/modules/volunteering/audience) visibility. A layer's visibility narrows its
map's; `null` follows the map.

| Name | Who holds it | What it covers |
| --- | --- | --- |
| `maps:read` | Every signed-in user (implicit) | Maps whose visibility lets them in. Public maps are open to everyone, anonymous visitors included. |
| `maps:edit` | Every signed-in user (implicit) | Drawing on a map, narrowed by the policy below. |
| `maps:manage` | `admin`, `coordinator` | Every map, its layers and floor plan, the admin routes. |

The policy of `maps:edit` allows a caller who holds `maps:manage`, or the map kind's `editPermission`, or whom an
owner module allows through `maps:edit:resolve`. That is how teams lets a team's leads edit the team's maps without
Maps importing it. The named scope `maps` gives tokens `maps:read`.

A map the caller may not see answers the same 404 as an unknown one. Anonymous callers get a 401 for every map that
is not public.

## Server

Maps adds one server util for modules: `ensureMap`.

```ts
ensureMap(event: H3Event, definition: EnsureMapDefinition): Promise<AdminMapDto>

type EnsureMapDefinition = {
  key: string // stable and unique: `first-aid-opr_123`
  kind: string
  owner: OwnerRef // { type: 'platform', id: null }, { type: 'operation', id }, ...
  name: Translated
  view?: MapViewport // defaults to the kind's
  visibility?: Visibility | null
  layers?: MapKindLayer[] // besides the kind's default layers
  features?: EnsureMapFeature[] // { layer?, featureKind, geometry, properties?, label?, sort? }
}
```

- **Idempotent by key.** When a map with the key exists, it is returned as it is. Its layers and features are only
  created with the map, so staff edits survive.
- **Validated.** The kind must be registered, the owner must exist (through `audience:owner:resolve`), and every
  feature must pass its feature kind. Otherwise it throws a 400.

## App

The components load Leaflet in the browser only. The server renders the frame with `data-map-*` attributes and a
skeleton.

| Component or composable | What it does |
| --- | --- |
| `<MapView map :layers :feature :height>` | A read-only map: layer toggles, popups with translated labels, a panel for the selected feature. `layers` lists the layer keys shown when it opens; `feature` focuses one. |
| `<MapEditor map :height>` | The map with leaflet-geoman's toolbar, limited to the kind's tools, snap to grid on plane maps, and the property form. Read-only for callers without `maps:edit`. |
| `useMap(keyOrId)` | `{ map, layers, providerLayers, features, canEdit, refresh, focus(featureId), fitBounds(), leaflet }`, shared with the `<MapView>` of the same map. `await` it. |

A feature kind's `component` shows in the selected-feature panel, with `feature` and `map` as props.

## Hooks

Your app answers these Nitro hooks from a server plugin (`server/plugins/*.ts`).

| Hook | Context | When |
| --- | --- | --- |
| `maps:seed:resolve` | `{ event, maps }` | Once, on the first request. Push `EnsureMapDefinition`s into `maps`; Maps creates the missing ones. |
| `maps:edit:resolve` | `{ event, user, map, allowed }` | When neither `maps:manage` nor the kind's `editPermission` allows an edit. Set `allowed = true` to allow it. |
| `maps:feature:created` | `{ event, map, feature }` | A feature was drawn. |
| `maps:feature:updated` | `{ event, map, feature, previous }` | A feature changed. |
| `maps:feature:deleted` | `{ event, map, feature }` | A feature was removed. |

Identify the user from `ctx.user`, never from the session on `ctx.event`: it is empty for bearer requests.

## Routes

Routes the module registers, and who may call them. `:map` is a map's id or key. Path builders come from
`@frigear-nu/maps/api` (`mapsApi`).

| Route | Who | What |
| --- | --- | --- |
| `GET /api/maps?ownerType&ownerId` | Anyone | The maps the caller may see. |
| `GET /api/maps/:map` | Anyone who may see it | The map, its visible layers and features, its provider layers and `canEdit`. |
| `GET /api/maps/:map/layers/:layerKey` | The layer's `permission` | A provider layer's GeoJSON. |
| `GET /api/maps/:map/underlay` | Anyone who may see it | The floor plan image, `nosniff`. |
| `POST /api/maps/:map/features` | `maps:edit` | Draws a feature. 409 `layer_not_editable` on a locked layer. |
| `PATCH`, `DELETE /api/maps/:map/features/:featureId` | `maps:edit` | Changes or removes a feature. |
| `GET`, `POST /api/admin/maps` | `maps:manage` | Lists (paginated) or creates maps. |
| `GET`, `PATCH`, `DELETE /api/admin/maps/:id` | `maps:manage` | One map. |
| `POST /api/admin/maps/:id/layers` | `maps:manage` | Adds a layer. |
| `PATCH`, `DELETE /api/admin/maps/:id/layers/:layerId` | `maps:manage` | One layer; deleting it deletes its features. |
| `POST`, `DELETE /api/admin/maps/:id/underlay` | `maps:manage` | Uploads (multipart `file`, `width`, `height`) or removes a floor plan. |

A floor plan is a PNG, JPEG or WebP, recognised by its bytes (415 otherwise). The server checks the size the browser
measured against the image, and refuses images over `maxUnderlayBytes` (413). The image is placed at
`[[0, 0], [height, width]]`, one plan unit per pixel.

## Database

Tables the module adds. Generate and commit a [migration](/modules/platform/module-kit/database) after installing.

| Table | What it holds |
| --- | --- |
| `maps` | `id` (`map_`), `key` (unique), `kind`, `base`, `ownerType`, `ownerId`, `name`, `view`, `underlay`, `visibility`, `source` (`admin` or `code`). |
| `map_layers` | `id` (`mpl_`), `mapId`, `key` (unique per map), `name`, `sort`, `visible`, `editable`, `visibility`. |
| `map_features` | `id` (`mpf_`), `mapId`, `layerId`, `featureKind`, `geometry` (GeoJSON), `properties`, `label`, `linkMapId`, `sort`. |

Geometries are GeoJSON `[x, y]`: `[longitude, latitude]` on geo maps, plane units on plane maps. Views and floor plan
bounds use Leaflet's `[lat, lng]` (`[y, x]`) order. Both dialects store JSON, with no PostGIS.

## Translations

Override any string in your app's `i18n/locales/<code>.json`, under the `maps` key. Maps ships Danish and English.
