`@frigear-nu/website` (`apps/website`) is the main Frigear application, built with Nuxt 4 on the
[base layer](/layers/base) and the Frigear modules. It is the successor to the
[previous Nuxt website](https://github.com/Frigear-nu/nuxt-frigear-nu). It is private and deployed to Cloudflare Workers.

## Quick setup

From the repository root (see [Local development](/getting-started/local-development) for requirements):

```bash
pnpm install
cp apps/website/.env.example apps/website/.env   # set NUXT_SESSION_PASSWORD
pnpm --filter @frigear-nu/website dev
```

## Modules

`nuxt.config.ts` extends `@frigear-nu/base` and registers these modules, in this order, next to Nuxt modules such as
`@nuxt/ui`, `@nuxthub/core`, `@nuxt/content`, `@nuxtjs/i18n`, `@pinia/nuxt` and `nuxt-qrcode`.

| Module | What the website configures |
| --- | --- |
| [UI](/modules/ui) | Defaults. |
| [Menu](/modules/menu) | Defaults (the base layer adds a content `main` menu). |
| [Auth](/modules/auth) | Login at `/sign-in`, register at `/sign-up` (or `https://frigear.nu/sign-up` in production), password, WebAuthn, magic link, email verification, Facebook and "Log in with frigear.nu". |
| [Users](/modules/users) | Staff user admin, MCP, email-change verification, profile at `/account/profile`. |
| [Authorization](/modules/authorization) | Defaults. |
| [Widget](/modules/widget) | Defaults. |
| [Admin](/modules/admin) | Open to the `admin`, `manager` and `coordinator` roles. |
| [Account](/modules/account) | Index, profile, security, documents and API token pages, plus a configured document list. |
| [Notify](/modules/notify) | `log` email driver by default; `NUXT_NOTIFY_*` selects a real one. |
| [Stripe](/modules/stripe) | Keys from the environment. |
| [Subscriptions](/modules/subscriptions) | `monthly`, `quarterly` and `yearly` membership plans, with price lookup keys from the environment. |
| [Payments](/modules/payments) | Defaults. |
| [Events](/modules/events) | All pages, including the admin pages, and MCP. |
| [Forms](/modules/forms) | Form and admin pages, MCP, and the seeded forms (see [Forms](#forms)). |
| [Cookie Consent](/modules/cookie-consent) | Policy link `/legal/gdpr`. |
| [OAuth Server](/modules/oauth-server) | Admin and applications pages, MCP. |
| [Preferences](/modules/preferences) | Defaults. |

It also depends on [Module Kit](/modules/module-kit) directly. [MCP](/modules/mcp) is not listed: other modules
install it as a dependency.

## Content

The base layer reads site content from `content/`. With two locales, the website keeps one tree per locale:

| Folder | Contents |
| --- | --- |
| `content/da`, `content/en` | `config.yaml` (name, logo, navigation, footer) and `pages/**` Markdown, per locale. The default locale is `da`, with `en` prefixed. |
| `content/events` | Event definition YAML files (for example `2026/01.general-assembly.yml`). |
| `content/_templates/events` | A local-development event template. |

Nothing in this repository reads `content/events` or `content/_templates` yet: they hold event definitions ported from
the old app, and the events module stores events in the database.

Translations for the app itself are in `i18n/locales`. Module strings can be overridden in the same files (see
[Module Kit](/modules/module-kit#overriding-module-strings-in-your-app)).

## Environment

Copy `apps/website/.env.example` to `.env`. Variables are read by the module named in the last column.

| Variable | Purpose | Read by |
| --- | --- | --- |
| `NUXT_SESSION_PASSWORD` | Required. Encrypts the session cookie. | nuxt-auth-utils (Auth) |
| `NUXT_ACL_ADMINS` | Comma-separated emails that are always admins; bootstraps the first admin. | Website |
| `NUXT_STRIPE_SECRET_KEY`, `NUXT_STRIPE_WEBHOOK_SECRET`, `NUXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` | Stripe credentials. | [Stripe](/modules/stripe) |
| `SUBSCRIPTIONS_MONTHLY_LOOKUP_KEY`, `SUBSCRIPTIONS_QUARTERLY_LOOKUP_KEY`, `SUBSCRIPTIONS_YEARLY_LOOKUP_KEY` | Stripe price lookup keys for the plans (defaults `membership_month`, `membership_quarter`, `membership_annual`). | [Subscriptions](/modules/subscriptions) |
| `NUXT_OAUTH_SERVER_PRIVATE_KEY`, `NUXT_OAUTH_SERVER_PREVIOUS_PUBLIC_KEYS` | Token signing key and, while rotating, the retired public keys. | [OAuth Server](/modules/oauth-server) |
| `NUXT_OAUTH_ADMIN_EMAILS` | Comma-separated emails allowed to manage OAuth applications. | Website policy |
| `NUXT_NOTIFY_EMAIL_DRIVER`, `NUXT_NOTIFY_EMAIL_FROM` and the provider keys | Email delivery. | [Notify](/modules/notify#environment-variables) |
| `FRIGEAR_SSO_URL`, `FRIGEAR_SSO_CLIENT_ID`, `FRIGEAR_SSO_CLIENT_SECRET` | "Log in with frigear.nu". Active on PR previews or when these are set. | Auth |
| `NUXT_FRIGEAR_FORCE_ID` | Use the frigear.nu user id as the local user id. | Auth |
| `NUXT_OAUTH_FACEBOOK_CLIENT_ID`, `NUXT_OAUTH_FACEBOOK_CLIENT_SECRET` | Facebook login; offered only when the client id is set at build time. | Auth |
| `NUXT_FORMS_SEED_ENABLED`, `NUXT_FORMS_APPLICATIONS_TO`, `NUXT_FORMS_ADMIN_EMAILS`, `NUXT_MAIL_TO`, `NUXT_CONTACT_<SUBJECT>` | Forms seeding, recipients and admins (see [Forms](#forms)). | Website |
| `DEPLOYMENT_HOST`, `CLOUDFLARE_WORKER_NAME`, `NUXT_HUB_CLOUDFLARE_DATABASE_ID`, `NUXT_HUB_CLOUDFLARE_KV_NAMESPACE_ID`, `NUXT_HUB_CLOUDFLARE_BUCKET_NAME` | Cloudflare deployment (see [Deployment](#deployment)). | Website |

## Forms

The website seeds and polices the [Forms](/modules/forms) module in its own code, so none of this is part of the module:

- **Seeded forms.** `forms/index.ts` and `forms/contact.ts` define three forms: `contact` (published, with a subject
  select), `project-application` and `board-member-application` (both drafts). They are inserted only when
  `forms.seed.enabled` is on, which `NUXT_FORMS_SEED_ENABLED=true` sets. Existing slugs are never overwritten, and a form
  can also be imported from the admin page.
- **Recipients.** `NUXT_FORMS_APPLICATIONS_TO` (comma-separated) is the email recipient list for both application forms.
  The contact form sends to `NUXT_MAIL_TO`, and `NUXT_CONTACT_<SUBJECT>` (for example `NUXT_CONTACT_SUPPORT`) routes one
  subject to its own address. Without a recipient, submissions are stored only.
- **Who may manage forms.** `server/plugins/forms-policy.ts` answers the `forms:authorize` hook: a user may manage
  forms and read submissions when their effective role is `admin`, `manager` or `coordinator`, or their email is in
  `NUXT_FORMS_ADMIN_EMAILS` (comma-separated). The role comes from the database and `NUXT_ACL_ADMINS`, not from the
  session.

The website has similar policy plugins in `server/plugins` for [Events](/modules/events), [OAuth Server](/modules/oauth-server)
and [Users](/modules/users).

## Database

Production uses Cloudflare D1, configured in `nuxt.config.ts` with a KV namespace (Stripe webhook idempotency and the
subscription plans cache) and an R2 bucket (form file uploads). Development uses a local SQLite file. Migrations live in
`apps/website/server/db/migrations/sqlite`; commands are in
[Local development](/getting-started/local-development#database).

## Deployment

The app builds with the `cloudflare_module` Nitro preset and ships to Cloudflare Workers.

- Pushing to `main` runs `.github/workflows/deploy-production.yml`, which deploys to production and applies D1
  migrations.
- Pull requests from collaborators run `deploy-preview.yml`: a per-PR D1 database and a Worker Preview (`pr-<n>`), both
  deleted when the PR closes. Both call the reusable `deploy-website.yml`.
- Locally, the root `cloudflare:*` scripts and `apps/website/scripts/deploy.sh` run the same steps against an
  existing `.output` build.
