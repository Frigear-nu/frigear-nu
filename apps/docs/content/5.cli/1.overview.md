The Frigear CLI creates projects from the [starters](/guide/concepts/glossary), adds apps of any platform (web,
mobile, desktop or your own) to a workspace, sets up their native projects, installs Frigear modules and upgrades a
workspace to new releases. It works in any pnpm workspace, not only in the
[Frigear repository](/guide/concepts/glossary). Its package is `@frigear-nu/cli`, a
[citty](https://github.com/unjs/citty) CLI published to npm.

## Run it

Run it without installing it:

```bash
pnpx @frigear-nu/cli --help
pnpx @frigear-nu/cli <command> --help
```

`pnpm create frigear-app` (or `npm create frigear-app@latest`) does the same as `init`: see
[Create a project](/cli/create-a-project#create-frigear-app).

Inside the Frigear repository, use the root `cli` script. It runs `packages/cli/bin/cli.mjs`, which loads the
TypeScript source with jiti, so there is no build step:

```bash
pnpm cli --help
```

::note
The starters and app templates are downloaded from the `Frigear-nu/frigear-nu` GitHub repository with
[giget](https://github.com/unjs/giget). If GitHub refuses the download (anonymous requests are rate limited), set
`GIGET_AUTH` to a GitHub token, for example `GIGET_AUTH=$(gh auth token)`.
::

## Commands

| Command | Purpose | Page |
| --- | --- | --- |
| `init` | Creates a new project from a starter. | [Create a project](/cli/create-a-project) |
| `platform add` | Adds an app of a platform (web, mobile, desktop or your own) to a workspace, with its root scripts. | [Platforms](/cli/platforms#platform-add) |
| `platform init` | Sets up a target in an app: `ios`, `android`, `apple-watch`, `tauri` or your platform's own. | [Platforms](/cli/platforms#platform-init) |
| `platform list` | Lists the platforms, templates and targets, and the workspace's apps per platform. | [Platforms](/cli/platforms#platform-list) |
| `app:create` | Adds an app from a template; the same as `platform add <template> <name>`. | [Platforms](/cli/platforms#appcreate) |
| `add` | Installs Frigear modules in a Nuxt app and adds them to its `nuxt.config`. | [Modules](/cli/modules#add) |
| `module:create` | Scaffolds a new Nuxt module under `packages/`. | [Modules](/cli/modules#modulecreate) |
| `package:rename` | Renames a workspace package and every reference to it. | [Refactoring](/cli/refactoring#packagerename) |
| `module:folder` | Turns a single-file local module into a folder module. | [Refactoring](/cli/refactoring#modulefolder) |
| `module:move` | Moves a local module or a package folder, fixing relative paths. | [Refactoring](/cli/refactoring#modulemove) |
| `upgrade` | Moves every `@frigear-nu/*` package to a new release and runs the migrations in between. | [Upgrade](/cli/upgrade) |

## Where it works

Every command takes `--cwd <dir>`: the directory it starts from. The default is `INIT_CWD` (the directory you ran
`pnpm` in), else the current directory, so `pnpm cli …` from a subfolder works on that subfolder.

From there, commands that work on a workspace look for the nearest `pnpm-workspace.yaml` above it. That is the
workspace root: root scripts, the lockfile and `pnpm install` live there. Run them from the root, the apps folder or
inside an app; the result is the same.

The **apps folder** is where `platform add` puts a new app and where `platform init` and `platform list` look for apps.
`--apps-dir auto` (the default) picks it from the `packages:` globs of `pnpm-workspace.yaml`:

1. the one-level glob folder (`apps/*`, `projects/*`, ...) you run the command from, or are inside of;
2. else `apps/`;
3. else the first one-level glob folder that is not `packages/`.

`--apps-dir <dir>` names it instead, relative to `--cwd`; it must be inside the workspace. A folder that no glob
covers is allowed, with a warning, because pnpm will not install an app there until you add it to
`pnpm-workspace.yaml`.

## Package managers

The workspace is a pnpm workspace: the commands find it by its `pnpm-workspace.yaml`. Installs and scripts go through
[nypm](https://github.com/unjs/nypm), which runs the package manager named by the root's `packageManager` field or
lockfile, and pnpm when it finds none.
