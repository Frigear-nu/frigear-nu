A cookie consent banner as a [Nuxt module](https://nuxt.com/docs/4.x/guide/modules), migrated from the old app. The
banner looks and behaves like before (bottom bar, collapses to a round button on scroll, hidden on `/authorize`), and
adds **categories**, a preferences dialog, gating helpers and consent that is stored on the user.

## Design

- **Opt-in per category.** `necessary` is always on; every other category is off until the visitor grants it. Rejecting
  is exactly as easy as accepting.
- **Specific and informed.** Each category can list its cookies (name, provider, purpose, duration); they are shown in
  the preferences dialog.
- **Versioned.** The consent version is your `version` option plus a hash of the category/cookie set. Adding a category
  or cookie (including from another module) asks everyone again. The old `accepted`/`rejected` cookie values are
  migrated.
- **Provable.** For signed-in users the timestamp, version and granted categories are stored on the `users` row.

## Quick Setup

From the workspace use `"@frigear-nu/cookie-consent": "workspace:*"`. `@nuxt/ui` is needed for the bundled components.
`@frigear-nu/users` + NuxtHub are optional; without them consent lives only in the cookie.

```ts
export default defineNuxtConfig({
  modules: ['@nuxt/ui', '@frigear-nu/cookie-consent'],
  cookieConsent: {
    version: '1', // bump to ask everyone again
    policyUrl: '/legal/gdpr',
    categories: [ // optional, defaults to necessary + analytics + marketing
      { key: 'necessary', required: true, label: { en: 'Necessary', da: 'Nødvendige' } },
      { key: 'analytics', label: 'Analytics', cookies: [{ name: '_ga', provider: 'Google', duration: '2 years' }] },
    ],
  },
})
```

```vue
<!-- app.vue, inside <UApp> -->
<CookieConsentBanner />
```

Put `<CookieConsentManage />` (a "Manage cookies" button) in the footer so visitors can change their mind. It opens the
preferences dialog rendered by the banner.

## Translations

Texts ship as `da`/`en` locale files under the `cookieConsent.*` namespace and are contributed to `@nuxtjs/i18n` with
`registerLocales` from [Module Kit](/modules/module-kit#translations-i18n). Without `@nuxtjs/i18n` the components fall
back to English through `useModuleT`. Override any string in your app's `i18n/locales/<code>.json`, including category
texts (`cookieConsent.categories.<key>.label` / `.description`) - custom categories use the same keys, or set `label` /
`description` directly in the config as a string or `{ da, en }` map.

## Gating scripts

```ts
const { isAllowed, acceptAll, rejectAll, save, reset, openPreferences } = useCookieConsent()

// Runs now if already granted, or as soon as it is; the returned function runs on withdrawal.
onCookieConsent('analytics', () => {
  const stop = startTracking()
  return () => stop()
})
```

On the server use `hasCookieConsent(event, 'analytics')` / `getCookieConsent(event)`.

## Hooks

| Hook | Where | Purpose |
| --- | --- | --- |
| `cookie-consent:extend` / `cookie-consent:resolved` | Nuxt (build) | See / adjust the final categories |
| `cookie-consent:change` `(state, previous)` | Nuxt app (client) | Every save, reject or withdrawal |
| `cookie-consent:ready` `(state)` | Nuxt app (client) | Initial state once the banner mounted |
| `cookie-consent:saved` `({ userId, state, acceptedAt })` | Nitro | After a signed-in user's consent was stored |

## Usage in Modules

Other modules contribute categories or cookies during `setup()`; they are merged by `key`, in any order:

```ts
import { extendCookieConsent } from '@frigear-nu/cookie-consent/utils'

extendCookieConsent(nuxt, {
  categories: [
    { key: 'necessary', required: true, cookies: [{ name: 'stripe_mid', provider: 'Stripe', duration: '1 year', purpose: 'Fraud prevention' }] },
  ],
})
```

## Data model

With `@frigear-nu/users` installed the module extends `users` (see [Module Kit](/modules/module-kit)):

| Column | Meaning |
| --- | --- |
| `cookie_consent_accepted_at` | Epoch ms of the latest response |
| `cookie_consent_version` | Consent version answered against |
| `cookie_consent_categories` | JSON of what was granted |

`GET`/`POST /api/cookie-consent` read and write them for the signed-in user. A returning user without a cookie on a new
device gets their stored choice back (unless the version changed). Because `extendDatabaseTable` only changes the
generated schema, **generate and commit migrations** in every consuming app and fixture, as described in
[Migrations](/modules/module-kit#migrations-and-database-backed-module-tests). Set `persistToUser: false` to opt out.
