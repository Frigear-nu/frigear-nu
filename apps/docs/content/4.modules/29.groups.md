---
title: Groups Module
description: User groups with members, managed in the admin area, that other modules share content with.
---

User groups as a [Nuxt module](https://nuxt.com/docs/4.x/guide/modules). A group has a localized name and description,
an icon and members. It owns no sharing logic: modules such as [`@frigear-nu/documents`](/modules/documents) store
group ids and ask this module whether a user belongs to them.

## Quick Setup

Requires `@frigear-nu/users` and NuxtHub with a database. `@frigear-nu/admin` and `@frigear-nu/menu` are optional (the
admin pages use the shared admin components; the menu adds the sidebar entry).

```ts
export default defineNuxtConfig({
  modules: ['@nuxthub/core', '@frigear-nu/users', '@frigear-nu/admin', '@frigear-nu/groups'],
  groups: {
    settings: {
      pages: { admin: true, adminGroup: true }, // /admin/groups and /admin/groups/:id, or custom paths
    },
  },
})
```

::warning
Every host app and test fixture must generate and commit a migration for the `user_groups` and `user_group_members`
tables. See [Module Kit](/modules/module-kit) and the repository `AGENTS.md`.
::

## Authorization

Managing groups is denied by default. The host decides through the `groups:authorize` Nitro hook:

```ts
export default defineNitroPlugin((nitro) => {
  nitro.hooks.hook('groups:authorize', (ctx) => { ctx.allowed = isStaff(ctx.userId) })
})
```

## Server helpers

Auto-imported in Nitro:

- `getUserGroupIds(userId)` - ids of every group the user belongs to.
- `isInGroups(userId, groupIds)` - whether the user belongs to at least one of them.

The `groups:deleted` hook fires after a group is deleted (its memberships are already gone); modules that reference
group ids clean up there.

## Admin API

Everything is under `/api/groups/admin/`, behind the gate above: `GET|POST /groups`, `GET|PATCH|DELETE /groups/:id`,
`GET|POST /groups/:id/members`, `DELETE /groups/:id/members/:userId` and `GET /users?q=` (user search for the member
picker).
