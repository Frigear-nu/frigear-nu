The account area as a [Nuxt module](https://nuxt.com/docs/4.x/guide/modules): opt-in pages built with
[`@nuxt/ui`](https://ui.nuxt.com) over the self-service routes of [Users](/modules/users) and the token routes of
[Auth](/modules/auth). It owns no tables and registers no server routes of its own.

::note
**Requires** `@nuxthub/core`, `@frigear-nu/module-kit`, [`@frigear-nu/auth`](/modules/auth) and
[`@frigear-nu/users`](/modules/users). **Optional:** [`@frigear-nu/menu`](/modules/menu) (menu tiles and the dashboard
page). The shipped pages need `@nuxt/ui` in the host app.
::

## Quick setup

```bash
npx nuxt module add @frigear-nu/account
```

```ts
export default defineNuxtConfig({
  modules: [
    '@nuxthub/core',
    '@frigear-nu/users',
    '@frigear-nu/menu', // optional
    '@frigear-nu/account',
  ],
  account: {
    settings: {
      pages: {
        profile: true, // or a custom path, e.g. '/me'
        security: true,
        index: true, // only registered with @frigear-nu/menu
        documents: true,
        idCode: true,
        apiTokens: true,
      },
      documents: [
        { id: 'handbook', label: { da: 'Håndbog', en: 'Handbook' }, path: '/assets/files/handbook.pdf' },
        { id: 'crew', label: 'Crew plan', path: '/assets/files/crew.pdf', roles: ['admin', 'crew'] },
      ],
    },
  },
})
```

## Options

All options live under `account.settings`.

| Option | Type | Default | Purpose |
| --- | --- | --- | --- |
| `pages.index` | `string \| boolean` | off | Dashboard page listing the menu tiles. Needs `@frigear-nu/menu`; skipped with a warning without it. `true` = `/account`. |
| `pages.profile` | `string \| boolean` | off | Profile page (name, avatar, email). `true` = `/account/profile`. |
| `pages.security` | `string \| boolean` | off | Password and passkeys. `true` = `/account/security`. |
| `pages.documents` | `string \| boolean` | off | Lists `documents` for download. `true` = `/account/documents`. |
| `pages.idCode` | `string \| boolean` | off | Frigear ID page; its body is the host's `AccountIdentificationArea` component. `true` = `/account/id`. |
| `pages.apiTokens` | `string \| boolean` | off | Create and revoke personal API tokens. `true` = `/account/api-tokens`. |
| `documents` | `AccountDocument[]` | `[]` | Files offered on the documents page. |

A page is enabled with `true` (default path), a custom path string, or left off. All account pages share one parent
route that renders the account header; a page whose path already exists in the app is not registered.

```ts
type AccountDocument = {
  id: string
  /** A string, or a locale map (falls back to `en`, then the first value). */
  label: string | Record<string, string>
  /** Where the file is served from, e.g. `/assets/files/handbook.pdf`. */
  path: string
  icon?: string
  /** Only listed for users whose session `role` is one of these. Omit to list for every signed-in user. */
  roles?: string[]
}
```

::warning
`roles` only filters the list. A file served from `public/` can be fetched by anyone who knows its URL; put sensitive
files behind a server route if that matters.
::


### API tokens and email changes

The API tokens page creates tokens through [Auth](/modules/auth); a new token is shown once, with the scopes and expiry
the user chose. When `users.settings.mcp` is on, it also shows a "Connect to MCP" card ([MCP](/modules/mcp)).

Verified email changes are a setting of Users (`users.settings.verifyEmailChange`); point `users.settings.profilePath`
at the profile page, which shows the result. See [Users](/modules/users#routes).

## Server

The account routes call the self-service routes of [Users](/modules/users#routes) (`/api/users/me/*`),
which require a cookie session.

## App

```ts
const { updateProfileDetails, changeEmailAddress, changePassword, pending, error } = useAccount()

await updateProfileDetails({ name: 'Ada Lovelace', avatar: 'https://example.com/ada.png' })
await changeEmailAddress({ email: 'ada@example.com' })
await changePassword({ currentPassword: 'old', newPassword: 'new-password', confirmNewPassword: 'new-password' })
```

Each call refreshes the user session afterwards; `pending` and `error` are refs.

The module also auto-imports the components `AccountHeader`, `AccountMenu`, `AccountIdentificationArea` and
`AccountIdentificationBadge`.

#### The Frigear ID placement

`pages.idCode` registers a page and an account menu tile, but the module has no opinion on what is shown there. The
body of the page is the `AccountIdentificationArea` component, empty by default. Provide a component with the same name
in your app (the module's components have a lower priority than the app's) to fill it, or to replace any other
`Account*` component:

```vue
<!-- app/components/Account/IdentificationArea.vue -->
<template>
  <MyFrigearIdCard />
</template>
```

`AccountIdentificationBadge` (the user id in the account header) can be overridden the same way.

### Menu contributions

With [Menu](/modules/menu) installed, each enabled page adds an item. `order` sorts within the menu.

| Item | Menu | Order | Page |
| --- | --- | --- | --- |
| `account` ("Account") | `account.dropdown` | -99 | `pages.index` |
| `id-code` ("Frigear ID") | `account` | 5 | `pages.idCode` |
| `profile` | `account`, `account.dropdown` | 10 | `pages.profile` |
| `security` | `account` | 20 | `pages.security` |
| `api-tokens` | `account` | 25 | `pages.apiTokens` |
| `documents` | `account` | 30 | `pages.documents` |

The source is registered for the `dashboard.account` menu.

## Page guard

With `@frigear-nu/authorization` installed, the module adds an `authenticated: true` route rule for `/account` and
`/account/**` (and each `/<locale>` prefix), so every page under it, including those other modules add (membership,
tickets, applications), is closed to guests. Set `authorization.redirectTo` to send guests to the login page instead of
a 401 error. Without the authorization module the pages are not guarded and the module logs a warning.

## Routes

None. The module registers no server routes.

## Translations

The module registers `da` and `en` locale files under the `account.*` namespace (key groups `title`, `menu.*`,
`identificationCode.*`, `profile.*`, `documents.*`, `security.*`; the full list is
`src/runtime/i18n/lang/en.json`). Without `@nuxtjs/i18n` the English defaults are used. Override strings in your app's
`i18n/locales/<code>.json`, see
[overriding module strings](/modules/module-kit#overriding-module-strings-in-your-app):

```json
{ "account": { "profile": { "title": "My details" } } }
```
