A generic admin area [Nuxt module](https://nuxt.com/docs/4.x/guide/modules). It owns **no domain features**: it
provides the shell (an `admin` layout with a sidebar), a guarded dashboard page and the places other modules plug into.
Domain admin UIs (forms, events, OAuth applications, users, ...) stay in their own modules and register here.

It builds on [`@frigear-nu/menu`](/modules/menu) (the sidebar is the `admin.nav` menu) and
[`@frigear-nu/widget`](/modules/widget) (the dashboard is the `admin.dashboard` area), and uses
[`@frigear-nu/authorization`](/modules/authorization) for the guard when it is installed. `@nuxt/ui` and `nuxt-auth-utils` (the signed-in user is shown in the header) are required.

## Quick Setup

```ts
export default defineNuxtConfig({
  modules: ['@nuxt/ui', '@frigear-nu/authorization', '@frigear-nu/admin'],
  admin: {
    settings: {
      base: '/admin',                        // path prefix of the area
      dashboard: true,                       // the page at `base`; false = off, or a custom path
      roles: ['admin', 'manager'],           // route rule on `<base>/**` (default ['admin']); false = no rule
      layout: true,                          // give pages under `base` the `admin` layout
    },
  },
})
```

- **Guard** - with `@frigear-nu/authorization` installed, `<base>/**` gets the route rule `{ roles }` (an explicit rule
  of yours wins). Without it the pages are not guarded on the client and a warning is logged. API routes are guarded by
  the modules that own them.
- **Layout** - every page whose path is under `base` (including other modules' pages) gets the `admin` layout unless
  it picked its own.

## Contributing

Modules never import the admin module at runtime; they use the two generic registries:

```ts
import { extendAdminNav, extendAdminDashboard } from '@frigear-nu/admin/utils'

// in a module's setup()
extendAdminNav(nuxt, { label: 'Forms', to: '/admin/forms', icon: 'i-lucide-clipboard-list', order: 20 })
extendAdminDashboard(nuxt, { component: resolver.resolve('./runtime/app/widgets/Submissions.vue'), order: 10 })
```

These are `extendMenu(nuxt, 'admin.nav', ...)` and `extendWidgets(nuxt, 'admin.dashboard', ...)`; a module can call those
directly (or push into `admin.nav` from a menu source) without depending on this package.

## UI conventions

Every `/admin/**` page uses the same flat, bordered look: no tinted cards, borders from `border-default`. The module
registers the building blocks globally, so a page's markup is the same everywhere. Modules that ship admin pages
declare `@frigear-nu/admin` as an optional module dependency (and `@frigear-nu/ui` for `useConfirmDialog`); a host
that enables those pages installs both.

| Component | Use |
| --- | --- |
| `<AdminPage>` | Page root; vertical rhythm (`space-y-6`). |
| `<AdminPageHeader>` | Title, `description`, `back="{ label, to }"` link for detail pages, `#actions` for buttons (the primary action goes last). |
| `<AdminToolbar>` | Row of search and filter controls above a table. |
| `<AdminTable>` | Bordered `UTable`; `#empty` and `#<column>-cell` slots pass through, `loading` and `@select` (row click) supported. |
| `<AdminSection>` | Bordered block with an optional `title`/`description`, `#actions`, `#footer`, and a `#flush` slot for edge-to-edge content such as a table. |
| `<AdminEmpty>` | Empty state: `icon`, `title`, `description` and a default slot for an action. |

```vue
<template>
  <AdminPage>
    <AdminPageHeader title="Events">
      <template #actions>
        <UButton icon="i-lucide-plus" label="New event" @click="creating = true" />
      </template>
    </AdminPageHeader>

    <AdminTable :data="events" :columns="columns" @select="open">
      <template #empty>
        <AdminEmpty icon="i-lucide-calendar" title="No events yet" />
      </template>
    </AdminTable>
  </AdminPage>
</template>
```

Rules of thumb:

- **Lists** are tables (`AdminTable`), with row actions in the last column; a row click opens the detail page.
- **Detail pages** use `AdminPageHeader` with `back`, then `AdminSection` blocks. A form that sits in a section puts its
  Save button in the section's `#footer` (`type="submit"` with `form="<id>"`).
- **Modals** keep their buttons in the `#footer` slot (Cancel `variant="subtle" color="neutral"`, then the primary action).
- **Destructive actions** ask first with `useConfirmDialog()` from `@frigear-nu/ui` (`destructive: true`), never
  `window.confirm`.
- **Errors**: page-level problems use `UAlert color="error" variant="subtle"`; failed actions use a toast.
- Text goes through `useModuleT` with an English default, and form-field hints use `UFormField`'s `description`.

Without widgets, the dashboard shows a card for every navigation entry.
