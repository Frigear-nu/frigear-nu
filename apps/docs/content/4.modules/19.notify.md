Notification driver/dispatch [Nuxt module](https://nuxt.com/docs/4.x/guide/modules). Lets feature modules (e.g.
[`@frigear-nu/users`](/modules/users)) dispatch email/SMS/simple notifications, and push UI toasts, without ever
deciding how they're delivered - that choice (and configuration) belongs to the app/consuming layer.

## Quick Setup

### Installation

```bash
pnpm add @frigear-nu/notify
```

To add from the workspace, use `workspace:*` instead of a version number in `package.json`:

```json
{
  "dependencies": {
    "@frigear-nu/notify": "workspace:*"
  }
}
```

## Usage in Modules

Other modules declare `@frigear-nu/notify` as a `moduleDependency`, so it's installed automatically wherever they're
used - you don't need to add it to `modules` yourself unless you want to configure it.

## Drivers

A driver is just a function that knows how to actually deliver a notification - log it, hand it to Resend, talk to
an SMTP server, forward it to `@nuxt/ui`'s `useToast`, etc. Each notification type is configured independently under
the `notify` key in `nuxt.config.ts`:

- `email`, `sms`, and `simple` all default to the built-in `log` driver (logs the notification instead of actually
  sending it) - a safe default for development/unconfigured setups.
- `ui` has no default - there's no sensible UI to push notifications to unless you configure one.

Only the configured driver for each notification type is ever resolved and loaded - unconfigured or unused drivers
(e.g. the `ui` driver when `notify.ui` isn't set) are never bundled, to keep the client bundle small.

```ts
export default defineNuxtConfig({
  notify: {
    email: {
      // Name of a built-in driver (`'log'`, the default) or a path to a function (default
      // export) matching the `EmailDriver` signature, for a real provider (Resend, SMTP, ...).
      driver: '~/server/utils/resend-email-driver',
    },
    sms: {
      // Matching the `SMSDriver` signature, for a real provider (Twilio, ...).
      driver: '~/server/utils/twilio-sms-driver',
    },
    simple: {
      // Matching the `SimpleDriver` signature, for generic, transport-agnostic notifications.
      driver: 'log',
    },
    ui: {
      // Built-in `'@nuxt/ui'` driver (forwards to `@nuxt/ui`'s `useToast`), or a path to a
      // function (default export) matching the `UIDriver` signature - a composable factory
      // invoked once, synchronously, during `useNotify()`'s own setup-time call.
      driver: '@nuxt/ui',
    },
  },
})
```

### UI Driver: `@nuxt/ui`

The built-in `@nuxt/ui` driver forwards `UINotification`s to [`useToast`](https://ui.nuxt.com/composables/use-toast).
It requires `@nuxt/ui` to be installed - an error is thrown at build time if `notify.ui.driver` is set to `'@nuxt/ui'`
without the module installed.

### Custom Driver

```ts
// server/utils/resend-email-driver.ts
import type { EmailDriver } from '@frigear-nu/notify/types'

const sendWithResend: EmailDriver = async (notification) => {
  // ... call your provider's API with notification.to/subject/body/text
}

export default sendWithResend
```

## Usage

### Server-side dispatch

`dispatchEmailNotification`, `dispatchSMSNotification`, and `dispatchSimpleNotification` are auto-imported
server-side wherever this module is installed:

```ts
await dispatchEmailNotification({
  to: user.email,
  subject: 'Welcome!',
  body: '<p>Thanks for signing up.</p>',
  text: 'Thanks for signing up.',
})

await dispatchSMSNotification({
  to: user.phone,
  body: 'Your verification code is 123456.',
})

await dispatchSimpleNotification({
  title: 'New signup',
  text: `${user.email} just signed up.`,
})
```

### UI notifications

When `notify.ui.driver` is configured, `useNotify` is auto-imported client-side to push `UINotification`s through the
configured UI driver:

```vue
<script setup lang="ts">
const notify = useNotify()

function onSuccess() {
  notify.addNotification(defineUINotification({
    title: 'Saved',
    text: 'Your changes have been saved.',
    type: 'success',
  }))
}
</script>
```
