---
title: Email Templates
description: Vue email templates for Notify, rendered with nuxt-email-renderer - typed sendEmailTemplate for the host, and module emails the host can override by file name.
---

Emails written as Vue components, rendered with [nuxt-email-renderer](https://nuxtemail.com) and sent through
[Notify](/modules/notify), as a [Nuxt module](https://nuxt.com/docs/4.x/guide/modules). It does two things:

- The host sends its own templates with a typed `sendEmailTemplate(name, props, message)`.
- Modules ([Auth](/modules/auth), [Users](/modules/users), [Subscriptions](/modules/subscriptions)) ship a template
  for every email they send. With this module installed, those emails are rendered from the templates. Without it, they
  go out as the plain HTML each module builds. The host overrides any module template by adding a file with the same
  name.

All the Vue rendering lives here: Notify and the feature modules stay free of Vue SSR.

::note
**Requires** `@frigear-nu/module-kit`, [`@frigear-nu/notify`](/modules/notify) and `nuxt-email-renderer`; all are
installed automatically.
::

## Quick setup

```ts
export default defineNuxtConfig({
  modules: ['@frigear-nu/email-templates'],
})
```

Add templates to `app/emails` (or `emails/`, or the `nuxtEmailRenderer.emailsDir` option). Every top-level `.vue` file
is a template, named by its file name. Build them from the [components](#components) so they match the module emails:

```vue [app/emails/welcome.vue]
<script setup lang="ts">
import { EmailButton, EmailDivider, EmailHeading, EmailLayout, EmailLinkFallback, EmailText } from '@frigear-nu/email-templates/components'

defineProps<{ name: string, url: string }>()
</script>

<template>
  <EmailLayout :preview="`Welcome, ${name}!`">
    <ESubject>Welcome, {{ name }}</ESubject>
    <EmailHeading>Welcome, {{ name }}!</EmailHeading>
    <EmailDivider />
    <EmailText>Thanks for signing up. Click the button below to get started.</EmailText>
    <EmailButton :href="url">Get started</EmailButton>
    <EmailLinkFallback :href="url" />
  </EmailLayout>
</template>
```

The `E*` components, `<ESubject>`, i18n (`$t` with `@nuxtjs/i18n`), `globalCss` and the DevTools preview all come
from [nuxt-email-renderer](https://nuxtemail.com). This module sets its `codeHighlighting` default to `false`, which
keeps Shiki out of the server bundle. Set `nuxtEmailRenderer.codeHighlighting: true` if you need `<ECodeBlock>`.

## Components

Styled building blocks, imported from `@frigear-nu/email-templates/components`. You have to import them: the renderer
registers only its own `E*` components globally. They use inline styles and table layout, because email clients do not
support CSS classes. Mix them freely with the renderer's `E*` components.

Every email has the same shape: a grey page, a white card with the logo header, the content, and a footer.

| Component | Props | Renders |
| --- | --- | --- |
| `EmailLayout` | `preview?`, `lang?` (`en`); slots: default, `footer` | The whole document: page, card, `EmailHeader` and `EmailFooter` (replace it with the `footer` slot) |
| `EmailHeader` | `logoUrl?` | Centred logo, 150px wide, or the brand name when no logo is configured |
| `EmailHeading` | `tone?: 'default' \| 'danger'` | The `h2` title; `danger` for security alerts |
| `EmailText` | `variant?: 'default' \| 'muted' \| 'small'` | A paragraph: body text, secondary text, fine print |
| `EmailButton` | `href`, `color?: 'primary' \| 'danger'` | Call-to-action button |
| `EmailLinkFallback` | `href`; slot for the lead-in | "Or copy this link to your browser: …" |
| `EmailDivider` | none | Horizontal rule |
| `EmailFooter` | slot | "This email was sent automatically for security reasons." |

Branding comes from the module options. Each option can also be set at runtime:

```ts
export default defineNuxtConfig({
  emailTemplates: {
    brandName: 'Frigear', // logo alt text, and the header when there is no logo
    logoUrl: '/logo.png', // absolute, or resolved against siteUrl
    siteUrl: 'https://frigear.nu',
    colors: { primary: '#2563eb', danger: '#dc2626' },
  },
})
```

| Environment variable | Option |
| --- | --- |
| `NUXT_EMAIL_TEMPLATES_BRAND_NAME` | `brandName` |
| `NUXT_EMAIL_TEMPLATES_LOGO_URL` | `logoUrl` |
| `NUXT_EMAIL_TEMPLATES_SITE_URL` | `siteUrl` |
| `NUXT_EMAIL_TEMPLATES_COLORS_PRIMARY`, `_DANGER` | `colors.primary`, `colors.danger` |

Use an absolute URL for the logo: mail clients cannot resolve relative paths.

## Server

`sendEmailTemplate` and `renderEmailTemplate` are auto-imported in server code.

```ts
await sendEmailTemplate('welcome', { name: user.name, url }, {
  to: user.email,
  replyTo: 'support@frigear.nu',
})
```

| Function | Signature |
| --- | --- |
| `sendEmailTemplate` | `(name, props, message) => Promise<void>`. Renders, then sends with `dispatchEmailNotification`. |
| `renderEmailTemplate` | `(name, props, { locale?, text? }) => Promise<{ subject?, body, text? }>`. Renders without sending. |

`message` is an `EmailNotification` without `body` (`to`, `replyTo`, `meta`), plus:

| Field | Purpose |
| --- | --- |
| `subject` | Overrides the template's `<ESubject>`. Required when the template has none. |
| `text` | Your own plain-text body, or `false` to send HTML only. By default it is rendered from the template. |
| `locale` | Locale to render with, when `@nuxtjs/i18n` is installed. |

The template names are typed, and so are each template's props. Both are generated into
`.nuxt/types/email-templates.d.ts` from every template the renderer will see, so a misspelled name or a missing prop
does not compile. Adding or removing a template in dev regenerates them.

## Module emails

A module dispatches its email exactly as before, with the plain HTML as the fallback, and names its template:

```ts
await dispatchEmailNotification({
  to,
  subject: 'Your sign-in link',
  body: `<p>…</p>`,
  text: `…`,
  template: { name: 'auth-magic-link', props: { name, url } },
})
```

The module ships the template, built from the [components](#components), and registers its directory with Notify's
`notify:email:templates` build hook. That hook
lives in Notify, so the module does not depend on this one:

```ts
// module setup()
nuxt.hook('notify:email:templates', sources => sources.push({ dir: resolver.resolve('./runtime/emails') }))
```

This module listens on Notify's `notify:email` runtime hook. When the notification names a template that exists, it
renders it and replaces `subject` (when the template has `<ESubject>`), `body` and `text`. If the template is missing,
or it throws or renders nothing, the error is logged and the fallback is sent. A broken template never blocks a sign-in
link.

Name module templates `<module>-<email>.vue` so they do not collide.

### Overriding a module template

Add a template with the same name to the app (or any layer) and it replaces the module's. Use the same props, and reuse
the components to keep the look. To only change the branding, use the [options](#components) instead.

```vue [app/emails/auth-magic-link.vue]
<script setup lang="ts">
import { EmailButton, EmailHeading, EmailLayout, EmailLinkFallback, EmailText } from '@frigear-nu/email-templates/components'

defineProps<{ name: string, url: string }>()
</script>

<template>
  <EmailLayout lang="da" preview="Dit login-link">
    <ESubject>Log ind på Frigear</ESubject>
    <EmailHeading>Hej {{ name }}</EmailHeading>
    <EmailText>Klik på knappen for at logge ind.</EmailText>
    <EmailButton :href="url">Log ind</EmailButton>
    <EmailLinkFallback :href="url">Eller kopier linket:</EmailLinkFallback>
  </EmailLayout>
</template>
```

Precedence, lowest to highest: module templates, then the layers' templates, then the app's.

| Template | Sent by | Props |
| --- | --- | --- |
| `auth-magic-link` | [Auth](/modules/auth): magic-link sign-in | `{ name, url }` |
| `auth-verify-email` | Auth: verify the address after registering | `{ name, url }` |
| `auth-password-reset` | Auth: forgot password | `{ url }` |
| `users-verify-email-change` | [Users](/modules/users): confirm a new email address | `{ name, url }` |
| `users-email-changed` | Users: notice to the old address, with an undo link | `{ name, newEmail, url }` |
| `users-password-changed` | Users: password changed notice | `{ name }` |
| `subscriptions-payment-link` | [Subscriptions](/modules/subscriptions): staff-sent payment link | `{ name, label, url }` |

## Bundle and runtime notes

- Rendering bundles Vue SSR and the template components into the Nitro server. Templates that a published module
  ships are inlined, so the Vue plugin compiles them.
- nuxt-email-renderer has no option for template directories outside the layers. This module therefore rebuilds its
  `#email-templates` virtual module with the module templates added underneath. It does not work with
  `experimental.nitroViteEnvironment` yet: in that mode the renderer only compiles `.vue` files from the layer
  directories.
