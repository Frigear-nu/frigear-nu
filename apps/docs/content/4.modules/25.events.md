Events and tickets as a [Nuxt module](https://nuxt.com/docs/4.x/guide/modules), built on
[`@frigear-nu/payments`](/modules/payments). It replaces the nuxt-content YAML events of the old app with database
tables, and handles **only** events and tickets; money is delegated to the payments module.

## Design

- **Prices live in the database** (minor units) and are charged through Checkout `price_data`; there are no Stripe ids
  to maintain per environment.
- **Ticket state follows payment state.** A paid ticket becomes `paid` only through the `payments:paid` hook, which is
  fed by verified Stripe events. Free tickets (total `0`) are issued immediately without Stripe.
- **Purchased tickets are snapshots.** Amount, currency and the chosen addons are copied onto the ticket, which has no
  foreign keys to the catalogue, so editing or deleting catalogue rows never changes what someone bought.
- **Staff access is the host's decision.** There is no shared permission system; see [Authorization](#authorization).

## Quick Setup

From the workspace use `"@frigear-nu/events": "workspace:*"`. Requires `@frigear-nu/payments` (and through it
`@frigear-nu/stripe` and `@frigear-nu/users`) and NuxtHub with KV. `@frigear-nu/subscriptions` and `@frigear-nu/menu`
are optional.

```ts
export default defineNuxtConfig({
  events: {
    settings: {
      pages: { events: true, event: true, tickets: true }, // '/events', '/events/:slug', '/account/tickets'
      reservationMinutes: 30, // how long an unpaid ticket keeps its seat (also the Stripe session lifetime)
    },
  },
})
```

Pages are opt-in and use [`@nuxt/ui`](https://ui.nuxt.com). With `@nuxtjs/i18n` installed, translated texts follow the
active locale; otherwise `en` is used.

## Translations

The module registers `da` and `en` locale files with [module-kit](/modules/module-kit#translations-i18n) under the
`events.*` namespace. Override any string in your app's `i18n/locales/<code>.json` (see
[overriding module strings](/modules/module-kit#overriding-module-strings-in-your-app)):

```json
{ "events": { "upcoming": { "title": "What's on" } } }
```

Key groups (parameters use `{name}`): `upcoming.*`, `ongoing.*`, `past.*`, `detail.*` (when, where and the ticket
purchase flow incl. `detail.tickets.payment.*`), `tickets.*` (including `tickets.status.*`), `cart.*`, plus top-level
messages such as `title`, `empty`, `loading`, `ticketReady`, `paymentReceived` and `purchaseFailed`. Without
`@nuxtjs/i18n` the English defaults are used.

## Data model

| Table                | Purpose                                                                                           |
| -------------------- | ------------------------------------------------------------------------------------------------- |
| `events`             | Slug, translated `name` / `description` / `body`, image, location, `startsAt` / `endsAt`, `status` (`draft`, `published`, `archived`), event-level `requiresMembership`. |
| `event_ticket_types` | Per event: `key`, name, `price` (`0` = free), `currency`, `hidePrice`, `capacity`, sale window, `maxPerUser`, `requiresMembership`, `isDefault`. |
| `event_addon_groups` | Per ticket type, e.g. "Food": `required` (pick at least one) and `multiple` (pick several).         |
| `event_addons`       | Choices in a group with their own `price` and optional `capacity`.                                 |
| `event_tickets`      | Purchased/reserved tickets: status, snapshot, `paymentId`, QR `code`, `checkedInAt`.               |

Translated texts are either a string or a `{ da, en }` map. `requiresMembership` is `null` (everyone), `'any'` (any
active subscription) or a list of plan keys.

::warning
Every host app and test fixture must generate and commit a migration for these tables (and the payments / users /
subscriptions tables it uses). See [Module Kit](/modules/module-kit) and the repository `AGENTS.md`.
::

## Purchase rules

`POST /api/events/:slug/purchase` with `{ ticketTypeId, addonIds? }` checks, in order: the event is published and not
over; the sale window; membership at **event and ticket level** (fails closed when `@frigear-nu/subscriptions` is not
installed); required/single-choice addon groups; addon capacity; the `events:purchase:before` hook; `maxPerUser`; ticket
capacity.

Capacity counts `paid` tickets plus `pending` ones inside the reservation window. D1 has no interactive transactions, so
after inserting the ticket the module verifies that it is among the first `capacity` seat holders (insertion order) and
removes it if it lost a race. An expired or failed payment frees its seat.

## Routes

Public: `GET /api/events`, `GET /api/events/:slug` (includes per-user `blocked` flags when signed in).

Signed-in: `POST /api/events/:slug/purchase`, `GET /api/events/tickets/me`, `GET /api/events/tickets/:id` (poll after
returning from Stripe), `POST /api/events/tickets/:id/pay` (resume payment).

Staff (see below): `POST /api/events/check-in` `{ code }`; `GET|POST /api/events/admin/events` (POST accepts the whole
nested catalogue), `PATCH|DELETE /api/events/admin/events/:id`, `GET /api/events/admin/events/:id/tickets` (attendees),
CRUD for `ticket-types`, `addon-groups` and `addons`, and `POST /api/events/admin/tickets/:id/cancel|refund`.

Check-in is idempotent: a second scan returns `alreadyCheckedIn` with the first scan time. Only `paid` tickets validate.
A refund starts at Stripe and the ticket turns `refunded` when `charge.refunded` arrives.

## Authorization

Staff routes are **denied by default**. Implement the `events:authorize` hook in the host app:

```ts
export default defineNitroPlugin((nitro) => {
  nitro.hooks.hook('events:authorize', async (ctx) => {
    ctx.allowed = await isEventStaff(ctx.userId)
  })
})
```

## Hooks

| Hook                      | When                                                                  |
| ------------------------- | --------------------------------------------------------------------- |
| `events:authorize`        | Staff gate (above).                                                   |
| `events:purchase:before`  | Throw to deny a purchase with host rules.                             |
| `events:ticket:paid`      | A ticket became paid (free tickets immediately). Send confirmations here. |
| `events:ticket:refunded`  | A ticket was fully refunded.                                          |

## App layer

Composables `useEvents()` (grouped ongoing/upcoming/past), `useEvent(slug)` (with `purchase()`), `useMyTickets()`;
components `EventCard`, `EventTicketPicker` and `EventTicketCard` (QR code); opt-in pages; and a "Tickets" item in the
`dashboard.account` menu when `@frigear-nu/menu` is installed.

## Not included

An admin UI, ticket confirmation emails (use `events:ticket:paid`) and import of tickets from the old app.

## Admin pages

Opt-in staff pages (`settings.pages.admin`, default `/admin/events`, and `settings.pages.adminEvent`, default
`/admin/events/:id`): the event list with a create dialog, and an event page for its details, ticket types and
attendees (cancel or refund a ticket). They are listed in the `admin.nav` menu, so
[`@frigear-nu/admin`](/modules/admin) shows them in its sidebar, and the Tickets entry appears on the account
dashboard. The API behind them is gated by the `events:authorize` hook (denied by default):

```ts
export default defineNitroPlugin((nitro) => {
  nitro.hooks.hook('events:authorize', async (ctx) => {
    ctx.allowed = await isEventStaff(ctx.userId)
  })
})
```

`GET /api/events/admin/events/:id` returns one event with all of its ticket types, whatever its status.
