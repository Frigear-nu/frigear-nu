Named, shareable navigation menus [Nuxt module](https://nuxt.com/docs/4.x/guide/modules). A **menu** (`main`,
`dashboard`, `account`, ...) is a named collection of items, filled by one or more **sources** - Nuxt Content (e.g. the
`main` website navigation), other modules (at build time, or dynamically at runtime), or both at once - and rendered
by different **views** (`MenuBar`, `MenuCards`). Data never encodes presentation: `description`/`icon` are optional
fields a view may use or ignore.

## Quick Setup

### Installation

```bash
pnpm add @frigear-nu/menus
```

To add from the workspace, use `workspace:*` instead of a version number in `package.json`:

```json
{
  "dependencies": {
    "@frigear-nu/menus": "workspace:*"
  }
}
```

## Vocabulary

- **Menu** — a named collection of items (`main`, `dashboard`, `account`, ...).
- **Source** — anything that fills a menu: Nuxt Content, `extendMenu`, or a module's `runtime/menus.ts` file.
- **Group** — the part after a menu's first dot. `dashboard.more` addresses group `more` of menu `dashboard`.
- **View** — a presentation component (`MenuBar`, `MenuCards`) rendering a menu's items.

## Usage in Modules

Other modules can declare `@frigear-nu/menus` as an optional `moduleDependency` (see
[`@frigear-nu/account`](/modules/users)'s dashboard tiles for an example), so it's only required when the host app
actually wants its contributed items rendered somewhere.

### Static items, known at build time

```ts
import { createResolver, defineNuxtModule } from '@nuxt/kit'
import { extendMenu } from '@frigear-nu/menus/utils'

export default defineNuxtModule({
  meta: { name: '@frigear-nu/example' },
  setup(options, nuxt) {
    // `'dashboard.more'` is parsed as menu `dashboard`, group `more` (split on the first dot only).
    extendMenu(nuxt, 'dashboard.more', [
      { label: 'Billing', description: 'Manage your subscription', to: '/billing' },
    ])
  },
})
```

### Dynamic items, needing runtime context (e.g. `useRuntimeConfig`)

```ts
import { createResolver, defineNuxtModule } from '@nuxt/kit'
import { registerMenuSource } from '@frigear-nu/menus/utils'

export default defineNuxtModule({
  meta: { name: '@frigear-nu/example' },
  async setup(options, nuxt) {
    const resolver = createResolver(import.meta.url)

    await registerMenuSource(nuxt, {
      resolver,
      file: './runtime/menus',
      menu: 'dashboard',
    })
  },
})
```

```ts
// runtime/menus.ts
import { defineMenuSource } from '@frigear-nu/menus/utils'

export default defineMenuSource((items) => {
  const config = useRuntimeConfig().public.example

  // Pushed into the `dashboard` menu's root group.
  if (config?.enabled) items.push({ label: 'Example', to: '/example' })

  // Pushed into a named group (in this or another menu) instead - created automatically if it
  // doesn't already exist. `extendMenuItem` is auto-imported, no need to import it explicitly.
  extendMenuItem('dashboard.more', { label: 'Security', to: '/security' })
})
```

Registration order between modules doesn't matter for either approach - items are only merged once every module has
finished setting up.

## Nuxt Content source

Enable the `@nuxt/content`-backed source for a menu under the `menus` key in `nuxt.config.ts` (requires
[`@nuxt/content`](https://content.nuxt.com) to be installed - a clear build-time error is thrown otherwise):

```ts
export default defineNuxtConfig({
  menus: {
    content: {
      // Reads `config.navigation` - the collection/field defined by `@frigear-nu/base` (see
      // the base layer docs) - as the `main` menu's base items.
      main: true,
      // ...or a custom collection/field:
      dashboard: { collection: 'dashboard', field: 'tiles' },
    },
  },
})
```

Content items are localized automatically when `@nuxtjs/i18n` is configured with `locales`, following the same
`config` → `config_en` collection-suffix convention used by `@frigear-nu/base`.

## Reading/rendering a menu

`useMenu` is auto-imported, and returns the same shape as [`useAsyncData`](https://nuxt.com/docs/4.x/api/composables/use-async-data)
(`{ data, pending, error, refresh }`), re-evaluating when the content locale changes:

```vue
<script setup lang="ts">
const { data: items } = useMenu('main')
const { data: more } = useMenu('dashboard.more')
</script>

<template>
  <MenuBar menu="main" />
  <MenuCards menu="account" />
</template>
```

Items are sorted by `order` (ascending; items without an `order` render last, in registration order).
