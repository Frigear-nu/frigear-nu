Named widget areas [Nuxt module](https://nuxt.com/docs/4.x/guide/modules), modelled on [`@frigear-nu/menu`](/modules/menu).
An **area** (`admin.dashboard`, `home.sidebar`, ...) is a named slot in a page. Modules **contribute widgets** (Vue
components) to it at build time and the host renders the area wherever it likes; neither side knows about the other.
The data is presentation-free and the components are loaded lazily, so an area only ships the widgets it renders.

## Quick Setup

```bash
pnpm add @frigear-nu/widget
```

```ts
export default defineNuxtConfig({
  modules: ['@frigear-nu/widget'],
})
```

## Contributing widgets

Call `extendWidgets` once in a module's `setup()`; registration order between modules doesn't matter.

```ts
import { createResolver, defineNuxtModule } from '@nuxt/kit'
import { extendWidgets } from '@frigear-nu/widget/utils'

export default defineNuxtModule({
  setup(_options, nuxt) {
    const resolver = createResolver(import.meta.url)
    extendWidgets(nuxt, 'admin.dashboard', {
      component: resolver.resolve('./runtime/app/widgets/NewMembers.vue'),
      order: 10,       // lower first; unordered last
      span: 2,         // grid columns in the default layout (1-4)
      props: { days: 30 },
      requires: 'admin', // free-form, for the filter hook below
    })
  },
})
```

The `id` defaults to the component's file name. Registering the same `id` in an area again replaces the earlier
widget, which is how a host overrides a module's widget.

## Rendering an area

```vue
<WidgetArea name="admin.dashboard">
  <template #empty>Nothing to show yet.</template>
</WidgetArea>
```

The default layout is a responsive grid; use the `item` slot (`{ widget, component }`) to lay the widgets out yourself,
or `useWidgets('area')` (same shape as `useAsyncData`) to read the widgets as data.

Both `<WidgetArea>` and `useWidgets` take an optional `context` (e.g. `{ user }`). Every entry is passed to each widget
as a prop, after the static `props`, and the context reaches the `widgets:filter` listeners as `ctx.context`.

## Tabs

Tabs are a second registry next to widgets: they live in their own list (the same area name can hold both), with the
same ordering, replacement and gating. A **tab area** is rendered as a tab list with the active tab's component below.
Modules contribute with `extendTabs`:

```ts
import { extendTabs } from '@frigear-nu/widget/utils'

extendTabs(nuxt, 'admin.users', {
  id: 'payments',                        // defaults to the component file name; used as the `?tab=` value
  component: resolver.resolve('./runtime/app/tabs/Payments.vue'),
  order: 20,                             // lower first; unordered last
  label: 'Payments',                     // plain fallback label (defaults to the id)
  labelKey: 'payments.admin.tab',        // i18n key, translated when `@nuxtjs/i18n` is installed
  icon: 'i-lucide-credit-card',
  requires: 'billing',                   // free-form, for the `tabs:filter` hook
})
```

Many modules can register into the same area. The host renders it with `<WidgetTabs>`:

```vue
<WidgetTabs name="admin.users" :context="{ user }" @refresh="refresh">
  <template #empty>No tabs.</template>
</WidgetTabs>
```

The active tab is kept in the `?tab=` query parameter. Each tab component receives its static `props`, then every entry
of `context` as a prop, and may emit `refresh`, which `<WidgetTabs>` re-emits so the host can reload its data. Read the
tabs as data with `useTabs('area', context)`; labels come back translated. Gate tabs with the `tabs:filter` runtime hook
(`ctx.tabs`, `ctx.context`), exactly like `widgets:filter`. Build-time hooks are `tabs:extend` and `tabs:resolved`.

## Gating widgets

The module never interprets `requires`. Listen to the `widgets:filter` runtime hook and drop what the current visitor
shouldn't see:

```ts
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook('widgets:filter', (ctx) => {
    const role = useUserSession().user.value?.role
    ctx.widgets = ctx.widgets.filter(widget => !widget.requires || widget.requires === role)
  })
})
```

::warning
Filtering only hides UI. Always enforce permissions on the server for the data a widget loads.
::
