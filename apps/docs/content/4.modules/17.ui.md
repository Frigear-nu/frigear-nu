title: UI

The shared building blocks for Frigear screens: the page components every admin and account page is made of (headings,
tabs, cards, tables, row menus, slideover forms), form inputs, a confirmation dialog, and the composables and helpers
for toasts, formatting, links and translated text. The module registers the components globally and auto-imports the
composables and helpers. How the pieces fit together is described in [UX patterns](/getting-started/ux-patterns).

::note
**Requires** `@nuxt/ui` and [`@frigear-nu/module-kit`](/modules/module-kit); both are installed automatically as module
dependencies.
**Optional** `nuxt-monaco-editor` (only `MonacoCodeEditor` needs it: install it when you use that component) and
`@nuxtjs/i18n`: when installed, the module contributes shared `da` and `en` strings and the locale composables follow
the active locale.

The module has no options. It registers its own `runtime` folder as a Tailwind source, so the classes the components
use are generated without any configuration in the host. Its playground at `packages/ui/playground` is for developing
and previewing components.
::

## Quick setup

```ts
export default defineNuxtConfig({
  modules: ['@frigear-nu/ui'],
})
```

## App

### Page components

The components behind every admin and account page. They are registered globally, with no prefix (`ConfirmDialog` is
the exception: it is lazy-imported and normally opened through `useConfirmDialog`). They carry structure
and spacing only; colours and radius come from Nuxt UI. Every built-in string can be replaced by a prop, and the
defaults are translated (see [the `patterns` strings](#the-patterns-strings)).

| Component | Props | Slots | Use | Replaces |
| --- | --- | --- | --- | --- |
| `PageHeading` | `title?`, `description?`, `breadcrumb?: string \| BreadcrumbItem[]` | `title`, `badge`, `description`, default (meta row), `actions` | Title block of an app page. A string `breadcrumb` is a plain label above the title; an array renders breadcrumbs (`[{ label: 'Users', to: '/admin/users' }, { label: 'Ada' }]`). Title size is `text-xl sm:text-2xl font-semibold`. | `AdminPageHeader` (`back` is now `breadcrumb`) |
| `PageTabs` | `items: (NavigationMenuItem & { value? })[]`, `v-model?` | none | Tabs under a heading. **Link mode** when items have `to` (each tab is a route); **state mode** with `v-model` (matches `value`). A bordered strip with an underline highlight; scrolls sideways on narrow screens and hides icons below `sm`. | `UTabs` used for page sections |
| `SectionCard` | `title?`, `description?`, `icon?`, `loading?`, `flush?` | `header`, `actions`, default, `footer` | A framed block of a page. `flush` removes the body padding for edge-to-edge content such as a list. A form's Save button goes in `footer`. | `AdminSection`, `UPageCard` as a form frame |
| `TableCard` | `loading?` | default (the `UTable`), `header`, `footer` | The framed surface a table sits in; `footer` holds total and pagination. There is deliberately no generic table wrapper: write `<TableCard><UTable :ui="tableUi()" /></TableCard>` so `UTable`'s own slot typing stays intact. | `AdminTable` surface |
| `RowMenu` | `items: DropdownMenuItem[] \| DropdownMenuItem[][]`, `subject?`, `variant?: 'ghost' \| 'outline'`, `size?` | none | The `⋯` menu of a table row or heading. Stops click propagation so it does not trigger the row's click; its accessible name is "Actions for {subject}". Use `variant="outline"` in a heading. | Loose row icon buttons, per-module dropdowns |
| `StatCard` | `label`, `value?`, `hint?`, `icon?`, `to?`, `loading?`, `empty?` | default (overrides `value`) | A number with a label and optional icon. `to` makes the card a link to the list it summarises. Shows `empty` when there is no value. | `AdminStatCard` |
| `ListCard` | `title`, `description?`, `loading?`, `isEmpty?`, `empty?`, `to?`, `toLabel?` | default (`<li>` rows), `actions` | A card with a short divided list and a "view all" link; `toLabel` defaults to the translated "View all". | `AdminListCard` |
| `DescriptionList` | `items: { key?, label, value? }[]`, `empty?`, `loading?`, `align?` | one slot per `key` | Label and value rows for key facts. A missing value shows "Not set" (or `empty`). | `AdminKeyValue` |
| `PageToolbar` | none | default (search and filters), `right` | The row of search and filter controls above a table. | `AdminToolbar` |
| `FormSlideover` | `title`, `description?`, `formId`, `submitLabel`, `loading?`, `disabled?` | default (the form) | A `USlideover` for create and edit forms. Footer: Cancel (`color="neutral" variant="outline"`) and a submit button wired to `form="<formId>"`. Emits `close`. | Create and edit modals |
| `ConfirmDialog` | `title?`, `description?`, `confirmText?`, `cancelText?`, `destructive?`, `dismissible?` | none | The modal behind `useConfirmDialog`; emits `close(boolean)`. Cancel is neutral and outlined, and defaults are translated. | Per-module delete modals |

There is no empty-state component and no page wrapper:

- Empty states are Nuxt UI's `UEmpty`: `variant="naked"` inside a card, naming the thing and offering exactly one action.
- A page root is `<div class="flex flex-col gap-4">`.

```vue
<script setup lang="ts">
const t = useModuleT('users')
const { data: user } = await useFetch(`/api/users/${useRoute().params.id}`)
const actions = useUserActions()
</script>

<template>
  <div class="flex flex-col gap-4">
    <PageHeading
      :title="user.name"
      :breadcrumb="[{ label: t('admin.users', 'Users'), to: '/admin/users' }, { label: user.name }]"
    >
      <template #badge>
        <UBadge :color="statusColor(user.status)" :label="user.status" />
      </template>
      <template #actions>
        <RowMenu :items="actions.menu(user)" :subject="user.name" variant="outline" />
      </template>
    </PageHeading>

    <SectionCard :title="t('admin.details', 'Details')">
      <DescriptionList
        :items="[
          { label: t('admin.email', 'Email'), value: user.email },
          { label: t('admin.phone', 'Phone'), value: user.phone },
        ]"
      />
    </SectionCard>
  </div>
</template>
```

### Form inputs

Global inputs are registered everywhere, with no prefix. All of them use `v-model`.

| Component | Model | Props | Purpose |
| --- | --- | --- | --- |
| `CurrencyInput` | `string` (currency code, default `'EUR'`) | `currencies?: Currency[]` | Currency select; every ISO currency the runtime knows unless `currencies` is given. |
| `MoneyInput` | `{ currency, amount }` (amount in minor units, default `{ currency: 'EUR', amount: 0 }`); also `v-model:amount` (major units) and `v-model:currency` | `currencies?: Currency[]` | Amount plus currency, converted to and from minor units. |
| `DateInput` | `Date \| string \| number \| undefined` | `type?: 'date' \| 'string'` (default `'date'`) | Date picker; emits a `Date`, or an ISO string with `type="string"`. |
| `IntervalInput` | `number` (seconds, default `86400`) | none | Amount plus minutes/hours/days unit; at least 60 seconds. |
| `TagInput` | `string[]` | `placeholder?`, `searchPlaceholder?`, `multiple?` (default `true`) | Create and pick tags. |
| `UrlInput` | `string` | none | URL field that requires `http://` or `https://`; emits `success(url)` for a valid value. |
| `IconInput` | `string` | `formItem?` | Iconify icon picker. |
| `SwitchToggle` | `boolean` | none | Switch. |
| `MarkdownTextarea` | `string` | `placeholder?`, `rows?`, `required?`, `disabled?`, `preview?`, `mdc?`, `mdcData?` | Textarea with an optional Write / Preview toggle. `mdc` renders the preview with MDC when the host provides it, `mdcData` feeds `{{ name }}` variables. |
| `TranslatedInput` | `Translated \| null \| undefined` | `placeholder?`, `multiline?`, `rows?`, `preview?` (default `true`), `mdc?`, `mdcData?`, `required?`, `disabled?` | Edits one string or a per-locale map, with a row per locale (configured locales plus any added by hand). |
| `MonacoCodeEditor` | `string` | `language?` (`'typescript'`), `height?` (`'160px'`), `fullscreen?` (`true`) | Monaco editor, optionally in a modal. |

`MonacoCodeEditor` needs the optional `nuxt-monaco-editor` module; install and register it in the host before using
the component.

### Composables and helpers

Everything below is auto-imported in a Nuxt app. The same helpers are also importable from `@frigear-nu/ui/composables`
and `@frigear-nu/ui/utils`, for code outside the Nuxt app.

#### Confirmations

```ts
interface ConfirmDialogOptions {
  title: string
  description?: string
  confirmText?: string // default 'Confirm'
  cancelText?: string // default 'Cancel'
  destructive?: boolean // style the confirm button as destructive
}

useConfirmDialog(): (options: ConfirmDialogOptions) => Promise<boolean> // true = confirmed, false = cancelled
```

`useConfirmDialog` is built on Nuxt UI's `useOverlay`. The dialog is not dismissible by clicking outside or pressing
escape, so the promise only resolves through the Cancel or confirm button; it is destroyed once it closes.

Every destructive action follows one convention: the title names the record, the description says what else is
affected, the confirm button names the verb and the object, and `destructive: true` styles it red.

```vue
<script setup lang="ts">
const confirm = useConfirmDialog()

async function removeApplication(app: { id: string, name: string }) {
  const confirmed = await confirm({
    title: `Delete ${app.name}?`,
    description: 'Every token issued to it stops working. This cannot be undone.',
    confirmText: 'Delete application',
    destructive: true,
  })
  if (!confirmed) return
  await $fetch(`/api/oauth/applications/${app.id}`, { method: 'DELETE' })
}
</script>
```

#### Errors, actions and clipboard

```ts
errorMessage(e: unknown, fallback?: string): string // see below
errorToToast(e: unknown, overrides?: Partial<ToastProps>): Partial<ToastProps> // an error toast carrying errorMessage(e)
useErrorToast(): (e: unknown, overrides?: Partial<ToastProps>) => void // toast.add(errorToToast(e, overrides))

useAction(): {
  busy: Ref<boolean>
  run<T>(fn: () => Promise<T>, options?: { success?: string | Partial<ToastProps> }): Promise<T | undefined>
}

useCopyToClipboard(): { copy(text: string): Promise<void> } // copies and shows a "Copied" toast
```

- `errorMessage` reads, in order, `statusMessage`, `data.message`, `data.statusMessage`, `response._data.message` and
  `message`, so it understands `$fetch` errors, `createError` payloads and plain `Error`s. It returns the fallback
  (by default the translated `patterns.genericError`) when there is nothing to read.
- `useAction().run` sets `busy` while `fn` runs, shows the `success` toast when it resolves, shows an error toast when
  it throws, and always clears `busy`. It replaces hand-written try / catch / saving blocks.
- `useCopyToClipboard` uses VueUse's `useClipboard` under the hood.

```vue
<script setup lang="ts">
const { busy, run } = useAction()
const { copy } = useCopyToClipboard()

const revoke = (id: string) => run(() => $fetch(`/api/tokens/${id}`, { method: 'DELETE' }), { success: 'Token revoked' })
</script>
```

#### Formatting and links

```ts
// utils: pure functions; accept a Date, an ISO string or a timestamp. `locale` defaults to English
formatDate(value, locale?): string
formatDateTime(value, locale?): string
formatTime(value, locale?): string
formatDateRange(start, end, locale?): string

useFormat(): { formatDate, formatDateTime, formatTime, formatDateRange, money } // same functions, locale already bound
// money(15000, 'DKK') is formatMoney from @frigear-nu/ui/money with the locale bound; amounts are in minor units

useLocaleLink(): {
  localize(to: string): string // prefixes the active locale when @nuxtjs/i18n is installed; unchanged otherwise
  strip(path: string): string // removes a leading locale code
  isActive(to: string, options?: { exact?: boolean }): boolean // the current route is `to` or below it
}

useNavLinks(items: MaybeRefOrGetter<MenuItem[]>, options?: { exact?: string[] }): ComputedRef<NavigationMenuItem[]>
```

- Always format dates and money through `useFormat()` so they follow the active locale. Set `frigearUi: { timeZone: 'Europe/Copenhagen' }` in the host `app.config.ts`: without it a UTC server and a visitor's browser format the same instant differently (hydration mismatch).
- `useLocaleLink` is not called `useLocalePath` so it never clashes with `@nuxtjs/i18n`'s own composable. Use it for
  every link a module builds, so a visitor on `/da/...` stays under `/da`.
- `useNavLinks` turns menu items (from `useMenu`) into `NavigationMenuItem`s with a localised `to` and a computed
  `active` flag. Paths in `exact` only match exactly, for items such as a dashboard at the area's base path. The admin
  sidebar, the account navigation and the site header all use it.

#### Status and styling

```ts
statusColor(status: string, overrides?: Record<string, BadgeColor>): BadgeColor
// success: published, active, trialing, paid, succeeded
// warning: pending, past_due, incomplete, scheduled
// error:   failed
// neutral: everything else

surfaceClass // 'bg-elevated/50 ring ring-default rounded-lg overflow-hidden', the frame of every card
tableUi(): TableProps['ui'] // the shared UTable styling used inside TableCard
```

`statusColor` makes status badges the same colour on every page: `<UBadge :color="statusColor(event.status)" :label="event.status" />`.
Pass `overrides` to recolour a module-specific status.

#### Translated text and locale

```ts
useTranslatedLocale(): ComputedRef<string> // the visitor's locale; `en` without @nuxtjs/i18n
useTranslatedLocales(): ComputedRef<string[]> // locales content can be translated into; ['en'] without @nuxtjs/i18n
useTranslatedFallbackLocale(): ComputedRef<string> // the default locale, used when a text lacks the current one
useUiT(namespace: string): (key: string, fallback: string, params?: Record<string, string | number>) => string

stripLocale(path: string, codes: string[]): string // '/da/events' with ['da', 'en'] -> '/events'
```

`useUiT` is an optional-i18n translator: it returns the message when `@nuxtjs/i18n` has the key, otherwise the English
fallback with `{name}` params replaced. The components use it, which is how every built-in string is translated
without making `@nuxtjs/i18n` required.

### Per-entity actions

`@frigear-nu/ui` provides the pieces; the actions for an entity live in the module that owns it, as a
`use<Entity>Actions()` composable: `create` and `edit` open a `FormSlideover` through `useOverlay()` and resolve with
the saved record (or `false`), `remove` confirms, toasts and refreshes, and `menu(record, { extra, onRemoved })` returns
the `RowMenu` items ordered Open, then edits, then the destructive action in its own red group. See
[UX patterns](/getting-started/ux-patterns#one-actions-composable-per-entity) for a full example.

## Translations

The module contributes shared `da` and `en` strings (when `@nuxtjs/i18n` is installed) that other modules and your app
reuse. Override any of them in your app's `i18n/locales/<code>.json` (see
[overriding module strings](/modules/module-kit#overriding-module-strings-in-your-app)); because other modules use
these keys, an override applies everywhere they appear.

| Namespace | Keys |
| --- | --- |
| `common` | `or`, `close`, `information`, `back`, `current`, `visit`, `refresh`, `expiresIn` |
| `actions` | `selectFiles`, `removeAllFiles`, `view`, `backTo`, `save`, `select`, `change`, `cancel` |
| `locale` | `switch` |
| `translated` | `translate`, `filled`, `missing`, `addLanguage`, `singleLanguage` (used by `TranslatedInput`) |
| `markdown` | `write`, `preview`, `empty` (used by `MarkdownTextarea`) |
| `patterns` | `notSet`, `moreActions`, `actionsFor`, `viewAll`, `copied`, `genericError`, `open`, `edit`, `delete` (used by the page components and helpers, [below](#the-patterns-strings)) |

```json
{ "actions": { "cancel": "Never mind" } }
```

### The `patterns` strings

The page components and helpers read the `patterns` namespace through `useUiT('patterns')`:

| Key | Used by |
| --- | --- |
| `notSet` | `DescriptionList` for a missing value ("Not set") |
| `moreActions` | `RowMenu` button label when no `subject` is given |
| `actionsFor` | `RowMenu` button label with a subject: "Actions for {subject}" |
| `viewAll` | `ListCard` link label (`toLabel`) |
| `copied` | `useCopyToClipboard` toast |
| `genericError` | `errorMessage` when an error carries no message |
| `open`, `edit`, `delete` | The standard labels of row-menu entries |

There are two ways to change one:

- **Per use**: every built-in string is also a prop (`empty` on `DescriptionList`, `toLabel` on `ListCard`,
  `subject` on `RowMenu`), so a single page can say something more specific.
- **Everywhere**: override the key in your app's `i18n/locales/<code>.json`. Other modules use these keys, so the
  override applies wherever they appear.

```json
{ "patterns": { "notSet": "Missing", "viewAll": "See everything" } }
```

Module-specific text does not belong here: modules ship their own namespace and read it with `useModuleT`.
