One-time payments on top of [`@frigear-nu/stripe`](/modules/stripe) and [`@frigear-nu/users`](/modules/users), as a
[Nuxt module](https://nuxt.com/docs/4.x/guide/modules). It is event-agnostic: other modules (for example
[`@frigear-nu/events`](/modules/events)) ask it to charge something and are told through hooks when the money arrives.

## Design

- **Stripe events are the only inbound signal.** The module has no webhook route and no signature handling of its own. It
  registers a handler with the core's [`registerStripeEventHandler`](/modules/stripe#in-a-module-build-time) and only
  `checkout.session.*` and `charge.refunded` events change a payment. The success redirect never marks anything as paid.
- **Prices are inline.** Checkout sessions use `price_data`, so there are no Stripe products or prices to keep in sync
  across production, staging and development.
- **Hooks, not coupling.** State transitions are announced through Nitro hooks; consumers filter on
  `payment.referenceType`.

## Quick Setup

From the workspace use `"@frigear-nu/payments": "workspace:*"`. It requires `@frigear-nu/stripe` and
`@frigear-nu/users` (and NuxtHub with `hub: { kv: true }`). Configure Stripe as described in
[Stripe](/modules/stripe#quick-setup).

```ts
export default defineNuxtConfig({
  modules: ['@frigear-nu/users', '@frigear-nu/stripe', '@frigear-nu/payments'],
  payments: {
    settings: { checkoutExpiresInMinutes: 30 }, // 30 - 1440, default 30
  },
})
```

## Database

One `payments` table: `id` (`pay_...`), `userId`, `status` (`pending | paid | failed | expired | refunded |
partially_refunded`), `amount` / `currency` (minor units), `description`, `referenceType` / `referenceId`,
`checkoutSessionId` (unique), `paymentIntentId`, `refundedAmount`, `metadata` (JSON), `paidAt`, `createdAt`, `updatedAt`.

::warning
Every host app (and test fixture) must generate and commit its own migration containing this table together with the rest
of its module configuration. See [Module Kit](/modules/module-kit) and the repository `AGENTS.md`.
::

## Server utils

Auto-imported in Nitro code:

| Util                                    | Description                                                                                                  |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `createPayment(input, event?)`          | Creates the Checkout session (`mode: 'payment'`) and a `pending` row. Returns `{ payment, url }`. Pass the request `event` to restrict `successUrl` / `cancelUrl` to the current origin. |
| `resumePayment(id, userId, event?)`     | Returns the open session's URL, or a fresh session once it expired. `409` when already paid.                  |
| `refundPayment(id, { amount? })`        | Asks Stripe for a (partial) refund. The status changes when `charge.refunded` arrives.                        |
| `getPayment`, `getPaymentByReference`, `listUserPayments` | Reads.                                                                                      |

`createPayment` takes `{ userId, items: [{ name, amount, currency, quantity? }], reference?: { type, id }, successUrl,
cancelUrl, description?, expiresInMinutes?, metadata? }`. Items must share one currency and sum above zero.

## Hooks

```ts
export default defineNitroPlugin((nitro) => {
  nitro.hooks.hook('payments:paid', ({ payment }) => { /* payment.referenceType, payment.referenceId */ })
})
```

| Hook                       | When                                                                          |
| -------------------------- | ----------------------------------------------------------------------------- |
| `payments:checkout:before` | Before the session is created; adjust `ctx.params` or throw to deny.          |
| `payments:paid`            | Once, when the payment became paid.                                           |
| `payments:failed`          | An asynchronous payment method failed.                                        |
| `payments:expired`         | The Checkout session expired unpaid.                                          |
| `payments:refunded`        | A refund changed the payment (`partially_refunded` or `refunded`).            |

Transitions are conditional updates, so a redelivered Stripe event emits nothing twice, and a `paid` payment is never
downgraded by a late `expired` event.

## Routes and composable

- `GET /api/payments` - the signed-in user's payments.
- `POST /api/payments/resume` with `{ paymentId }` - checkout URL for an unpaid payment.
- `usePayments()` - `{ payments, refresh, status, resume(paymentId) }`.

## Translations

The module registers `da` and `en` locale files with [module-kit](/modules/module-kit#translations-i18n) under the
`payments.*` namespace: `payments.status.<status>` display labels for each payment status and
`payments.defaultDescription`. API error messages stay English.

Override any of them in your app's `i18n/locales/<code>.json` (see
[overriding module strings](/modules/module-kit#overriding-module-strings-in-your-app)):

```json
{ "payments": { "status": { "partially_refunded": "Partly refunded" } } }
```

Status keys: `pending`, `paid`, `failed`, `expired`, `refunded`, `partially_refunded`.
