---
title: MCP Module
description: Modules contribute MCP tools that are only listed and callable within the scopes the caller holds, without leaking other people's personal data.
---

[Nuxt module](https://nuxt.com/docs/4.x/guide/modules) on top of
[`@nuxtjs/mcp-toolkit`](https://mcp-toolkit.nuxt.dev) and [`@frigear-nu/auth`](/modules/auth). It serves one MCP
endpoint (`/mcp`) for everybody. What a client sees in `tools/list` depends on who is calling: an
ordinary user sees their own tools, and staff tools only appear when the host's policy lets that user in.

Exposing tools is opt-in per module: a module only contributes its MCP tools when `settings.mcp` is `true`
(default `false`). This applies to `account`, `events`, `forms`, `subscriptions` and `oauthServer`:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  account: { settings: { mcp: true } },
  events: { settings: { mcp: true } },
})
```

Clients authenticate with a user API token (`Authorization: Bearer fnu_…`, created under
`/account/api-tokens`), an OAuth access token, or a cookie session.

## Rules every tool follows

- **Scopes.** Every definition declares the scopes it needs (the ones its module registers with `addAuthScope`).
  A token without them never sees the tool, and a direct call is refused.
- **Admin tools use the module's own gate.** `events:manage` plus the `events:authorize` host hook, `forms:manage`
  plus `forms:authorize`. Both must pass, on every listing and every call.
- **"My" tools take no user id.** They act on the authenticated user (`ctx.user`), so there is nothing to tamper with.
- **Personal data of others is opt-in.** Staff tools return ids, statuses and counts. Names, emails, form answers and
  file names need a separate `*:pii` scope (`events:pii`, `forms:pii`) on top of the manage scope. Responses carry a
  `notice` explaining what was withheld and why, so the agent can tell the user.
- **No exfiltration levers.** Where form submissions are delivered (`delivery`: recipients, webhooks) cannot be read
  or changed through MCP. The tool descriptions, errors and the server instructions say so, and tell the agent to
  ask the user to change it in the admin UI.
- **Session-only areas stay out.** User administration and OAuth application administration are session-only and
  not exposed.
- **Fail closed.** A definition not created with the scoped definers is dropped at runtime, a tool whose input
  cannot be described as JSON Schema is dropped (and logged) instead of breaking the listing, and a failing policy
  hook hides the tool.

## Exposed tools

| Module         | Tool                                            | Scopes                          |
| -------------- | ----------------------------------------------- | ------------------------------- |
| events         | `list-events`, `get-event`, `my-tickets`        | `tickets:read`                  |
| events (staff) | `list-all-events`, `get-event-definition`, `create-event`, `update-event`, `update-ticket-type` | `events:manage`               |
| events (staff) | `list-attendees`                                | `events:manage` (+ `events:pii` for names/emails) |
| forms          | `list-forms`, `get-form`, `submit-form`         | `forms:submit`                  |
| forms (staff)  | `list-all-forms`, `get-form-definition`, `create-form`, `update-form` | `forms:manage` |
| forms (staff)  | `list-submissions`, `get-submission`            | `forms:manage` (+ `forms:pii` for answers) |
| oauth-server   | `my-oauth-applications`                         | `oauth:read`                    |
| account        | `get-my-profile`                                | `profile:read`                  |
| subscriptions  | `my-subscriptions`                              | `subscriptions:read`            |

`submit-form` always submits as the caller and works for forms open to everyone or to signed-in users; forms that
need their own token or password are refused.

## Adding tools to a module

```ts [module.ts]
import { addMcpDefinitions } from '@frigear-nu/mcp/utils'

// moduleDependencies: { '@frigear-nu/mcp': { version: '>=0.0.1' } }
addAuthScope(nuxt, { name: 'notes:read', description: 'Read your notes' })
// Opt-in: only register when the host enabled it (`settings.mcp`), as the built-in modules do.
if (options.settings?.mcp === true) addMcpDefinitions(nuxt, resolver.resolve('./runtime/server/mcp'))
```

Put files in `runtime/server/mcp/{tools,resources,prompts}`. Subfolders of `tools/` become groups.

```ts [runtime/server/mcp/tools/my-notes.ts]
export default defineScopedMcpTool({
  description: 'List my notes',
  scopes: ['notes:read'],
  handler: (_args, { user }) => listNotes(user.id),
})
```

```ts [runtime/server/mcp/tools/admin/list-all-notes.ts]
export default defineScopedMcpTool({
  description: 'List every note (staff)',
  scopes: ['notes:manage'],
  gate: canManageNotes, // (event, principal) => boolean, e.g. your `notes:authorize` hook
  handler: (_args, ctx) => {
    const allow = ctx.hasScope('notes:pii')
    const notes = listAllNotes().map(note => redactPii(pick(note, ['id', 'text', 'ownerEmail']), { allow, fields: ['ownerEmail'] }))
    return { notice: piiNotice(allow, 'notes:pii', 'Owner emails'), notes }
  },
})
```

| Option        | Description |
| ------------- | ----------- |
| `scopes`      | Required. At least one scope the credential must carry. |
| `sessionOnly` | Never exposed to API tokens or OAuth tokens. |
| `gate`        | Extra check run on every listing and call; identify the caller from `principal.user.id`, not the session. |

Return explicit allow-listed fields (`pick`) and never a raw database row. Define input schemas with plain types:
zod transforms and `z.coerce.date()` cannot be sent to clients as JSON Schema; parse with your REST schema inside the
handler instead.
