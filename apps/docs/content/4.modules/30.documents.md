title: Documents Module

---

Documents as a [Nuxt module](https://nuxt.com/docs/4.x/guide/modules). It replaces the static `account.settings.documents`
list. Staff upload files to NuxtHub blob, organise them in folders, give every item an icon and a localized
title/description, and share it with [user groups](/modules/groups) or everyone. With `@frigear-nu/menu` a *Documents*
tile is added to the account menu.

## Design

- **Nothing is public.** Files are served only through `GET /api/documents/:id/download`, which checks the viewer first.
  Hidden documents answer 404 so ids cannot be probed.
- **Sharing.** Each item is shared with `everyone` (every signed-in user) or with selected groups. New items start with
  `groups` and no groups, so nothing leaks by default.
- **Folders gate their contents.** An item is only visible when every folder above it is visible too.
- **Managers see everything** and manage everything; who a manager is, is the host's decision (see below).

## Quick Setup

Requires `@frigear-nu/users`, [`@frigear-nu/groups`](/modules/groups) and NuxtHub with a database and **blob**.
`@frigear-nu/admin`, `@frigear-nu/menu` and `@frigear-nu/account` are optional.

```ts
export default defineNuxtConfig({
  modules: ['@nuxthub/core', '@frigear-nu/users', '@frigear-nu/groups', '@frigear-nu/documents'],
  documents: {
    settings: {
      pages: { documents: true, admin: true }, // /account/documents and /admin/documents, or custom paths
      maxFileSize: 25 * 1024 * 1024,           // bytes (default 25 MB)
      accept: ['application/pdf', 'image/*'],   // MIME types / wildcards (default: PDF, text, images, office files)
    },
  },
})
```

The browse page nests under the account layout when `@frigear-nu/account` provides one. The folder being shown is the
`?folder=<id>` query.

::warning
Every host app and test fixture must generate and commit a migration for the `documents` and `document_shares` tables.
See [Module Kit](/modules/module-kit) and the repository `AGENTS.md`.
::

## Authorization

Managing documents is denied by default. The host decides through the `documents:authorize` Nitro hook:

```ts
export default defineNitroPlugin((nitro) => {
  nitro.hooks.hook('documents:authorize', (ctx) => { ctx.allowed = isStaff(ctx.userId) })
})
```

## API

- `GET /api/documents?parent=` - the folder (or root) as the signed-in user may see it, with breadcrumb.
- `GET /api/documents/:id/download` - the file, after the visibility check.
- Manager API under `/api/documents/admin/`: `GET /items?parent=`, `POST /items` (folder), `POST /items/upload`
  (multipart: a `file` part and a `meta` JSON part), `PATCH|DELETE /items/:id` (deleting a folder deletes its
  contents and files) and `GET /groups`.

## Migrating from `account.settings.documents`

That option is gone. Create groups for the roles you used in `roles`, upload the files in `/admin/documents`, share them
with those groups, then remove the old files from `public/`.
