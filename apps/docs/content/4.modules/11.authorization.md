## `@frigear-nu/authorization`

Handles **only authorization**: what an already-identified user may do. Authentication stays in
[`@frigear-nu/users`](/modules/users). The design follows
[nuxt-authorization](https://github.com/barbapapazes/nuxt-authorization): the app defines policies as functions, and the
current user is injected into them automatically by a resolver (one for the app, one for the server).

The module extends the `users` table with a `role` column (`text`, not null, default `'user'`) through
[`extendDatabaseTable`](/modules/module-kit). The column is copied into the session at login/registration time, so a role
change takes effect after the user signs in again (or after your code calls `setUserSession`).

```ts
export default defineNuxtConfig({
  modules: ['@nuxthub/core', '@frigear-nu/users', '@frigear-nu/authorization'],
})
```

::note
The module only changes the generated Drizzle schema. Generate and commit a migration for `users.role` in every host app
and fixture that uses it - see [Migrations and database-backed module tests](/modules/module-kit).
::

### Defining abilities

Put abilities in `shared/utils/abilities.ts` (auto-imported in the app **and** the server) or `shared/abilities.ts`.
`defineAbility`, `allow` and `deny` are auto-imported; the first argument of a policy is the resolved user, the rest are
the arguments you pass when checking.

```ts
// shared/utils/abilities.ts
export const isAdmin = defineAbility(user => user.role === 'admin')

export const editPost = defineAbility((user, post: Post) =>
  user.id === post.userId || user.role === 'admin' || deny({ message: 'Not your post' }))

// Let unauthenticated visitors reach the policy (it receives `null`).
export const viewPost = defineAbility({ allowGuest: true }, (user, post: Post) => post.published || user?.id === post.userId)
```

Without `allowGuest`, guests are denied before the policy runs. A policy returns a boolean, `allow()`, or
`deny({ statusCode?, message? })` (default status 403).

### Server

```ts
export default defineEventHandler(async (event) => {
  const post = await findPost(getRouterParam(event, 'id'))
  await authorize(event, editPost, post) // throws a 403 h3 error when denied
  if (await allows(event, isAdmin)) { /* ... */ }
})
```

`allows`, `denies` and `authorize` take the `event` first. The server resolver reads the `nuxt-auth-utils` session user by
default.

### App

```vue
<Can :ability="editPost" :args="[post]">
  <button>Edit</button>
  <template #fallback><span>Read only</span></template>
</Can>
<Cannot :ability="isAdmin">You are not an admin.</Cannot>
```

```ts
const { allows, authorize } = useAuthorization() // also auto-imported on their own
if (await allows(editPost, post)) { /* ... */ }
```

::warning
Client checks only improve the UI. Always enforce permissions on the server with `authorize(event, ...)` or route rules.
::

### Route rules

Declarative rules live in `nuxt.config.ts`, keyed by pattern (`/admin/**` prefix, `*` single segment, or an exact path).
All matching rules must pass. Pages are gated by a global route middleware (also during SSR); rules for `/api/**` are also
enforced by a Nitro middleware.

```ts
export default defineNuxtConfig({
  authorization: {
    routes: {
      '/admin/**': { roles: ['admin'] },
      '/api/admin/**': { roles: ['admin'] },
      '/billing': { ability: 'isAdmin' }, // export name from the abilities file; no arguments
      '/members/**': {}, // any logged-in user
      '/pricing': { guest: true },
    },
    redirectTo: '/login', // used for unauthenticated page visits; otherwise a 401 error is shown
  },
})
```

Guests get `401`; a wrong role or a denied ability gets `403`. Rules can also be set per page, and **replace** the matching
config rules for that page:

```vue
<script setup lang="ts">
definePageMeta({ authorize: isAdmin }) // an ability object, an ability name, or { roles, ability, args, guest }
</script>
```

### Options

| Option | Description |
| --- | --- |
| `abilities` | Path to the abilities file (needed to refer to abilities by name). Defaults to `shared/utils/abilities.ts` or `shared/abilities.ts`. |
| `resolvers.server` | Path to a default-export `(event) => user \| null` function replacing the session resolver. |
| `resolvers.client` | Path to a default-export `() => user \| null` function replacing the session resolver in the app. |
| `routes` | Route rules, see above. |
| `redirectTo` | Redirect target for unauthenticated page navigation. |
