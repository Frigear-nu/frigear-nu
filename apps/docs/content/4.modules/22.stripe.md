Provider plumbing for [Stripe](https://stripe.com) as a [Nuxt module](https://nuxt.com/docs/4.x/guide/modules). It owns the
Stripe client, the link between a user and a Stripe customer, and **one** webhook endpoint. Feature modules such as
[`@frigear-nu/subscriptions`](/modules/subscriptions) register listeners for the Stripe events they care about; they never
verify signatures or deal with retries themselves.

## Design

- **Stripe is the source of truth for catalog data.** The core stores no products or prices, only per-user state
  (the customer id).
- **No org-specific rules and no copy in Stripe.** Policy (seasons, discounts, ...) is injected by the host through hooks
  in the feature modules, not encoded in Stripe metadata.
- **Modules compose through events.** Subscriptions, payments and host apps share one webhook and one customer per user.

## Quick Setup

```bash
pnpm add @frigear-nu/stripe
```

From the workspace use `"@frigear-nu/stripe": "workspace:*"`.

```ts
export default defineNuxtConfig({
  modules: ['@nuxthub/core', '@frigear-nu/users', '@frigear-nu/stripe'],
  hub: { db: { dialect: 'sqlite', driver: 'libsql' }, kv: true }, // kv is required, see below
  stripe: {
    settings: {
      webhookPath: '/api/stripe/webhook', // default
    },
  },
})
```

### Environment variables

| Variable                           | Purpose                                                       |
| ---------------------------------- | ------------------------------------------------------------- |
| `NUXT_STRIPE_SECRET_KEY`           | Server-side secret API key (`sk_...` / restricted key).       |
| `NUXT_STRIPE_WEBHOOK_SECRET`       | Signing secret of the webhook endpoint (`whsec_...`).         |
| `NUXT_STRIPE_API_VERSION`          | Optional. Overrides the pinned Stripe API version.            |
| `NUXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` | Publishable key (`pk_...`), exposed to the client.          |

These map to `runtimeConfig.stripe.secretKey`, `runtimeConfig.stripe.webhookSecret`, `runtimeConfig.stripe.apiVersion`
(private) and `runtimeConfig.public.stripe.publishableKey`. `apiVersion` defaults to the `STRIPE_API_VERSION` constant
exported from `@frigear-nu/stripe` (currently `2026-09-30.endive`, matching the pinned `stripe` SDK). Never read
`process.env` yourself; use runtime config. `unstorage` must be resolvable by the host app (NuxtHub KV needs it).

### KV requirement

Webhook idempotency (and the subscriptions plan cache) use [NuxtHub KV](https://hub.nuxt.com/docs/kv). Enable it in the
host app and in any fixture or playground:

```ts
hub: { kv: true }
```

The module declares `hub.kv: true` as a default for `@nuxthub/core`, and **throws at build time** if KV is still
disabled. Processed event ids are stored under `stripe:event:<event id>` (other modules use their own prefix, for
example `subscriptions:plans:*`). No extra database table is needed.

## Database

The module extends the [`users`](/modules/users) table with a nullable `stripeCustomerId` (`stripe_customer_id`) column, using the same programmatic
`extendDatabaseTable` mechanism as other modules (see [Module Kit](/modules/module-kit)). Do **not** add it to your host
`extend.sqlite.ts`.

::warning
`extendDatabaseTable` changes the generated Drizzle schema, not the database. Generate and commit migrations (SQL,
snapshot and journal together) in every app or fixture that uses the module, with the full module configuration. See the
migration workflow in [Module Kit](/modules/module-kit) (see also the repository `AGENTS.md`). The module does not ship a
migration for the host: **every host app must generate and commit its own**, after the module is added.
::

## Server utilities

| Utility                          | Description                                                                                  |
| -------------------------------- | -------------------------------------------------------------------------------------------- |
| `useStripe()`                    | Shared `Stripe` instance built on `fetch`, so it runs on Cloudflare Workers. Throws a 500 when `secretKey` is missing. |
| `ensureStripeCustomer(userId)`   | Returns the customer id (`Promise<string>`): the stored `stripeCustomerId`, else a Stripe search by email, else a new customer, which is then persisted. Concurrent calls converge on one id; throws 404 for an unknown user. Called lazily by consumers. |
| `getStripeCustomerUser(customerId)` | Resolves the local `users` row for a Stripe customer id, or `null`.                       |

All three are auto-imported in Nitro, as are `onStripeEvent` and `defineStripeEventHandler`.

## Webhook endpoint

`POST /api/stripe/webhook` (relocate with `settings.webhookPath`). It reads the raw body, verifies the signature with the
async/subtle-crypto API (`constructEventAsync`), requires no session, and dispatches the event to the registered
handlers. Make sure no auth or CSRF middleware sits in front of it.

| Status | Meaning                                                                                           |
| ------ | ------------------------------------------------------------------------------------------------- |
| `200`  | `{ received: true }`, or `{ received: true, duplicate: true }` for an already processed event id. |
| `400`  | Missing `stripe-signature` header, missing body, or an invalid signature.                          |
| `500`  | `NUXT_STRIPE_WEBHOOK_SECRET` is not set, or at least one handler threw (Stripe will retry).        |

### Stripe dashboard setup

1. In **Developers > Webhooks**, add an endpoint pointing at `https://<your-host>/api/stripe/webhook`.
2. Select the events your installed modules need (for example the list in [Subscriptions](/modules/subscriptions#stripe-dashboard-setup)).
3. Copy the signing secret into `NUXT_STRIPE_WEBHOOK_SECRET`.

For local development, forward events with the Stripe CLI and use the secret it prints:

```bash
stripe listen --forward-to localhost:3000/api/stripe/webhook
```

## Listening to Stripe events

The API mirrors the menu module's `registerMenuSource` / `defineMenuSource`, and is exported from
`@frigear-nu/stripe/utils` (together with the types `StripeEventType`, `StripeEventOf`, `StripeEventHandler`,
`StripeEventHandlerContext` and `RegisteredStripeEventHandler`).

```ts
registerStripeEventHandler(nuxt: Nuxt, options: {
  events: string[] | '*'  // Stripe event types, or '*' for every event
  handler: string         // absolute path to a file whose default export is a defineStripeEventHandler(...) result
  order?: number          // lower runs first, default 100
}): void

defineStripeEventHandler<T extends StripeEventType>(
  handler: (event: StripeEventOf<T>, ctx: StripeEventHandlerContext) => void | Promise<void>,
)

onStripeEvent<T extends StripeEventType>(
  type: T | T[] | '*',
  handler: (event: StripeEventOf<T>, ctx: StripeEventHandlerContext) => void | Promise<void>,
): void

type StripeEventHandlerContext = {
  stripe: Stripe          // the useStripe() instance
  userId: number | null   // local user owning the event's customer, null if unknown
  event: H3Event          // the Nitro event of the webhook request
}
```

### In a module (build time)

```ts
import { createResolver, defineNuxtModule } from '@nuxt/kit'
import { registerStripeEventHandler } from '@frigear-nu/stripe/utils'

export default defineNuxtModule({
  meta: { name: '@frigear-nu/example' },
  setup(options, nuxt) {
    const resolver = createResolver(import.meta.url)

    registerStripeEventHandler(nuxt, {
      events: ['customer.subscription.updated', 'checkout.session.completed'], // or '*'
      handler: resolver.resolve('./runtime/server/stripe/example-events'),
      order: 10, // optional
    })
  },
})
```

`handler` must be an absolute path. Handlers are collected into a generated server template (`#stripe/handlers`) once
every module has finished `setup()`, so registration order between modules does not matter and everything is bundled for
Nitro/Workers with no runtime scanning. Registering the same handler file for the same events twice is a no-op.

### The handler file

```ts
// runtime/server/stripe/example-events.ts
import { defineStripeEventHandler } from '@frigear-nu/stripe/utils'

export default defineStripeEventHandler<'customer.subscription.updated' | 'checkout.session.completed'>(
  async (event, { stripe, userId, event: h3Event }) => {
    // `event` is a Stripe.Event narrowed to the generic's event types.
    // `userId` is null if the customer is unknown.
    if (!userId) return
    // ...must be idempotent
  },
)
```

### In a host app (runtime)

```ts
// server/plugins/stripe.ts
export default defineNitroPlugin(() => {
  onStripeEvent('invoice.payment_failed', async (event, ctx) => {
    // notify the user, flag the account, ...
  })
})
```

Runtime handlers run with the default order (`100`), after build-time handlers of equal order (registration order is
kept).

### Delivery, idempotency and retries

- Handlers matching the event type (or `'*'`) run sequentially, sorted by `order` (lower first, stable for equal values).
  An error in one is logged and does not stop the others.
- If **any** handler throws, the webhook responds `500` and Stripe retries the whole event. Handlers must therefore be
  idempotent.
- The event id is written to KV (`stripe:event:<id>`, TTL 7 days) only **after all handlers succeed**. Duplicate
  deliveries of an already processed event are acknowledged (`duplicate: true`) without running handlers again.
- The Nitro hook `stripe:event` (`(event: Stripe.Event, ctx: StripeEventHandlerContext) => void | Promise<void>`) is fired
  after the handlers ran, for observability. An error in it is logged and never fails the webhook.
