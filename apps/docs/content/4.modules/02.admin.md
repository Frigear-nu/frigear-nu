title: Admin
description: Generic admin area - guarded shell, dashboard and navigation that other modules contribute to.
---

A generic admin area. It owns **no domain features**: it provides the shell (an `admin` layout with a sidebar), a
guarded dashboard page and the registries other modules plug into. Domain admin UIs (forms, events, OAuth
applications, users, ...) stay in their own modules and register here.

::note
**Requires** [`@frigear-nu/module-kit`](/modules/module-kit), [`@frigear-nu/menu`](/modules/menu) (the sidebar is the
`admin.nav` menu), [`@frigear-nu/widget`](/modules/widget) (the dashboard is the `admin.dashboard` area) and
`nuxt-auth-utils` (the signed-in user is shown in the header).
**Optional** [`@frigear-nu/authorization`](/modules/authorization), used for the role guard.

`@nuxt/ui` is not declared as a module dependency, but the layout and components are built on Nuxt UI, so the host
installs it.
::

## Quick setup

```ts
export default defineNuxtConfig({
  modules: ['@nuxt/ui', '@frigear-nu/authorization', '@frigear-nu/admin'],
  admin: {
    settings: {
      roles: ['admin', 'manager'],
    },
  },
})
```

## Options

All options live under `admin.settings`.

| Option | Type | Default | Purpose |
| --- | --- | --- | --- |
| `base` | `string` | `'/admin'` | Path prefix of the area. A trailing slash is trimmed. |
| `dashboard` | `boolean \| string` | `true` | The dashboard page at `base`. `false` turns it off (other modules' pages still get the layout); a string is a custom path. |
| `roles` | `string[] \| false` | `['admin']` | Roles allowed into the area, applied as a route rule on `<base>/**`. `false` sets no rule: guard the area yourself. |
| `layout` | `boolean` | `true` | Gives every page under `base` the `admin` layout unless it picked its own. |

Behaviour of the generated route rules:

- **Guard**: `{ roles }` on `<base>/**`, only when `@frigear-nu/authorization` is installed. Without it nothing guards the
  pages on the client and a warning is logged. An explicit rule of yours wins. API routes are guarded by the modules
  that own them.
- **Layout**: `{ appLayout: 'admin' }` on `<base>` and `<base>/**` (the dashboard at `base` itself is not matched by
  the wildcard, so it gets its own rule). A rule of yours wins.
- **Locales**: with `@nuxtjs/i18n` the rules are repeated for each `/<locale>` prefix.
- **Account menu**: unless `dashboard` or `roles` is `false`, an "Admin" entry is added to the `account.dropdown` menu,
  shown only to users holding one of the roles.

## Server

None. The module registers no server routes.

## App

### Registries

Modules never import the admin module at runtime. They use these helpers from `@frigear-nu/admin/utils` in their
`setup()`:

```ts
import { extendAdminNav, extendAdminDashboard, adminRoute } from '@frigear-nu/admin/utils'

extendAdminNav(nuxt, { label: 'Forms', to: adminRoute(nuxt, 'forms'), icon: 'i-lucide-clipboard-list', order: 20 })
extendAdminDashboard(nuxt, { component: resolver.resolve('./runtime/app/widgets/Submissions.vue'), order: 10 })
```

| Export | Signature | Purpose |
| --- | --- | --- |
| `extendAdminNav` | `(nuxt: Nuxt, items: MenuItem \| MenuItem[]) => void` | Adds sidebar entries: `extendMenu(nuxt, 'admin.nav', ...)`. |
| `extendAdminDashboard` | `(nuxt: Nuxt, widgets: WidgetDefinition \| WidgetDefinition[]) => void` | Adds dashboard widgets: `extendWidgets(nuxt, 'admin.dashboard', ...)`. |
| `adminRoute` | `(nuxt: Nuxt, ...segments: string[]) => string` | Path below the configured base: `adminRoute(nuxt, 'events', ':id')` is `/admin/events/:id`. Use it so defaults follow the host's `base`. |
| `ADMIN_NAV_MENU` | `'admin.nav'` | Menu name of the sidebar. |
| `ADMIN_DASHBOARD_AREA` | `'admin.dashboard'` | Widget area name of the dashboard. |

A module can also call `extendMenu` / `extendWidgets` directly, without depending on this package.

Without widgets, the dashboard shows a card for every navigation entry.

### Runtime config

`runtimeConfig.public.admin` holds the resolved values:

```ts
type PublicModuleOptions = {
  base: string
  dashboard?: string // undefined when the dashboard is off
}
```

### Layout and page

| Name | Purpose |
| --- | --- |
| `admin` layout | Sidebar (the `admin.nav` menu), header with the signed-in user, plus `LanguageSelect` and `AccountMenu` when the host provides them. |
| Dashboard page | `admin-dashboard` at the dashboard path, rendering `<WidgetArea name="admin.dashboard">`. Skipped if a page already exists at that path. |

### Components

Every `/admin/**` page uses the same flat, bordered look (no tinted cards, borders from `border-default`). The
components are registered globally.

| Component | Props | Slots | Use |
| --- | --- | --- | --- |
| `<AdminPage>` | | default | Page root; vertical rhythm (`space-y-6`). |
| `<AdminPageHeader>` | `title?`, `description?`, `back?: { label, to }` | default (badges, metadata), `actions` / `links` (buttons; the primary action goes last), `headline`, `title`, `description` | Heading of every page; `back` renders a link above the title on detail pages. |
| `<AdminToolbar>` | | default | Row of search and filter controls above a table. |
| `<AdminTable>` | `data`, `columns`, `loading?`, `empty?` | `empty`, `#<column>-cell` (all slots pass through to `UTable`) | Bordered `UTable`; emits `select(event, row)` on row click. `empty` is a shortcut for an `AdminEmpty` title. |
| `<AdminSection>` | `title?`, `description?`, `loading?` | default, `header`, `actions`, `flush`, `footer` | Bordered block; `flush` is for edge-to-edge content such as a table. |
| `<AdminEmpty>` | `icon?`, `title`, `description?` | default (an action) | Empty state. |
| `<AdminKeyValue>` | `items: { key, label, value? }[]`, `loading?` | `#<key>` with `{ item }` | Label/value list for key facts; falsy values show an en dash. |
| `<AdminStatCard>` | `label`, `loading?`, `empty?` | default (the value) | Summary tile for widget areas such as `admin.*.overview`; shows `empty` when the slot is empty. |

```vue
<template>
  <AdminPage>
    <AdminPageHeader title="Events">
      <template #actions>
        <UButton icon="i-lucide-plus" label="New event" @click="creating = true" />
      </template>
    </AdminPageHeader>

    <AdminTable :data="events" :columns="columns" @select="open">
      <template #empty>
        <AdminEmpty icon="i-lucide-calendar" title="No events yet" />
      </template>
    </AdminTable>
  </AdminPage>
</template>
```

Modules that ship admin pages declare `@frigear-nu/admin` as an optional module dependency (and
[`@frigear-nu/ui`](/modules/ui) for `useConfirmDialog`); a host that enables those pages installs both.

### Page conventions

- **Lists** are tables (`AdminTable`), with row actions in the last column; a row click opens the detail page.
- **Detail pages** use `AdminPageHeader` with `back`, then `AdminSection` blocks. A form in a section puts its Save
  button in the section's `#footer` (`type="submit"` with `form="<id>"`).
- **Modals** keep their buttons in the `#footer` slot (Cancel `variant="subtle" color="neutral"`, then the primary action).
- **Destructive actions** ask first with `useConfirmDialog()` from `@frigear-nu/ui` (`destructive: true`), never
  `window.confirm`.
- **Errors**: page-level problems use `UAlert color="error" variant="subtle"`; failed actions use a toast.
- Text goes through `useModuleT` with an English default; form-field hints use `UFormField`'s `description`.
