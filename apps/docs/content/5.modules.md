A **module** is a [Nuxt module](https://nuxt.com/docs/4.x/guide/modules) that adds a feature to an application.
Modules live under `packages/` and are consumed with the pnpm `workspace:*` protocol. Each page follows the same
layout: requirements, quick setup, options, then server, app, hooks, routes and database reference.

::note
Every module is a **Nuxt 4** module (Nuxt `^4.6`, app code under `app/`), and every Quick setup is a Nuxt 4
`nuxt.config.ts`. New to the modules? The [workspace starter](/guides/workspace-starter) sets up a Nuxt 4 app with
sign-in, account pages and a user admin.
::

## Identity and access

| Module | What it does |
| --- | --- |
| [Account](/modules/account) | Profile, security, documents and API token pages for signed-in users. |
| [Auth](/modules/auth) | Sign-in (password, magic link, OAuth, passkeys), API tokens, and one `requireAuth` for every credential. |
| [Authorization](/modules/authorization) | Abilities, policies, route rules, `<Can>` and a `role` on users. |
| [MCP](/modules/mcp) | Scope-gated MCP tools that other modules contribute. |
| [OAuth Server](/modules/oauth-server) | OAuth 2.0 / OpenID Connect server for applications your users sign in to. |
| [Frigear Resource](/modules/frigear-resource) | Accept frigear.nu access tokens in a service, so one mobile app signs in once and calls every service. |
| [OAuth Client](/modules/oauth-client) | PKCE sign-in for browser SPAs and Capacitor apps, with rotating refresh tokens, secure storage and an authorized `$api`. |
| [Preferences](/modules/preferences) | Typed per-user preferences, optionally forwarded as OAuth claims. |
| [Users](/modules/users) | The user entity, staff administration and self-service profile, email and password changes. |

## How they fit together

Most feature modules install what they need through `moduleDependencies`, so a host lists only the modules it uses
directly. The main chains:

- **Sign-in:** `users` installs `auth`, `notify` and `menu`. `account`, `authorization`, `preferences` and
  `oauth-server` build on `users` and `auth`.
- **Mobile apps:** `mobile` installs `oauth-client` when `oauthClient` is configured. The app signs in at an issuer such as
  `oauth-server`, and each service it calls verifies the token with `frigear-resource`.
- **Commerce:** `subscriptions`, `payments` and `events` build on `stripe` and `auth`. `events` can read memberships from
  `subscriptions`.
- **Admin screens:** `admin` provides the shell. `users`, `subscriptions`, `payments`, `events`, `forms` and
  `oauth-server` add pages when it is installed.
- **Extension points:** `menu`, `widget` and `mcp` are registries that other modules contribute to.

Writing your own? Follow [Writing a module](/getting-started/writing-a-module), which starts from the
`pnpm cli module:create` command described in [CLI](/packages/cli), and see [Module Kit](/modules/module-kit) for the
helpers.
