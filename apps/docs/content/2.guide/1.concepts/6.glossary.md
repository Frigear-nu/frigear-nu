These docs use one word for each concept. This page lists those words, and every other page links here the first time
it uses one.

Each row gives the term, its meaning and the page that explains it in full. The last column lists the words the docs
used before. Avoid them in new text. A dash means there is no old word to avoid.

## Apps and modules

| Term | Meaning | Where it is explained | Instead of |
| --- | --- | --- | --- |
| **host app** | The Nuxt app that installs Frigear modules and configures them. Pages for app developers may say "your app". | [Architecture](/guide/concepts/architecture) | host application, consuming app, consuming application |
| **hosting platform** | Where you deploy the host app, such as Cloudflare, Vercel or a Node server. | [Deployment](/get-started/deployment) | the host's environment |
| **module** | A Nuxt module published as `@frigear-nu/<name>` that adds one feature to a host app. | [Modules](/modules) | building block |
| **package** | Any npm package in the repository, named in install and publish steps and for tooling that is not a module. | [Architecture](/guide/concepts/architecture) | — |
| **base layer** | The shared Nuxt layer a host app extends for config, interface defaults and content pages. Its package is `@frigear-nu/base`. | [Base layer](/modules/platform/base-layer) | — |
| **options** | Module options sit under the module's config key in `nuxt.config.ts`. Option tables show the full path from that key. | [Documentation](/contribute/documentation#writing) | — |
| **Frigear repository** | This monorepo, `Frigear-nu/frigear-nu`. | [Overview](/contribute/overview) | — |
| **starter** | A ready-made project in `.starters/` that you copy to start a new host app, such as the workspace starter. | [Installation](/get-started/installation) | boilerplate |
| **your workspace** | The pnpm workspace a starter creates for you. | [Project structure](/get-started/project-structure) | — |
| **frigear.nu** | The live Frigear service, which is also the default issuer. | [Frigear website](/examples/apps/frigear-nu-website) | Frigear SSO |
| **Frigear website app** | The reference host app in `apps/website` that runs frigear.nu. | [Frigear website](/examples/apps/frigear-nu-website) | frigear.nu website |
| **test fixture** | A minimal Nuxt app under `test/fixtures/` that installs a module from source so tests can boot it. | [Testing](/contribute/writing-a-module/testing) | fixture app, test app |
| **playground** | A dev app under `packages/<name>/playground` for working on one package. It is not a test fixture. | [Scaffold](/contribute/writing-a-module/scaffold) | — |

## People and permissions

| Term | Meaning | Where it is explained | Instead of |
| --- | --- | --- | --- |
| **staff** | People your host app lets into management screens and APIs. Your app decides who is staff in a policy hook, never a module. | [Auth and scopes](/guide/concepts/auth-and-scopes) | back office users, privileged users |
| **admin area** | The screens under `/admin`, drawn by the [Admin](/modules/interface/admin) module. | [Admin](/modules/interface/admin) | back office, back-office, admin UI, user admin |
| `admin` **role** | A value of the role column that Authorization adds to users. It is a role name, not a synonym for staff. | [Authorization](/modules/identity/authorization) | — |
| **policy hook** | A Nitro hook that your app answers to allow an action, denied by default. Its name is `<module>:authorize`. | [Auth and scopes](/guide/concepts/auth-and-scopes#policy-gates) | policy gate, host policy, staff gate |
| **staff guard** | For module authors: one helper that checks sign-in, the module's staff scope and its policy hook. In code it is `defineStaffGuard`. | [Auth server API](/modules/identity/auth/server#staff-guards) | — |
| **guard** / **route rule** | Authorization's check before a page or route runs, by role or ability. In client mode it only shapes the interface. | [Authorization](/modules/identity/authorization) | page guard, role guard |
| **principal** | Who made a request: the signed-in user, how they proved it and the scopes that proof carries. In code it is `AuthPrincipal`. | [Auth and scopes](/guide/concepts/auth-and-scopes#the-principal) | authenticated user |
| **signed-in user** | The person behind a principal, when only the person matters. | [Auth and scopes](/guide/concepts/auth-and-scopes) | logged-in user |
| **visitor** | Someone with no valid credential. | [Auth and scopes](/guide/concepts/auth-and-scopes) | guest |

"Policy gate" stays only as the function name `definePolicyGate`.

## Signing in

| Term | Meaning | Where it is explained | Instead of |
| --- | --- | --- | --- |
| **sign in** / **sign-in** | "Sign in" is the verb and "sign-in" the noun or adjective. Sign up and sign out follow the same pattern. | [Authentication](/get-started/authentication) | log in, log out, Log in with frigear.nu |
| **Sign in with frigear.nu** | Auth's built-in sign-in against frigear.nu for previews and local development. Its option is `oauth.frigear`. | [Auth](/modules/identity/auth) | Log in with frigear.nu, frigear SSO |
| **server mode** | Auth signs users in on the host app's own server and keeps them in a cookie session. This is the default. | [Auth](/modules/identity/auth) | server-rendered mode, confidential mode |
| **client mode** | Auth for an app without its own server, such as a single-page application (SPA) or a Capacitor app. It signs in at an issuer and keeps the tokens. | [Client mode](/modules/identity/auth/client-mode) | SPA mode, public client mode |
| **session** | A sealed cookie that keeps a person signed in to one host app in server mode. It grants full access (`*`) except personal-data scopes. | [Auth and scopes](/guide/concepts/auth-and-scopes#the-principal) | — |
| **issuer** | The server where users sign in and which issues tokens to other apps. Frigear's issuer is the OAuth Server module. | [Identity](/guide/concepts/identity#the-roles) | identity provider, Frigear OAuth server |
| **OAuth Server** | The module that turns a host app into an issuer, always capitalised and linked. | [OAuth Server](/modules/identity/oauth-server) | — |
| **OAuth provider** | A third-party sign-in service that Auth supports through nuxt-auth-utils, such as GitHub, Google or a generic OpenID Connect server. | [Auth](/modules/identity/auth#oauth-providers) | — |
| **OAuth application** | An app registered at an issuer so its users can sign in through it. It is stored in `oauth_applications`. | [Routes and clients](/modules/identity/oauth-server/routes-and-clients) | OAuth client |
| **public** / **confidential** | The two OAuth application types, fixed at creation. A confidential one is a server that keeps a client secret, and a public one has no secret. | [Identity](/guide/concepts/identity#confidential-and-public-clients) | public client, confidential client |
| **configured client** | A public OAuth application defined in the `clients` option of OAuth Server instead of in the admin area. | [Routes and clients](/modules/identity/oauth-server/routes-and-clients#configured-clients) | config client, static client |

The routes `/login` and `/register` keep their names as code. Quote "Create account" only when you quote the
interface.

## Tokens and scopes

| Term | Meaning | Where it is explained | Instead of |
| --- | --- | --- | --- |
| **API token** | A long-lived token a user creates on their account page for scripts and agents. It starts with `fnu_` by default. | [Auth server API](/modules/identity/auth/server#user-api-tokens) | user API token, personal token |
| **access token** | A short-lived signed JSON Web Token (JWT) that an issuer gives an OAuth application for a signed-in user. | [Auth and scopes](/guide/concepts/auth-and-scopes#the-principal) | OAuth token, bearer JWT |
| **scope** | A permission string in the form `resource:action` that limits what a token may do. An example is `tickets:read`. | [Auth and scopes](/guide/concepts/auth-and-scopes#scopes) | — |

## Extension points

| Term | Meaning | Where it is explained | Instead of |
| --- | --- | --- | --- |
| **extension point** | A place where one module adds things to another without importing it, either a registry or a hook. | [Extension points](/guide/concepts/extension-points) | plug-in point, contribution point |
| **registry** | A build-time list that modules add entries to, such as menus, widgets, tabs, scopes and Model Context Protocol (MCP) tools. | [Extension points](/guide/concepts/extension-points) | virtual registry |
| **hook** | A Nitro runtime hook that a module calls and that listeners in the host app or other modules answer. | [Extension points](/guide/concepts/extension-points) | — |
| **widget area** | A named slot where the Widget module renders the components modules add. | [Widget](/modules/interface/widget) | — |

## Database

| Term | Meaning | Where it is explained | Instead of |
| --- | --- | --- | --- |
| **migration** | A generated SQL (Structured Query Language) file that changes the database schema. You commit one whenever a module adds or changes tables. | [Database](/get-started/database#migrations) | schema change file |
| **dialect** | The database type a schema is written for: SQLite or PostgreSQL. | [Database](/get-started/database#sqlite-and-postgresql) | — |
| **NuxtHub** | The module that gives the host app its database and blob storage. Its package is `@nuxthub/core`. | [Database](/get-started/database) | — |
| **Drizzle** | The TypeScript object-relational mapper (ORM) that modules use to define tables and generate migrations. | [Module Kit database](/modules/platform/module-kit/database) | — |

## Tools and acronyms

| Term | Meaning | Where it is explained | Instead of |
| --- | --- | --- | --- |
| **Nitro** | Nuxt's server engine, where server routes, server plugins and hooks run. | [Glossary](/guide/concepts/glossary) | server runtime |
| **PKCE** | Proof Key for Code Exchange: a one-time secret that proves the app finishing a sign-in is the app that started it. | [Identity](/guide/concepts/identity) | — |
| **SPA** | Single-page application: a browser app with no server of its own. | [Identity](/guide/concepts/identity) | — |
| **JWKS** | JSON Web Key Set: the public keys an issuer publishes at `/.well-known/jwks.json` so others can verify its tokens. | [Signing keys](/guide/going-further/signing-keys) | — |
| **PII** | Personally identifiable information. Personal-data scopes such as `events:pii` guard it, and wildcards never include them. | [Auth and scopes](/guide/concepts/auth-and-scopes#scopes) | personal data scope |
| **ACL** | Access control list. In the starter, `NUXT_ACL_ADMINS` lists the emails that always get the admin role. | [Authentication](/get-started/authentication#roles-and-the-first-admin) | — |

## How to use a term

Link a term to this page the first time a page uses it, then write it plainly. Put the plain word first and the code
name once after it, as the [writing rules](/contribute/documentation#writing) explain.
