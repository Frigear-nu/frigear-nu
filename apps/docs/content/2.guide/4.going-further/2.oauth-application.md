An **application** is an OAuth client of [`@frigear-nu/oauth-server`](/modules/identity/oauth-server): it has a `client_id`,
redirect URIs, and optionally roles that may sign in to it. This recipe registers one and picks its type. The module page
has the full reference; the other side of the sign-in is in [Auth client mode](/modules/identity/auth/client-mode) (browser and
mobile apps) and [Auth](/modules/identity/auth) (server-rendered apps).

## Pick a client type

The server has two client types, and the type is fixed when the application is created.

| Your app | Type | Why |
| --- | --- | --- |
| Server-rendered web app (Nuxt with a server, Auth's [Log in with frigear.nu](/modules/identity/auth)) | **Confidential** | The secret stays on your server. It is sent on every token request, next to PKCE. |
| Browser SPA, Capacitor / mobile app, desktop app, CLI | **Public** | Anything shipped to a browser or a device can be extracted, so a secret there is not a secret. PKCE (S256) protects the code exchange, and refresh token rotation protects the refresh token. |
| Machine to machine (no user) | Not supported | `/oauth/token` only takes the `authorization_code` and `refresh_token` grants, and every token belongs to a signed-in user. There is no `client_credentials` grant. |

- **PKCE with S256 is mandatory for both types.** A request without `code_challenge_method=S256` is a `400`.
- A public client has no secret at all: the server stores a throwaway hash and never shows it. Sending a `client_secret`
  to a public client is refused (`401 invalid_client`), not ignored.
- A confidential client without its secret gets `401 invalid_client` on every token and revoke request.
- [Auth in client mode](/modules/identity/auth/client-mode) is a public client by design, and a production build that embeds
  `NUXT_PUBLIC_AUTHENTICATION_CLIENT_CLIENT_SECRET` fails.
- The type cannot be changed afterwards: register a new application instead.

## Create it in the admin UI

Needs the admin page (`oauthServer.settings.pages.admin: true`, with `@frigear-nu/admin` installed) and a user the host's
`oauth:authorize` hook allows (denied by default, see [Who is an admin](/modules/identity/oauth-server)).

1. Open **OAuth applications** in the **Settings** group of the admin sidebar (`/admin/oauth`) and choose
   **Add application**.
2. **Client type**: *Confidential* or *Public*.
3. **Name** (shown on the consent screen) and **Website URL**: the origin of the app, without a path
   (`https://app.example.com`; http only for localhost). The field is required for every type, native apps included: use
   the app's website, and put the native callback in **Redirect URIs**.
4. **Redirect URIs**: see [Redirect URIs](#redirect-uris). **Preview URL pattern** (for example `https://*.vercel.app`)
   accepts the callback path on preview deployments, where `*` is one hostname label.
5. **Allowed roles**: leave empty to let every signed-in user in, or list the roles that may. Roles come from the host's
   `oauth:user:roles` hook.
6. Optional: **Login URL** (where the **Open** button of the user's application list goes, default the website URL),
   **Description**, **Icon**, **Priority** (order in that list) and **Tags**.
7. **Add application**. A modal shows the **Client ID** (`app_…`) and, for a confidential client, the **Client secret**
   once.

A row's menu has **Edit application**, **Copy client ID**, **Disable application** (sets `isActive` to false), **New
client secret**, **Sign everyone out** and **Delete application**. The edit form is also reachable at
`/admin/oauth?application=<id>`.

## Create it in nuxt.config

`oauthServer.clients` defines **public** applications in config. Use it when the app ships with its `client_id` compiled
in (a mobile app, a SPA, a starter) and the id must be the same in every environment, and when the registration should be
versioned with the app. Ids are free-form (`mobile`, `com.example.app`); `app_…` is reserved for admin-created ones.

```ts [nuxt.config.ts (the issuer)]
export default defineNuxtConfig({
  oauthServer: {
    cors: { paths: ['/api/'] },
    clients: [
      {
        // Mobile (Capacitor): custom-scheme redirect, webview origins for CORS.
        id: 'bills-mobile',
        name: 'Bills (mobile)',
        redirectUris: ['nu.frigear.bills:/auth/callback'],
        // Accepted under `nuxt dev` only.
        devRedirectUris: ['http://localhost:3001/auth/callback'],
        corsOrigins: ['capacitor://localhost', 'https://localhost'],
      },
      {
        // Web SPA: the origin is taken from the redirect URI.
        id: 'bills-web',
        name: 'Bills (web)',
        redirectUris: ['https://bills.example.com/auth/callback'],
        devRedirectUris: ['http://localhost:3000/auth/callback'],
      },
    ],
  },
})
```

- **Config cannot hold a confidential client.** `type` only accepts `'public'` (a secret does not belong in config), and
  an invalid entry fails the build. Register confidential clients in the admin UI (or with `createApplication`).
- Other fields: `websiteUrl`, `description`, `icon`, `allowedRoles`, `tags`, `corsOrigins` (see
  [CORS](#cors-for-browser-and-capacitor-clients)). The table is in
  [OAuth Server](/modules/identity/oauth-server).
- `NUXT_OAUTH_SERVER_CLIENTS` (JSON) replaces the list at runtime.
- The row is created on the first OAuth request, and the config wins on every read. In the admin UI it shows **Managed in
  nuxt.config**: staff can disable it and change the priority and login URL, and any other change or a delete is
  `409 managed_by_config`. Remove the client from config to turn it into an ordinary application.
- An id that already belongs to a confidential application is ignored, with a warning in the server log.

## Redirect URIs

The server accepts a `redirect_uri` only when it is an **exact string match** (no prefixes, wildcards or query strings,
no fragment) of one of:

- `websiteUrl` + `callbackPath` (default `/auth/frigear`), for admin-created applications. Configured clients do not get
  this implicitly: every URI is listed.
- an entry of **Redirect URIs** (`redirectUris`, at most 20): `https`, or `http` for `localhost`, `127.0.0.1` and
  `[::1]` (loopback is matched exactly, so list the port you use);
- the **Preview URL pattern**, for web redirects.

Native redirects are for public clients only (a confidential client is limited to `https` and loopback): a private-use
scheme with one slash, `nu.frigear.bills:/auth/callback` (the app id in lowercase), or a webview origin such as
`capacitor://localhost/auth/callback`. Web schemes, `javascript:`, `data:`, `file:`, credentials and fragments are
rejected.

| Client | Register |
| --- | --- |
| [Auth client mode](/modules/identity/auth/client-mode) in a browser | `<origin>/auth/callback` (its `callbackPath` default), plus `http://localhost:3000/auth/callback` for development |
| [Auth client mode](/modules/identity/auth/client-mode) in a native app | `<native.scheme in lowercase>:/auth/callback` |
| Auth's [Log in with frigear.nu](/modules/identity/auth) | `<origin>/auth/frigear`, which is `websiteUrl` + the server's default `callbackPath`: no extra entry needed |

`devRedirectUris` exist for configured clients only. For an admin-created application, add the localhost URI to
**Redirect URIs** (and remove it before production, since nothing marks it as development).

## Scopes, consent and roles

- **Scopes.** An app may request `openid`, `profile`, `email`, `oauthServer.scopes` and the API scopes modules register.
  Unsupported scopes are dropped silently, and a request whose scopes are all unsupported is a `400`. No `scope` means
  `openid profile email`. `staffOnly` and role-restricted scopes are dropped for users who may not hold them. See
  [API access](/modules/identity/oauth-server).
- **Consent.** Every sign-in shows the consent screen (`/authorize`) with the requested scopes. It cannot be skipped per
  application.
- **Allowed roles.** An application with roles refuses other users with `403` at the authorization request and
  `access_denied` at the token endpoint. The check runs again on every refresh, so removing a role or disabling the
  application stops the next refresh.
- **Refresh tokens.** The server always issues one with a user grant (there is no `offline_access` scope: it is dropped
  as unsupported, so asking for it is harmless). Each refresh replaces the token, and using an old one revokes its whole
  family. Lifetimes are server options: `accessTokenTtl` (default 900 s), `refreshTokenTtl` (30 days) and `codeTtl`
  (600 s), not per application.

## Secrets

- A confidential client's secret is **shown once**, in the modal after creating the application and after **New client
  secret**. Only a hash is stored, so a lost secret is replaced, not recovered.
- **Rotate** with **New client secret** (`POST /api/admin/oauth-server/applications/:id/secret`). The old secret stops
  working at once and every refresh token of the application is revoked, so everyone is signed out. Public clients have no
  secret to rotate (`400`).
- **Store it** in the server's runtime config, set through the environment (for Auth's SSO,
  `NUXT_FRIGEAR_SSO_CLIENT_SECRET`), and never in `runtimeConfig.public`, a committed file, or a browser or mobile bundle.
- **Sign everyone out** revokes all refresh tokens without changing the secret (use it after a leak of tokens).
  **Disable application** blocks new sign-ins and refreshes; **Delete application** also removes its codes and tokens.
  Access tokens already issued stay valid until they expire (15 minutes by default).
- A user can have their own sessions ended with `revokeUserGrants(userId, applicationId?)`; see the
  [module reference](/modules/identity/oauth-server).

## CORS for browser and Capacitor clients

Native redirects need none, but the **webview** of a Capacitor app (`capacitor://localhost` on iOS,
`https://localhost` on Android) and a SPA on another origin call the server from a browser, so CORS applies.

- `oauthServer.cors.origins`: exact origins (never `*`) that may call `/oauth/token`, `/oauth/revoke`, `/oauth/userinfo`
  and the `/.well-known` documents. `NUXT_OAUTH_SERVER_CORS_ORIGINS` takes a comma separated list.
- A configured client adds its own origins: by default those of its redirect URIs that have one (a native
  `nu.frigear.bills:/…` has none), or `corsOrigins` (`false` adds none). For a mobile client list the two webview
  origins in `corsOrigins`.
- An **admin-created** application adds no origins: list them in `cors.origins`.
- `oauthServer.cors.paths`: path prefixes of the host's own API (`['/api/']`) that the same origins may call with a
  bearer token. `/oauth/authorize` is never opened (a navigation, with cookies), and cookies never travel cross-origin, so
  session-only routes answer `401` to these clients.

## Connect the app

**Public client, browser or mobile.** Point [Auth in client mode](/modules/identity/auth/client-mode) at the issuer. There is
no secret option.

```ts [nuxt.config.ts (the app)]
export default defineNuxtConfig({
  modules: ['@nuxt/ui', '@frigear-nu/auth'],
  authentication: {
    mode: 'client',
    client: {
      issuer: 'https://id.example.com',
      clientId: 'bills-mobile', // or app_… for an admin-created application
      scopes: ['openid', 'profile', 'email'], // must contain 'openid'
      discovery: false, // the Frigear OAuth server's own paths
      native: { scheme: 'nu.frigear.bills' }, // nu.frigear.bills:/auth/callback
    },
  },
})
```

**Confidential client, server-rendered app.** Use Auth's single sign-on (`oauth.frigear`) with the Client ID and secret
from the modal. Create it with the app's origin as **Website URL**: `<origin>/auth/frigear` is then accepted without a
**Redirect URIs** entry.

```bash [.env (the app)]
NUXT_FRIGEAR_SSO_URL=https://id.example.com
NUXT_FRIGEAR_SSO_CLIENT_ID=app_…
NUXT_FRIGEAR_SSO_CLIENT_SECRET=…
```

With both set, `GET /auth/frigear` signs users in at the issuer. The options are in
[Log in with frigear.nu](/modules/identity/auth).

**A service that only receives the tokens** (an API behind the app) is not a client: it verifies the access token with
[Frigear Resource](/modules/identity/frigear-resource) and needs no application of its own.

For other issuers and the full checklist of what the client needs, see [Use your own OAuth server](/guide/going-further/own-oauth-server).

## Troubleshooting

| Symptom | Likely cause |
| --- | --- |
| `401 invalid_client` at `/oauth/token` | Wrong `client_id`; a confidential client without its secret (or with an old one after rotation); or a **secret sent to a public client**. Remove the secret from a public client's app. |
| The authorize page says "The redirect_uri is not allowed for this application" | Not an exact match: compare scheme, case, port, trailing slash and path (`appid:/auth/callback`, one slash). A native URI on a confidential client is never accepted. |
| "Unknown or disabled application" | Wrong `client_id`, or the application is disabled. |
| `invalid_grant` on a refresh | The refresh token was already used (two tabs or two devices sharing one, or a response lost after rotation), was revoked (**Sign everyone out**, a rotated secret), or expired. The whole family is revoked: sign in again. |
| `invalid_grant`: redirect_uri does not match | The token request's `redirect_uri` differs from the authorization request's, or the code was reused or expired (`codeTtl`). |
| `access_denied` at the token endpoint, or `403` at authorize | The user lacks an allowed role, the application is disabled, or `oauth:application:access` vetoed. |
| `409 managed_by_config` in the admin UI | The application is a configured client: edit `oauthServer.clients`. |
| `500 not_configured` | `oauthServer.clients` (or `NUXT_OAUTH_SERVER_CLIENTS`) is invalid; the server log names the problem. |
| Browser CORS error on the token request or the API | The origin is not in `cors.origins` (or the client's `corsOrigins`), or the API path is not under `cors.paths`. The authorization endpoint is never CORS-enabled, by design. |
| A confidential client in a mobile app or SPA | Do not. Register a public client: a secret in the bundle is public, and Auth's client mode fails the build for it. |
