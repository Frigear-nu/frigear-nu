[Auth in client mode](/modules/identity/auth/client-mode) signs users in as a **public client** with PKCE. It does not need
[`@frigear-nu/oauth-server`](/modules/identity/oauth-server), or frigear.nu: any issuer that meets the checklist below works.
Point `authentication.client.issuer` at it, register the app, and the rest of the app (the [mobile shell](/modules/interface/mobile), `$api`,
the login page) is unchanged.

## Requirements

Check each item at the issuer before you debug the app.

- [ ] **Discovery.** `GET <issuer>/.well-known/openid-configuration` (or `oauth-authorization-server`, RFC 8414)
  answers JSON whose `issuer` equals the configured `issuer` exactly, including any trailing path. Without discovery,
  set `authentication.client.discovery: false`: the client then uses the Frigear OAuth server paths, or the ones you list
in `authentication.client.endpoints` (listing endpoints alone does not turn discovery off).
- [ ] **PKCE with S256.** The issuer accepts `code_challenge_method=S256`. When the discovery document has
  `code_challenge_methods_supported`, it must list `S256`: the client refuses the issuer otherwise.
- [ ] **A public client with no secret.** The client has `token_endpoint_auth_method: none`: the token and revoke
  endpoints accept a `client_id` without `client_secret`. Never put a secret in the app: it would ship in the bundle, and a
  production build that embeds `NUXT_PUBLIC_AUTHENTICATION_CLIENT_CLIENT_SECRET` fails.
- [ ] **Exact redirect URIs.** Register each URI exactly, with no wildcards:
  - web: `<origin>/auth/callback`, for example `https://app.example.com/auth/callback` and, for development,
    `http://localhost:3000/auth/callback`;
  - native: `<appId in lowercase>:/auth/callback`, for example `com.example.app:/auth/callback` (a custom scheme with one
    slash, no host). Some providers call this a private-use URI scheme or a "native" application type.

  With `callbackPath` or `native.redirectUri` changed, register the changed URIs.
- [ ] **CORS from the webview.** The token, revocation, userinfo and discovery endpoints, and your API, answer
  requests from `capacitor://localhost` (iOS) and `https://localhost` (Android) and your dev origin, with the
  `Authorization` header allowed. Use exact origins, never `*`. The authorization endpoint is a navigation and needs no
  CORS.
- [ ] **Refresh tokens.** The client is allowed the `refresh_token` grant and the `offline_access` scope, and rotates
  refresh tokens (a used one is replaced, and a replayed one revokes the family). Add `offline_access` to
  `authentication.client.scopes`, or the session ends when the access token expires.
- [ ] **`iss` in the authorization response.** The issuer returns `iss` in the redirect (RFC 9207) and advertises
  `authorization_response_iss_parameter_supported: true`. The client rejects a response whose `iss` differs from the
  issuer, and one without `iss` when the issuer advertises support for it.
- [ ] **An id_token.** The scopes must include `openid`: the signed-in user (`useUserSession().user`) is mapped from the
  id_token's claims (`sub`, `name`, `email`, `picture`, `role`), and a sign-in whose response has no valid id_token
  fails. A userinfo endpoint is needed only with `client.userinfo: true`, or when your `client.mapUser` calls
  `userinfo()`.

## Frigear OAuth server

With [`@frigear-nu/oauth-server`](/modules/identity/oauth-server) on the issuer, a client is a **public application**: PKCE only
and no secret. Define it in config so its `client_id` is the same in every environment (the full walkthrough, including
confidential clients, is [Create an OAuth application](/guide/going-further/oauth-application)):

```ts [nuxt.config.ts (the issuer)]
export default defineNuxtConfig({
  oauthServer: {
    // Your own API that the app calls with the access token.
    cors: { paths: ['/api/'] },
    clients: [{
      id: 'bills',
      name: 'Bills',
      redirectUris: ['nu.frigear.bills:/auth/callback'],
      // Accepted under `nuxt dev` only.
      devRedirectUris: ['http://localhost:3001/auth/callback'],
      // The webviews' origins; native redirect URIs have none to derive.
      corsOrigins: ['capacitor://localhost', 'https://localhost'],
    }],
  },
})
```

| Option | Purpose |
| --- | --- |
| `oauthServer.clients` | Public clients with a fixed `client_id`. `NUXT_OAUTH_SERVER_CLIENTS` replaces the list with JSON. |
| `oauthServer.cors.origins` | Exact origins that may call the token, revoke, userinfo and discovery endpoints. The origins of configured clients are added. |
| `oauthServer.cors.paths` | Path prefixes of your own API that those origins may call with a bearer token. |

The app side:

```ts [nuxt.config.ts (the app)]
export default defineNuxtConfig({
  modules: ['@nuxt/ui', '@frigear-nu/auth'],
  authentication: {
    mode: 'client',
    client: {
      issuer: 'https://id.example.com',
      clientId: 'bills',
      scopes: ['openid', 'profile', 'email', 'offline_access'],
      native: { scheme: 'nu.frigear.bills' },
    },
  },
})
```

::note
Configured clients and `cors.paths` are options of the OAuth server release that adds them. Without them, register the
application in the admin UI as a public client, add the native redirect URI to it, and list the webview origins in
`oauthServer.cors.origins`. See [OAuth Server](/modules/identity/oauth-server).
::

## frigear.nu

frigear.nu runs the Frigear OAuth server. Use `issuer: 'https://frigear.nu'`.

- Staff register the client by hand in the admin area (**Public client**, with the redirect URIs above). Ask a staff
  member of frigear.nu; there is no self-service registration.
- CORS already allows `capacitor://localhost` and `https://localhost`, so the webview needs nothing more.
- Services behind the app accept the same access token through
  [OAuth Resource](/modules/identity/oauth-resource), so one sign-in serves every service.

## Keycloak

Setting names vary between versions; the intent is what matters.

Create a client in the realm: **Client authentication** off (public), **Standard flow** on, **Direct access grants** off.
Set **Valid redirect URIs** to the web and native callback URIs and **Web origins** to `capacitor://localhost`,
`https://localhost` and your dev origin (it sets CORS). Under **Advanced**, set **Proof Key for Code Exchange Code Challenge
Method** to `S256`. The issuer is `https://<host>/realms/<realm>`. Refresh token rotation is on when **Revoke Refresh Token**
is enabled in the realm's token settings. The `offline_access` scope must be a client scope of the client.

## Auth0

Create an application of type **Native** (apps in a Capacitor webview) or **Single Page Application** (browser only). Add
the callback URIs to **Allowed Callback URLs**, the origins to **Allowed Origins (CORS)** and **Allowed Web Origins**, and
enable **Refresh Token Rotation** under the application's settings. Add `audience` to `authentication.client.authorizationParams`
when you call an API registered at Auth0, and allow offline access on that API. The issuer is
`https://<tenant>.auth0.com/` (or your custom domain).

## Zitadel

Create an application of type **Native** (authentication method **None**, with PKCE) or **User Agent**. Register the
redirect URIs, set **Refresh Token** under grant types, and add the origins under **Additional origins**. Native apps accept
custom-scheme redirects; set the application to **Development mode** to register `http://localhost` redirects. The issuer
is your instance URL.

## Troubleshooting

| Symptom | Likely cause |
| --- | --- |
| The browser shows `invalid_redirect_uri` or `redirect_uri_mismatch` | The URI is not registered exactly. Compare scheme, case, slashes and the path (`appId:/auth/callback`, one slash). |
| `config` error: issuer mismatch | The discovery document's `issuer` differs from `authentication.client.issuer`, for example `http` against `https` or another path. |
| `config` error: `invalid_client` | The client is confidential, or its id is wrong. Register a public client. |
| Sign-in works in the browser, then the token request fails in the app | CORS: the token endpoint does not allow `capacitor://localhost` or `https://localhost`. |
| Signed in, but the session ends after the access token expires | No `offline_access` scope, no `refresh_token` grant, or the provider issues no refresh token to public clients. |
| Signed out after the first refresh | The provider rotated the refresh token and the response did not carry the new one, or two apps share one refresh token. |
| The `$api` calls get `401` and the user is signed out | The API does not accept the token (audience, issuer) even after a refresh. |
| The `$api` calls get `401`, the user stays signed in | No token was sent: the request's origin is not `client.apiBase`, the issuer or one of `client.apiOrigins`. |
| The sign-in fails right after the redirect back | No id_token in the token response: add `openid` to the scopes, and check that the issuer returns one to this client. |
| The app does not come back after signing in on a device | The native URL scheme is not registered in the iOS or Android project. Run `frigear-mobile native` and `frigear-mobile doctor`. |
| A production build fails with a client secret error | `NUXT_PUBLIC_AUTHENTICATION_CLIENT_CLIENT_SECRET` (or an old `NUXT_PUBLIC_OAUTH_CLIENT_SECRET`) is set. Remove it and use a public client. |
