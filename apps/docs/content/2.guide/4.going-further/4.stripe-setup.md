The [Stripe](/modules/commerce/stripe) module owns one verified webhook endpoint. [Payments](/modules/commerce/payments)
and [Subscriptions](/modules/commerce/subscriptions) register listeners on it for the events they need. This recipe sets
up the Stripe side once, so all of them work.

Stripe stays the source of truth for catalog data: the modules store no products or prices, only the customer id per user.

## Before you start

- `@nuxthub/core` with KV enabled (`hub.kv`, set by default). Webhook idempotency stores processed event ids in
  [NuxtHub KV](https://hub.nuxt.com/docs/kv) under `stripe:event:<event id>`, and `unstorage` must be resolvable by the
  host app. No extra table is needed.
- The modules installed and configured, as in the [Stripe](/modules/commerce/stripe) module's quick setup:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxthub/core', '@frigear-nu/users', '@frigear-nu/stripe'],
  hub: { db: { dialect: 'sqlite', driver: 'libsql' }, kv: true },
  stripe: {
    settings: { webhookPath: '/api/stripe/webhook' }, // default
  },
})
```

## 1. Add the webhook endpoint

1. In the Stripe dashboard, open **Developers > Webhooks** and add an endpoint pointing at
   `https://<your-host>/api/stripe/webhook` (or your `settings.webhookPath`).
2. Select the events your installed modules need (below).
3. Copy the signing secret into `NUXT_STRIPE_WEBHOOK_SECRET`.

Make sure no auth or CSRF middleware sits in front of the route: it reads the raw body and verifies the signature with
`constructEventAsync`.

### Events to subscribe to

| Module | Events |
| --- | --- |
| [Payments](/modules/commerce/payments) | `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`, `checkout.session.expired`, `charge.refunded` |
| [Subscriptions](/modules/commerce/subscriptions) | `customer.subscription.created`, `.updated`, `.deleted`, `.paused` and `.resumed` |
| Subscriptions with Payments installed | `invoice.paid`, `invoice.payment_failed`, `invoice.voided` and `invoice.marked_uncollectible`, for subscription invoices |

[Events](/modules/features/events) sells tickets through Payments, so it needs the Payments events. Without Payments no
invoice event is handled.

## 2. Set the keys

Read them through runtime config, never `process.env`.

| Variable | Runtime config | Purpose |
| --- | --- | --- |
| `NUXT_STRIPE_SECRET_KEY` | `stripe.secretKey` | Server-side secret API key (`sk_...` or a restricted key). |
| `NUXT_STRIPE_WEBHOOK_SECRET` | `stripe.webhookSecret` | Signing secret of the webhook endpoint (`whsec_...`). |
| `NUXT_STRIPE_API_VERSION` | `stripe.apiVersion` | Optional. Overrides the pinned API version. |
| `NUXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` | `public.stripe.publishableKey` | Publishable key (`pk_...`), exposed to the client. |

Without the secret key the Stripe client throws `501 not_configured`. Without the webhook secret the endpoint answers
`501 not_configured`.

## 3. Prepare products and billing

This step only applies to [Subscriptions](/modules/commerce/subscriptions).

- **Products and prices.** Create recurring prices. Use lookup keys to keep config environment-independent, because test
  and live have different price ids. No metadata or copy is needed in Stripe.
- **Billing portal.** In Settings > Billing > Customer portal, enable cancellation and payment method updates. Enable
  subscription updates only with `allowChangeInPortal: true`, and list the prices the portal may switch between.

One-time Payments need no products or prices: checkout sessions use inline `price_data`.

## Local development

Forward events with the Stripe CLI and use the secret it prints as `NUXT_STRIPE_WEBHOOK_SECRET`:

```bash
stripe listen --forward-to localhost:3000/api/stripe/webhook
```

## What the endpoint answers

| Status | Meaning |
| --- | --- |
| `200` | `{ received: true }`, or `{ received: true, duplicate: true }` for an already processed event id. |
| `400` | `bad_request`: missing `stripe-signature` header, missing body, or an invalid signature. |
| `501` | `not_configured`: `NUXT_STRIPE_WEBHOOK_SECRET` is not set. |
| `500` | `handler_failed`: at least one handler threw, and Stripe will retry the whole event. |

Handlers run sequentially and must be idempotent. The event id is written to KV (TTL 7 days) only after all handlers
succeed, so a duplicate delivery is acknowledged without running them again.
