Every module's API looks the same, so a client (the app, MCP, a test) can guess a URL and an error shape. The handlers
use the server toolkit from `@frigear-nu/module-kit/server`. Import it explicitly: it is not auto-imported, so nothing
clashes with h3's own helpers.

## URLs

- Everything lives under `/api/<module>`. Staff routes live under `/api/admin/<module>/...` (admin first, like the
  `/admin/<module>` pages), so a host can guard all of them with one `routeRules['/api/admin/**']`. The module's main
  resource is the module path itself: `GET /api/admin/events` lists events, `GET /api/admin/events/:id` reads one.
- Anything that is implicitly the caller's lives under `/api/<module>/me/...`.
- Ids are path params, collections are plural, and an action that is not CRUD is `POST /<resource>/:id/<verb>`.
- Partial update is `PATCH`, replacing a value is `PUT`, and a state change is never `GET`.
- Exceptions: spec endpoints (`/.well-known/*`, `/oauth/*`), webhooks and OAuth callbacks registered at a provider.
- Keep the paths in one place, `src/runtime/utils/api.ts`, as typed builders the app, tests and docs use.

## Registering routes

Register every route from one table in `module.ts` with `addModuleRoutes` from `@frigear-nu/module-kit/utils`. `file` is
relative to `./runtime/server/routes/`. `path` is joined onto `base` (required), and a path starting with `/` ignores
`base`. `''` is `base` itself.

```ts
import { addModuleRoutes } from '@frigear-nu/module-kit/utils'

addModuleRoutes(resolver, [
  { method: 'get', path: '', file: 'admin/events.get' },
  { method: 'post', path: '', file: 'admin/events.post' },
  { method: 'get', path: ':id', file: 'admin/event.get' },
  { method: 'patch', path: ':id', file: 'admin/event.patch' },
  { method: 'post', path: ':id/clone', file: 'admin/event-clone.post' },
  { method: 'get', path: '/api/events/me/tickets', file: 'me/tickets.get' },
], { base: '/api/admin/events' })
```

## Handler order

1. Authenticate and authorize (`requireAuth`, or the module's staff guard). Never answer 404 before 401 or 403.
2. Parse the path params, then the body or query, with h3's validated helpers and zod:
   `getValidatedRouterParams(event, idParams().parse)`, `readValidatedBody(event, schema.parse)`,
   `getValidatedQuery(event, schema.parse)`. No raw `readBody`, `getQuery` or `getRouterParam(...)!` on JSON routes, and
   no wrappers around the validated helpers.
3. Load the target, then act.

```ts
// src/runtime/server/routes/admin/thing.patch.ts
import { idParams, notFound } from '@frigear-nu/module-kit/server'
import { z } from 'zod'

const body = z.object({ name: z.string().trim().min(1).max(120) })

export default defineEventHandler(async (event) => {
  await myModuleStaff.require(event)
  const { id } = await getValidatedRouterParams(event, idParams().parse)
  const input = await readValidatedBody(event, body.parse)
  const thing = await findThing(id)
  if (!thing) throw notFound('Thing not found.')
  return toThingDto(await updateThing(id, input))
})
```

## Input

`idParams(name = 'id')` is a non-empty string and `intIdParams(name = 'id')` a positive integer (coerced). Both are zod
schemas for `getValidatedRouterParams`, so ids are validated the same way in every module.

```ts
const { id } = await getValidatedRouterParams(event, idParams().parse)
const { id: userId } = await getValidatedRouterParams(event, intIdParams().parse)
```

## Errors

Errors go through `apiError(status, code, message, data?)` and its shortcuts. The message is the `statusMessage` the UI
shows, and `data.code` is a snake_case code.

| Helper | Status | `data.code` |
| --- | --- | --- |
| `apiError(status, code, message, data?)` | any | `code` |
| `badRequest(message?, data?)` | 400 | `bad_request` |
| `validationError(issues, message?)` | 400 | `validation_failed`, issues in `data.issues` |
| `forbidden(message?, data?)` | 403 | `forbidden` |
| `notFound(message?, data?)` | 404 | `not_found` |
| `conflict(message?, data?)` | 409 | `conflict` |
| `notConfigured(message?, data?)` | 501 | `not_configured` |

Each returns an h3 error to `throw`. `requireAuth` answers the same way, with the codes `unauthorized`,
`session_required` and `insufficient_scope`.

```ts
import { conflict, notFound } from '@frigear-nu/module-kit/server'

if (!form) throw notFound('Form not found.')
if (await slugTaken(body.slug)) throw conflict('That slug is taken.', { field: 'slug' })
```

### Field issues

h3's `readValidatedBody(event, schema.parse)` answers a failed parse with a 400 whose `data` carries the zod error only as
text. When the client needs per-field issues, such as a form that marks each input, parse yourself with
`schema.safeParse` and throw `validationError(issues)`. The issues arrive in `data.issues`. Forms `submit` is the
example:

```ts
const result = definition.schema.safeParse(await readBody(event))
if (!result.success) throw validationError(result.error.issues)
```

## Responses

- Create: `created(event, dto)` (201). Update or action: 200 with the DTO. Delete or revoke: `noContent(event)` (204).
- Every response is an allowlisted DTO built by a `to<Entity>Dto()` in `server/utils`, never a database row. Dates are
  ISO strings (`isoDate`), and the DTO types live in `src/types.ts`.

| Helper | Purpose |
| --- | --- |
| `created(event, dto)` | Sets 201 and returns `dto`. |
| `noContent(event)` | Sets 204 and returns `null`, for deletes and revokes. |
| `isoDate(value)` | A `Date`, epoch milliseconds or date string as an ISO string; `null` and `undefined` as `null`. |

## Pagination

Admin lists are paginated, `{ items, total, page, pageSize }`, with `pageQuery()` and `paginate()`. They speak the query
keys of `useTableQuery` (`@frigear-nu/ui`): `page`, `pageSize` (default 20, at most 100), `q`, `sort`, `order` and the
`filters` keys. Small bounded lists (tokens, roles, plans) stay plain arrays.

```ts
import { likeContains, orderByQuery, pageQuery, pageRange, paginate } from '@frigear-nu/module-kit/server'

const listQuery = pageQuery({ sort: ['startsAt', 'slug'], filters: { status: z.enum(['draft', 'published']).optional() } })

export default defineEventHandler(async (event) => {
  await eventsStaff.require(event)
  const query = await getValidatedQuery(event, listQuery.parse)
  const where = and(
    query.q ? likeContains(schema.events.slug, query.q) : undefined,
    query.status ? eq(schema.events.status, query.status) : undefined,
  )
  const orderBy = orderByQuery({ startsAt: schema.events.startsAt, slug: schema.events.slug }, query, { tiebreaker: schema.events.id })
  const { limit, offset } = pageRange(query)
  const [rows, [totals]] = await Promise.all([
    db.select().from(schema.events).where(where).orderBy(...orderBy).limit(limit).offset(offset),
    db.select({ total: count() }).from(schema.events).where(where),
  ])
  return paginate({ items: rows.map(toEventDto), total: totals?.total ?? 0, query })
})
```

`likeContains` searches case-insensitively on both dialects without letting `%` and `_` in the search act as wildcards.

## Staff access

Use one guard per module, from `@frigear-nu/auth`:

```ts
// src/runtime/server/utils/staff.ts
export const myModuleStaff = defineStaffGuard({ hook: 'my-module:authorize', scope: 'my-module:manage', message: 'You cannot manage things.' })
```

`myModuleStaff.require(event)` is for reads and ordinary edits (API tokens with the scope work).
`myModuleStaff.require(event, { sessionOnly: true })` is for credentials, money and billing. `myModuleStaff.can(event,
userId)` is for places where a yes or no is needed, such as MCP tools. `require` returns `{ userId, principal }`; load the
full user with `loadAuthUser(userId)` when a route needs it. See [Auth and scopes](/guide/concepts/auth-and-scopes).

## Naming

- **Server utils.** Every module's `server/utils` is auto-imported into one Nitro namespace, so an exported name must be
  unique across all modules: prefix it with the module (`toFormTokenDto`, `toAuthTokenDto`, never a generic
  `toTokenDto`). Two modules exporting the same name clash and one silently wins.
- **Path builders.** Each module keeps typed path builders in `src/runtime/utils/api.ts` (`authApi`, `eventsApi`,
  `formsApi`, ...) and exports them as `@frigear-nu/<pkg>/api`. Import them from there in app code and tests, not from
  `./utils`, which also holds build-time helpers that pull in `@nuxt/kit`. Relative imports inside the package stay
  relative.

```ts
import { authApi } from '@frigear-nu/auth/api'
```

## Testing routes

`@frigear-nu/module-kit/testing` has two helpers for end-to-end tests against a fixture started with `setup()` from
`@nuxt/test-utils/e2e`:

- `apiClient({ cookie?, bearer? })` acts as one caller. `json<T>(method, path, body?)` resolves with the parsed body of a
  2xx response (`null` for 204) and rejects otherwise. `fetch(method, path, body?)` resolves with the raw `Response`
  whatever its status.
- `expectApiError(promise, status, code?)` asserts that the request failed with `status` (and `data.code`), and resolves
  with the error body.

```ts
import { apiClient, expectApiError } from '@frigear-nu/module-kit/testing'

const staff = apiClient({ cookie: staffCookie })
const created = await staff.json<{ id: string }>('POST', '/api/admin/events', { slug: 'party' })
await expectApiError(apiClient({ cookie: memberCookie }).json('DELETE', `/api/admin/events/${created.id}`), 403, 'forbidden')
expect((await staff.fetch('DELETE', `/api/admin/events/${created.id}`)).status).toBe(204)
```
